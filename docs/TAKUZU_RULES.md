# Takuzu — 正式ゲームルール

この文書は Simple Games 収録タイトル「Takuzu」の唯一のルールソースである。
実装(`apps/simple-games/src/games/takuzu/game/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。数値を変える場合はここを先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Hint は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

ゲーム ID は `takuzu`、i18n キーの接頭辞は `takuzu`、保存キーの接頭辞は `tk.` である。
名称は一般名の「Takuzu」を使う(§14)。

## 1. 盤面

- N×N のマス。**N は偶数**である。マスに入るのは `0` か `1` の 2 つだけ。
- プレイ中の各マスの状態: 未定 / `0` / `1`。
- **初期数字は固定**で、プレイヤーは動かせない(§4)。初期数字とプレイヤーの数字は
  別々に保持する — 混ぜると、§11 の fail-closed 検証が言えなくなる。

サイズは 3 種類(スマートフォンの画面に収まる形で決めた):

| サイズ | 1 行の 0 と 1 | 用途                            |
| ------ | ------------- | ------------------------------- |
| 6×6    | 3 個ずつ      | 導入帯(レベル 1〜20)            |
| 8×8    | 4 個ずつ      | 標準帯(レベル 21〜60・デイリー) |
| 10×10  | 5 個ずつ      | 上位帯(レベル 61〜100)          |

奇数サイズは作らない(行を 2 等分できないので規則 2 が何も言わなくなる)。
12×12 以上も作らない(1 マスが指で押せる大きさを下回る。Nonogram §1 と同じ床)。

**盤面に翻訳の要る文字は 1 つも載らない。**数字は ASCII の `0` と `1` に固定し、
言語を変えても盤面表記は変わらない([I18N_POLICY.md](I18N_POLICY.md)
「盤面の数字は全言語で ASCII の 0-9 固定」)。盤面は RTL でも左右反転しない。

## 2. 勝利

- **勝利**: すべてのマスが埋まり、§3 の 3 規則をすべて満たした時点。
- 敗北は存在しない。ミス回数の制限も、ライフも、ゲームオーバーもない(§14)。

判定は「埋まっている」かつ「§9 の違反が 1 つも出ていない」で行い、解と照合しない。
表示と判定が同じ読みから出るので、「きれいに見えるのに完成しない盤面」は作れない。

## 3. ルール(3 つ)

**規則 1 — 同じ数字は縦にも横にも 3 つ続かない。**

```
0 1 1 _   → 右端は 0(1 にすると 1 が 3 つ続く)
1 _ 1     → 中は 0
```

**規則 2 — 各行・各列で、`0` と `1` はちょうど N/2 個ずつ。**

```
6×6 の 1 行:  0 0 1 0 1 _   → 0 が既に 3 個なので、残りは 1
```

**規則 3 — 同じ並びの行が 2 つ、同じ並びの列が 2 つあってはならない。**

比べるのは**同じ軸どうし**である。行は行とだけ、列は列とだけ比べる。ある行とある列が
たまたま同じ並びになるのは違反ではない。

出題は常に一意解を持つ(§5)。

## 4. 操作

- **タップ**: 未定 → `0` → `1` → 未定 の循環。これが操作の全部である。
- **初期数字のマスは変更できない。**タップしても何も起きない。

**長押しもモード切り替えも作らない。** Nonogram は「塗る」と「×」という性質の違う
2 つの印を持つので、長押しと ×モードのトグルが要る(NONOGRAM_RULES.md §3)。
Takuzu の 3 状態は 1 本の循環の上に並んでいて、どれも同じ「数字を置く」操作である。
分岐する操作がないところに 2 つ目のジェスチャーを足すと、覚えることだけが増える。

## 5. 「推測なし」の保証

**これがこのタイトルの中心的な設計判断である。**

出題は必ず、**次の 3 つの技法だけで最後まで解ける**。

1. **ペアと穴** — 隣り合う 3 マスに同じ数字が 2 つと未定が 1 つあれば、その未定は
   反対の数字で確定する。`1 1 _` も `_ 1 1` も `1 _ 1` も、規則 1 を 3 つの位置から
   読んだ同じ話である。
2. **行・列カウント** — 一方の数字がその行(列)で N/2 個に達したら、残りの未定は
   すべてもう一方で確定する(規則 2)。
3. **重複禁止からの確定** — 未定が 2 マスで `0` と `1` が 1 個ずつ足りない行(列)は、
   埋め方が 2 通りしかない。同じ軸に完成した行(列)があって、既に書かれたマスすべてで
   一致しているなら、規則 3 がその一方を禁じるので残りは一意に決まる。

未定 1 マスの行に専用の規則は要らない。書かれたマスが奇数個なら 2 つの数の個数は
等しくなり得ないので、技法 2 が先に発火している。

**3 つとも健全である。**どれも「合法な完成形すべてが一致する値」しか書かない。
したがってこの技法だけで埋め切れる盤面は解が 1 つだけであり、推測なしで必ず完成できる。

理由: 推測で数字を置かされる二値パズルは、プレイヤーの論理を裏切る。
Sudoku・Minesweeper・Nonogram で推測を排したのと同じ理由で、ここでも排する。

**技法の実装は 1 つだけ持ち、3 人の利用者が共有する** — 生成時の検査(§6)、
Hint(§8)、`guarantee.test.ts`。約束と検査と助けを別々に実装すると、静かに食い違う
(Sudoku §8 のグレーダーと同じ理由)。

## 6. 盤面生成と Seed

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。

1. **完成盤を作る。**合法な行(半分が `0`、3 連続なし)は、サイズごとの短い固定の
   アルファベットである — 6 幅で 14 本、8 幅で 34 本、10 幅で 84 本しかない。これを
   seed でシャッフルし、上から 1 行ずつ置く。アルファベット自体が規則 1 と規則 2 を
   満たし、行を使い回さないので規則 3 も行については構成上ただになる — 埋めながら
   見るのは列だけでよい。最後に列同士の重複を確認する。置いた行が 20,000 を超えたら
   その seed は諦める。
2. **掘る。**マスを seed 由来のシャッフル順に 1 つずつ取り除き、§5 のソルバーが
   全マスを確定できる間だけ取り除きを残す。帯の目標(§7)に達したら止める。
   **1 パスで十分である** — 初期数字が減ればソルバーの言えることは減る一方なので、
   あるとき取り除けなかったマスが、あとで取り除けるようになることはない。
3. 目標に届かなければ **seed を派生させて作り直す**(`<seed>#2`, `#3`, …)。上限 24 回。
4. 上限に達したら、その時点で最も深く掘れた候補を出題する。

不変条件:

- 同じ seed なら、必ず同じ盤面になる(golden テストで固定する)。
- 出題は §5 の 3 技法だけで解ける(推測不要・解は一意)。
- **初期数字の個数は目標であって約束ではない。**手順 4 の盤面は、一意解であることも
  推測が要らないことも変わらないが、帯が求めたより易しい。出荷してよい唯一の失敗の形
  なのでこれを選んである。発生率は監視する(現状、全 100 レベルと 730 日ぶんの
  デイリーで 0 件)。

### 予算は仕事量で門にする

これは**端末の予算**であって、開発機やテストランナーの予算ではない。だから門は
壁時計ではなく**ソルバーが読んだ行の本数**(`solverWork`)で測る。掘削は数十回の
フル解答であり、フル解答は全行全列の掃きの積み上げなので、生成コストはこの数に
比例する。同じ seed なら、どのマシンでも常に同じ数になる。理由ごと
[SUDOKU_RULES.md](SUDOKU_RULES.md) §7 に詳しい(並列テストで壁時計は最大 41 倍ぶれる)。

実測(開発機、全 100 レベルを §7 の割り当てで生成 + デイリー 365 日):

| サイズ   | n   | 行読み p50 | p90    | 最悪   | 壁時計 p50 | 壁時計 最悪 |
| -------- | --- | ---------- | ------ | ------ | ---------- | ----------- |
| 6×6      | 20  | 2,614      | 3,747  | 3,988  | 5.5ms      | 20.8ms      |
| 8×8      | 40  | 8,136      | 13,285 | 27,269 | 5.1ms      | 23.7ms      |
| 10×10    | 40  | 21,988     | 31,109 | 33,585 | 13.7ms     | 36.3ms      |
| デイリー | 365 | 8,269      | 10,710 | 13,878 | 4.1ms      | 25.9ms      |

**この表の壁時計の列は、順序からして壊れている。**6×6 の p50(5.5ms)が 8×8 の
p50(5.1ms)より遅い。6×6 は level 1 から走るので JIT の暖機を丸ごと被っており、
測っているのは盤面の大きさではなく実行順である。同じ走査で行読みは
2,614 → 8,136 → 21,988 とサイズどおりに並ぶ。門をどちらに立てるかは、余裕の大小では
なく**測っているものが違う**というこの一点で決まる。

門(`guarantee.test.ts` が全 100 レベルとデイリー帯を走査して固定する):

- 1 盤面あたりの行読みは **60,000 未満**(実測の最悪はレベル 98 の 33,585。約 1.8 倍の
  余裕を取ってある)。サイズごとに分けないのは、これが端末の約束ではなく**退行の門**
  だからである — 捕まえたいのは「技法が安い順の打ち切りをやめた」「掘削が確定済みの
  行を読み直し始めた」であって、そのどちらもサイズを問わず数字に出る。
- 派生シードは **8 回以下**(実測の最悪はレベル 63 の 5 回。91 レベルは 1 回目で決まる)。
  上限の 24 回よりずっと手前に置いてあるので、手順 4 に落ちるより先に警告が出る。
- 手順 4 の発生は 0 件。掘削は帯の目標に届いている。
- 壁時計は計測して出力するだけで、判定には使わない。

端末の予算は 1 盤面 100ms 未満。超えた場合の対処順序: ①掘削の目標を上げる
②派生シードの上限を下げる ③(最後の手段)ビルド時生成したパズルパックの同梱。
**低スペック実機での実測はまだ行っていない。**上の数字は開発機のものであり、端末での
実測は [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) §2 で確認する。

## 7. レベル(1〜100)とデイリー

**レベル**: level 番号だけからサイズ・初期数字の割合・seed を決定的に導出する。
コンテンツパイプラインもダウンロードもなし。誰が遊んでも同じレベルは同じ盤面。

| レベル帯 | サイズ | 初期数字の割合 | 個数    |
| -------- | ------ | -------------- | ------- |
| 1〜20    | 6×6    | 50% → 31%      | 18 → 11 |
| 21〜60   | 8×8    | 45% → 28%      | 29 → 18 |
| 61〜100  | 10×10  | 40% → 27%      | 40 → 27 |

帯の内側では線形に下がり、隣り合うレベルが跳ねない。seed は `takuzu-level-<n>`。

**帯の変わり目で割合が上がるのは意図的である。**同じ割合でも盤面が大きいほど難しい —
1 つの推論が届く距離が伸び、規則 2 が効き始めるまでに読む行が長くなる。割合をそのまま
持ち越すと、帯の 1 レベル目が壁になる(Nonogram §6 の充填率と同じ形)。

**レベル数は 100 で、999 には引き伸ばさない。**999 にすると 1 レベルあたりの変化が
マス 1 個を割り、同じ盤面が seed 違いで何百も並ぶだけになる(Sudoku §9 / Nonogram §6
の圧縮判断を、最初から採る)。レベルは順番に解放し、解放済みはいつでも選び直せる
(seed が同じなので同じ盤面)。

**デイリー**: 1 日 1 問。seed は `takuzu-daily-<YYYY-MM-DD>`(端末のローカル日付のみ。
サーバー時刻もネットワークも使わない)。

- **毎日 8×8・初期数字 36%(23 個)固定。**曜日でサイズや深さを変えると
  「当たり日 / 外れ日」という圧を生むため採らない(Sudoku §10)。
- **過去 30 日は無条件に開いている。**前の日を解かないと次が開かない、という連鎖解錠は
  付けない — 貯まった過去日を宿題にしない。
- 達成した日は記録する。**ストリークは数えない・表示しない。**

中断はレベル用・デイリー用の **2 スロットを独立して保持**する(§11)。別のレベルを
始めると、レベル用スロットは置き換わる(確認を出す)。

## 8. Undo と Hint

- **Undo は作らない。**すべてのマスはタップで 未定 → `0` → `1` → 未定 と一巡する(§4)。
  すべての手がもともと可逆なゲームに Undo を重ねても、同じ操作が 2 つ並ぶだけである。
  Minesweeper が「取り消せては困るから」作らないのと逆の理由で、ここでは
  「取り消しがもう存在するから」作らない。

  **Sudoku が Undo を持つのは、あちらの手が非自明に不可逆だからである。**数字を入れると
  そのマスのメモが消え、同じ行・列・ボックスのメモからも自動で消える(Sudoku §3)。
  1 タップで消えた候補を手で復元することはできない。Takuzu にはメモも自動消去もないので、
  その理由が発生しない。**同じ機能を全タイトルに並べることが原則ではない**
  ([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))。

- **Hint は作る。無制限・無料。**現在の盤面に §5 の技法を適用し、**新しく確定するマスを
  1 つ示す**(数字は入れない)。根拠になる行または列も強調する — 規則 3 による確定なら、
  比べた相手の行(列)も一緒に示す。ただし**規則を破っている行(列)があるときは、先に
  その行を示す** — 壊れた並びの上に積んだ確定を教えても、正しい導きにならないためである。
  平易な一文を添え、**技法名は UI に出さない**(文章量の最小化 —
  [I18N_POLICY.md](I18N_POLICY.md))。解と直接照合して「ここが間違い」と教える形は
  採らない — それは §5 の論理ではなく答え合わせだからである(§9)。どちらも見つからない
  ときは「今わかる手が見つかりません」と表示し、盤面は変えない。

## 9. 違反表示

常時オンで、3 規則それぞれに対応する:

- 同じ数字が縦横に 3 つ続いたとき、その 3 マス。
- 行(列)の一方の数字が N/2 を超えたとき、その数字のマス。**埋まりきる前に出す** —
  超えた時点で、その行はもう完成できない。
- 埋まった行(列)が、同じ軸の別の埋まった行(列)と同じ並びになったとき、両方。
  埋まっていない行は放っておく。まだ何かの重複ではない。

**これはルール違反の指摘であって、答え合わせではない。**規則を破っていない数字は、
それが解と違っていても何も言われない。

**「解と違う」の表示は作らない。**Sudoku はミスの即時表示を設定トグル(既定オン)で
持っているが、ここには置かない。Sudoku のミスは「一意解と異なる数字」という定義を
必要とするのに対し、Takuzu で置ける数字は 2 つしかなく、規則を破らない誤りは
「まだ矛盾していないだけ」である。それを警告色にするのは論理の支援ではなく解答の開示になる。

この判断の結果として、**このゲームには盤面をまたいで覚える設定が 1 つもなく、
`tk.prefs` キーが存在しない**(§11)。ミス回数も概念ごと存在しないので、記録も表示もしない。

## 10. 時間と統計

- **プレイ中に時計を表示しない**(ブランド原則)。経過時間は内部で記録し、結果画面と
  統計でのみ見せる。
- 統計: クリア数、**サイズ別の最短時間**、合計プレイ時間、デイリー達成日数。
- **スコアは作らない。**ランキングもストリークも作らない。自己ベストの更新は、更新した
  ときだけ静かに示す。

## 11. 中断と再開

- レベル用とデイリー用の**2 スロットを独立して保持する**。レベルを中断してデイリーを
  遊んでも、どちらも失われない。
- 保存するのは モード / seed / レベル番号または日付 / サイズ / 初期数字 / 解 /
  プレイヤーの数字 / Hint 回数 / 経過秒数 / 保存時刻。**ミス回数は持たない** —
  このゲームにミスという概念がない(§9)。
- **どちらのスロットのレコードかを決めるのはキーである。**両スロットは同じ形のレコードを
  持つので、レベル用のキーに入っている `mode: 'daily'` のレコードは「デイリーだった」の
  ではなく壊れている。復元せず既定値へ落とす([ARCHITECTURE.md](ARCHITECTURE.md))。
  この規則は `src/test/savedGameSlots.test.ts` が二重スロットのゲームを走査して自動強制する。
- **検証は fail-closed。**プレイから生まれえないレコードは読み捨ててホームへ戻す:
  - 解が §3 の 3 規則を破っている
  - サイズが 6 / 8 / 10 でない、または配列の長さがサイズと合わない
  - 初期数字またはプレイヤーの数字に `0` / `1` / 未定 以外が入っている
  - プレイヤーの数字が初期数字のマスを上書きしている(タップは初期数字を動かさない — §4)
  - 初期数字が解と食い違っている
- 背景へ回るとき、盤面の保存と未計上秒の計上を**同じ同期処理で**行う。OS は別のイベント
  なしにアプリを終了できるため、盤面だけを保存すると前回の同期以降の秒数が永久に失われる。
- 保存キーは `tk.saveGame` / `tk.saveDaily` / `tk.stats` / `tk.progress` / `tk.flags` の
  **5 つ**。`tk.stats` はサイズ別の記録、`tk.progress` は解放済みレベルとレベル別・
  日付別のベスト(デイリー達成日はこの疎マップから導出し、カレンダー専用のレコードは
  持たない)、`tk.flags` はチュートリアル完了。**`tk.prefs` は無い** — 覚える設定が
  1 つもないため(§9)。
- 保存の失敗でゲームを止めない。バリデータは例外を投げない。

## 12. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ原則 1 文・図中心([I18N_POLICY.md](I18N_POLICY.md))。

1. タップで 空 → `0` → `1` → 空。同じ数字は 3 つ続けない。
2. どの行・列も、`0` と `1` が同じ数になる。
3. 同じ並びの行(列)は 2 つ作れない。

詳細ルール・攻略・FAQ はアプリに入れず、ゲーム別 Landing Page
(`https://pixapps.ai/simple-games/games/takuzu/<locale>/`)へ分離する。チュートリアルの
「詳しく見る」から開く。オフラインでは静かに何もしない(ゲームは止めない)。

## 13. 演出とアクセシビリティ

- **`0` と `1` は数字の形で区別する。**2 つの控えめな地色は補助であって、色だけに意味を
  持たせない。地色を全部外しても盤面は読めなければならない。
- 違反表示も色だけに頼らない。警告色に枠を併用する。
- 初期数字とプレイヤーの数字は、色ではなく字の太さで分ける。
- Reduced Motion が有効なら、数字が変わる演出は即時にする。
- 各マスはボタンで、**行・列と状態(未定 / `0` / `1` / 初期数字)**を読み上げる。
  初期数字であることが読み上げから分かること。
- **10×10 の 320px でのタップ精度は、まだ実機で確認していない。**
  [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) §2 の門で確認し、通らなければ上位帯を
  8×8 に落として**この文書を先に直す**。

## 14. 意図的な差分

ブランド原則により合わせないもの:

- ミス回数制限・ライフ制・ゲームオーバー(しない。そもそもミス判定をしない — §9)
- プレイ中のタイマー表示、ストリーク、オンラインランキング、スコア(しない)
- Hint を広告視聴やコインの報酬にすること(しない。常に無料・無制限 — §8)

設計判断として合わせないもの:

- **●○ や色タイルの表記。**ASCII の `0` と `1` は 14 言語すべてで同じに読め、読み上げも
  一意になる([I18N_POLICY.md](I18N_POLICY.md))。丸や色のタイルにすると盤面の意味が
  凡例に依存し、読み上げは「白い丸」のような見た目の説明に落ちる。
- **奇数サイズ。**行を `0` と `1` で等分できず、規則 2 が何も言わなくなる(§1)。
- **12×12 以上。**1 マスが指で押せる大きさを優先する(§1。Nonogram §1 と同じ床)。
- **Binairo / 0h h1 を名乗ること。**どちらも他社の商品名である。Othello を使わず
  Reversi と呼んだのと同じ物差しで、一般名の Takuzu を使う
  ([REVERSI_RULES.md](REVERSI_RULES.md))。
- **変種ルール**(3 値化・奇数盤・対角制約など)。v1 は 1 規則セットだけを扱う。
- **Undo**(作らない。§8)/ **「解と違う」の表示**(作らない。§9)
- **推測が必要な盤面・複数解の盤面**(出さない。§5)
- **問題データの同梱・配信**(すべて端末上で生成する。§6)

合わせたもの:

- 3 規則の標準セット、一意解、常時の違反表示、タップ 1 種類だけの操作。
