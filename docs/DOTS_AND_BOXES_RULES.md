# Dots and Boxes — 正式ゲームルール

このドキュメントが Dots and Boxes の仕様の正本である。実装
(`apps/simple-games/src/games/dots-and-boxes/`)、テスト、Quick Rules はここに従う。
コードはここへ `§n` で言及する。挙動を変えるときは、同じコミットでこの文書を直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

ゲーム ID は `dots-and-boxes`、i18n キーの接頭辞は `dotsAndBoxes`、保存キーの接頭辞は
`db.` である。Web 版の先行公開(ベータ)タイトルであり、アプリには正式収録していない
([WEB_VERSION.md](WEB_VERSION.md)「先行公開(ベータ)」、issue #197)。

## 1. 盤面と対局者

- 盤は箱が **3×3(小)/ 4×4(中)/ 5×5(大)** の 3 サイズ(`game/types.ts` の
  `BOXES_FOR`)。1 辺の箱数を N とすると、点は (N+1)²、辺は横 (N+1)×N 本と
  縦 N×(N+1) 本で、合計 E = 2N(N+1) 本。
- 辺の番号: 横の辺 `h(r, c) = r × N + c`(r = 0..N は点の行、c = 0..N−1)、
  縦の辺 `v(r, c) = (N+1) × N + r × (N+1) + c`(r = 0..N−1、c = 0..N は点の列)。
  箱 (r, c) の番号は `r × N + c` で、その 4 辺は上 `h(r, c)`・下 `h(r+1, c)`・
  左 `v(r, c)`・右 `v(r, c+1)`。
- 盤面は 2 本の文字列で表す。`edges` は 1 辺 1 文字 — `0` = 未使用、`1` = 自分が
  引いた、`2` = CPU が引いた。`boxes` は 1 箱 1 文字 — `.` = 空き、`p` = 自分、
  `c` = CPU。**辺に持ち主を持たせる**のは §10 の描き分け(どちらが引いた線か)の
  ためで、盤面規則には関与しない(規則が見るのは「引かれているか」だけ)。
- 対局相手は CPU だけ(オンライン対戦・ローカル対人戦は作らない —
  [PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))。**先攻は常に自分**(§11)。
- 盤サイズはホームで選ぶ。最後に選んだサイズを `db.prefs` に覚え、次にホームを
  開いたときそのボタンが先頭の強調になる(進行中の対局があればそちらが優先)。

## 2. 一手の解決

1. 未使用の辺を 1 本タップして引く(`game/engine.ts` の `claim`)。
2. その辺で **4 辺そろった箱は、引いた側のもの**になる。1 本で 2 箱そろうこともある
   (内側の辺は 2 つの箱に接する)。
3. **箱が 1 つでもできたら、同じ側が続けてもう 1 手**。できなければ手番交代。
4. 引かれた辺への入力は何も起きない — 引かれた辺はボタンではなくなる(§10)。

## 3. 終了条件

- 全部の辺が引かれたら終局。箱の多い方の勝ち。
- 箱の総数は 9 / 16 / 25 なので、引き分けは 4×4 だけで起きる(8 対 8)。
- 遷移は `status`(`'playing' | 'won' | 'lost' | 'draw'`)で一度だけ起きる
  (`game/session.ts`)。

## 4. CPU

- 強さは 1 段階。盤サイズが遊びの選択肢である(§11)。
- 1 手ごとに次の順で辺を選ぶ(`game/cpu.ts` の `chooseCpuMove`)。探索木は持たない。
  1. **箱を完成できる辺**があれば引く。2 箱同時にできる辺を優先する。
  2. なければ、**どの箱にも 3 辺目を与えない「安全な」辺**。
  3. それも無ければ、各候補について「引いたあと相手が完成できる辺を取り続ける」
     貪欲な回収を模擬し、**渡す箱が最少の辺**。
- 同じ段の中の同点は、セッションのシードと手数から決定的に選ぶ:
  `createRng(`${seed}:cpu:${moveCount}`)` でシャッフルした順の先頭。同じシードで
  同じ手順を踏めば CPU は必ず同じ辺を返す。ゴールデンテスト
  (`game/compatibility.test.ts`)が固定する。
- 仕事量は有界である: 模擬の回収は 1 回あたり高々箱の数だけ辺を引くので、5×5 でも
  1 手の選択で引く辺(候補 + 模擬)は数千本に届かない。テストは壁時計ではなくこの
  仕事量(`cpuCost.work`)で門にする(`game/cpu.test.ts`)。
- CPU の 1 本は約 450ms 置いてから盤面に現れる(`CPU_DELAY_MS`、
  `state/GameContext.tsx`)。1 本の timeout がセッションを依存に張られ、選択は
  その**中**で走る([GAME_LIFECYCLE.md](GAME_LIFECYCLE.md)「CPU 探索」)。
  CPU が箱を完成して手番を続けるときは、次の 1 本がまた 450ms 後に現れる —
  **連続手は 1 本ずつ見える**。タイマーを張り直すのはセッションの変化だけで、
  ループも待ち合わせも書かない。アンマウント・Undo・新規対局はこの遅延を破棄する。

## 5. Undo

- **無制限・無料**。自分の直前の決定点(自分が辺を引く直前の局面)まで戻す。
  その後の CPU の連続手はまとめて取り消される。CPU の手番の途中には戻さない。
- 自分が箱を完成して続けて引いた場合、その 1 本 1 本がそれぞれ決定点である。
- 履歴は `UNDO_HISTORY_LIMIT`(100)件まで。5×5 でも辺は 60 本なので実質無制限。
- Undo は振り直しではない: 戻して同じ辺を引けば、CPU も同じ辺を返す(§4 の決定性)。
- 広告視聴や課金による Undo は作らない([ADS_POLICY.md](ADS_POLICY.md))。

## 6. 助けの形

- 助けは Undo ひとつ(§5)。無料で、無制限で、初回起動から使える。
- **Hint は作らない**: 盤面は完全に見えており、隠れた情報がない。次の一手を教える
  機能は CPU がプレイヤーの側でも打つことになる(docs/REVERSI_RULES.md §7 と同じ)。
- 未使用の辺は淡い線で常に見えている(どこに引けるかは盤面そのものが示す)。

## 7. スコアと統計

- 対局中のスコアは両者の箱数だけで、上のバーに常に出す(「あなた n · CPU m」)。
- 統計は盤サイズごとに `played`(開始した回数)・`wins`・`losses`・`draws`、全体で
  `totalPlaySeconds`。ストリークは数えないし表示しない。
- 対局を放棄して新しく始めた場合、負けには数えない(`played` には既に数えている)。
- プレイ時間は逐次計上(bookedRef 方式、Connect Four と同じ)。

## 8. 中断と再開

- **途中保存する。**ターン制で、保存して開き直した盤面は保存した瞬間と同じである。
- 保存スロットは 1 つ(`db.saveGame`、schemaVersion 1)。`size` / `seed` / `edges` /
  `boxes` / `toMove` / `moveCount` / `elapsedSeconds` / `savedAt`
  (`storage/gamePersistence.ts`)。**手番は保存する** — 箱を完成した側が続けて
  引くので、盤面からは導出できない。
- CPU の手番中(遅延中・連続手の途中)に離れた場合も、保存した手番のまま戻り、
  再開時に CPU が続きを打つ。
- **Undo 履歴は保存しない**。再開した対局はその局面から始まる。
- 壊れた保存は読み捨てて、ホームへ戻る(勝手に新しい対局を始めない)。検証は
  fail-closed:
  - 盤サイズが 3 つのどれでもない、`edges` / `boxes` の長さがサイズと合わない、
    文字が上の記号以外。
  - 4 辺そろった箱に持ち主が無い、またはそろっていない箱に持ち主がある
    (`isConsistent`)。
  - **手数が引かれた辺の本数と一致しない**(1 手は必ず 1 本なので、両者は必ず
    一致する。手数は CPU の抽選の半分(§4)なので、食い違う保存を再開させると
    保存した対局とは違う応手を返す)。
  - 手数 0 なのに CPU の手番(先攻は常に自分 — §1)。
  - 終局済みの盤面(全部の辺が引かれている)。

## 9. Quick Rules(アプリ内チュートリアル)

3 ステップ・図中心・各 1 文程度(初回起動時に表示、以後はホームから):

1. 点と点の間をタップすると線が 1 本引ける。
2. 箱の 4 辺目を引いたらその箱は自分のもの。続けてもう 1 本。
3. 線が全部引けたら、箱の多い方が勝ち。

各ステップに 2×2 の小さな盤の図を置く。初回の「はじめる」は 3×3 の対局を始める。
ガイドを公開するまで「詳しく見る」は出さない(`src/ui/landing.ts`)。

## 10. 演出とアクセシビリティ

- 盤面は CSS grid で、点のトラック(10px)と辺のトラック(`1fr`)を交互に並べる。
  未使用の辺は `<button>` でトラックのセルいっぱいを覆い、当たり判定は透明な
  疑似要素で**太さ 24px 以上**(見た目の線は 4px 以下)。引かれた辺は操作できない
  要素になる。
- 引かれた辺は持ち主で描き分ける: 自分 = タイトルのアクセント色の実線、CPU =
  このゲームの第 2 色(`--db-cpu`、ゲーム内容の色)の**破線**。箱には持ち主の印を
  SVG で置く(自分 = ●、CPU = ✕)。**色だけに頼らない**。第 2 色は地色
  (`--surface`)に対してライト・ダークとも 3:1 以上(`ui/contrast.test.ts`)。
- 直前に引かれた辺には短い強調を付ける(手数をキーに 1 回だけ。Reduced Motion では
  出さない)。CPU の連続手を目で追えるためである。
- 手番行は 1 行固定: 「あなたの番」/「もう 1 本!」(自分が箱を取った直後)/
  「CPU が考えています…」。終局後は空。盤面が跳ねない。
- 読み上げ: 盤は `group`、未使用の辺はボタンで「横の線 r, c」「縦の線 r, c」
  (線の左端・上端にある点の行・列、1 始まり)、箱は「箱 r, c」。引かれた辺と箱は
  持ち主を含めて読み上げる。
- キーボード: 辺は普通のボタンなので Tab / Enter(Space)で引ける。引いたボタンは
  消えるので、フォーカスは次の未使用の辺へ移す。CPU の手番中も辺のボタンは
  無効化しない(`aria-disabled`)— 無効化するとフォーカスが毎手失われる。
  Ctrl/Cmd+Z で Undo。確認ダイアログや結果カードの間は盤面ごと `inert` になり、
  キーも受けない。
- 効果音は既存の合成音(`services/sound`)のみ: 線で `select`、箱の完成で `match`、
  勝ちで `clear`、負け・引き分けで `gameOver`。設定に従う。
- **決着してから結果カードが出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。
- **時計を出さない**。経過時間は統計にだけ残る。
- 360×640 の画面で 5×5(点 6×6)がスクロールなしに収まる。

## 11. 意図的な差分

市中の Dots and Boxes アプリを調べたうえで、意図的に合わせないものを記録する。

**ブランド原則により合わせないもの**

- **Undo・盤サイズを広告や課金に結び付けない**。3 サイズとも最初から選べる。
- レーティング・ランキング・オンライン対戦はない。記録は端末の中だけにある(§7)。
- デイリーやストリークで毎日呼び戻さない。

**設計判断として合わせないもの**

- **線はタップで引く。ドラッグで点から点へ引く操作は作らない。**辺ごとのボタンは
  太さ 24px 以上の当たり判定を持ち、タップで十分正確に狙える。ドラッグを足しても
  正確さは上がらず、pointer 契約(`pointercancel`・ドラッグ後の click の扱い、
  `src/test/pointerContractWiring.test.ts`)の負担だけが増える。
- **先攻は常に自分**。先後の選択は置かない — 盤サイズが遊びの選択肢であり、
  選択肢を 2 つ重ねる理由がない。
- **CPU の強さは 1 段階**。難易度の代わりに盤サイズ(3 / 4 / 5)を選ぶ。
- **CPU は連鎖・ループの終盤理論(ダブルクロス、長連鎖の規則)を使わない。**
  §4 の貪欲 + 安全手 + 最少献上の 3 段で止める。完全読みの CPU は「勝てない相手」に
  しかならず、上限を超える探索は 450ms の「間」を待ちに変える
  ([GAME_LIFECYCLE.md](GAME_LIFECYCLE.md)「CPU 探索」)。
- **Hint は作らない**(§6)。
