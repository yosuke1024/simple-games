# Sudoku — 正式ゲームルール

この文書は Simple Games 収録タイトル「Sudoku」の唯一のルールソースである。
実装(`apps/simple-games/src/games/sudoku/game/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。数値を変える場合はここを先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Hint / Undo は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

## 1. 盤面

- 9×9 = 81 マス。3×3 のボックス 9 個に分かれる。
- マスは「初期数字(固定)」「プレイヤーが入れた数字」「空」のいずれか。
- 各マスはメモ(候補数字 1〜9 の任意の組)を持てる。
- 使用する数字は ASCII の `1`〜`9` に固定する(言語を変えても盤面表記は変わらない)。

## 2. 勝利条件

81 マスすべてが埋まり、各行・各列・各ボックスに 1〜9 がちょうど 1 個ずつ入った状態。
これは「盤面に重複がない」ことと同義であり、実装は重複ゼロ + 空マスゼロで判定する。

出題は常に一意解を持つ(§7)。したがって完成形は 1 つだけであり、
「正解と異なる数字」を機械的に判定できる。

## 3. 操作

1. マスを選ぶ(初期数字のマスも選べる。選ぶと同じ数字がハイライトされる)
2. 数字パッドで 1〜9 を入れる / 消す
3. メモモードのとき、数字パッドはメモの追加・削除になる

規則:

- 初期数字のマスは変更できない。
- 数字を入れると、そのマスのメモは消える。
- 数字を入れると、**同じ行・列・ボックスのメモから同じ数字を自動で消す**
  (手作業の消し込みを省く。ルールを変える支援ではない)。
- 数字を消すと、そのマスは空に戻る。メモは復元しない(Undo で戻せる)。
- 数字パッドは各数字の残り個数(9 − 盤上の個数)を表示し、9 個置き終えた数字は無効化する。

## 4. ミスと支援

- **ミス上限はない。ゲームオーバーもない。** 3 ミスで失格のような仕様は採らない。
- ミスの定義: 一意解の値と異なる数字を空マスに入れたとき、ミス 1 回。
  同じマスに続けて別の誤答を入れれば、その都度 1 回。
- **ミスの即時表示**(誤答マスを警告色にする)は設定で切り替え。**既定はオン**。
  オフのときも重複表示(下記)は出る。
- **重複表示は常時オン**: 同じ行・列・ボックスに同じ数字が 2 個以上あるとき、
  その数字のマスを警告表示する。これはルール違反の指摘であり、答え合わせではない。
- ミス回数は記録し、クリア画面と統計で見せる。プレイ中はカウンタを常時表示しない。

### Undo

- 無制限(実装上の上限は Number Match と同じ 2000 手)。
- Undo の対象は「数字の配置」「数字の消去」「メモの変更」。
- Undo はミス回数を戻さない(誤答した事実は消えない)。Hint 使用回数も戻さない。
- 保存された中断ゲームに Undo 履歴は含めない(Number Match と同じ)。

## 5. Hint

Hint は「次に論理だけで確定できるマス」を 1 つ示す。答えを埋めるのではなく、
**なぜそこが確定するのかを示す**(§8 のグレーダーの解法パスを流用する)。

- 対象マスと、根拠になる行 / 列 / ボックスを強調表示する。
- 短い一文を添える。**技法名(Naked Single、X-Wing など)は UI に出さない。**
  平易な言い換えのみ(例:「この行で 5 が入るのはここだけ」)。
  理由: 文章量を最小化する UI 原則([I18N_POLICY.md](I18N_POLICY.md))と、
  多言語での用語統一コストを避けるため。技法名は内部表現・テスト・
  Landing Page の解説にのみ使う。
- Hint は数字を入れない。プレイヤーが自分で入れる。
- 無制限・無料。使用回数は記録し、クリア画面と統計で見せる。
- 論理的な次の一手が存在しないことは、一意解を持つ盤面では起こらない
  (§7 の生成条件により、常にティア内の技法だけで進める)。
  万一検出できなかった場合は「今わかる手が見つかりません」を表示し、盤面は変えない。

## 6. 難易度ティア

難易度は「解くのに必要な最高技法」で定義する。**全ティアで推測(仮置き・
試行錯誤)なしに解けることを保証する。**

| ティア | 必要技法(最高到達) | 初期数字の目安 |
| --- | --- | --- |
| Easy | Naked Single / Hidden Single | 36〜45 |
| Medium | + Locked Candidates (pointing / claiming) / Naked Pair / Hidden Pair | 30〜36 |
| Hard | + Naked Triple / Hidden Triple / X-Wing | 26〜32 |

- 技法の適用順は「安い技法から」。グレーダーは Easy の技法だけで解ければ Easy、
  Medium の技法が 1 回でも必要なら Medium、Hard の技法が必要なら Hard と判定する。
- Expert 以上(XY-Wing、Swordfish、各種チェーン)は初期リリースでは扱わない。
  それらが必要な盤面は生成時に破棄する。
- 初期数字の個数は結果であって目標ではない。上の範囲は生成の目安であり、
  ティア判定は必ずグレーダーが行う。

## 7. 盤面生成と Seed

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。

生成手順:

1. **完成盤を作る** — 空盤にランダム化バックトラッキング(候補順を seed でシャッフル)。
2. **対称に掘る** — 180° 回転対称のペア単位でマスを消す。中央マスは単独。
   掘る順番も seed 由来のシャッフルで決める。
3. **一意性を保つ** — 1 ペア消すたびにソルバーで解の個数を数え、
   2 個以上になったら直前の状態へ戻す(そのペアは掘らない)。
4. **ティアを確認する** — 掘り終えた盤面をグレーダーにかける。
   目標ティアと一致すればそれを採用する。
5. **合わなければ派生 seed で再試行** — `<seed>#2`, `<seed>#3`, … と決定的に
   seed を派生させ、最大 12 回試す。それでも合わなければ、その時点で
   目標ティアに最も近い候補を採用する(生成が失敗して遊べないことはない)。

不変条件:

- 出題は必ず一意解を持つ。
- 出題は必ず目標ティアの技法だけで解ける(推測不要)。
- 同じ seed は常に同じ盤面を返す(golden テストで固定する)。
- 初期数字は 17 個以上(数学的な下限)。実際には §6 の範囲に収まる。

性能予算(端末上で同期実行):

| ティア | 予算 |
| --- | --- |
| Easy / Medium | 1 盤面あたり 50ms 未満 |
| Hard | 1 盤面あたり 200ms 未満 |

超えた場合の対処順序: ①対称性の緩和 ②試行上限の調整
③(最後の手段)ビルド時生成したパズルパックの同梱。初期リリースでは①②に留める。

## 8. グレーダー(解法パス)

グレーダーは人間の解き方を模し、安い技法から順に適用して盤面を解く。

適用順:

1. Naked Single(あるマスの候補が 1 つ)
2. Hidden Single(ある行/列/ボックスでその数字が入れるマスが 1 つ)
3. Locked Candidates — pointing / claiming
4. Naked Pair / Hidden Pair
5. Naked Triple / Hidden Triple
6. X-Wing

各ステップは「対象マス(または除去する候補)」「根拠のユニット」「技法」を返す。
これが Hint の材料になる。1 ステップも適用できず未完成なら、その盤面は
初期リリースの対象外(生成時に破棄)。

## 9. レベルモード(1〜999)

Number Match と同じく level 1〜999。level から (難易度ティア, seed) を決定的に導出する。

seed は `sudoku-level-<n>`。ティアは次のバンドと重みで決める。
重みは level 由来のハッシュで決定的に判定するので、同じ level は常に同じティアになる。

| レベル帯 | Easy | Medium | Hard | 意図 |
| --- | --- | --- | --- | --- |
| 1–20 | 100% | 0% | 0% | 操作とメモに慣れる |
| 21–60 | 70% | 30% | 0% | Medium の技法に少しずつ触れる |
| 61–150 | 40% | 60% | 0% | Medium が主線に |
| 151–400 | 15% | 70% | 15% | Hard が混じり始める |
| 401–700 | 5% | 60% | 35% | Hard が珍しくなくなる |
| 701–999 | 0% | 45% | 55% | Hard 主体。ただし全部 Hard にはしない |

最後の帯でも Medium を 45% 残すのは、999 まで同じ濃度の難問が続くと
「消化」になり、ブランドの静かさに反するため。難易度は上げるが単調にはしない。

- レベルは順番に解放する(クリアした level の次が解放)。Number Match と同じ。
- 解放済みレベルはいつでも選び直せる。再挑戦は同じ盤面(seed が同じ)。

## 10. デイリーチャレンジ

- 1 日 1 問。seed は `sudoku-daily-<YYYY-MM-DD>`(端末のローカル日付のみ。
  サーバー時刻もネットワークも使わない)。
- **難易度は毎日 Medium 固定。** 曜日で難易度を変えると「当たり日 / 外れ日」という
  圧を生むため採らない。
- 過去の日付に遡って挑戦できる(Number Match と同じ)。達成した日は記録する。
- **ストリーク(連続日数)は数えない・表示しない。** 記録するのは達成日そのもの。

## 11. 中断と再開

- レベル用とデイリー用の**2 スロットを独立して保持する**(Number Match §14 と同じ)。
  レベルを中断してデイリーを遊んでも、どちらも失われない。
- 保存対象: 盤面(初期数字 / 入力 / メモ)、ミス回数、Hint 回数、経過秒数、seed、
  level または日付。Undo 履歴は保存しない。
- 保存タイミング: 手を進めたとき、画面を離れるとき、アプリが背景に回るとき。
- 保存の失敗でゲームを止めない。壊れた保存データは読み捨てて既定値に戻す。

## 12. スコアと統計

**スコアは作らない。** Sudoku の実質的な指標は時間だが、プレイ中に時計を見せると
急かすことになるため、内部でのみ記録する。

- クリア画面: 経過時間 / ミス回数 / Hint 回数。自己ベストを更新したときだけ静かに示す。
- 統計: 難易度別のクリア数、ベストタイム、平均タイム、デイリー達成日の一覧。
- オンラインランキングは作らない(ブランド原則)。

## 13. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ原則 1 文・図中心([I18N_POLICY.md](I18N_POLICY.md))。

1. 各行・各列・各 3×3 ブロックに 1〜9 を 1 つずつ。
2. マスを選んで数字を入れる。迷ったらメモに候補を残す。
3. 詰まったら Hint。どこが決まるかを教える。

詳細ルール・攻略・FAQ はアプリに入れず、ゲーム別 Landing Page
(`https://pixapps.ai/simple-games/games/sudoku/<locale>/`)へ分離する。
チュートリアルの「詳しく見る」から開く。オフラインでは何も起きない(ゲームは止めない)。

## 14. 本家的な実装との意図的な差分

ブランド原則により合わせないもの:

- ミス上限 / ゲームオーバー(採用しない)
- プレイ中のタイマー表示(しない)
- 連続日数ストリークとその表示(しない)
- Hint を広告視聴やコインの報酬にすること(しない。常に無料・無制限)
- スコアとオンラインランキング(作らない)

設計判断として合わせないもの:

- Expert 以上の技法を要する難易度(初期リリースでは出さない)
- 問題データの同梱・配信(すべて端末上で生成する)
- Hint への技法名表示(平易な言い換えのみ。§5)

合わせたもの:

- 9×9 / 3×3 ボックスの標準ルール、一意解、メモ機能、数字の残数表示、
  同数字ハイライト、重複の強調、180° 対称の初期配置。
