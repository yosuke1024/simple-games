# Simple Games — 多言語ポリシー(I18N)

**One app. Many games. Many languages.**

## 目的

広告費ではなくオーガニック流入で成長する。多言語のストア掲載・対応国の拡大・
ゲーム名検索が主要な流入経路であり、言語対応はマーケティング施策そのものである。
ただし「壊れた翻訳・崩れたレイアウトを出さない」を言語数より常に優先する
(下の「優先順位」)。

## 言語解決と地域フォールバック

実装は [`apps/simple-games/src/i18n/index.ts`](../apps/simple-games/src/i18n/index.ts)。
カタログは全言語をアプリに同梱する(オフライン要件。ダウンロード式にしない)。

解決順(`resolveLocale`):

1. アプリ内で明示的に選んだ言語
2. 端末の優先言語リストを先頭から順に走査(Android の「アプリ別の言語設定」は
   このリストに現れる)
3. 英語

初回起動時に言語選択画面は出さない。上記の解決だけで即プレイ可能にする。

地域バリアントは親言語へフォールバックする(`matchLocale`):

| 入力タグ          | 解決先 | 備考                                   |
| ----------------- | ------ | -------------------------------------- |
| `en-IN` / `en-GB` | `en`   | 地域 → 親言語                          |
| `ja-JP`           | `ja`   | 同上                                   |
| `in` / `in-ID`    | `id`   | Android のレガシーインドネシア語コード |
| `fr`(未対応言語)  | なし   | リストの次の言語へ。全滅なら英語       |

zh-Hans / zh-Hant のスクリプト解決(zh-TW → zh-Hant 等)は中国語対応時に
`matchLocale` へ追加する。

言語選択 UI の言語名は常にその言語自身の表記で表示する(`LANGUAGE_NAMES`。
例: 日本語 / हिन्दी / ไทย)。

## 対応言語の一覧

現状は **14 言語・319 キー**(10 ゲームすべての文言を含む)。`Messages` 型の強制に
より、1 言語でも 1 キーでも欠ければビルドが通らない。

### 翻訳の状態は「等級」ではなく「来歴と、検証できた事実」で書く

以前ここには `machine_draft` → `reviewed` → `native_reviewed` という 3 段階があり、
「リリース前にネイティブレビューを通す必要がある」と書いてあった。**この等級は廃止した。**

理由は二つある。

1. **その門は既に通り過ぎたあとだった。** アプリは 12 言語を機械翻訳ドラフトのまま
   リリースしている。通っていない門を「必ず通る」と書いた文書は、原則を守るふりでしかない。
2. **その門は開かない。** この製品は一人でつくっている(One human, many AIs)。
   14 言語のネイティブレビュアーを雇う日は来ない。供給できない前提に品質を賭けない。

**ただし、供給できないのはネイティブレビューだけである。** それ以外に品質を緩める理由はない。
実際、作者はタイ語を読めなくても、**タイ語の逆翻訳は読める**。
そこで検証できるのは「意味が壊れていないか」であって「自然に書けているか」ではない。
この二つを分けて扱えば、成立する門が一つ残る(下の「リリース前の門」)。

代わりに、**嘘のつきようがない 2 つの事実**だけを書く。

**来歴** — 誰が書いたか

| 値        | 意味                                                   |
| --------- | ------------------------------------------------------ |
| `source`  | 原文。他のすべてがこれと比較される                     |
| `author`  | 作者が書いた。作者がその言語のネイティブである場合のみ |
| `machine` | AI の助けを借りて書いた。**ネイティブは読んでいない**  |

**検証済み事実** — 何が確認できたか。それぞれ、やったか / やっていないかだけ

| 事実                 | 誰が                     | 何を保証するか                                                           |
| -------------------- | ------------------------ | ------------------------------------------------------------------------ |
| 機械チェック         | CI                       | 数値・用語・構造・マークアップ・禁止表現(**英日のみ**)。**意味は見ない** |
| 独立逆翻訳           | **訳を書いた実行者以外** | 逆翻訳という材料が存在すること                                           |
| 作者の逆翻訳レビュー | 作者                     | **逆翻訳に現れた意味差を検出したこと**。下の限界を参照                   |
| 別モデル監査         | Codex                    | 原文・訳文・正本ルール(あれば逆翻訳も)を突き合わせた第三者の指摘         |
| 読者からの報告       | 読者(ネイティブ)         | 自然さ。届いた範囲でのみ                                                 |

**手順を厚くしても `machine` は `author` にならない。** 逆翻訳を別セッションに出しても、
作者が意味を確認しても、Codex に監査させても、その言語のネイティブは一人も読んでいない。
`author` が保証するのは自然さであり、それは上の表のどれでも代替できない。
段階を増やすほど「まだネイティブは読んでいない」という単純な事実がぼやける。

### 自然さのレビューは、ゲートではなく読者から来る

意味は上の門で押さえられる。押さえられないのは**自然さ**で、これは
ネイティブにしか判定できない。雇えないだけで、**ネイティブは既にいる。読者である。**

- `machine` のページは、**そのことをページ自身が言う**。品質の主張ではなく事実の開示。
  **現状これはガイドページのみ実装済みで、アプリ UI 側は未実装**(下記)
- 併せて誤り報告の導線を出す(ガイドページは `mailto:`。実装は
  `pixapps-landing/tools/build-game-guides.js`、テストが欠落を検出する)
- 報告が来たら作者一人が判断し、AI が直す。人間は増えない

黙って機械翻訳を出すより誠実で、`docs/BRAND.md` の路線とも合う。

ロケールタグは小文字で持つ(`zh-hans` / `pt-br`)。端末が返すタグは
`matchLocale` が小文字化してから突き合わせる。

### 誤訳が「約束の反故」になる文言

以下は、誤訳の代償が「読みにくい」ではなく「守れない約束を配る」になる文言。
報告が来たとき最優先で見る場所であり、新しい言語で最初に確認する場所でもある。

1. **課金**: `removeAdsTitle` / `adSupportBody` / `removeAdsAction` /
   `restorePurchase` / `purchaseThanks`。
   「一度だけの購入」「永久に」がぼやけていないか。サブスクと読めないか。
   `adSupportBody` は、ポリシー本文を外に出したあともアプリ内に残る
   「広告と課金がある」という事実の説明であり、オフラインでも読める(下記 3)。
2. **削除**: `resetData` / `resetConfirmTitle` / `resetConfirmBody` / `delete`。
   「元に戻せない」を弱めていないか。`resetConfirmBody` も同様にオフラインで
   読める側に残した文言である。
3. **プライバシー**: ~~`privacy1`〜`privacy5`~~ → **廃止(2026-08-02)**。
   プライバシーポリシーと利用規約はアプリに同梱せず、
   <https://pixapps.ai/simple-games/privacy> と `/terms` へリンクする形に変えた
   (`packages/brand` の `PRIVACY_URL` / `TERMS_URL`、`docs/PRIVACY_POLICY.md`)。
   14 言語ぶんのカタログごと消えたので、この門の対象からも外れた
   (**未承認 240 → 168 件**)。

   経緯を残しておく。Web 版に AdSense を入れる際、「プライバシー文言の機械翻訳は
   禁止」と「広告の説明を省略することはできない」が正面衝突し、一度は
   `privacyWebAds` の 12 言語を英語原文のまま置くという例外を設けた。**その例外は
   撤回した** — 板挟みの原因は「同じ文面を 14 部持っていること」自体であって、
   訳し方ではなかったからである。同種の板挟みに出会ったら、例外条項を彫る前に
   **その文面がアプリの中にある必要があるのか**を先に疑うこと。

   なお主語の統一(全言語で `PixApps`、一人称を使わない。2026-08-01 決定)は
   公開ページ側の文面規則として引き続き有効。同じ理由で `reviewFeedbackBody` は
   逆に**一人称単数**にしてある(メールを読むのは法人ではなく作者本人であるため)。

4. **破壊的操作の確認ダイアログ**: `confirmNewGameBody`(進行中のゲームが失われる) /
   `minesConfirmSwitchBody`(進行中の盤面が置き換わる)。
   誤訳がそのままデータ損失になる。`resetConfirmBody` と同じ扱いで、
   「失われる」が「保存される」「中断できる」に読めないこと。
5. **無料・オフライン・paywall 不在の保証**: `tagline` / `step3Body` /
   `sudokuStep3Body`。`tagline` はゲーム別ホームとコレクションホームの両方に出る
   (コレクション専用の `collectionTagline` は「完全無課金」を主張していたため廃止。
   docs/BRAND.md「表現ルール」)。
   「ヒントと戻すは常に無料」「オフラインで動く」「アカウント不要」は
   ブランドそのものであり、弱めても盛っても約束の反故になる。

上の 1〜5 が**リリース前の門の対象**。以下は門ではないが、言語追加時に見る。

6. **ゲーム名**: `numberMatchName` は定訳がないため全言語で英語のまま。
   `minesName` はドイツ語のみ Minesweeper のまま(Minensucher は掃海艇を指すため。
   2026-08-01 決定。逆翻訳の担当が、この記述を見ない状態で同じ指摘に到達した)。
   `slideName` は簡体字 数字华容道 / 繁体字 數字推盤 と地域差を反映済み。
7. **固定幅に載る短いラベル**: `undo` / `hint` / `settings` / `resetData` /
   `restorePurchase`。ドイツ語 `Rückgängig` が最長(実測でオーバーフローなし)。

インド系言語(ta / te / bn / mr)は後続ウェーブとして検討する。
言語を増やすより、出している言語を直すほうが先(優先順位 §)。

### リリース前の門 — 高リスクキーは逆翻訳を作者が読む

以前ここには「状態にかかわらずリリース前に必ず人間レビューを通す」と書いてあり、
それは成立していなかった。だが**成立しない理由はネイティブ性であって、人間レビューではない。**
訳文そのものを読めなくても、逆翻訳を読めば意味は判定できる。

**門(リリースをブロックする):** 下の「約束の反故になる文言」の各キーについて、
**出荷する全言語**で次を通してからリリースする。

1. **独立逆翻訳** — 原文を見せていない実行者(別セッション / Codex)に、
   訳文だけを渡して ja または en へ戻させる
2. **作者が逆翻訳を読む** — 約束が壊れていないかだけを見る。
   「一度だけの購入」がサブスクに読めないか。「元に戻せない」が弱まっていないか。
   復元されるものが誤っていないか
3. **機械チェック** — プレースホルダー整合(`i18n.test.ts`)、禁止表現・用語
   (`.github/scripts/check-principles.sh` §6)。**禁止表現を見られるのは英語と
   日本語だけ**で、残り 12 言語で同じ主張がされていないことは grep では判定できない
   (「完全無料」は言語ごとに別の字面になる)。そこは 1 と 2 の担当である

対象は **12 の `machine` 言語 × 14 キー = 168 件**の短文で、通しで読む作業に収まる。
**供給できる門なので、書いたからには通す。**

#### 門は文書ではなくコードで強制する

「門を復活させた」と書いただけでは、未通過のままリリースを作れてしまう。実装:

| もの                       | 役割                                                                         |
| -------------------------- | ---------------------------------------------------------------------------- |
| `src/i18n/highRiskKeys.ts` | 対象キー。`keyof Messages` 型なのでキー名変更は型エラー                      |
| `src/i18n/provenance.ts`   | 来歴。`Record<Locale, …>` なので言語追加時の記入漏れは型エラー               |
| `src/i18n/gateRecord.json` | 承認記録。**読んだ英語と訳文のハッシュ**を持つ                               |
| `src/i18n/gate.test.ts`    | 失効・不正な記録は**常に落ちる**。未承認は `I18N_GATE_STRICT=1` でのみ落ちる |
| `scripts/i18n-gate.mjs`    | `status` / `pending <lang>` / `approve <lang> <key> --by <who>`              |

承認は言語ではなく**その時読んだ文字列の組**に対して与えられる。英語か訳文を
あとから編集すると承認は失効し、通常の `pnpm test` が落ちる。

`pending` は**訳文だけを出力し、英語を絶対に出さない**。原文を並べて渡した時点で
逆翻訳は独立でなくなるため、道具の側で不可能にしてある。

未承認を常時 red にしないのは、12 言語が門より前に出荷済みで、
恒常的に赤いテストは誰も読まなくなるため。リリース手順
(`docs/RELEASE_CHECKLIST.md` §3)が strict 版を回す。

**門ではない(開示と読者報告に委ねる):** 上記以外のキー全部。
量が桁違いで、かつ誤訳の代償が「読みにくい」で収まるため。

#### この門の限界(過信しない)

保証できるのは「**逆翻訳に現れた意味差を作者が検出した**」までであって、
「意味が壊れていない」ではない。逆翻訳者が次をやると、欠陥は逆翻訳を素通りする:

- 曖昧な訳文を、一方の意味に勝手に決めて戻す
- 否定・条件・数量のスコープを、自然な原語へ補正してしまう
- 「必須 / 推奨」「削除 / 非表示」「復元 / 再購入」の強さや操作の差を平坦にする
- 訳文で欠落した情報を、定型表現やドメイン知識から補って戻す
- 前後のキーから意図を推測し、壊れた訳文を正しく復元してしまう

実例がある: es ガイドの `Una disposición que no consigue terminar`(主語が逆)は、
逆翻訳では「解き終えられない配置は捨てて作り直します」と正しい意味に補正されていた。

そして**自然さは端から対象外**。不自然なタイ語は、逆翻訳すると自然な日本語に戻る。
自然さは `machine` 来歴の開示と読者からの報告でしか埋まらない。

### 併せて、契約的な事実は翻訳に賭けない

門を通しても、文言が単独で契約を背負っていれば事故の幅は大きいままなので、設計側でも減らす:

1. **契約的な事実は Google Play 自身に語らせる。** 価格、買い切りかサブスクか、
   返金の扱いは Play が各言語で正しく表示する。アプリ側の文言に求めるのは
   「それと矛盾しないこと」で、契約内容を単独で背負わせない。
2. **文を短く保つ。** 訳のブレる余地を構造的に減らす。長い説明文ほど誤訳が入る。

**現状、この門はまだ一度も通していない。** 既にリリース済みの 12 言語が未通過であり、
次のリリースまでに通す必要がある。ここに書いた以上、通すまでは「通した」と書かない。

## 長文ガイド(Learn More のリンク先)は別の言語リスト

アプリ内 UI の 14 言語と、詳細ルールを載せたゲーム別 Landing Page の言語は
**別物**であり、一致させない。

|          | UI カタログ                           | ゲーム別ガイド                                           |
| -------- | ------------------------------------- | -------------------------------------------------------- |
| 置き場所 | `apps/simple-games/src/i18n/locales/` | 別リポジトリ `tools/game-guides-content.js` の `LOCALES` |
| 単位     | 短いラベル 302 キー                   | 1 ゲームあたり数千語の長文                               |
| 現在     | 14 言語                               | en / ja / es                                             |
| 参照元   | `i18n/index.ts`                       | `apps/simple-games/src/ui/landing.ts` の `PAGE_LOCALES`  |

ガイドを 14 言語へ機械翻訳で一括展開しない。理由は 2 つある。

1. **誤訳がそのままルールの誤りになる。** UI ラベルの誤訳は不便で済むが、
   「推測せずに解ける」「ヒントは無制限で無料」といった保証を書いた長文の誤訳は、
   守れない約束を配ることになる(`docs/PRODUCT_PRINCIPLES.md`)。
2. **自動生成の大量ページはドメイン全体の評価を落とす。** 検索流入が主動線である
   以上、60 ページの機械翻訳は目的に対して逆に働く。

書かれていない言語は英語ページへフォールバックする。404 でも機械翻訳の
ルールブックでもなく、英語であることを隠さずに読ませるのが現状の答え。

**手順は「ページを公開してから `PAGE_LOCALES` に足す」**。逆順にすると、
アプリが存在しない URL へ利用者を送る。

### ガイドの来歴と検証済み事実

来歴の値は `pixapps-landing/tools/game-guides-content.js` の `LOCALE_META[locale].provenance`
にも持っており、**`machine` のページは来歴と誤り報告導線をページ自身に出す**
(テストが欠落を検出する)。

| コード | 来歴    | 機械チェック | 独立逆翻訳 | 作者の確認 | 別モデル監査 | 備考                                                                                                                                                                              |
| ------ | ------- | ------------ | ---------- | ---------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| en     | source  | ―            | ―          | ―          | ―            | すべての事実の基準。`docs/<GAME>_RULES.md` と一致していること                                                                                                                     |
| ja     | author  | 済           | ―          | ―          | ―            | 作者がネイティブ                                                                                                                                                                  |
| es     | machine | 済           | **未**     | **未**     | 済           | 用語はアプリの `locales/es.ts` に準拠(bloque / casilla / cifra / ficha / hueco / Comodín / Piedra / Pista / Deshacer)。造語 4 件は `simple-games-wording.js` の `coinages` に記録 |

`es` の「独立逆翻訳」が未なのは、**逆翻訳を書いた本人がやってしまったため**。
自己確認なので済とは書けず、作者が読んだ逆翻訳も同じ理由で「作者の確認」には数えない。
実測でも、その逆翻訳が見つけた実欠陥は 5 件中 0 件だった
(発見経路は訳文の読み直し・原文との突き合わせ)。

「別モデル監査」は Codex が 2 回実施した。ただし**独立逆翻訳が存在しない状態での監査**なので、
原文・訳文・正本ルールの三者照合であって、逆翻訳を含む四者照合ではない。
それでも**英語ガイド自体の事実誤認**を検出している
(Number Match の難易度軸が `NUMBER_MATCH_RULES.md` と矛盾。en / ja / es の 3 言語とも修正済み)。
やり直す手順は `.claude/skills/guide-translation/SKILL.md`。

**この表の `author` は、手順を厚くしても得られない。** ネイティブが読んだときだけ変わる。

## 言語追加手順

1. `apps/simple-games/src/i18n/locales/<code>.ts` を 1 ファイル追加する
   (`en.ts` をコピーして翻訳)
2. `apps/simple-games/src/i18n/index.ts` に登録する
   (`Locale` 型・`catalogs`・`LANGUAGE_NAMES`)

**カタログを追加するだけならこれで完結する**。それ以上の作業が必要になったら実装側の退化とみなす。

ただし**リリースするには別途、高リスクキーの門を通す**(上の「リリース前の門」)。
この 2 手順は「ビルドが通る」までの話であって、「出荷してよい」までの話ではない。

- `Messages` 型が全キーの存在をコンパイル時に強制する。キーが 1 つでも欠けると
  ビルドが通らない(実行時の「翻訳漏れで英語混じり」を型で排除)。
- テスト(`i18n.test.ts`)が空文字・プレースホルダー名の不一致・
  制御文字/マークアップ混入を検出する。

## 文言設計

- **文章量の最小化は UI 原則である。** チュートリアルは最大 3 ステップ・各 1 文。
  文章より図とハイライトで示す。ボタンは短い動詞・名詞。
- **文字列連結禁止。** 全文をキー側で管理し、可変部は `{var}` 埋め込みで渡す
  (語順が言語ごとに違うため)。
- 複数形が必要なキーが現れた時点で ICU 相当の複数形キーを導入する
  (現状は該当キーなし)。
- 盤面の数字は全言語で ASCII の 0-9 固定。
- 文中の日付・数値はロケール書式で整形する。

## レイアウト耐性チェックリスト

言語追加・画面追加のたびに確認する:

- [ ] 長い文言(ドイツ語等)でボタン・見出しがはみ出さない
- [ ] CJK(日中韓)で行間・折り返しが破綻しない
- [ ] デーヴァナーガリー・タイ文字の上下に伸びる字形が切れない
- [ ] OS のフォントサイズ拡大(font scaling)で崩れない
- [ ] テキストは折り返しを許容するレイアウトにする(固定幅で切り捨てない)
- [ ] 盤面のサイズ・配置は言語によって変わらない
- [ ] 画像・スクリーンショット素材に文字を焼き込まない

## RTL 方針

Arabic(および RTL 言語全般)は初期対象から**外す**。理由: RTL は UI chrome 全体の
検証が必要で、「壊れたレイアウトを出さない」が言語数より優先するため。

追加の条件(すべて満たすまで着手しない):

1. レイアウトの logical properties 化の監査
2. 主要画面の RTL レンダリングテスト
3. ネイティブレビューの確保

3 は現状供給できない(上の「翻訳の状態」節)。**それが Arabic を追加しない理由そのもの**であり、
矛盾ではない。他言語では自然さを開示と読者報告に委ねられるが、RTL では
自然さの前に**レイアウトが壊れているかどうか**をネイティブ以外が判定できないため、
同じ逃げ道が使えない。

**盤面は RTL でも左右反転しない。** UI chrome の方向とゲーム盤の方向は
別々に判断する。

## フォント方針

- 同梱フォントは Nunito の latin サブセットのみ(約 36KB)。
- 非ラテン文字はすべて OS のシステムフォントに委ねる。巨大なマルチスクリプト
  フォントは同梱しない(アプリ容量を増やさない)。
- 盤面の数字は ASCII 0-9 のため、どの言語でも同一の見た目になる。

## ストアローカライズ

`apps/simple-games/store/listing.md` が持つのは**英語の正文と表現の約束だけ**で、
言語別の掲載文はこのリポジトリでは管理しない(ストア運用側で管理する)。

理由は単位が違うこと。掲載文は Play Console の**掲載言語スロット**単位で必要になるが、
その単位はアプリのロケールと一致しない。アプリは言語ごとにカタログ 1 つで、地域
バリアントを親言語へ解決する(`pt-PT` → `pt-br`、`zh-HK` → `zh-hant`)。一方 Play は
地域ごとに別スロットを持ち、埋めなかったスロットの利用者にはデフォルト言語の掲載
ページが出る。つまり対応は **1 対 多**であり、`locales/*.ts` と 1 対 1 に並べると
かえって取り違える。

各言語で管理する項目:

1. アプリ名
2. 短い説明
3. 詳細説明
4. スクリーンショットキャプション
5. リリースノート
6. IAP 商品名
7. IAP 説明文

**地域スロット専用の掲載文でも、ゲーム名と IAP 商品名は「その端末が実際に解決する
カタログ」の表記を据え置く。** 本文の語法だけ地域に寄せてよい。例: pt-PT のページで
"Puzzle deslizante" と書いても、その端末のアプリは `pt-br.ts` を読むので画面には
"Quebra-cabeça deslizante" が出る。ストアで見た名前とアプリ内の名前が食い違うのは、
翻訳の不自然さより重い。

広告・課金の文言も同じ理由で、カタログの `adSupportBody` / `removeAdsTitle` と
割れないようにする。これらは高リスクキーでもあるため、掲載文だけ先に直して
カタログを置き去りにしない。

## スクリーンショット方針

訴求文は短句に限る:

> Many games. One app. / Fully offline. / No subscriptions. / Banner ads only. / Open source.

不自然なキーワード詰め込みをしない。文字は素材に焼き込まず、言語別に重ねる。

## コミュニティ翻訳

- locale の追加・修正手順は [CONTRIBUTING.md](../CONTRIBUTING.md) に記載する
  (リポジトリは公開されており、翻訳 PR を受け付ける)。
- About 画面への Help Translate 導線は M-L10N で追加する。
- **初期品質はコミュニティに依存しない。** リリースに必要な言語は自前で
  ドラフト + レビューを済ませる。コミュニティ翻訳は改善の上乗せとして扱う。

## テスト一覧

`apps/simple-games/src/i18n/i18n.test.ts` で固定している挙動:

- 地域バリアント → 親言語フォールバック(en-IN → en 等)
- レガシー `in` → `id` マッピング
- 未対応言語で null(次の候補へ進む)
- アプリ内の明示選択が端末言語より優先
- 端末の優先言語リストを順に走査
- 全滅時・リスト空時の英語フォールバック
- 全 locale が全キーを非空文字列で持つ
- プレースホルダー名が英語と全 locale で一致
- カタログ文字列に制御文字・マークアップが混入していない
- `{var}` の変数置換(未知トークンはそのまま残す)

将来案: 擬似ローカライズ(キーを機械的に伸長・アクセント化した擬似 locale)で
レイアウト耐性を自動検証する。

## 優先順位

判断に迷ったら上から順に守る:

3. レイアウト耐性(崩れた画面を出さない)
4. 英語フォールバックが常に機能する
5. ストアローカライズ
6. 対応言語数
7. コミュニティ翻訳の受け入れ
