## これまでに決まったこと

製品オーナーの判断(2026-10-19)と計画で決めたこと。理由と未決の点は、計画の「47. Chess」にある。

- 対局相手は CPU だけ。難易度は Easy / Normal / Hard。先後(白 = 先手 / 黒 = 後手)を選べ、次の対局から適用する。
  デイリー・時計・レーティングは無い。
- 盤は常に自分が手前。駒は物理色(明 / 暗)で塗る — Checkers / Connect Four の役割色の例外で、Reversi /
  Gomoku の黒白と同じ側。駒の絵は自作の SVG。
- 駒の動き・キャスリング・アンパッサン・昇格は FIDE のとおり。引き分けはステイルメイト・駒不足・三回同形・
  50 手規則(双方 50 手 = 100 プライ)で自動成立する(FIDE の申請制との意図的な差分)。終局理由を 1 行で示し、
  ステイルメイトには専用の文言を使う。
- 助けは Undo(無制限・無料。CPU の応手と自分の 1 手をまとめて戻す)と合法手の点(合法手の無い駒には、点も
  叱る通知も出さない)。キャスリング・アンパッサン・昇格も点で示し、昇格は 4 択(クイーンが先頭)。Hint・
  評価バー・棋譜解析・「取られる」警告・投了・引き分けの提案は作らない。
- CPU の読みは難易度別: Easy は 1 手読み + seed の揺らぎ、Normal は固定深さ 2〜3、Hard は反復深化 α–β +
  ノード上限(仮 20,000 — 実測で決める。上限に達したら完了済みの深さの最善を返す)。静止探索は取る手のみ
  (Easy に付けるか・王手を受けている局面の扱いは未決 — 計画)。手の順序は MVV-LVA。深さ 1 で 1 手詰めを
  必ず見る。同点は `createRng(`${seed}:cpu:${moveCount}`)` で決める。Zobrist 鍵は 32bit × 2(BigInt を使わない)。
- 統計は難易度別の `played` / `wins` / `losses` / `draws` と、総プレイ秒。放棄は負けに数えない。
- 保存は着手リストで、読み込みでは初期局面から再生して検証する(非合法手・終局後・手数上限超過を拒否 —
  fail-closed)。
- 規則の正しさは perft で確かめる。提案時の使い捨ての試作での一致は、実装で再現するまで「検証済み」と書かない。
- 画面と公開文面に「強い」「AI」と書かない。
