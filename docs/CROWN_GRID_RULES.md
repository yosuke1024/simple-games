# Crown Grid — 正式ゲームルール

この文書は Simple Games 収録タイトル「Crown Grid」の唯一のルールソースである。
実装(`apps/simple-games/src/games/crown-grid/game/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。コードはここへ `§n` で言及する。数値や挙動を変えるときは、
同じコミットでこの文書を先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Hint は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

ゲーム ID は `crown-grid`、i18n キーの接頭辞は `crownGrid`、保存キーの接頭辞は `cg.` である。
**2026-10-02 に Web 先行公開から正式収録した**(アプリにも収録。保存スキーマはこの収録で
凍結。[WEB_VERSION.md](WEB_VERSION.md)「先行公開」、issue #194)。古典的な
Star Battle(1 星)系のメカニクスを、Simple Games の名前と表現で作る。他社の名称・
アセット・画面デザインは複製しない(§14)。

## 1. 盤面

- N×N のマス。盤面は **N 個の連結な領域**(上下左右で繋がったマスの集まり)に
  分割されている。領域は薄い地色と太い境界線で示す(§13)。
- プレイ中の各マスの状態: 空 / `×` / 王冠。`×` は「ここに王冠は置けない」という
  プレイヤーのメモであって、規則にも勝利判定にも関わらない(§2、§6)。

サイズは難易度ごとに 1 つ(スマートフォンの画面に収まる形で決めた):

| 難易度 | サイズ | 用途           |
| ------ | ------ | -------------- |
| Easy   | 6×6    | 導入           |
| Medium | 8×8    | 標準・デイリー |
| Hard   | 9×9    | 上位           |

10×10 以上は作らない(1 マスが指で押せる大きさを下回る。Nonogram §1 と同じ床)。
**サイズは難易度の一部であって難易度そのものではない** — 難易度を決めるのは §7 の
技法の集合であり、同じ 8×8 でも技法次第で Easy にも Hard にもなり得る。だから
Medium と Hard の間は 1 マスしか違わない。

**盤面に翻訳の要る文字は 1 つも載らない。**王冠は言語非依存のインライン SVG
(`CrownGlyph`)、消去は `×`(U+00D7)の記号で、言語を変えても盤面表記は変わらない
([I18N_POLICY.md](I18N_POLICY.md))。領域番号は読み上げにだけ現れ、盤面には描かない。

## 2. 勝利

- **勝利**: 王冠が **N 個**置かれ、§3 の規則を 1 つも破っていない時点。
- 敗北は存在しない。ミス回数の制限も、ライフも、ゲームオーバーもない(§14)。

判定は「王冠が N 個」かつ「§5 の違反が 1 つも出ていない」で行い、**解と照合しない**。
N 個の王冠がどの行・列・領域にも 2 つ以上なければ、鳩の巣により各行・各列・各領域に
ちょうど 1 つずつある。出題は一意解なので(§7)、この状態は解と一致する。
表示と判定が同じ読みから出るので、「きれいに見えるのに完成しない盤面」は作れない。
`×` は判定に関わらない — `×` が残っていても、間違った `×` があっても、王冠が正しければ完成である。

## 3. ルール

**規則 1 — 各行・各列・各領域に王冠はちょうど 1 つ。**

**規則 2 — 王冠どうしは接しない。斜めも含む(8 近傍)。**

```
♛ · ·      · ♛ ·
· · ·  ○   · · ♛  ×(斜めに接している)
· ♛ ·
```

出題は常に一意解を持つ(§7)。

## 4. 操作

- **タップ**: 空 → `×` → 王冠 → 空 の循環。
- **なぞる(ドラッグ)**: 通ったマスに `×` を置く。**空マスにだけ書く** — 王冠や既にある
  `×` には触れない。押した指が 2 マス目に達した時点でそのなぞりはストロークになり、
  **開始マスも `×` になる**(Nonogram §3 の「動いたらストローク」と同じ判定。トグルではない —
  同じマスを行き来しても `×` が消えることはない)。指が離れるか、OS がポインタを取り上げた
  (`pointercancel`)時点でストロークは終わり、書いた分は残る。
- **キーボード**(あれば): `H` = Hint(§6)。画面のボタンと同じ処理を呼ぶだけの別の
  入力経路で、ボタンは残す。押しっぱなしのキーリピートでは発火しない。結果カードと
  確認ダイアログの間は効かない。

**長押し・モード切り替え・自動 `×` は作らない。** 王冠と `×` は 1 本の循環の上に並んで
いて、どちらも同じ「印を置く」操作である(Takuzu §4 と同じ理由)。なぞりは `×` を
まとめて置くための近道で、王冠を置くのは常に 1 タップずつ — 王冠は 1 行に 1 つしか
ないので、まとめて置く場面がない。自動 `×`(王冠を置いたら周囲を自動で消す)は
「どこが埋まるか」を読む作業そのものを肩代わりするので作らない(§14)。

## 5. 違反表示

常時オンで、2 規則それぞれに対応する。該当する**王冠**を警告色と枠で示す — 枠は `--warn`、
王冠の記号は同じ色相を地色の上で 4.5:1 に届く濃さへ寄せた `--cg-warn-ink`(§13):

- 同じ行・同じ列・同じ領域に王冠が 2 つ以上あるとき、その行(列・領域)の王冠すべて。
- 王冠どうしが接している(8 近傍)とき、その両方。

**これはルール違反の指摘であって、答え合わせではない。**規則を破っていない王冠は、
それが解と違っていても何も言われない。`×` は規則の対象外なので、`×` に違反表示はない。

## 6. Hint

**Hint は作る。無制限・無料。**マスを書き換えることはしない。次の順で 1 つだけ示す:

1. **違反があれば、それを示す**(§5 の王冠)。壊れた並びの上に積んだ確定を教えても、
   正しい導きにならない(Takuzu §8 と同じ順序)。
2. **解に無い王冠があれば、その 1 つを「この王冠は成立しない」として示す**(行順で最初のもの)。
   一意解の出題なので、解に無い王冠は「まだ矛盾していないだけ」ではなく確実に誤りであり、
   その上に技法を積んでも導けるものが無い。Takuzu §9 は「解と違う」表示を退けているが、
   あちらは常時表示であり、こちらは**プレイヤーが Hint を押したときにだけ、1 つだけ**言う
   (§14)。
3. **技法ソルバーの次の一手**(§7)。`place`(このマスは王冠)または `eliminate`(この
   マスに王冠は置けない)を、根拠になった行 / 列 / 領域と、根拠を担うマス(候補)ごと
   強調して示す。一文は技法と根拠の家の種類(行 / 列 / 領域)の組ごとに 1 つ用意してあり、
   三つの視覚語で導きを平易に説明する — **強調**(根拠になった家。それ以外のマスは
   紙色の薄い幕で沈む、§13)/ **色つき**(根拠を担う候補マス)/ **枠つき**(その一手が
   確定するマス)。**技法名は今も UI に出さない。**この対応(技法 × 家の種類 → 一文)は
   `ui/hintMessage.ts` の `hintMessageKey` 1 か所だけが持つ。
   (2026-09-27 の実機プレイテスト(iPad、8×8)で「Hint を押しても、どこが強調されて
   いるのか分からない」「一文が理由を説明していない」という指摘があり、強調表示と
   一文の両方をこの形に直した — 経緯は §13。)
4. どれも見つからないときは「今わかる手が見つかりません」と表示し、盤面は変えない。

**プレイヤーの `×` は信用しない。**技法ソルバーは盤面の王冠だけを前提に候補を組み立て、
`×` を一切読まない — 間違った `×` の上に推論を積まないためである。ただし、ソルバーが
消そうとするマスがすべてプレイヤー自身の `×` で既に埋まっているなら、その一手は
「もう知っていること」なので黙って適用し、次の一手を探す。`place` の一手が `×` の上に
落ちることはあり得て、そのときは「その `×` は間違い」を示していることになる。

Hint の技法集合は常に全部(T1〜T5)である。出題はティアの技法だけで解けるように
作ってあるので(§7)、Easy の盤面で T5 の Hint が出ることはない(唯一の例外は §8 手順 5 で
Easy が上のティアへ落ちた盤面で、発生は 0 件)。

## 7. 技法とティア

**これがこのタイトルの中心的な設計判断である。**難易度は盤面の大きさではなく、
**解くのに必要な技法の集合**で定義する。

候補 = まだ王冠を置きうるマス。王冠を置くと、その行・列・領域と 8 近傍の候補が消える。
「家(house)」= 行・列・領域のいずれか。王冠のまだ無い家の候補が 0 になったら矛盾。

| 技法 | 名前        | 内容                                                                                                                                                                               |
| ---- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1   | single      | 家の候補がちょうど 1 マス → そこは王冠(`place`)。                                                                                                                                  |
| T2   | confinement | 領域の候補がすべて 1 行(1 列)に収まる → その行(列)の、領域外の候補を消す。双対: 行(列)の候補がすべて 1 領域に収まる → その領域の、行(列)外の候補を消す。                           |
| T3   | attack      | あるマスに王冠を置くと(その行・列・領域・8 近傍を消した結果)どこかの家の候補が 0 になる → そのマスの候補を消す。                                                                   |
| T4   | pair        | 2 領域の候補が合わせてちょうど 2 行(2 列)に収まる → その 2 行の、他領域の候補を消す。双対: 2 行(2 列)の候補が合わせてちょうど 2 領域に収まる → その 2 領域の、2 行外の候補を消す。 |
| T5   | hypothesis  | 深さ 1 の仮置き。候補マスに王冠を仮置きし、T1〜T3 を不動点まで走らせて矛盾したら、そのマスの候補を消す。候補の少ない家から順に試し、最初に矛盾した 1 マスを一手とする。            |

**5 つとも健全(sound)である。**どれも「合法な完成形すべてが一致する結論」しか出さない。
したがって技法だけで王冠 N 個まで確定できた盤面は解が 1 つだけである。生成では
それでも完全探索で数える(§8) — 技法ソルバーは健全性を信じる相手ではなく、検査される
相手だからである。技法は**安い順に**適用し、上位の技法は下位の技法が何も言えなく
なってから初めて参照する。これが人の解き方であり、仕事量が小さく収まる理由でもある。

技法の実装は 1 つだけ持ち、3 人の利用者が共有する — 生成時の等級判定(§8)、Hint(§6)、
`guarantee.test.ts`。約束と検査と助けを別々に実装すると、静かに食い違う(Takuzu §5)。

**ティア**(技法の集合 — 上位は下位を含む):

| ティア | 技法集合 | 条件                                               |
| ------ | -------- | -------------------------------------------------- |
| Easy   | {T1, T2} | この集合だけで解ける                               |
| Medium | {T1〜T4} | この集合で解け、**かつ Easy の集合では解けない**   |
| Hard   | {T1〜T5} | この集合で解け、**かつ Medium の集合では解けない** |

等級判定は「Easy 集合で不動点まで → 解けなければ Medium 集合で続き → 解けなければ Hard
集合で続き」と 1 本の流れで行う(技法は単調 — 候補が減っても導ける結論は減らない — なので、
下位集合の不動点から続きを解いても結果は変わらない)。T5 でも解けない盤面は等級なしで、
出題しない。

## 8. 生成と Seed(仕事量で門にする)

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。

1. **王冠を置く。**行ごとに列を seed でシャッフルして 1 つずつ選ぶバックトラック。列は
   重複せず、隣の行の王冠とは列が 2 以上離れる(規則 2)。
2. **領域を切る。**各王冠を種にした**多点ランダム成長**。まず各領域が(領域の順に)王冠の
   隣のマスを 1 つずつ取る — これで **どの領域も 2 マス以上**(`MIN_REGION_SIZE` = 2)になる。
   王冠どうしは行・列を共有せず接しもしないので、2 つの王冠に隣接するマスは存在せず、この
   1 周は必ず全領域で成功する。その後は領域ごとに seed から「食欲」(重み)を引き、重みに
   比例して領域を選び、その領域に隣接する未割り当てマスを 1 つ足す — 全マスが埋まるまで。
   1 マスずつ隣に足すので連結は構成上保証され、重みの差が領域サイズのばらつきになる。
   **1 マスの領域は作らない。**それは自分の王冠そのもので、盤面を読む前に 1 つ答えを渡して
   しまう(6×6 なら問題の 6 分の 1)。
3. **一意にする。**無作為に育てた領域はほぼ必ず別解を持つ。行ごとに王冠の列を選ぶ完全探索で
   別解を数本取り、その王冠のうち意図した解と違うマスを**隣の領域へ 1 マス動かす** — 動かす
   マスは意図した解の王冠ではないので解は合法のまま、隣の領域には別解の王冠が 2 つ入るので
   別解は死ぬ。両領域の連結を保てる移動だけを選び、外れて孤立する欠片は一緒に動かす。
   **移動元に残る部分(意図した王冠を含む側)が `MIN_REGION_SIZE` を下回る移動は候補にしない。**
   残った候補のうち最も少ないマスで済む移動を取る — ただし「最少」だけでは領域は守れない
   (2 マスの領域の余りの 1 マスは常に 1 マスの移動で、それを取ると王冠だけが残る)ので、
   下限は順位付けではなく規則として置いてある。どの別解にも合法な移動が無ければ、
   その盤面は捨てる。
   別解が尽きるまで繰り返し(`REPAIR_LIMIT` 回まで)、尽きなければその盤面は捨てる。
   最後の完全探索が「意図した解だけが残った」と数えたものだけが先へ進む。
   領域の成長の形(食欲のばらつき・蛇行)はティアごとに変えてある — ティアを決めるのは
   あくまで手順 4 の技法ソルバーで、形は当たりの確率を動かすだけである。
4. **等級を判定し**(§7)、求めるティアに一致すれば出荷する。一致しなければ
   **seed を派生させて作り直す**(`<seed>#2`, `#3`, …)。派生シードは `ATTEMPT_LIMIT`
   (= 400)本で必ず止まる。
5. 上限に達したら、それまでの候補(一意で、等級の付いた盤面)のうち**求めるティアに
   最も近いもの**を `fallback: true` で出荷する。優先は、求めるティアより易しい候補の
   うち最も高い等級(= 求めるティアの技法集合で解ける最善の候補)。易しい候補が無いときに
   限り、より難しい候補のうち最も低い等級を取る — Easy にはそれより易しいティアが無いので、
   Easy の手順 5 は常にこちらになる。記録する `attempts` は実際に引いた派生シードの数
   (手順 5 では `ATTEMPT_LIMIT`)。
6. **例外を投げるのは 1 つの場合だけ**: `ATTEMPT_LIMIT` 本の派生シードから一意で等級の付く
   盤面が 1 つも出なかったとき。これは質の落ちた盤面ではなく**生成器が壊れている**ことを
   意味し(実測では 1,000 試行あたり Easy 639・Medium 481・Hard 371 が一意で等級の付く
   候補になる)、何も押せない空の盤面を渡すよりは失敗として表に出す(Takuzu の
   `game/generator.ts` と同じ線)。

不変条件:

- 同じ seed なら、必ず同じ盤面になる(`compatibility.test.ts` の golden で固定する)。
- 出題は一意解で、そのティアの技法集合だけで解ける(推測不要)。
- **どの領域も `MIN_REGION_SIZE`(2)マス以上。**(`guarantee.test.ts` が全盤面で確かめる。)
  保存済みの盤面の読み込みには課さない(§11)— 下限を入れる前の盤面(golden v1)も
  一意解であることは変わらないので、中断中のゲームはそのまま戻る。
- **ティアの一致は目標であって約束ではない。**手順 5 の盤面は一意解であることは
  変わらないが、ティアが求めたものと違う。Medium / Hard では求めたより易しく、ティアの技法で
  解けることも変わらない — 出荷してよい失敗の形なのでこれを選んである。Easy だけは
  易しい側が無いので求めたより難しい盤面になり、「Easy の技法だけで解ける」はその盤面に
  限って成り立たない(Hint は T1〜T5 を使うので詰みにはならない — §6)。いずれも発生率は
  監視する(現状 0 件 — 下の表)。手順 5 そのものは `guarantee.test.ts` が派生シードの
  上限を小さくして直接確かめる。

### 予算は仕事量で門にする

これは**端末の予算**であって、開発機やテストランナーの予算ではない。だから門は
壁時計ではなく**ソルバーの走査数**(`solverWork`)で測る — 技法ソルバーが読んだ家・試した
候補・立てた仮説と、完全探索の探索ノードの合計。同じ seed なら、どのマシンでも常に
同じ数になる。理由ごと [SUDOKU_RULES.md](SUDOKU_RULES.md) §7 と
[TAKUZU_RULES.md](TAKUZU_RULES.md) §6 に詳しい。

実測(開発機 Node 22、`guarantee.test.ts` が走査するのと同じ集合。難易度ごとに固定
シード 40 本、デイリーは 2026-08-01 から 730 日):

| ティア   | n   | 走査数 p50 | p90     | 最悪    | 試行 p50 / 最悪 | 壁時計 p50 | 壁時計 最悪 |
| -------- | --- | ---------- | ------- | ------- | --------------- | ---------- | ----------- |
| Easy     | 40  | 2,071      | 11,473  | 16,657  | 5 / 30          | 0.9ms      | 10.6ms      |
| Medium   | 40  | 3,797      | 20,169  | 28,385  | 2 / 9           | 0.8ms      | 3.1ms       |
| Hard     | 40  | 76,566     | 318,382 | 471,789 | 5 / 43          | 6.4ms      | 52.2ms      |
| デイリー | 730 | 5,391      | 20,281  | 70,026  | 2 / 17          | 0.7ms      | 6.4ms       |

(`MIN_REGION_SIZE` を入れた後の値。入れる前は Easy の試行 p50 / 最悪が 1 / 5、Hard が
10 / 71 で、1 マスの領域を含む盤面が Easy 35/40・Medium 29/40・Hard 15/40・デイリー
506/730 あった。1 マスの領域は Easy の 2 技法がそのまま読める手掛かりだったので、下限を
入れて Easy は当たりにくくなり(試行が増え)、Hard は逆に当たりやすくなった。)

**走査数の列は再現し、壁時計の列は再現しない。**同じ集合を別の機会に測ると走査数は 1 も動かず、
壁時計は JIT の暖機と隣のテストの負荷で数倍ぶれる(同じ集合を続けて 2 度測ると、Easy の最悪は
10.6ms と 14.9ms、デイリーの最悪は 6.4ms と 14.4ms だった)。門は走査数と試行回数に立てる。

門(`guarantee.test.ts` が上の集合を走査して固定する):

- 1 盤面あたりの走査数は **2,000,000 未満**(実測の最悪は Hard の 471,789。約 4.2 倍の余裕)。
  サイズごとに分けないのは、これが端末の約束ではなく**退行の門**だからである — 捕まえたいのは
  「技法が安い順の打ち切りをやめた」「修復が収束しなくなった」「完全探索の枝刈りが外れた」で
  あって、そのどれもサイズを問わず数字に出る。
- 派生シードは **160 回以下**(実測の最悪は Hard の 43 回。上限 `ATTEMPT_LIMIT` = 400 より
  ずっと手前に置いてあるので、手順 5 に落ちるより先に警告が出る)。
- 手順 5 の発生は 0 件。全盤面が一意で、等級が求めるティアに一致し、1 マスの領域が無い。
- 壁時計は計測して出力するだけで、判定には使わない。

端末の予算は 1 盤面 100ms 未満で、Hard の最悪 52ms(開発機、40 面中)はその内側にある。
Hard が高くつくのは 1 試行が重いからではなく(1 試行 ≈ 1ms)、無作為に育てた盤面のうち
T5 を要するものが 1 割ほどしかないからで(実測 1,000 試行中 94 — 残りは修復で捨てられるか
別のティアに落ちる)、試行回数が幾何分布の裾を引く。超えた場合の
対処順序: ① Hard の領域成長の形を T5 が要る側へ寄せる ② `REPAIR_LIMIT` / `ATTEMPT_LIMIT`
を下げる ③(最後の手段)Hard を 8×8 に落として**この文書を先に直す**。
**低スペック実機での実測はまだ行っていない。**

## 9. モードとデイリー

- **難易度モード**: Easy / Medium / Hard を選んで遊ぶ(§1、§7)。レベル 1〜100 は作らない —
  issue #194 が求めたのは 3 段階が実際の解法難度に対応することであり、100 段の坂は
  水増しになる。seed は `crown-grid-<difficulty>-<token>`(token = 起動時刻 + 乱数)。
  **同じ seed なら同じ盤面**なので、「同じ盤面で再挑戦」も中断からの復帰も正確に成立する。
  クリア画面の第一ボタンは「新しい盤面」(同じ難易度・新しい seed)、第二が同じ盤面での再挑戦。
  プレイ中のヘッダの ↻ も同じ 2 択を出す(`ui/components/RestartDialog.tsx`、2026-10-02)。デイリーは再挑戦だけ。
- **デイリー**: 1 日 1 問。seed は `crown-grid-daily-<YYYY-MM-DD>`(端末のローカル日付のみ。
  サーバー時刻もネットワークも使わない)。**毎日 Medium(8×8)固定。**曜日で難易度を
  変えると「当たり日 / 外れ日」という圧を生むため採らない(Sudoku §10)。
- **デイリーは今日の 1 問だけ。** 過去の日付には遡れず、一覧も入口も持たない。日付が過ぎた
  中断中のデイリーは次に読み込むとき(起動・ゲームを開く)にレコードごと捨て、ホームの
  「デイリーチャレンジ」はつねに今日の問題へ向く。遊んでいる最中の盤面は日付が変わっても
  取り上げない。達成した日の記録は残す(`docs/PRODUCT_PRINCIPLES.md`「デイリーは今日の 1 問」、
  2026-10-02 に過去日への遡りを廃止)。
- **ストリークは数えない・表示しない。**

中断は難易度モード用・デイリー用の **2 スロットを独立して保持**する(§11)。
難易度を変えて始めると、難易度モードのスロットは置き換わる(確認を出す)。
最後に選んだ難易度は `cg.prefs` に残り、次回のホームはその難易度を第一に出す(§11)。

## 10. 時間と統計

- **プレイ中に時計を表示しない**(ブランド原則)。経過時間は内部で記録し、結果画面と
  統計でのみ見せる。
- 統計: 難易度別に プレイ回数 / クリア数 / 最短時間 / 合計プレイ時間、デイリーは
  達成日ごとの時間(`dailyTimes`)。Minesweeper §9 と同形。
- **スコアは作らない。**ランキングもストリークも作らない。自己ベストの更新は、更新した
  ときだけ静かに示す。
- クリア画面の記録は、難易度モードではその難易度の最短時間、デイリーではその日の記録。
  記録があれば差を符号付きで添える(`+0:18` / `−0:05`)。比べる相手は自分の記録だけで、
  初めてのクリアには何も添えない(`ui/components/BestDelta.tsx`)。

## 11. 中断と再開

- 難易度モード用・デイリー用の **2 スロットを独立して保持する**。
- 保存するのは(`cg.saveGame` / `cg.saveDaily`、v1)mode / seed / difficulty / dailyDate /
  size / regions(1 マス 1 文字、`'a'`〜`'i'`)/ solution(行順に王冠の列 index を 1 桁ずつ)/
  marks(1 マス 1 文字: `'.'` 空 / `'x'` `×` / `'q'` 王冠)/ hintCount / elapsedSeconds /
  savedAt。**ミス回数は持たない** — このゲームにミスという概念がない(§5)。
- **どのスロットのレコードかを決めるのはキーである。**2 つのスロットは同じ形のレコードを
  持つので、難易度用のキーに入っている `mode: 'daily'` のレコードは「デイリーだった」の
  ではなく壊れている。復元せず既定値へ落とす(`gameSlotSchema(key, expectedMode)`、
  `src/test/savedGameSlots.test.ts` が強制)。
- **スロットを置き換える前に確認する。**中断中の難易度と違う難易度を選んだときは確認を
  出す(同じものを選ぶのは再開)。デイリーは今日の 1 問だけなので、別の日を選ぶ場面はない。
- **検証は fail-closed。**プレイから生まれえないレコードは読み捨ててホームへ戻す:
  - size が difficulty のサイズと合わない、または文字列の長さが合わない
  - regions が N 個の連結領域で盤面を覆っていない(未知の文字を含む・欠番がある・非連結)
  - solution が §3 の規則を破っている(列の重複・斜め接触・領域に王冠が 2 つ)
  - regions が解を 2 つ以上許す(§8 の完全探索を読み込み時にもう一度、2 本目が見つかった
    時点で止めて数える。§8 は複数解を出さず、§2・§6 はそれを前提にしている)。
    1 マスの領域(§8 の下限)は検査しない — 下限を入れる前の盤面も一意解なので正しく遊べる。
  - marks に `'.'` / `'x'` / `'q'` 以外が入っている
  - mode が `daily` なのに日付が無い
- 背景へ回るとき、盤面の保存と未計上秒の計上を**同じ同期処理で**行う(Minesweeper §10)。
- 保存キーは `cg.saveGame` / `cg.saveDaily` / `cg.stats` / `cg.flags` / `cg.prefs` の **5 つ**。
  `cg.prefs` は最後に選んだ難易度だけを持つ — 盤面の遊び方を変える設定は 1 つもない(§14)。
- 保存の失敗でゲームを止めない。バリデータは例外を投げない。

## 12. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ原則 1 文・図中心([I18N_POLICY.md](I18N_POLICY.md))。

1. 各行・各列・各色の領域に王冠を 1 つ。
2. 王冠どうしは隣り合わない — 斜めもだめ。
3. タップで `×` → 王冠、なぞって `×` をまとめて置く。詰まったら Hint。

ゲーム別 Landing Page はまだ無いので、「詳しく見る」は出ない。

## 13. 演出とアクセシビリティ

- **領域は色だけで区別しない。**薄い地色 9 色(ライト / ダークで各 9 色 —
  `ui/crown-grid.css`。色はゲームの中身なので、Minesweeper の数字や Water Sort の液体と
  同じ線でゲームの CSS が持つ — [architecture/css-split.md](architecture/css-split.md))に
  加えて、**領域どうし・領域と盤の外周のあいだに 2px のインクの継ぎ目**を引く。地色を
  全部外しても盤面は読めなければならない。地色の上のインク(王冠・`×`、違反表示の王冠を
  含む)は 4.5:1 以上のコントラストを満たす(実測値は `ui/crown-grid.css` の冒頭、
  `ui/contrast.test.ts` が CSS から計算し直して固定する)。
- **領域は「角丸のかたまり」として描く。**マスの背景はインク(`--cg-wall`)で、地色は
  マスの `::before` が 1 枚のタイルとして持つ。タイルは、隣が別領域か盤の外である辺
  (境界の辺)だけ `--cg-gap`(1px)ぶん内側に寄せる — 両側のタイルが 1px ずつ引くので、
  境界は必ず 2px のインクになる。同じ領域どうしの辺は寄せないので、タイルは継ぎ目なく
  並ぶ。隣り合う 2 辺がともに境界な角(凸の角)は `--cg-round`(5px)で丸め、凹の角は
  丸めない — 向こう側のタイルがそこで丸まって欠けを作る。マスを数えるための 1px の罫線
  (`--line`)は、右辺・下辺が境界でない側にだけ残す。境界は render 側(`tileClasses`)が
  4 辺の境界フラグと 4 隅の凸フラグとして計算し、クラス `cg-b-t` / `cg-b-r` / `cg-b-b`
  / `cg-b-l`(境界の辺)と `cg-c-tl` / `cg-c-tr` / `cg-c-br` / `cg-c-bl`(凸の角)で盤面と
  Quick Rules の図(§12)の両方に渡す — 実際のマス集合が同じ規則を描くので、2 箇所が
  食い違うことはない。
- **王冠は言語非依存のインライン SVG。**`♛`(U+265B)はフォントによって太さ・傾き・
  代替字形が違い、端末やロケールで同じ盤面が違って見えてしまうため、`CrownGlyph`
  (台座 + 3 つの山と山の先の玉。宝石などの装飾はなし — 玉が無いと 15px では棘の列に見える)を `fill="currentColor"` で描く。ShapeIcon
  ([SHAPE_REGIONS_RULES.md](SHAPE_REGIONS_RULES.md))と同じ理由・同じ方針である。`×` は
  そのまま `×`(U+00D7)の文字。
- 王冠と `×` はインク色の記号。違反表示は警告色 + 枠で、色だけに頼らない(§5)。違反の
  王冠だけは `--ink` ではなく `--cg-warn-ink` で描く — 共通の `--warn` は地色の上で
  2.95〜4.15:1 にしかならないので、同じ色相をライトでは濃く、ダークでは明るく寄せて
  4.5:1 に届かせた色である。枠は `--warn` のまま(文字ではなく 2 つ目の合図)。
- **Hint はスポットライトで示す**(§6)。表示中(`hint !== null`)、根拠になった家・
  根拠を担う候補・確定するマス・違反のマスのどれでもないマスには `cg-cell-dim` が付き、
  紙色(`--paper`)の幕を不透明度 62% で被って沈む — 領域の地色がどの色でも、ライトでも
  ダークでも、同じだけ沈む(`--paper` はテーマに追随するため)。根拠を担う候補
  (`step.support`)は `cg-cell-support` で accent 34% の色つき、確定するマス
  (`step.cells`)は `cg-cell-hint` で accent 3px の太い枠。**枠はすべてタイル(`::before`)の
  inset の影で描く** — 絶対配置のタイルは親ボタンの `outline` の上に描かれるので、
  `outline` で引いた枠は見えない(2026-09-27 の実機スクリーンショットで判明。違反の枠(§5)も
  同じ直しを受けた)。根拠になった家
  (`step.houses`)自体には重ねる色を置かない — 幕で沈んだ他のマスに対して、地色が
  そのまま見えることが強調になる。違反(`cg-cell-hint-broken`)は今までどおり `--warn`
  3px の枠で、この強調より優先して示す。
  (2026-09-27 の実機プレイテスト以前は、根拠の家と候補をどちらも accent 12%/28% の
  薄い重ねだけで示していて、領域の地色の上では見えづらかった — 今は幕で沈める側と
  地色のまま残す側のコントラストが合図になる。)
- 各マスはボタンで、**行・列・領域番号と状態(空 / `×` / 王冠)**を読み上げる。違反に
  関わる王冠は「ルール違反」を添える。
- 9×9 が 320px 幅に収まるようにマスの大きさを clamp する(Takuzu §13 と同じ算段)。
- **押下は地色の切り替えで示す。**`filter` の連続変化ではなく、タイルに半透明の重ね
  (ライト `rgba(0,0,0,.06)` / ダーク `rgba(255,255,255,.08)`、`linear-gradient` 1 色)を
  乗せるだけ — 低スペック端末での再描画が軽い。
- **王冠を新しく置いた一瞬、その行・列・領域と 8 近傍のマスが光る**(`cg-cell-reach`、
  700ms、地色 → `--accent-soft` → 地色)。「どこが埋まったか」を置いた直後に見せる
  だけの一過性の表示であって、印でも自動 `×` でもない(§14)。置いたマス自身は光らない。
  `×` を置いても起きない。
- 印が変わるとき(王冠・`×` のどちらを置いても)は一拍のポップで現れる — 王冠は
  `transform: scale(.6) → 1`、`×` は `opacity: 0 → 1`、ともに 90ms ease-out。王冠 ↔ `×`
  の入れ替えでも必ず新しく現れる。
- **盤面が完成してから結果カードが出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。
  その間、盤面ルートに一度だけ `--accent-soft` の淡い光が乗って消える(`cg-board-solved`、
  opacity 0 → 1(30%)→ 0、900ms — Number Path / Shape Regions と共通の仕組み)。同時に、
  置かれている王冠が行順に少しずつ間を置いて着地し直す(`cg-settle`、240ms、1 つあたり
  40ms 遅れ)。結果カードが出る頃には両方とも消えている。
- Reduced Motion が有効なら、上記のアニメーションはすべて即時になり
  (`src/ui/styles.css` の全体ルール)、**どれも終わった後に何も残らない** — 光は消え、
  ポップは最終形のまま、王冠は元の位置のままである。
- ボードの上では `touch-action: none`(なぞりをブラウザのスクロールに取られない)。
  ポインタはキャプチャし、`pointercancel` はストロークをそこで止める。

## 14. 意図的な差分

ブランド原則により合わせないもの:

- ミス回数制限・ライフ制・ゲームオーバー(しない。そもそもミス判定をしない — §5)
- プレイ中のタイマー表示、ストリーク、オンラインランキング、スコア(しない)
- Hint を広告視聴やコインの報酬にすること(しない。常に無料・無制限 — §6)

設計判断として合わせないもの:

- **他社の名称・アセット・画面デザイン。**「Queens」等は他社の商品名であり、複製しない。
  古典的な Star Battle(1 星)のメカニクスを、独自の名前・表現で作る(Reversi / Takuzu と
  同じ物差し)。
- **Undo。**すべてのマスはタップで 空 → `×` → 王冠 → 空 と一巡する(§4)。すべての手が
  もともと可逆なゲームに Undo を重ねても、同じ操作が 2 つ並ぶだけである(Takuzu §8)。
  なぞりで置いた `×` も、1 マスずつタップで外せる(なぞりが書くのは空マスだけなので、
  外す相手は自分で置いたものに限る)。
- **自動 `×`**(王冠を置いたら周囲を自動で消すこと)。「どこが埋まるか」を読む作業が
  この パズルの中身であり、それを肩代わりすると盤面を埋めるだけの作業になる(§4)。
  王冠を置いた一瞬だけ利き筋のマスが光る(§13)のは表示であって、印ではない。
- **長押し・モード切替**(作らない。§4)。
- **「解と違う」の常時表示**(作らない。§5)。ただし **Hint は解に無い王冠を指摘する**(§6)。
  Takuzu §9 が「解と違う」表示を退けたのは、あちらの誤りが「まだ矛盾していないだけ」で
  あり、警告色にすると解答の開示になるからである。ここでは一意解の出題なので誤りは
  定義でき、しかも常時ではなく **Hint を押したときに 1 つだけ**言う。誤った王冠の上に
  積める推論は存在しないので、それ以外の Hint に意味が無い。
- **サイズだけで難易度を変えること**(§1、§7)。issue #194 の要求はティアが実際の解法難度に
  対応することであり、9×9 だから難しいのではなく、T5 が要るから難しい。
- **10×10 以上・2 星以上の変種**(作らない。指で押せる大きさと、1 循環で済む操作を優先する)。
- **推測が必要な盤面・複数解の盤面**(出さない。§7、§8)。
- **問題データの同梱・配信**(すべて端末上で生成する。§8)。
- **レベル 1〜100**(作らない。§9)。

合わせたもの:

- 1 行・1 列・1 領域に 1 つ、8 近傍非接触、一意解、常時の違反表示、タップ循環 + なぞり `×`。

### 比較対象との対応(2026-09-29 確認、issue #210)

公式 Help([LinkedIn Help — Queens](https://www.linkedin.com/help/linkedin/answer/a6269510)、
2026-09-29 閲覧)が挙げる規則と、このゲームの対応(5 種類の練習セットの位置づけは
[PUZZLE_PRACTICE_SET.md](PUZZLE_PRACTICE_SET.md)):

| 公式の規則 / 機能                                        | Crown Grid                                                              |
| -------------------------------------------------------- | ----------------------------------------------------------------------- |
| 各行・各列・各色の領域に王冠(クイーン)をちょうど 1 つ   | 規則 1(§3)。同じ                                                         |
| 王冠どうしは隣り合わない — 斜めも含む(8 近傍)           | 規則 2(§3)。同じ。**チェスのクイーンの長距離斜め攻撃は公式にも無く、足していない**(`engine.test.ts`) |
| タップで 空 → × → 王冠 を循環                            | §4。同じ                                                                 |
| Hint(王冠を置くべき領域、または誤った配置を示す)         | Hint(違反 → 解に無い王冠 → 技法の一手、§6)                                |
| Auto-check(違反を赤い縞で示す設定)                       | 違反表示は常時オンで設定なし(§5)                                          |
| Auto-place ×(王冠を置くと周囲を自動で ×)                | 作らない(§14)。置いた一瞬だけ利き筋が光る(§13)                             |
| Undo / Clear                                             | 作らない(§14)。タップ循環と「同じ盤面で再挑戦」                             |
| 盤面サイズ・領域数(Help に記載なし)                      | 6×6 / 8×8 / 9×9(§1)                                                      |
| 1 日 1 問                                                | 難易度 3 種 + デイリー。新しい盤面はいつでも(§9)                          |

合法手と勝利条件は一致しており、違いは支援の形だけである。公式の問題・解答・アセットは
取得も転載もしない(すべて端末上で生成する — §8)。

## 15. Club House

正典は [architecture/club.md](architecture/club.md) §6 と §16。ここにはこのゲームの側で決まることだけを書く。

- **順位表の名前(`params`)** は `{ difficulty }`(`easy` / `medium` / `hard`。サイズは難易度の一部で、§1 のとおり難易度が決める)。デイリー(毎日 Medium)も同じ形で載る。
- **結果画面が送る事実(`facts`)** は `{ elapsedSeconds, hints }`。共有(`ShareAction`)の `details` と同じセッションの値(`elapsedSeconds` / `hintCount`)から作り、ここで計算しない。
- **順位の軸は時間**で、短いほうが上(`order: 'elapsedSeconds'`、`direction: 'asc'`)。表示するだけの値は順位に使わない。
- **デイリーは Today の挑戦へ、それ以外はランキングの表へ**(club.md §6・§16)。デイリーは全員が同じ 1 つの盤面なので、デイリーの局だけ結果画面が `daily`(その日付)と `boardDigest` を付けて送り、その日の挑戦に結果が集まる(順位は日の中だけ)。デイリー以外の局は、盤面を揃えずに難易度ごとのランキングの表へ送る(`boardDigest` は `null`)。Today の `Play` はこのゲームを普通の入口で開くだけで、盤面は渡されない。
- **`boardDigest`**(`game/challenge.ts`)は、局の**開始時の盤面**を `game/rng.ts` の `hashSeed` に通した `cg1:` + 8 桁 hex。元の文字列は領域(region)の 1 セル 1 文字の文字列(`a` が領域 0。`game/serialize.ts` の `encodeRegions`、compatibility.test.ts が固定している文字列)。解は領域から一意に決まるので混ぜない。サイズは長さから決まる。盤面は遊んでも動かず、動いた後の盤面は使わない。2 台の端末が同じ盤面を作ったかを確かめるための印で、改ざん防止ではない。生成が版で変わっても、違う盤面が 1 つの挑戦に混ざらない。2026-08-01 のデイリーと 2026-10-02 のデイリーなどの値は `game/challenge.test.ts` が固定する(動かすと全端末のデイリーが一致しなくなる)。
- **デイリーは最初に終えた結果が数えられる**(1 メンバー 1 件。club.md §6-3)。送るのはクリアした結果だけで、一度見た答えでの再挑戦は同じ挑戦ではない。
- ゲーム自体は変わらない。統計・自己ベスト・レベル進行・保存データ・結果画面の既存の表示には触れない。
