## これまでに決まったこと(2026-10-20 — オーナーが 5 本をまとめて採った提案の仕様と、計画の判断。詳細は計画)

製品オーナーの判断(2026-10-20、5 本の採用とブリーフ)と計画で決めたこと。理由と未決の点は、計画の
「54. Nested Tic-Tac-Toe」にある。

- 3×3 の小盤が 3×3 に並ぶ盤で、CPU と三目並べを打つ。対局相手は CPU だけ。難易度は Easy / Normal /
  Hard。先手 / 後手を選べ、次の対局から適用する。デイリー・時計・レーティングは無い。
- 初手は 81 マスのどこでも。以後、相手は直前に打たれたマスの小盤内での位置と同じ位置の小盤に打つ
  (送り)。送り先の小盤が閉じていれば、開いている小盤のどこにでも打てる。
- 小盤で 3 つ並べればその小盤を取る。取られた小盤と満杯の小盤は閉じる(残りのマスには打てず、送り先にも
  ならない)。引き分けの小盤はどちらのものでもない。取った小盤を大盤で 3 つ並べれば勝ち。
- **全小盤が閉じて大盤にラインが無ければ引き分け**(共通の規則として凍結。出典は Phase 2 で確認日つきで
  比較の節に書く)。「取った小盤の多い側の勝ち」は採らない。
- 助けは Undo(無制限・無料。CPU の応手と自分の 1 手をまとめて戻す)と、打てる小盤の表示(規則の
  可視化)。Hint・評価バー・棋譜・投了・引き分けの提案は作らない。
- 打てるマスだけが押せる。閉じた小盤や送り先以外の小盤を押しても、叱る通知も音も出さない。
- CPU の読みは α–β + 評価関数。探索はプレイヤーの着手を起点にだけ、1 本の 450ms タイマーの中で走る。
  Hard は反復深化 + ノード上限で、上限に達したら完了済みの深さの最善で打つ。**ノード上限は低スペック
  実機の p95 で決める**(提案時の試作の数値は使わない。段取りは未決 — 計画)。同点は
  `createRng(`${seed}:cpu:${moveCount}`)` で決める。Easy / Normal の中身は未決 — 計画。
- 統計は難易度別の `played` / `wins` / `losses` / `draws` と、総プレイ秒(提案の表に無い。盤面 4 本と同じ
  計上を引き継ぐ)。放棄は負けに数えない。
- 保存は `nt.saveGame`(1 スロット)/ `nt.stats` / `nt.flags` / `nt.prefs`(先後。難易度を入れるかは
  未決 — 計画)。中身は着手リストで、読み込みでは空の盤から再生して検証する(非合法手・終局後・手数
  超過を拒否 — fail-closed)。再開後の Undo は未決 — 計画。
- 印は形(✕ と ○)で描き、文字を置かない。色は役割色(自分 = アクセント)。先後と印の対応は未決 —
  計画。
- 「送り」を Quick Rules の先頭に置く。
- 市中で別の名で呼ばれる同形式との対応(出典・確認日・商標と両ストアの検索結果)は、この文書の比較の節に

## Quick Rules(文案。仮)

3 ステップ・図中心・各 1 文。送りを先頭に置く。本文を書くときに確定する。

1. 打ったマスの位置が、相手が次に打つ小さな盤を決める。
2. 送られた盤が閉じていれば、空いている盤のどこにでも打てる。
3. 小さな盤を 3 つ並べて取れば勝ち。
