# Reversi — 正式ゲームルール

このドキュメントが Reversi の仕様の正本である。実装(`apps/simple-games/src/games/reversi/`)、
テスト、Quick Rules はここに従う。コードはここへ `§n` で言及する。挙動を変えるときは、
同じコミットでこの文書を直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

ゲーム ID は `reversi`、i18n キーの接頭辞は `reversi`、保存キーの接頭辞は `rv.` である。
名称は一般名の「Reversi」を使う(「Othello」は商標であり使わない)。

## 1. 盤面と対局者

- 8×8 の 64 セル。各セルは空か、黒石か、白石を持つ(`game/types.ts`。行優先の配列、
  0 = 空、1 = 黒、2 = 白)。
- 初期配置は中央 4 セル: d4・e5 が白、d5・e4 が黒(0 始まりで `(3,3)`・`(4,4)` が白、
  `(3,4)`・`(4,3)` が黒)。
- **黒か白かはプレイヤーが選ぶ**(ホーム画面。既定は黒)。黒が先手なので、
  **色の選択がそのまま先攻・後攻の選択である** — 画面のボタンにも「黒(先攻)」
  「白(後攻)」と書き、プレイヤーがその対応を知っている前提に立たない。
  選択は次の対局に適用される設定であり、**対局中のゲームには触らない** — 始めた
  色のまま終わる。保存キーは `rv.prefs`、セッションは `playerColor` を持ち、CPU は
  残りの色を持つ(`cpuColorOf`)。対局相手は CPU だけである —
  オンライン対戦もローカル対人戦も作らない([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md)
  「初期リリースで実装しないもの」)。
- 石は色だけを描く。文字も数字も置かない — 盤面は全言語で同じに読める
  ([I18N_POLICY.md](I18N_POLICY.md))。

## 2. 一手の解決

1. 石は空セルにのみ置ける。置いた石と自分の既存の石が 8 方向のいずれかで相手の石を
   **1 個以上挟む**場合のみ合法である。
2. 挟まれた相手の石は、その全方向ぶんすべて自分の色に返る。返さない選択はない。
3. **返せる場所がないプレイヤーはパスとなる**(§4)。合法手があるときにパスは選べない。

## 3. 終了条件

- 両者とも合法手がないとき(盤面が埋まったときを含む)対局は終わる。
- 石の多い側の勝ち。同数は引き分け。勝敗は `status`
  (`'playing' | 'won' | 'lost' | 'draw'`)で一度だけ遷移する(`game/session.ts`)。
- 終局の瞬間に両者の石数を提示する。負けを叱る文言は書かない。

## 4. パス

- 手番に合法手がなければ**自動でパス**し、相手の手番になる。プレイヤーに「パス」ボタンを
  押させない — ルール上の帰結であって選択ではないため。
- パスが起きたときは一時通知で伝える(誰の手番が飛んだか)。通知は情報であって
  エラーではないので、音は鳴らさない。
- パスの連続 = 双方に手がない = 終局(§3)。

## 5. CPU(白)

- 探索は**プレイヤーの着手(タップ)を起点にのみ**走る。ポーリングも先読みもしない
  ([GAME_LIFECYCLE.md](GAME_LIFECYCLE.md)「CPU 探索」)。
- 難易度は 3 つ(`easy` / `normal` / `hard`):
  - **easy** — 合法手からシード決定的にランダムで選ぶ。角も平気で譲る。
  - **normal** — 1 手読み。位置の重み表 + 着手可能数で評価し、最善を選ぶ。
  - **hard** — 反復深化 α–β 探索(最大 6 手読み、残り 10 空きからは終局まで読む)。
    ノード上限 `HARD_NODE_LIMIT`(12,000)に達したら**完了済みの深さの最善で打つ** —
    上限は正直に守り、長時間 CPU を占有する「強い CPU」は作らない(issue #26 非目標)。
    上限値は実測で決めた: 上限まで使い切る手で開発機 180ms 程度、低スペック端末でも
    下記の 450ms の間(ま)に収まる。**間に収まる範囲でいちばん強い CPU** が
    この選択であって、間からはみ出す強さは採らない。探索は盤面を作り直さず
    1 つの `Int8Array` へ着手と復元を行う(`game/cpu.ts`)。ルール自体は
    `game/engine.ts` の 1 セットだけで、速いコピーを別に持たない。
- 同点の候補はセッションのシードと手数から決定的に選ぶ:
  `createRng(`${seed}:cpu:${moveCount}`)`。同じシードで同じ手順を踏めば、CPU は必ず
  同じ手を返す。ゴールデンテスト(`game/compatibility.test.ts`)が固定する。
- CPU の着手は約 450ms 置いてから盤面に現れる(`CPU_DELAY_MS`)。探索が一瞬でも、
  相手の手番が**手番として見える**ためであって、思考の演出を盛るためではない。
  アンマウント・Undo・新規対局はこの遅延を破棄する。

## 6. Undo

- **無制限・無料**。自分の直前の決定点まで戻す — CPU の応手と自分の一手(間に挟まった
  パスを含む)がまとめて取り消される。CPU の手番の途中には戻さない。
- Undo は振り直しではない: 戻して同じ手を打てば、CPU も同じ手を返す(§5 の決定性)。
- 広告視聴や課金による Undo は作らない([ADS_POLICY.md](ADS_POLICY.md))。

## 7. 助けの形

- **合法手は常に盤面に示す**(小さな点)。リバーシで初心者が最初に躓くのは
  「どこに置けるか」というルールの読み取りであり、これはルールの可視化であって
  最善手の提案ではない。Minesweeper の旗やSudoku のメモと同じ側にある。
- **Hint(最善手の提案)は作らない**: 盤面は完全に見えており、隠れた情報がない。
  次の一手を教える機能は CPU がプレイヤーの側でも打つことになる
  (docs/SLIDING_PUZZLE_RULES.md §8 と同じ判断)。
- 助けは Undo(§6)と合法手の表示だけ。どちらも無料で、初回起動から使える。

## 8. スコアと統計

- スコアという数はない。対局の結果は勝ち / 負け / 引き分けと最終石数だけである。
- 統計は難易度ごとに `played`(開始した回数)・`wins`・`losses`・`draws`、全体で
  `totalPlaySeconds`。ストリークは数えないし表示しない。
- 対局を放棄して新しく始めた場合、負けには数えない(`played` には既に数えている)。
  記録されるのは実際に終局した対局だけ — 統計が脅しになってはならない。
- プレイ時間は逐次計上(bookedRef 方式、2048 と同じ)。

## 9. 中断と再開

- **途中保存する。** 盤面はターン制で、保存して開き直した盤面は保存した瞬間と同じ
  である(docs/GAME_2048_RULES.md §10 と同じ理由)。
- 保存スロットは 1 つ(`rv.saveGame`)。盤面(64 文字、セルごとに `0`/`1`/`2`)・手番・
  難易度・シード・手数・経過秒を持つ(`game/serialize.ts`)。
- CPU の手番中(遅延中)に離れた場合はその手番のまま保存され、再開時に CPU が打つ。
- **Undo 履歴は保存しない**。再開した対局はその局面から始まる。
- 壊れた保存は読み捨てて、ホームへ戻る(勝手に新しい対局を始めない)。検証は
  fail-closed: 初期 4 石が欠けた盤面・駒種以外の文字・終局済みの盤面は破棄する。

## 10. Quick Rules(アプリ内チュートリアル)

3 ステップ・図中心・各 1 文(初回起動時に表示、以後はホームから):

1. 挟んだ石は全部返る — 点のあるマスに置ける。
2. 置ける場所がなければ自動でパス。
3. 盤面が埋まったとき、石が多いほうの勝ち。

詳細は Landing Page へ。ガイドを公開するまで「詳しく見る」は出さない
(`src/ui/landing.ts`)。オフラインでは何も起きない(ゲームは止めない)。

## 11. 演出とアクセシビリティ

- 石は DOM 要素。返る石は Y 軸の反転(scaleX)で 220ms、置いた石は 120ms のポップ。
  要素は増やさない — 粒子も画面揺れもない。
- Reduced Motion(アプリ設定または OS)では反転・ポップともに無効。石は新しい色で
  すでにある状態で描かれる。
- 最後に置かれた石には小さな印を付ける(CPU の手を見失わないため)。
- 盤面は `role="grid"` 相当のボタン群。各セルは「空 / 黒 / 白」と行列を読み上げ、
  合法手のセルだけが押せる。
- 石数(黒 n – 白 m)は常時表示する。これは急かす表示ではなく現在の形勢である。
  **時計を出さない**。経過時間は統計にだけ残る。
- 効果音は既存の合成音(`services/sound`)のみ: 着手で `select`、石が返るとき `match`、
  パス通知は無音、勝ちで `clear`、負け・引き分けで `gameOver`。設定に従う。

## 12. 意図的な差分

市中のリバーシ / オセロ系アプリを調べたうえで、意図的に合わせないものを記録する。

**ブランド原則により合わせないもの**

- **Undo・強さ解放を広告や課金に結び付けない**。難易度は最初から全部選べる。
- レーティング・ランキング・オンライン対戦はない。記録は端末の中だけにある(§8)。
- デイリーやストリークで毎日呼び戻さない。

**設計判断として合わせないもの**

- ~~**色は選べない(プレイヤーは常に黒・先手)**~~ → **撤回した(2026-08-07)**。
  「先後の体験差は難易度で吸収できる」と書いていたが、吸収できるのは強さであって
  **先手か後手かという遊びの違いではない**。既定を黒(先攻)にしておけば初回起動は
  何も変わらず、白で受けたい人はそれを選べる。既定と禁止を取り違えた判断だった。
- **最強 CPU を作らない**。hard は「よく考えるが読み切らない」上限付き探索であり、
  完全読みの終盤ソルバーや定石データベースは積まない(§5、issue #26)。
- **棋譜・解析・形勢グラフを持たない**。対局が終わったら結果だけが残る。盤面を
  最優先にし、情報量を足さない(BRAND.md)。
