# Sudoku 6×6 — 正式ゲームルール

この文書は Simple Games 収録タイトル「Sudoku 6×6」の唯一のルールソースである。
実装(`apps/simple-games/src/games/sudoku-6x6/game/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。コードはここへ `§n` で言及する。数値や挙動を変えるときは、
同じコミットでこの文書を先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Hint / Undo は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

ゲーム ID は `sudoku-6x6`、i18n キーの接頭辞は `sudoku6x6`、保存キーの接頭辞は `s6.`
である。配信チャンネルは **Web 先行公開(`web-beta`)** で、アプリには正式収録していない
([WEB_VERSION.md](WEB_VERSION.md)「先行公開」、issue #210)。
[Sudoku](SUDOKU_RULES.md)(9×9)とは**独立したゲーム ID**で、盤面・保存・Hint・生成の
コードを共有しない(`games/A` から `games/B` を import しない —
[ARCHITECTURE.md](ARCHITECTURE.md))。9×9 の表示名を変えたものではなく、9×9 の実装にも
保存にも一切触れない(§14)。5 種類の練習セットの中での位置づけと、比較対象との対応表は
[PUZZLE_PRACTICE_SET.md](PUZZLE_PRACTICE_SET.md)。

## 1. 盤面

- 6×6 = 36 マス。**2 行 × 3 列のボックス 6 個**に分かれる(上 3 個・下 3 個ではなく、
  3 段 × 2 列に並ぶ: 行 0–1 / 2–3 / 4–5 と列 0–2 / 3–5 の組み合わせ)。
- マスは「初期数字(固定)」「プレイヤーが入れた数字」「空」のいずれか。
- 各マスはメモ(候補数字 1〜6 の任意の組)を持てる。
- 使用する数字は ASCII の `1`〜`6` に固定する(言語を変えても盤面表記は変わらない —
  [I18N_POLICY.md](I18N_POLICY.md))。

サイズは 6×6 の 1 つだけ。4×4 も 8×8 も作らない — このタイトルは「6×6 の小さな数独」で
あって、大きさの梯子ではない(§14)。難易度は §6 の技法の集合で定義する。

## 2. 勝利条件

36 マスすべてが埋まり、各行・各列・各ボックスに 1〜6 がちょうど 1 個ずつ入った状態。
これは「盤面に重複がない」ことと同義であり、実装は重複ゼロ + 空マスゼロで判定する
(解と照合しない。出題は一意解なので一致する — §7)。

## 3. 操作

1. マスを選ぶ(初期数字のマスも選べる。選ぶと同じ数字がハイライトされる)
2. 数字パッドで 1〜6 を入れる / 消す
3. メモモードのとき、数字パッドはメモの追加・削除になる

規則(Sudoku §3 と同じ):

- 初期数字のマスは変更できない。
- 数字を入れると、そのマスのメモは消える。
- 数字を入れると、**同じ行・列・ボックスのメモから同じ数字を自動で消す**
  (手作業の消し込みを省く。ルールを変える支援ではない)。
- 数字を消すと、そのマスは空に戻る。メモは復元しない(Undo で戻せる)。
- 数字パッドは各数字の残り個数(6 − 盤上の個数)を表示し、6 個置き終えた数字は無効化する。
- **キーボード**(あれば、`ui/useGameKeys` 経由): 矢印で選択を動かす、`1`〜`6` で入れる、
  Backspace / Delete / `0` で消す、`N` でメモモード切替、Ctrl/Cmd+Z で Undo、`H` で Hint。
  押しっぱなしのキーリピートでは動かさない。結果カードと確認ダイアログの間は効かない。

### 完成の合図

正解の数字を入れて行・列・ボックスのどれかに 1〜6 が揃った瞬間、そのユニットのマスが
一拍(0.7 秒)だけ薄く光り、正解音が高く鳴る(Sudoku §3 と同じ演出。採点ではない)。
Reduced Motion では光らせず、音だけ残す。判定は「6 マスに 6 種の数字」というルールの
事実で(`engine.ts` の `unitsCompletedBy`)、解と照合しているのは音の高さを決める側だけ。

## 4. ミスと支援

- **ミス上限はない。ゲームオーバーもない。**
- ミスの定義: 一意解の値と異なる数字を空マスに入れたとき、ミス 1 回。同じマスに続けて
  別の誤答を入れれば、その都度 1 回。
- **ミスの即時表示**(誤答マスを警告色にする)は設定で切り替え。**既定はオン**
  (`s6.prefs` の `highlightMistakes`。共有の設定画面にこのゲームの節として出す —
  `loadSettingsSection`)。オフのときも重複表示(下記)は出る。
- **重複表示は常時オン**: 同じ行・列・ボックスに同じ数字が 2 個以上あるとき、その数字の
  マスを警告表示する。これはルール違反の指摘であり、答え合わせではない。
- ミス回数は記録し、クリア画面と統計で見せる。プレイ中はカウンタを常時表示しない。

### Undo

- 無制限(実装上の上限は 2000 手)。
- Undo の対象は「数字の配置」「数字の消去」「メモの変更」。
- Undo はミス回数を戻さない。Hint 使用回数も戻さない。
- 保存された中断ゲームに Undo 履歴は含めない。

**Undo を作る理由**: 数字を入れると同じ行・列・ボックスのメモが自動で消え、1 タップで
消えた候補を手で復元することはできない(Sudoku §3、Takuzu §8 の対比)。

## 5. Hint

Hint は「次に論理だけで確定できるマス」または「次に消せる候補」を 1 つ示す。答えを埋める
のではなく、**なぜそこが確定するのかを示す**(§8 のグレーダーの解法パスを流用する)。

- 対象マスと、根拠になる行 / 列 / ボックスを強調表示する。
- 短い一文を添える。**技法名(Naked Single、Locked Candidates など)は UI に出さない。**
  平易な言い換えのみ(例:「この行で 5 が入るのはここだけ」)。
- Hint は数字を入れない。プレイヤーが自分で入れる。
- 無制限・無料。使用回数は記録し、クリア画面と統計で見せる。
- 論理的な次の一手が存在しないことは、一意解を持つ盤面では起こらない(§7 の生成条件により
  常にティア内の技法だけで進める)。万一検出できなかった場合(プレイヤーが誤答を積んだ
  あとを含む)は「今わかる手が見つかりません」を表示し、盤面は変えない。

## 6. 難易度ティア

難易度は**「許容する技法の集合」と「掘削の下限(初期数字の少なさ)」**で定義する。
どちらも生成時に構成として保証する([Sudoku](SUDOKU_RULES.md) §6 と同じ形)。
**全ティアで推測(仮置き・試行錯誤)なしに解けることを保証する。**

| ティア | 許容技法(これだけで解けることを保証)     | 初期数字の下限 | 対称性    |
| ------ | ---------------------------------------- | -------------- | --------- |
| Easy   | Naked Single / Hidden Single             | 16             | 180° 対称 |
| Medium | + Locked Candidates(pointing / claiming) | 11             | 180° 対称 |
| Hard   | + Naked Pair / Hidden Pair               | 8              | なし      |

各ティアは前ティアの許容技法を含み、かつ掘削の下限がより低い。上のティアほど
「使える手筋が増える」と同時に「手掛かりが減る」(実測の初期数字は §7 の表:
Easy 16 / Medium 12 / Hard 10 が中央値)。

### なぜ「必要な技法」で定義しないのか(2026-09-30 実測で変更)

当初この表は Crown Grid §7 と同じく「Medium は Easy の集合では解けない」「Hard は
Medium の集合では解けない」を**構成として保証する**定義だった。実装して
`guarantee.test.ts` と同じ固定シード(難易度ごとに 40 本)で測ったところ、派生 seed を
上限 60 本まで使っても条件を満たす盤面が見つかったのは **Medium 4 / 40、Hard 0 / 40**
で、残り(Medium 36 本・Hard 40 本)はすべて `fallback` になった。仕事量も
Medium p50 98,719・最悪 103,670、Hard p50 252,875・最悪 254,742 と、下の定義の
約 50〜60 倍だった。6×6 は下限まで掘っても singles だけで解けてしまう盤面が
ほとんどで、Hard の掘り方(単セル・下限 8)で別に掘った盤面でも、Locked Candidates が
要るのは約 1%(先頭 328 盤で 3 盤)、Pair が要るのは約 1,500 盤に 1 盤(先頭 4,633 盤で
3 盤)だった。「必要」を守るには毎回ほぼ fallback を出すか、予算の何十倍も探すことになる。

そこで本節の旧指示(「Hard の『Pair が要る』が実測で稀すぎる場合は、この表を
Sudoku §6 の形(許容技法 + 深さ)へ戻して、この文書を先に直す」)に従い、Medium も
含めて上の形に戻した。**保証できるもの(許容技法と掘削の下限)で定義し、保証できない
もの(必要性)は約束しない。**

- グレーダーは「実際に要した最低のティア」を返す(`gradeTier`、統計とテストで使う)。
  実測では Medium・Hard・デイリーの盤面も、ほぼすべて singles だけで解ける
  (§7 の表)。体感の差は初期数字の少なさから来る。
- X-Wing・Swordfish・チェーン類は扱わない。それらが必要になる掘削は生成時に巻き戻す。

## 7. 盤面生成と Seed

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。
(`generator.ts` の `generatePuzzle(seed, difficulty)`。)

1. **完成盤を作る** — 空盤にランダム化バックトラッキング(候補順を seed でシャッフル)。
2. **掘る** — Easy / Medium は 180° 回転対称のペア単位、Hard は単セル単位。順番は seed
   由来のシャッフル。**1 手ごとにグレーダーで検査する** — そのティアの技法集合だけで
   解き切れるか(`grader.ts` の `solvableWithin`)。解き切れない削除は巻き戻す。技法は
   すべて健全なので、グレーダーが解き切った盤面の解はその 1 つだけである(Sudoku §7 の
   不変条件②は①を含む)。ティアの下限個数に達したら止める。**1 パスで十分**(手掛かりが
   減れば解は増える一方 — Takuzu §6)。
3. **出荷前に確かめる** — 下限個数を守っているか、ティアの技法集合で解けるか、完全探索
   (`countSolutions`)で解がちょうど 1 つか。前の 2 つは手順 2 の構成で成り立ち、3 つ目は
   そこから従うが、3 つとも改めて確かめる。あわせて等級(`gradeTier`: Easy 集合で解けるか、
   だめなら Medium、だめなら Hard)を記録する。等級は報告であって出荷条件ではない(§6)。
4. 確認に落ちた場合だけ **seed を派生させて作り直す**(`<seed>#2`, `#3`, …)。派生 seed は
   `ATTEMPT_LIMIT`(60)本で必ず止まる。これは防御であり、§7 の表の全盤面は 1 本目で
   出荷している。
5. **例外を投げるのは 1 つの場合だけ**: 派生 seed を使い切っても出荷できる盤面が 1 つも
   無いとき(生成器が壊れている — 不公平な盤面を渡すより失敗として表に出す)。
   旧手順にあった「易しい候補を `fallback` 付きで出す」は、§6 の定義変更で不要になった
   (掘った盤面は常にそのティアの技法で解ける)ので廃止した。

不変条件:

- 同じ seed なら、必ず同じ盤面になる(`compatibility.test.ts` の golden で固定する)。
- 出題は一意解で、そのティアの技法集合だけで解ける(推測不要)。生成の最後に完全探索
  (`solver.ts` の `countSolutions`、2 つまで数える)で「解はちょうど 1 つ」を数え直す。
- 実際に要した技法の分布は `guarantee.test.ts` が出力する(§6 は必要性を約束しない)。

### 予算は仕事量で門にする

門は壁時計ではなく**仕事量**(`solverWork` = グレーダーが走査したユニットの数 +
完全探索が試した配置の数)で測る。同じ seed なら、どのマシンでも常に同じ数になる。
理由ごと [SUDOKU_RULES.md](SUDOKU_RULES.md) §7 に詳しい。

実測(開発機 = Apple Silicon の Mac、Node 25.5、`guarantee.test.ts` を単独で実行。
走査するのは難易度ごとに固定シード `sudoku-6x6-<difficulty>-g1`〜`g40`、デイリーは
2026-08-01 から 730 日。2026-09-30 計測)。仕事量と初期数字は seed の関数でどの機械でも
同じ。壁時計はこの機械の 1 回分:

| ティア   | n   | 仕事量 p50 | p90   | 最悪  | 派生 seed 最悪 | fallback        | 初期数字 p50(範囲) | 実際に要した技法      | 壁時計 p50 | 壁時計 最悪 |
| -------- | --- | ---------- | ----- | ----- | -------------- | --------------- | ------------------ | --------------------- | ---------- | ----------- |
| Easy     | 40  | 1,046      | 1,238 | 1,376 | 0(全て 1 本目) | 廃止(§7 手順 5) | 16(16〜16)         | singles 40            | 0.37ms     | 1.81ms      |
| Medium   | 40  | 1,632      | 2,057 | 2,081 | 0(全て 1 本目) | 廃止            | 12(12〜14)         | singles 40            | 0.39ms     | 1.20ms      |
| Hard     | 40  | 4,233      | 4,490 | 4,677 | 0(全て 1 本目) | 廃止            | 10(9〜12)          | singles 39 / locked 1 | 0.95ms     | 4.69ms      |
| デイリー | 730 | 1,651      | 2,027 | 2,279 | 0(全て 1 本目) | 廃止            | 12(12〜16)         | singles 730           | 0.31ms     | 0.53ms      |

門(`guarantee.test.ts`): 仕事量の上限 **12,000**(全盤面の最悪 4,677 の約 2.6 倍)、
seed の上限 **1 本**(派生 seed を 1 本も使わない)、全盤面が一意で、そのティアの技法集合で
解け、`gradeTier` の報告がそのティア以下で、下限個数(と Easy / Medium の対称性)を守る。
壁時計は出力だけ。端末の予算は 1 盤面 100ms 未満で、生成は UI スレッドで同期に走る。
超えた場合の対処順序: ① Hard の下限を上げる ② `ATTEMPT_LIMIT` を下げる。
**低スペック実機での実測はまだ行っていない。**

## 8. 技法(グレーダー)

グレーダー(`grader.ts`)は候補を伝播させながら、安い順に技法を試す:

1. **Naked Single** — 候補が 1 つのマス。
2. **Hidden Single** — 行 / 列 / ボックスで、ある数字の候補が 1 マスだけ。
3. **Locked Candidates(pointing)** — ボックス内である数字の候補が 1 行(列)に収まる →
   その行(列)のボックス外から消す。
4. **Locked Candidates(claiming)** — 行(列)内である数字の候補が 1 ボックスに収まる →
   そのボックスの行(列)外から消す。
5. **Naked Pair** — 同じユニットで 2 マスの候補が同じ 2 数字 → 他のマスからその 2 数字を消す。
6. **Hidden Pair** — 同じユニットで 2 数字の候補が同じ 2 マスにしか無い → その 2 マスの
   他の候補を消す。

どれも健全で、「どの解も使えない候補」しか落とさない。グレーダーは実際に要した最高技法を
返し(統計とテストで使う)、`findStep` は Hint のために「次の一手」を根拠(対象マス・
ユニット・数字)付きで返す。**技法の実装は 1 つだけ持ち、生成・Hint・`guarantee.test.ts`
が共有する。**

## 9. モードとデイリー

- **難易度モード**: Easy / Medium / Hard を選んで遊ぶ。レベル 1〜100 は作らない(9×9 と
  違い、このタイトルの供給は「好きな難易度の新しい盤面」であって坂ではない — issue #210)。
  seed は `sudoku-6x6-<difficulty>-<token>`(token = 起動時刻 + 乱数)。同じ seed なら
  同じ盤面。クリア画面の第一ボタンは「新しい盤面」(同じ難易度・新しい seed)、第二が
  同じ盤面での再挑戦。
- **デイリー**: 1 日 1 問。seed は `sudoku-6x6-daily-<YYYY-MM-DD>`(端末のローカル日付のみ)。
  **毎日 Medium 固定。**過去 30 日は無条件に開いている。達成した日は記録する。
  **ストリークは数えない・表示しない。**
- 中断は難易度モード用・デイリー用の **2 スロットを独立して保持**する(§11)。
- 最後に選んだ難易度は `s6.prefs` に残り、次回のホームはその難易度を第一に出す(初期値 Easy)。

## 10. 時間と統計

- **プレイ中に時計を表示しない。**経過時間は内部で記録し、結果画面と統計でのみ見せる。
- 統計: 難易度別に プレイ回数 / クリア数 / 最短時間 / 合計プレイ時間、デイリーは達成日ごとの
  時間(`dailyTimes`)。Crown Grid §10 と同形。ミス回数と Hint 回数は結果カードに出す。
- **スコアは作らない。**自己ベストの更新は、更新したときだけ静かに示す(`BestDelta`)。

## 11. 中断と再開

- 難易度モード用・デイリー用の **2 スロット**(`s6.saveGame` / `s6.saveDaily`、v1)。
- 保存するのは mode / seed / difficulty / dailyDate / givens(36 文字: `1`〜`6` / `.`)/
  solution(36 文字: `1`〜`6`)/ entries(36 文字: `1`〜`6` / `.`)/ notes(36 個の整数、
  6 ビットのマスク)/ mistakeCount / hintCount / elapsedSeconds / savedAt。
  **Undo 履歴は持たない。**
- **どのスロットのレコードかを決めるのはキーである**(`gameSlotSchema(key, expectedMode)`)。
- **スロットを置き換える前に確認する**(中断中と違う難易度・違う日を選んだとき)。
- **検証は fail-closed**: 文字列の長さが 36 でない / solution が §2 を満たさない / givens が
  solution と食い違う / entries が givens のマスを上書きしている / notes が 0〜63 の範囲外
  または数字の入ったマスにメモがある / mode が `daily` なのに日付が無い、または日付が
  あるのに難易度が medium でない、のいずれかは読み捨ててホームへ戻す。
- 背景へ回るとき、盤面の保存と未計上秒の計上を**同じ同期処理で**行う。
- 保存キーは `s6.saveGame` / `s6.saveDaily` / `s6.stats` / `s6.flags` / `s6.prefs` の
  **5 つ**。`s6.prefs` は最後に選んだ難易度と `highlightMistakes`(§4)を持つ。
- 保存の失敗でゲームを止めない。バリデータは例外を投げない。
- **ベータ中の注意**: スキーマを変えることがある(`WebBetaNotice` が伝える)。

## 12. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ 1 文・図中心。

1. 各行・各列・各 2×3 ボックスに 1〜6 を 1 つずつ。
2. マスを選んで数字を入れる。メモモードで候補を書ける。
3. 詰まったら Hint。次に確定するマスと理由を示す。

Learn More は出ない(ゲーム別ガイドは未公開。ベータのため)。

## 13. 演出とアクセシビリティ

- 盤面は 6×6 のボタン。**ボックスの境界は太い罫線**(2 行ごと・3 列ごと)。初期数字は太字、
  プレイヤーの数字はアクセント色。選択中のマスの行・列・ボックスは薄い地色、同じ数字は
  一段強い地色(Sudoku §13 と同じ読み)。
- 各マスはボタンで、**行・列と内容(空 / 初期数字 n / 入力 n)**を読み上げる。メモは
  読み上げに含めない(`aria-hidden`)。
- 違反(重複・ミス)は警告色 + 枠で、色だけに頼らない。
- 数字パッドは 6 キー 1 段(残り個数つき)。320px 幅で盤面と数字パッドが縦に収まる
  (6×6 は 9×9 より余裕があるので、マスは 9×9 より大きく取る — `clamp(40px, …, 56px)`)。
- **盤面が埋まってから結果カードが出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。
  Reduced Motion では即時。

## 14. 意図的な差分

ブランド原則により合わせないもの:

- ミス回数制限・ゲームオーバー(しない。§4)
- プレイ中のタイマー表示、ストリーク、オンラインランキング、スコア(しない)
- Hint / Undo を広告視聴やコインの報酬にすること(しない。常に無料・無制限)
- 1 日 1 問だけの供給(しない。難易度を選べばいつでも新しい盤面 — §9)

設計判断として合わせないもの:

- **他社の名称・アセット・画面デザイン。**「Mini Sudoku」は他社の商品名として使わない
  (数独の一般名は Sudoku で、このタイトルは大きさをそのまま名乗る)。
- **9×9 との共有**(しない)。別 ID・別フォルダ・別保存領域。9×9 のレベル・デイリー・
  フリープレイ・統計には触れない。
- **4×4 / 8×8 / 12×12**(作らない。§1)。
- **レベル 1〜100**(作らない。§9)。
- **Clear ボタン**(作らない。「同じ盤面で再挑戦」が同じ結果を与える)。
- **推測が必要な盤面・複数解の盤面**(出さない。§6、§7)。
- **問題データの同梱・配信**(すべて端末上で生成する。§7)。

### 比較対象との対応(2026-09-29 確認、issue #210)

公式 Help([LinkedIn Help — Mini Sudoku](https://www.linkedin.com/help/linkedin/answer/a8029251)、
2026-09-29 閲覧)は「各数字は各行・各列・各領域にちょうど 1 回」とだけ書き、盤面の寸法・
ブロックの形は書いていない。寸法(6×6)とブロックの形(2 行 × 3 列)は同日に第三者の解説
2 本(playminisudoku.com、minisudoku.com)で確認した — 公式の問題データは参照していない。

| 公式の規則 / 機能                       | Sudoku 6×6                                                 |
| --------------------------------------- | ---------------------------------------------------------- |
| 各行・各列・各領域に各数字を 1 つ       | §2。同じ                                                   |
| 6×6・2 行 × 3 列のボックス・数字 1〜6   | §1。同じ(第三者解説で確認)                                 |
| キーパッドで入力                        | 数字パッド(§3)                                             |
| Notes(1 マスに複数の候補)               | メモモード(§3)                                             |
| Hint(マスを示す / 誤りを知らせる)       | Hint(次の一手と根拠、§5)。誤りは設定による即時表示(§4)     |
| Undo / Clear                            | Undo は同じ。Clear は作らない(再挑戦)                      |
| 設定: 残り個数の表示 / 領域のハイライト | 数字パッドの残り個数と選択中の行・列・ボックスの地色を常時 |
| 1 日 1 問                               | 難易度 3 種 + デイリー(§9)                                 |

合わせたもの: 6×6・2×3 ボックス・1〜6、一意解、メモ、Undo、Hint。
公式の問題・解答・アセットは取得も転載もしない(すべて端末上で生成する — §7)。
