# Old Maid / ババ抜き — rules

No. 76、`old-maid`、保存 `om.*`、Web先行公開。オーナー選定2026-11-03。
4人（あなた＋CPU3人）。通常52枚とジョーカー1枚。同じ数字の2枚を組にして捨て、
自分の番に、次のまだ札を持つ人から伏せ札を1枚引く。引いた札と同じ数字があれば
自動でペアを捨てる。手札が0枚になった人は上がり。最後にジョーカーを持つ人が負け。
開始時もペアを自動整理。あなたの札が0枚なら直ちに成功結果へ進み、残りCPU観戦は求めない。
成功結果は自分が何番目に上がったかだけを述べ、残るCPUの順位は捏造しない。
初期整理で0枚なら席順で上がり順を記録（同時上がりの便宜上の固定順）。

自分の番には引く相手の札をすべて同じ裏面・寸法で提示し、1枚選んでめくる。
相手の札順は毎手決定的にシャッフルし、Jokerの位置を固定しない。自分の手札は表。
非公開札の値をDOM、aria、属性へ漏らさない。CPUも手札の枚数だけで無作為に引く。
引いた札の表示はあなた自身の手番だけ。CPU同士のペアは公開してよいが、単独札は表示しない。
運のゲームなので偽のCPU難易度は設けない。Undoなし。

2026-11-04の公開後改善: 相手の公開枚数を伏せ札の束で示し、引く相手を席の枠で案内する。
少ない伏せ札は中央に大きく並べ、自分の手札も中央へまとめる。単独札のめくりとペア成立を分けて描き、
公開された札には誰の動きだったかを付ける。演出は440ms／ペア580msで、演出が終わるまで次の手番と
表示しない。Reduced Motionでは演出を省略する。上がった相手には上がり順を表示する。

3ステップ図付き説明・同じ配札からの再挑戦・新しいゲーム・統計・共有・途中再開。
CPUの拍、移動・ペア成立演出は停止とReduced Motionに対応。保存schema v1では
53枚の完全な分割、一意性、ペアの偶数性、手札内の重複ランク不在、手番、上がり順を検査。
