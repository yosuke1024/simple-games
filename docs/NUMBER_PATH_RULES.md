# Number Path — 正式ゲームルール

この文書は Simple Games 収録タイトル「Number Path」の唯一のルールソースである。
実装(`apps/simple-games/src/games/number-path/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。コードはここへ `§n` で言及する。数値を変える場合はここを先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Undo と Hint は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

ゲーム ID は `number-path`、i18n キーの接頭辞は `numberPath`、保存キーの接頭辞は `np.`
である。**Web 先行公開(ベータ)チャンネル**のタイトルであり、アプリには正式収録しない
([WEB_VERSION.md](WEB_VERSION.md)「先行公開」、
[plans/2026-09-26-crown-grid-number-path-shape-regions.md](plans/2026-09-26-crown-grid-number-path-shape-regions.md))。
古典的な Hamiltonian path パズルを Simple Games の名前と表現で作る — 他社の名称・
アセット・画面デザインは複製しない。

## 1. 盤面

- W×H のマス。いくつかのマスに **数字 1〜K** が書かれている(1 が始点、K が終点)。
  隣り合うマスの間の辺のいくつかに **壁** がある。
- 数字は各値ちょうど 1 つずつ、K は 2 以上。壁は隣接するマスの間にだけある(外周には無い)。
- 盤面は生成後に変わらない。プレイヤーが書くのは**道**(§3)だけである。

難易度は 3 つ(スマートフォンの画面に収まる形で決めた):

| 難易度 | 盤面 | 数字の個数 K | 壁の本数 |
| ------ | ---- | ------------ | -------- |
| Easy   | 5×5  | 6〜8         | 0〜5     |
| Medium | 6×6  | 5〜7         | 0〜9     |
| Hard   | 7×7  | 4〜6         | 0〜14    |

8×8 以上は作らない — 320px 幅で 1 マスが指でなぞれる大きさ(約 40px)を下回る
(Nonogram §1 と同じ床)。難しさはマスの数ではなく、**数字が少ないこと**(道の自由度が
増える)と、§6 の探索が一本道から遠いことで出す。

**盤面に翻訳の要る文字は 1 つも載らない。**数字は ASCII の `1`〜`9` に固定し、壁は
太い辺、道は太い線で描く([I18N_POLICY.md](I18N_POLICY.md))。盤面は RTL でも左右反転しない。

## 2. 勝利

- **勝利**: 道が全マスをちょうど 1 回ずつ通り、末尾が K にあり、§3 の規則を 1 つも
  破っていない時点。
- 敗北は存在しない。ミス回数の制限も、ライフも、ゲームオーバーもない(§12)。

判定は道そのものを §3 で読んで行い、保存している解と照合しない(`engine.ts` の
`isSolution`)。出題は一意解なので(§6)、規則を満たした道は必ず解と一致する — だから
「きれいに見えるのに完成しない盤面」は作れない。

## 3. ルール

**1 本の道を、1 から引く。**

1. 道は 1 のマスから始まり、上下左右に 1 マスずつ進む(斜めには進まない)。
2. **壁の辺は越えられない。**
3. 同じマスを 2 回通らない。
4. **数字は 1 → 2 → … → K の順に通る。**次に来るべき数字でない数字マスには入れない。
5. K に着いたら道はそこで終わる。K の先には伸びない。
6. 完成した道は全マスを覆う(§2)。

出題は常に一意解を持つ(§6)。道の**接頭辞規則**(1〜5)は `engine.ts` の
`isLegalPrefix` が 1 か所で読み、勝利判定(§2)と保存の fail-closed 検証(§9)が
同じ関数を使う。

## 4. 操作

道は**なぞって**引く。操作の全体は次の 1 つの読みで説明できる — **触れたマスを順に
1 つずつ読み、道の末尾なら何もしない・道の上なら**そこまで**切り詰める・末尾から入れる
マスなら 1 マス伸ばす・それ以外なら何もしない**(`engine.ts` の `applyTrace`)。

- **なぞる(ドラッグ)**: 道の末尾(最初は 1)を押して隣へなぞると伸びる。1 つ前のマスへ
  なぞり返すと 1 マス戻る。道に沿って何マスもなぞり返せば、そこまで戻る。
- **タップ**: 道の途中のマスをタップすると、そこまで道を切り詰める。末尾に隣接する
  入れるマスをタップすると 1 マス伸びる(片手・キーボード用)。
- 道の途中のマスから、あるいは末尾に隣接するマスからなぞり始めた場合も同じ読みで、
  そのマスへ切り詰め(または伸ば)してから続きをなぞる。
- **入れないマスは、単に伸びないだけ**である。壁の向こう・隣接していないマス・
  順番でない数字・通過済みのマスのどれについても、エラー音も警告も出さない。
  道は常に §3 の 1〜5 を満たしており、「違反表示」という概念がない。
- **マウス**: 左ボタンのドラッグが指と同じ。右ボタン・中ボタンは何もしない。
  盤面の上でブラウザのコンテキストメニューは出さない。
- **キーボード**(`ui/useGameKeys` 経由。画面に無い機能をキーボード専用にしない):
  矢印キーで末尾から 1 マス伸ばす(1 つ前のマスへ向けた矢印は 1 マス戻る —
  なぞり返しと同じ)。Backspace / Delete で 1 マス戻る。Ctrl/Cmd+Z で Undo(§5)。
  H で Hint(§5)。押しっぱなしのキーリピートでは動かさない。結果カードと確認
  ダイアログの間は効かない。
- **指を奪われたとき**(`pointercancel` — 通知シェード、着信、掌の接触): なぞりは
  そこで止まり、**描いたぶんは残る**。取り消すのは Undo の仕事であり、OS の都合で
  黙って消さない。ドラッグの終わりにブラウザが残す click は捨てる(同じ操作を 2 度
  再生しない。`src/test/pointerContractWiring.test.ts`)。
- 盤面は `touch-action: none` で、なぞりがスクロールやズームに化けない。ポインタは
  捕捉(pointer capture)し、速いフリックでも通過マスを線分でサンプリングして
  飛ばさない(Nonogram の stroke と同じ形)。

**長押しもモード切替も作らない。**書く印は「道」1 種類で、伸ばすと戻すはどちらも
なぞり 1 本の上にある。

## 5. Undo と Hint

- **Undo は作る。無制限・無料。**1 手 = **1 ストローク**(1 回のドラッグで変わった全部)、
  または 1 回のタップ伸長、または 1 回の切り詰め(タップ / Backspace / 矢印)。履歴は
  セッション上に持ち(上限 500。実際の対局で届く数ではなく、無限に伸びないための蓋)、
  **保存しない** — 再開時の履歴は空(§9)。Undo は Hint 回数を戻さない。
  Retry(同じ盤面を最初から)は共通の `tryAgain` で、確認を出してから行う。

  **Undo を作るのは、なぞりが一度に多くを変えるからである。**1 回のフリックで 5 マス
  伸び、道の途中をタップすれば 10 マス消える。Takuzu のタップ循環のように「同じ操作を
  もう一度すれば元に戻る」形ではないので、Undo が要る。切り詰めをタップ 1 つで
  できることは Undo の代わりにならない — 消した 10 マスをもう一度なぞるのは作業である。

- **Hint は作る。無制限・無料。**順に:
  1. 現在の道が一意解の**接頭辞でなければ**、最後に正しかったマスを示す
     (「ここまで戻る」)。そのマスの先の道は warn 色で描く。
  2. 接頭辞なら、解の**次の 1 マス**を示す。

  マスを書き換えることはしない。プレイヤーが自分でなぞる。

  **これは Water Sort §8 と同じ「証明付き」の助け**である。出題は生成時に探索ソルバーが
  「解がちょうど 1 つ」と証明した盤面だけで(§6)、その解はセッションと一緒に持つ。
  だから「解の次のマス」は当てずっぽうではなく、従えば必ず完成する唯一の続きである。
  Takuzu / Futoshiki の Hint が「解と照合しない」のは、あちらの技法ソルバーが人間の
  推論をなぞるからで、ここでは推論の単位が「道 1 本」であり、次の 1 マスを証明できるのは
  一意性そのものである(§12)。技法名も推論の説明文も UI に出さない — 示すのは 1 マスだけ。

- Hint の使用回数は記録し、結果カードで事実として見せる(コストにはしない)。
- Hint が「ここまで戻る」を出すとき、道は §3 を満たしている(満たさない道は引けない)。
  「間違い」ではなく「一意解から外れた」であり、警告色で示すのは戻る先ではなく外れた
  区間である。

## 6. 生成と Seed とティア

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。

1. **道を作る。**空の格子に蛇行の初期路を置き、seed 由来の **backbite 変換**を
   `16 × マス数` 回かける(片方の端を選び、その格子隣接マスのうち道上で隣り合って
   いないものを選び、その間を反転する)。backbite は全マスを覆う道を全マスを覆う道へ
   写すので、**Hamiltonian path は探索せずに常に手に入る**。
2. **手がかりを多めに置く。**始点 = 1、終点 = K で、途中の番号を道上に等間隔 +
   seed の揺らぎで置く(ティアの上限 + Easy / Medium 6、Hard 8)。壁は道が使っていない
   隣接辺から seed 順に一定割合(Easy / Medium 60%、Hard 70%)を選ぶ。
3. **一意性を確認する。**探索ソルバー(`solver.ts`)で解を 2 つまで数える。多めの盤面が
   一意でなければ(7×7 で 6%、5×5 でほぼ 0)、その seed は諦めて派生 seed へ。
4. **削減する。**まず途中の番号を seed 順に 1 つずつ外し、一意を保つ限り外したままにする
   (外した番号のぶん残りを 1〜K に振り直す)。目標本数はティアの範囲から seed で 1 つ引く
   (Hard なら 4・5・6 のどれか)。次に壁を seed 順に外し、一意を保つ限り外す
   (下限 0 — 必要な壁だけが残る)。番号が先なのは、番号がティアの第 1 軸だからで
   (壁が残っている間に番号を減らす)、そのあと残る壁は「その本数の番号で道が 1 本に
   決まるために要る壁」である。
5. **ティアに合えば出荷。**合わなければ **seed を派生させて作り直す**(`<seed>#2`, `#3`, …)。
   上限 24 回。上限に達したら、ティアに最も近い候補を `fallback` 付きで出荷する。

### 一意性の探索ソルバー

道の末尾から未訪問マスへの深さ優先探索で、各候補手を取る前に枝刈りする:

1. **合法性** — 開いた辺・未訪問・数字マスは次に来るべき番号のときだけ・K は最後の 1 マス
   としてだけ。
2. **連結性** — 新しい末尾から未訪問マスだけを通って全未訪問マスに届くこと。
3. **行き止まり** — 未訪問マスの出入口(未訪問の隣 + 新しい末尾)が 2 未満なら、そこは
   道の終点にしかなれず、それが許されるのは K だけ。
4. **次の数字への到達可能性** — まだ入れない後の番号を跨がずに次の番号へ届くこと。

仕事量はソルバーが展開したノード数(`SolveResult.nodes`)で、生成 1 回の仕事量は
全試行のノード数 + backbite 回数(`GeneratedPuzzle.work`)。

### ティア

ティアは **2 軸**で定義する(`types.ts` の `TIERS`)。数値は実測で決めた(下の表)。

| 難易度 | 数字 K | 壁    | 分岐回数 `branches` |
| ------ | ------ | ----- | ------------------- |
| Easy   | 6〜8   | 0〜5  | 0〜12(ほぼ一本道)   |
| Medium | 5〜7   | 0〜9  | 12〜120             |
| Hard   | 4〜6   | 0〜14 | 30〜800             |

- **第 1 軸 — 手がかりの数。**数字が少ないほど、数字と数字の間の道が長く自由になる。
  マスあたりの数字は Easy 約 1/4、Medium 約 1/6、Hard 約 1/10 で、ティアが上がるほど
  薄い。壁の本数は上限だけを持ち(下限 0)、削減で必要なぶんだけが残る。
- **第 2 軸 — 分岐回数。**一意性を証明する探索(上の 1〜4 の枝刈り付き)で、**候補手が
  2 つ以上残ったノードの数**。0 なら枝刈りだけで道が一本道に決まる盤面で、大きいほど
  探索が仮置きと後戻りを繰り返した盤面である。Easy は上限で「ほぼ一本道」だけを通し、
  Medium / Hard は下限で「一本道の盤面」を落とす。この数は盤面サイズに強く依存する
  (5×5 の中央値 5、6×6 で 32、7×7 で 119)ので、範囲はサイズごとに読む —
  ティアをまたいで比べる数ではない。
- 上位ティアは「サイズが大きいだけ」ではない: 同じ 7×7 でも数字を 9 個置けば分岐は
  数回に落ちる。Hard は 4〜6 個で分岐 30 以上の盤面だけである。

### 予算は仕事量で門にする

これは**端末の予算**であって、開発機やテストランナーの予算ではない。だから門は壁時計では
なく**ソルバーのノード数 + backbite 回数**(`work`)で測る。同じ seed なら、どのマシンでも
常に同じ数になる。理由ごと [SUDOKU_RULES.md](SUDOKU_RULES.md) §7 と
[TAKUZU_RULES.md](TAKUZU_RULES.md) §6 に詳しい(並列テストで壁時計は最大 41 倍ぶれる)。

実測(開発機、2026-09-26。難易度ごとに 200 seed + デイリー 730 日):

| ティア   | n   | 仕事量 p50 | p90    | 最悪   | 1 回目で決まる率 / 最悪試行 | 壁時計 p50 | p90    | 最悪   |
| -------- | --- | ---------- | ------ | ------ | --------------------------- | ---------- | ------ | ------ |
| Easy     | 200 | 967        | 1,190  | 3,389  | 93% / 3                     | 0.5ms      | 1.1ms  | 3.8ms  |
| Medium   | 200 | 2,758      | 4,429  | 15,117 | 79% / 4                     | 2.0ms      | 3.4ms  | 11.1ms |
| Hard     | 200 | 8,436      | 15,739 | 59,752 | 82% / 5                     | 8.2ms      | 16.8ms | 69.5ms |
| デイリー | 730 | 2,664      | 4,876  | 18,411 | 75% / 5                     | 1.9ms      | 3.6ms  | 15.1ms |

出荷された盤面の手がかり(同じ集合): Easy は K = 6 / 7 / 8 がほぼ 3 等分、壁は 1〜3 本が
中心(0〜5)。Medium は K = 5 / 6 / 7 が 3 等分、壁 3〜6 本が中心(2〜8)。Hard は
K = 4 / 5 / 6 が 3 等分、壁 7〜11 本が中心(5〜14)。分岐回数の p10 / p50 / p90 は Easy
2 / 5 / 10、Medium 15 / 32 / 71、Hard 42 / 119 / 311。

**仕事量の列は再現し、壁時計の列は再現しない。**

門(`guarantee.test.ts` が難易度ごとに 40 seed とデイリー 730 日を走査して固定する):

- 1 盤面あたりの仕事量は **120,000 未満**(実測の最悪は Hard の 59,752。約 2 倍の余裕)。
  サイズごとに分けないのは、これが**退行の門**だからである — 捕まえたいのは
  「枝刈りを 1 つ外した」「削減が同じ盤面を解き直し始めた」であって、どちらもサイズを
  問わず数字に出る。
- 派生 seed は **8 回以下**(実測の最悪は 5 回)。上限の 24 回よりずっと手前に置いてあるので、
  手順 5 の fallback に落ちるより先に警告が出る。
- fallback の発生は 0 件。出荷した盤面はすべてティアの範囲内。
- 壁時計は計測して出力するだけで、判定には使わない。

端末の予算は 1 盤面 100ms 未満で、生成は UI スレッドで同期に走る(Worker は使わない —
[GAME_LIFECYCLE.md](GAME_LIFECYCLE.md))。Hard の壁時計は開発機で p90 17ms、200 seed の
最悪が 70ms(5 回試行の seed)。超えた場合の対処順序: ①ティアの分岐範囲を広げて試行回数を
減らす ②削減の初期壁の割合を上げる(1 解あたりのノード数が減る) ③(最後の手段)Hard を
6×6 に落とす(**この文書を先に直す**)。**低スペック実機での実測はまだ行っていない。**

不変条件:

- 同じ seed なら、必ず同じ盤面になる(`compatibility.test.ts` の golden で固定する。
  ベータ中はスキーマ変更が許されるが、黙って変えないための門として最初から敷く)。
- 出題は一意解(§2)。解は生成時の探索が証明したものをセッションと一緒に持つ(§5)。
- **ティアの範囲は目標であって約束ではない。**手順 5 の fallback 盤面は、一意解であることも
  変わらないが、ティアが求めたより易しいか難しい。出荷してよい唯一の失敗の形なのでこれを
  選んである。発生率は監視する(現状 0 件)。

## 7. モードとデイリー

- **難易度モード**: Easy / Medium / Hard を選んで遊ぶ。seed は
  `number-path-<difficulty>-<token>`(token = 起動時刻 + 乱数。Takuzu の `newSeedToken`)。
  同じ seed なら同じ盤面なので、「同じ盤面で再挑戦」も中断からの復帰も正確に成立する。
  クリア画面の第一ボタンは同じ盤面での再挑戦、第二が「新しい盤面」(同じ難易度・新しい seed)。
  レベル 1〜100 は作らない(段階的な進行は存在せず、水増しになる)。
- **デイリー**: 1 日 1 問。seed は `number-path-daily-<YYYY-MM-DD>`(端末のローカル日付のみ。
  サーバー時刻もネットワークも使わない)。難易度は**毎日 Medium 固定**(曜日で当たり外れを
  作らない — Sudoku §10)。**過去 30 日は無条件に開いている**(前の日を解かないと次が
  開かない、という連鎖解錠は付けない)。達成した日は記録する。**ストリークは数えない・
  表示しない。**
- 中断は難易度モード用・デイリー用の **2 スロットを独立して保持**する(§9)。難易度を
  変えて始めると難易度スロットは置き換わる(確認を出す)。デイリーで中断中の日と違う日を
  選んだときも確認を出す(同じ日を選ぶのは再開)。
- 最後に選んだ難易度は `np.prefs` に残り、次回はその位置から始まる。チュートリアル直後に
  始まる盤面もこの難易度(初期値 Easy)。

## 8. 統計

- **プレイ中に時計を表示しない**(ブランド原則)。経過時間は内部で記録し、結果画面と
  統計でのみ見せる。
- 難易度別に: プレイ回数、クリア回数、最短時間、合計プレイ時間。デイリー: 達成日数
  (ストリークなし)。Minesweeper §9 と同形(`np.stats` = 難易度別 + `dailyTimes`)。
- **スコアは作らない。**ランキングもストリークも作らない。自己ベストの更新は、更新した
  ときだけ静かに示す。
- クリア画面の記録は、難易度モードではその難易度の最短時間、デイリーではその日の記録と比べる。
  記録があれば差を符号付きで添える(`+0:18` / `−0:05`)。比べる相手は自分の記録だけで、
  初めてのクリアには何も添えない(`ui/components/BestDelta.tsx`)。

## 9. 中断と再開

- 難易度モード用・デイリー用の **2 スロットを独立して保持する**。
- 保存するのは モード / seed / 難易度 / 日付 / 幅 / 高さ / 数字(マス index と番号の疎な列)/
  壁(辺の列挙: `h<i>` = マス i とその下、`v<i>` = マス i とその右)/ 解(マス index の列)/
  道(マス index の列)/ Hint 回数 / 経過秒数 / 保存時刻。**Undo 履歴は保存しない**(§5)。
  **ミス回数は持たない** — このゲームにミスという概念がない(§4)。
- **どのスロットのレコードかを決めるのはキーである。**2 つのスロットは同じ形のレコードを
  持つので、難易度用のキーに入っている `mode: 'daily'` のレコードは「デイリーだった」の
  ではなく壊れている。復元せず既定値へ落とす(`gameSlotSchema(key, expectedMode)`、
  `src/test/savedGameSlots.test.ts` が自動強制)。
- **検証は fail-closed。**プレイから生まれえないレコードは読み捨ててホームへ戻す:
  - 盤面が組み立たない(サイズが難易度と合わない、数字が 1〜K 各 1 つでない、壁が辺を指さない)
  - 解が Hamiltonian でない(全マスを覆わない・隣接していない・重複がある)、壁を跨ぐ、
    数字の順を破る、K で終わらない
  - 道が接頭辞規則(§3 の 1〜5)を破る(1 から始まらない・隣接していない・重複・壁・数字順・
    K の先)
  - 解けている(完成した盤面は履歴であり、再開しない)
  - デイリーのレコードが medium 以外の難易度を名乗る(§7 の毎日 medium 固定に反する。
    自己矛盾のない他難易度の盤面が紛れ込んでいても通さない — `storage/schemas.ts` の
    `validatePersistedGame`)
- 背景へ回るとき、盤面の保存と未計上秒の計上を**同じ同期処理で**行う。OS は別のイベント
  なしにアプリを終了できるため、盤面だけを保存すると前回の同期以降の秒数が永久に失われる。
- 保存キーは `np.saveGame` / `np.saveDaily` / `np.stats` / `np.flags` / `np.prefs` の **5 つ**。
  `np.flags` はチュートリアル完了、`np.prefs` は最後に選んだ難易度だけ(§7)— 盤面の
  遊び方を変える設定は 1 つもない。
- 保存の失敗でゲームを止めない。バリデータは例外を投げない。
- **ベータ中の注意**: 先行公開の間はスキーマを変えてよく、その場合この保存データは消える
  ことがある。ホームの `WebBetaNotice` がそのことを英日で告げる([WEB_VERSION.md](WEB_VERSION.md))。

## 10. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ 1 文・図中心([I18N_POLICY.md](I18N_POLICY.md))。

1. **数字を順にたどる** — 1 から 1 本の線を引き、数字を順に通る。
2. **全部のマスを 1 回ずつ** — 線は全マスをちょうど 1 回通り、最後の数字で終わる。
3. **壁は越えない** — 太い辺は壁。戻るときは線をなぞり返すか、線の途中をタップ。

Learn More は出ない(ゲーム別ガイドは未公開。ベータのため)。詳細ルール・攻略・FAQ を
アプリ内に持たない方針は変わらない。

## 11. 演出とアクセシビリティ

- 道は各マスの入口 / 出口方向から描く太線(DOM + CSS のみ。Canvas なし)。経路上の各マス
  (`np-cell-on`)には線と同径の円を線の下に重ねる(`::before`)。曲がり角では 2 本の線分が
  この円で結ばれるので、角が 1 本の折れ線に見える(直線区間や始点では、円がそのまま丸い
  端になる)。「ここまで戻る」の Hint で外れた区間は、円も線と同じ warn 色にする。
- 末尾のマスに線が入ってくる区間だけ、入ってくる辺から中心へ 90ms で伸びる(手前のマス側の
  半分は最初から出ている)。これは**道を伸ばした**ときだけで、戻す(切り詰める)ときは
  何も動かさない — 直前の描画と比べて経路が真に伸びた(前の経路がそのまま先頭一致で、
  1 マス以上増えた)ときにだけ末尾のマスに `np-cell-grow` を立てる。末尾の丸い印
  (`.np-end`)は末尾が動くたびに 90ms のポップで現れる — こちらは伸ばしても戻しても、
  末尾は必ず動きを見せる(セルをまたいで再マウントされるので、切り詰めでも自然に動く)。
  線が伸びる方向は辺ごとに `scaleY` / `scaleX` を使い分ける(上下は `scaleY`、左右は
  `scaleX`)。
- 数字はインクの ASCII 数字で、丸い地の上に置く。**通過済みの数字は塗りつぶし**、未通過は
  縁取りだけ — 色だけでなく塗りの有無で分かる。**次に通るべき数字**(`np-cell-next`:
  通過済みの数字の最大値 + 1 のマス、K を超えたら無し)は輪を太くする。静的な表示で、
  動きは付けない。壁は太い辺(インク色)で、両端を丸める。
- Hint の対象マスは太い輪で示す。「ここまで戻る」のとき、戻る先より先の道は warn 色で描く
  (輪 + 色の二重で、色だけに頼らない)。
- 各マスはボタンで、**行・列・数字(あれば)・「道の n 番目」または「道の外」・(Hint の
  対象なら)その旨**を読み上げる — 輪の色は画面を見ている前提の合図で、読み上げが唯一の
  伝達手段になる利用者にも同じマスが分かるようにする。追加した円・伸びる線・末尾のポップは
  すべて `aria-hidden` で、読み上げは変えない。
- **盤面が解けた一拍**: `session.status === 'solved'` のとき盤面ルートに `np-board-solved`
  が付き(`GameScreen` が渡す `solved` prop)、盤 1 枚に重ねた `::after` が地色
  (`--accent-soft`)で 0 → 100%(30% 地点で最大)→ 0 に 900ms だけ光って消える。要素は
  1 つ、動かすのは `opacity` だけ。終わったあとは何も残らない。
- Reduced Motion が有効なら、線が伸びる遷移・末尾のポップ・解けた一拍はすべて即時になる
  (`src/ui/styles.css` の全体ルールが animation / transition を 0.01ms にする。ゲーム側に
  分岐は無い)。
- **盤面が埋まってから結果カードが出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。
  完成した道を見る時間であり、その間に押せるものはない。Reduced Motion では即時に出す。
- 効果音は既存の合成音(`services/sound`)のみ: **道が伸びたとき**(なぞり・タップ・矢印)は
  `select`。**道が縮んだとき**は、なぞり戻し・タップでの切り詰め・逆向きの矢印・Backspace の
  どれで縮めても同じ `undo`(§4 が「同じ操作」と呼ぶものは同じ音にする)。Undo(§5)も
  `undo`。クリアで `clear`。
- **7×7 の 320px でのなぞり精度は、まだ実機で確認していない。**Web 先行公開の反応で見る
  ([WEB_VERSION.md](WEB_VERSION.md)「先行公開」)。通らなければ Hard を 6×6 に落として
  **この文書を先に直す**。

## 12. 意図的な差分

ブランド原則により合わせないもの:

- ミス回数制限・ライフ制・ゲームオーバー(しない。そもそもミス判定をしない — §4)
- プレイ中のタイマー表示、ストリーク、オンラインランキング、スコア(しない)
- Undo / Hint を広告視聴やコインの報酬にすること(しない。常に無料・無制限 — §5)

設計判断として合わせないもの:

- **他社の名称・アセット・画面デザイン。**古典的な Hamiltonian path パズルを Simple Games の
  名前と表現で作る(Reversi / Takuzu と同じ物差し)。
- **8×8 以上。**1 マスが指でなぞれる大きさを優先する(§1)。
- **レベル 1〜100。**段階が存在しないので作らない(§7)。
- **違反表示。**入れないマスには入れないので、違反した道は存在しない(§4)。
- **推測が必要な盤面・複数解の盤面**(出さない。§6)。
- **技法ソルバー。**共通要件の「技法ソルバー(難易度の門 + Hint)」に対し、このタイトルは
  **探索ソルバー 1 つ**で両方を担う。理由: 道 1 本を引くパズルの人間の技法(角の出入口・
  行き止まりの回避・次の数字への到達)は、そのまま §6 の枝刈り 1〜4 であり、別の
  ソルバーに積み直しても同じ判断が 2 か所に置かれるだけである。難易度の門は枝刈り付き探索の
  分岐回数(§6「ティア」)、Hint は一意解の次の 1 マス(§5)で、どちらも同じ探索の結果を読む。
  Hint が解と照合する形なのは、Water Sort §8 と同じ「証明付きの次の一手」であり、
  Takuzu / Futoshiki の「答え合わせを Hint にしない」判断は、あちらに技法の推論があるから
  成り立つものである。
- **壁の本数の下限。**ティア表(§6)の壁は上限だけで、下限は 0。壁は難しさの調整弁ではなく
  「その本数の数字で道を 1 本に決めるために要るもの」で、要らない壁を残す理由がない。
- **問題データの同梱・配信**(すべて端末上で生成する。§6)。

合わせたもの:

- 一意解、順番どおりの数字、全マス 1 回、壁、なぞりの操作、Undo(1 手 = 1 ストローク)。

### 比較対象との対応(2026-09-29 確認、issue #210)

公式 Help([LinkedIn Help — Zip](https://www.linkedin.com/help/linkedin/answer/a7445030)、
2026-09-29 閲覧)が挙げる規則と、このゲームの対応(5 種類の練習セットの位置づけは
[PUZZLE_PRACTICE_SET.md](PUZZLE_PRACTICE_SET.md)):

| 公式の規則 / 機能                                     | Number Path                                                                 |
| ----------------------------------------------------- | --------------------------------------------------------------------------- |
| 全マスを埋める 1 本の道を引く                          | §2・§3。同じ                                                                  |
| 番号のマスを順に通る                                   | §3 規則 4。同じ                                                               |
| 壁(`|` / `—`)は通れない                              | §3 規則 2。同じ                                                               |
| 交差・再訪・分岐(Help に明記なし。1 本の道という定義から不可) | 構造上できない — 道は 1 列で、同じマスを 2 回通れない(§3 規則 3、`engine.test.ts` が再訪・斜め・順番違いを拒否) |
| 1 を押してなぞる、なぞり返しで消す                     | §4。同じ                                                                      |
| Hint(最初の誤りまで道を消し、次の正しい 1 歩を示す)   | Hint は道を書き換えない: 唯一の解から外れた地点(「ここまで戻る」)、または次の 1 マスを示す(§5) |
| Undo / Clear                                          | Undo は同じ(1 手 = 1 ストローク)。Clear は「同じ盤面で再挑戦」                   |
| 盤面サイズ(Help に記載なし)                            | 5×5 / 6×6 / 7×7(§1)                                                          |
| 1 日 1 問                                              | 難易度 3 種 + デイリー。新しい盤面はいつでも(§7)                              |

合法手と勝利条件は一致しており、違いは支援の形だけである。公式の問題・解答・アセットは
取得も転載もしない(すべて端末上で生成する — §6)。
