# Futoshiki — 正式ゲームルール

この文書は Simple Games 収録タイトル「Futoshiki」の唯一のルールソースである。
実装(`apps/simple-games/src/games/futoshiki/game/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。数値を変える場合はここを先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Hint / Undo は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

ゲーム ID は `futoshiki`、i18n キーの接頭辞は `futoshiki`、保存キーの接頭辞は `ft.` である。
名称は新聞パズルの定番名「Futoshiki」をそのまま使う — 一般名詞(不等式)であって
他社の商品名ではない。

**この文書の数字は実測である。**生成の仕事量、派生シードの回数、帯の端点、技法ごとの
要求実績はすべて `guarantee.test.ts` が走査するのと同じ集合から取っている(§8)。
唯一まだ測っていないのは低スペック実機での生成時間で、そこにはそう書いてある。
測る前に数字を置かない — 「だいたいこのくらい」を先に書くと、実装がその数に合わせに
行くか、誰も直さないまま文書だけが嘘になる。

## 1. 盤面

- N×N のマス。**N は 4・5・6・7 のいずれか**である。マスに入るのは `1`〜`N` の数字。
- **各行・各列に 1〜N がちょうど 1 つずつ入る**(ラテン方陣)。
- マスは「初期数字(固定)」「プレイヤーが入れた数字」「空」のいずれか。
- 各マスはメモ(候補数字 1〜N の任意の組)を持てる。
- **隣り合う 2 マスの間には不等号が置かれることがある。**記号は `<` と `>` の 2 つで、
  **とがった側が小さい方のマスを指す。**縦横に隣接するペアにだけ置き、斜めには置かない。
  すべての隣接ペアに置くわけではなく、一部だけである(何本置くかは §8・§9)。
- 初期数字とプレイヤーの数字は別々に保持する — 混ぜると、§11 の fail-closed 検証が
  言えなくなる。
- 出題は常に一意解を持つ(§7)。

サイズは 4 種類(スマートフォンの画面に収まる形で決めた):

| サイズ | 使う数字 | 用途                            |
| ------ | -------- | ------------------------------- |
| 4×4    | 1〜4     | 導入帯(レベル 1〜15)            |
| 5×5    | 1〜5     | 前半帯(レベル 16〜45)           |
| 6×6    | 1〜6     | 標準帯(レベル 46〜80・デイリー) |
| 7×7    | 1〜7     | 上位帯(レベル 81〜100)          |

3×3 以下は作らない(不等号を数本置くだけで盤面が全部決まり、パズルにならない)。
8×8 以上も作らない(§14)。

**盤面に翻訳の要る文字は 1 つも載らない。**数字は ASCII の `1`〜`9` に固定し、不等号は
ASCII の `<` と `>` に固定する([I18N_POLICY.md](I18N_POLICY.md)「盤面の数字は全言語で
ASCII の 0-9 固定」)。言語を変えても盤面表記は変わらない。

**盤面は RTL でも左右反転しない。**これは他のタイトルより強い要求である — 反転すれば
横向きの不等号がすべて逆の意味になり、盤面がそのまま嘘になる。ホームのタイルに使う
グリフ `≶`(U+2276)はクロームであって盤面の一部ではない。

## 2. 勝利

- **勝利**: すべてのマスが埋まり、各行・各列が 1〜N の並べ替えになっていて、すべての
  不等号が満たされた時点。
- 敗北は存在しない。ミス回数の制限も、ライフも、ゲームオーバーもない(§14)。

判定は「埋まっている」かつ「§5 の違反が 1 つも出ていない」で行い、解と照合しない。
出題は一意解を持つので(§7)、規則を満たす完成形はそもそも 1 つしかない —
照合しても同じ結論になる。表示と判定が同じ読みから出るので、「きれいに見えるのに
完成しない盤面」は作れない。

## 3. ルール(2 つ)

**規則 1 — 各行・各列に 1〜N がちょうど 1 つずつ。**

```
5×5 の 1 行:  3 1 _ 5 2   → 空きは 4(1・2・3・5 は既にこの行にある)
```

**規則 2 — 不等号に従う。とがった側が小さい。**

```
2 < _        → 右は 3 以上
_ > 4        → 左は 5 以上(4×4 ならこの並びは置けない)
```

不等号は鎖になれる。鎖は両端から範囲を締める:

```
4×4 の 1 行:  _ < _ < _ < _   → 左から 1 2 3 4 に確定する
```

この 2 つで全部である。ボックス(Sudoku の 3×3)も対角の制約もない。

## 4. 操作

1. マスを選ぶ(初期数字のマスも選べる。選ぶと盤上の同じ数字がハイライトされ、その
   マスの行・列が控えめに示される)
2. 数字パッドで 1〜N を入れる / 消す
3. メモモードのとき、数字パッドはメモの追加・削除になる

**パッドは盤面のサイズに追従する。**4×4 ならキーは 4 つ、7×7 なら 7 つ。その盤面に
存在しない数字のキーは出さない。

規則:

- 初期数字のマスは変更できない。
- 数字を入れると、そのマスのメモは消える。
- 数字を入れると、**同じ行・同じ列のメモから同じ数字を自動で消す**(手作業の消し込みを
  省く。ルールを変える支援ではない)。消す先は 2 本だけである — Sudoku は 3 つ目に
  ボックスを持つが、ここにはない(§3)。
- **数字の入っているマスにはメモを置けない。**表示と食い違うメモを持たせない。
- 数字を消すと、そのマスは空に戻る(そのマスのメモも一緒に消える)。**自動で消えた
  同じ行・列のメモは復元しない** — 戻すのは Undo の仕事である(§5)。
- 数字パッドは各数字の残り個数(**N − 盤上の個数**。初期数字を含む)を表示し、N 個
  置き終えた数字は無効化する。

**残数表示が成立するのは、このゲームに不変量があるからである。**解では各数字が
ちょうど N 回現れる(各行に 1 つずつ)。だから「N − 盤上の個数」は盤面の見た目ではなく
**解についての事実**で、最初から最後まで意味が変わらない。

**Kakuro にはこの不変量が存在しない。**あちらで数字が盤面に何回現れるかは、レイアウト
(run の並び)と解の中身で決まり、規則からは決まらない。引く先の定数がないので数えても
意味がなく、Kakuro のパッドは残数表示を持たない(理由は `docs/KAKURO_RULES.md` 側に
書く。本文書の時点では未作成)。**同じ部品を全タイトルに並べることが原則ではない**
([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))。

**不等号ごしのメモ自動消去は作らない。**`3 < _` の左に 3 を置いた瞬間、右のマスから
1〜3 のメモを機械的に消すことはできる。だがそれは §7 の技法 1 をプレイヤーの代わりに
実行することである。同じ行・列の自動消去は「同じ数字は 2 つ置けない」という**書いた
瞬間に確定している事実の転記**であるのに対し、不等号ごしの絞り込みは**推論そのもの**で
あり、このパズルの中身である。中身を先に消す支援は作らない。次の一手が要るときは
Hint がある(§6)。

## 5. ミスと支援

- **ミス上限はない。ゲームオーバーもない。**3 ミスで失格のような仕様は採らない。
- **違反表示は常時オン**で、§3 の 2 規則それぞれに対応する:
  - 同じ行(列)に同じ数字が 2 個以上あるとき、その数字のマス。
  - **両側が埋まった不等号**の大小が向きと逆のとき、その 2 マスと不等号。
    **片側しか埋まっていない不等号は何も言わない** — まだ違反ではない。
- **これはルール違反の指摘であって、答え合わせではない。**規則を破っていない数字は、
  それが解と違っていても違反表示には出ない。
- **ミスの即時表示**(一意解と異なる数字を警告色にする)は設定トグル。**既定はオン。**
  オフのときも違反表示は出る。
- ミスの定義: 一意解の値と異なる数字を空マスに入れたとき、ミス 1 回。同じマスに
  続けて別の誤答を入れれば、その都度 1 回。
- ミス回数は保存レコードに持ち(§11)、クリア画面で見せる。プレイ中にカウンタを
  常時表示しない。統計には積まない(§10)。

### 設定の置き場所

このトグルは `ft.prefs.highlightMistakes` に入り、**ゲーム自身がシェルの設定画面へ
差し込む**(`app/registry.ts` の `loadSettingsSection`)。**Sudoku に次いで 2 例目**で
ある。ゲームの選択肢はゲームと一緒に置き、シェルは場所を貸すだけにする — そうしないと
シェルが全タイトルの設定を知ることになる。

設定画面はホームからのみ到達し、そのときどのゲームも mount されていない。だから
**マウント時に 1 回読むだけで足りる**(実行中の盤面と競合しえない)。

### Undo

- **無制限**(実装上の上限は Sudoku / Number Match と同じ 2000 手)。
- 対象は「数字の配置」「数字の消去」「メモの変更」。
- **Undo はミス回数を戻さない**(誤答した事実は消えない)。Hint 使用回数も戻さない。
- **保存された中断ゲームに Undo 履歴は含めない**(§11。Sudoku / Number Match と同じ)。

**Undo を作るのは、この操作が非自明に不可逆だからである。**数字を 1 つ入れると、
そのマスのメモが消え、同じ行・列のメモからも自動で消える(§4)。1 タップで消えた候補を
手で復元することはできない。Takuzu が Undo を作らないのは正反対の理由で、あちらは
タップ 1 種類ですべての状態が一巡するのでもともと可逆である
([TAKUZU_RULES.md](TAKUZU_RULES.md) §8)。

## 6. Hint

**無制限・無料。**現在の盤面に §7 の技法を適用し、**新しく確定するマスを 1 つ示す**。

- **数字は入れない。**プレイヤーが自分で入れる。
- **根拠を一緒に示す。**行 / 列で決まったならその行(列)を、不等号で決まったなら
  **その鎖のマスと不等号**を強調する。「なぜそこが確定するのか」を示すのが Hint で
  あって、答えを埋めるのは Hint ではない。
- 短い一文を添える。**技法名(不等号伝播、Hidden Single など)は UI に出さない。**
  平易な言い換えのみ(例:「この不等号の並びで、ここは 1 しか入らない」「この行で
  4 が入るのはここだけ」)。理由は文章量を最小化する UI 原則
  ([I18N_POLICY.md](I18N_POLICY.md))と、多言語での用語統一コストを避けるため。
  技法名は内部表現・テスト・Landing Page の解説にのみ使う。
- **盤面が既に規則を破っているときは、先にその違反を示す。**技法の推論は矛盾のない
  盤面でしか正しくないので、壊れた盤面の上に積んだ確定を教えても導きにならない。
- **解と直接照合して「ここが間違い」と教える形は Hint では採らない** — それは §7 の
  論理ではなく答え合わせだからである。その用途はミスの即時表示(§5)が別に担っており、
  そちらは設定で切れる。
- 論理的な次の一手が存在しないことは、§8 の生成条件により起こらない。万一検出できな
  かった場合は「今わかる手が見つかりません」を表示し、盤面は変えない。
- 使用回数は記録し、クリア画面で見せる。

## 7. 「推測なし」の保証と技法

**これがこのタイトルの中心的な設計判断である。**

出題は必ず、**次の技法だけで最後まで解ける**。各マスは候補集合を持ち、削れなくなるまで
以下を繰り返す(不動点反復)。

1. **不等号伝播** — `a < b` は**両端を締める**。a は N になれず、b は 1 になれない。
   鎖はさらに締める: `a < b < c` なら a ≤ N−2、c ≥ 3 である。一般に、あるマスから
   下向きに k マスの鎖がぶら下がっていればその値は k+1 以上、上向きに m マスなら
   N−m 以下。両側から挟めば範囲になる。すでに数字が入っているマスに接する不等号は、
   隣の候補をその値で切る(`3 < _` の右は 4 以上)。
2. **naked single** — あるマスの候補が 1 つだけになったら、それを書く。
3. **hidden single** — ある行(列)で、ある数字が入れるマスが 1 つだけなら、そこに書く。
4. **pair** — 同じ行(列)の 2 マスが同じ 2 候補しか持たないなら、その 2 数はその
   2 マスのものなので、同じ行(列)の他のマスの候補から外せる(naked pair)。逆に、
   ある 2 数が同じ 2 マスにしか入れないなら、その 2 マスはその 2 数のものである
   (hidden pair)。

**ティアは作らない。**全レベルがこの 4 技法すべてを許容し、難易度は不等号の本数と
初期数字の個数という**2 つの数**だけが担う(§9)。

当初の計画は Sudoku 型の 3 ティア(Easy = 伝播 + naked single / Medium = + hidden
single / Hard = + pair)だった。実装時に**出荷する 160 面が実際にどの技法を要求するかを
数えて棄却した**:

| 技法          | 要求した盤面(160 面中) |
| ------------- | ---------------------- |
| 不等号伝播    | 160                    |
| naked single  | 160                    |
| hidden single | 57                     |
| naked pair    | 0                      |
| hidden pair   | 1                      |

**pair を名乗るティアは、160 面中 1 面しか使わない技法を看板にすることになる。**
これは [SUDOKU_RULES.md](SUDOKU_RULES.md) §6 が実測で棄却したのと同じ形である
(あちらは subset 系が必要になるのが約 20 面に 1 面だった)。ティア名は「保証できるもの」
であっても、**中身のない名前を 3 つ並べれば、プレイヤーにとっては嘘と区別がつかない。**

hidden single(57/160)には実際の分かれ目があるので、2 ティアなら成立する。それでも
作らないのは、このロジック節の隣 2 本 — Nonogram はサイズと充填率、Takuzu はサイズと
初期数字率 — がどちらもティアを持たず、**数で難易度を作る形で揃っている**ためである。
ティアを足すなら帯の端点を全て測り直し、golden を全て取り直すことになる。それは
「実測が要求したとき」にやる。

**デイリーに難易度の名前はつかない。**6×6・不等号 23 本・初期数字 9 個で固定である
(§9)。

**4 技法とも健全である。**どれも「合法な完成形すべてが一致する値」しか書かない。
したがってこの技法だけで埋め切れる盤面は**解が 1 つだけ**であり、推測なしで必ず完成
できる。**一意性は健全性から出るので、解の個数を別に数える必要はない**(Takuzu §5 と
同じ構造。Sudoku が一意解を別途検査するのは、あちらの掘削が技法での可解性と一意性を
別の門として持っているからである)。

理由: 推測で数字を置かされるパズルは、プレイヤーの論理を裏切る。Sudoku・Minesweeper・
Nonogram・Takuzu で推測を排したのと同じ理由で、ここでも排する。

**技法の実装は 1 つだけ持ち、3 人の利用者が共有する** — 生成時の検査(§8)、Hint(§6)、
`guarantee.test.ts`。約束と検査と助けを別々に実装すると、静かに食い違う
(Sudoku §8 のグレーダーと同じ理由)。

## 8. 盤面生成と Seed

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。

1. **ラテン方陣を作る。**空盤にランダム化バックトラッキング(候補順を seed で
   シャッフル)で 1〜N を埋める。
2. **不等号を選ぶ。**縦横の隣接ペアは全部で 2N(N−1) 本ある。この中から §9 の帯が定める
   本数を seed 由来のシャッフル順に選び、**向きは解から読む。**
   **向きは選択肢ではない。**解が決めるので、生成の時点で不等号と解が矛盾することは
   ありえない。§11 が「不等号と解の矛盾」を破棄の理由に挙げているのは、生成の失敗に
   備えているのではなく、**保存レコードの破損**に備えているのである。
3. **初期数字を掘る。**全マスが埋まった状態から seed 由来のシャッフル順に 1 つずつ
   取り除き、**§7 のソルバーが全マスを確定できる間だけ**取り除きを残す。帯の目標
   (§9)に達したら止める。
   **1 パスで十分である** — 初期数字が減ればソルバーの言えることは減る一方なので、
   あるとき取り除けなかったマスが、あとで取り除けるようになることはない(Takuzu §6 と
   同じ論法)。
   **掘り切りの下限は 1 個ではなく 0 個である。**不等号だけでラテン方陣が一意に決まる
   盤面は存在するので、初期数字ゼロの出題は規則としては正しい。実際にどの帯がそこまで
   届くかは実測で決まる(下記)。
4. 目標に届かなければ **seed を派生させて作り直す**(`<seed>#2`, `#3`, …)。上限つき。
   **派生では手順 1 からやり直す** — 不等号だけを選び直すと、同じラテン方陣に対する
   試行が偏り、失敗が相関する。
5. 上限に達したら、その時点で最も深く掘れた候補を出題する。

不変条件:

- 同じ seed なら、必ず同じ盤面になる(golden テストで固定する)。
- 出題は §7 の技法だけで解ける(推測不要・解は一意)。
- 不等号は必ず解と整合する(手順 2 より構成上)。
- **初期数字の個数と不等号の本数は目標であって約束ではない。**手順 5 の盤面は、一意解で
  あることも推測が要らないことも変わらないが、帯が求めたより易しい。**出荷してよい唯一の
  失敗の形**なのでこれを選んである。発生率は監視する。

### 予算は仕事量で門にする

これは**端末の予算**であって、開発機やテストランナーの予算ではない。だから門は壁時計では
なく**ソルバーが読んだ行・列・不等号の本数**(`solverWork`)で測る。掘削は数十回のフル
解答であり、フル解答は候補集合の掃きの積み上げなので、生成コストはこの数に比例する。
同じ seed なら、どのマシンでも常に同じ数になる。

理由ごと [SUDOKU_RULES.md](SUDOKU_RULES.md) §7 に詳しい — 並列テストで壁時計は最大
41 倍ぶれ、最も余裕のある Easy ですら 50ms の予算に対して 107.2ms を記録した。
**稀に落ちる門は、通らない門と同じくらい悪い。**壁時計は計測して出力するだけで、判定には
使わない。

端末の予算は 1 盤面 100ms 未満。超えた場合の対処順序: ①掘削の目標(不等号の本数と
初期数字)を緩める ②派生シードの上限を下げる ③(最後の手段)ビルド時生成したパズル
パックの同梱 — Sudoku §7 と同順。**③を採ったらこの文書に書く**(採るまでは §14 のとおり
「作らないもの」である)。

### 実測

`guarantee.test.ts` が走査するのと同じ集合(全 100 レベル + デイリー 730 日)。
行読みは seed が同じなら常に同じ数になるので、この列だけが門になる — 壁時計を
判定に使わない理由は上記と [SUDOKU_RULES.md](SUDOKU_RULES.md) §7 に詳しい。

| サイズ   | n   | 行読み p50 | 最悪   |
| -------- | --- | ---------- | ------ |
| 4×4      | 15  | 1,270      | 1,864  |
| 5×5      | 30  | 4,100      | 23,199 |
| 6×6      | 35  | 8,736      | 29,913 |
| 7×7      | 20  | 20,490     | 34,192 |
| デイリー | 730 | 8,820      | 16,070 |

門:

- 1 盤面あたりの行読みは **60,000 未満**(実測の最悪はレベル 91 の 34,192。約 1.75 倍の
  余裕)。サイズごとに分けないのは、これが端末の約束ではなく**退行の門**だからである。
- 派生シードは **8 回以下**(実測の最悪はレベル 45 の 4 回。100 レベル中 3 レベルが
  引き直し、730 日のデイリーは 0 件)。上限の 24 回よりずっと手前に置いてあるので、
  手順 5 に落ちるより先に警告が出る。
- **手順 5 の発生は 0 件**(全 100 レベル + 730 日)。掘削は帯の目標に必ず届いている。
- 壁時計は計測して出力するだけで、判定には使わない(160 面で約 300ms、最悪の 1 面が
  約 6ms)。

**技法の要求実績**(出荷する 160 面が実際にどの技法を必要としたか。§7 がティアを
作らない根拠):不等号伝播 160 / naked single 160 / hidden single 57 /
naked pair 0 / hidden pair 1。

**まだ測っていない数は 1 つだけである**: 低スペック実機での 1 盤面あたりの生成時間。
上の数字はすべて開発機のものであり、端末の予算(1 盤面 100ms 未満)に対する実測は
[RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) §2 で確認する。

## 9. レベル(1〜100)とデイリー

**レベル**: level 番号だけからサイズ・不等号の本数・初期数字の個数・seed を決定的に
導出する。コンテンツパイプラインもダウンロードもなし。誰が遊んでも同じレベルは同じ盤面。

| レベル帯 | サイズ | 不等号の本数 | 初期数字 |
| -------- | ------ | ------------ | -------- |
| 1〜15    | 4×4    | 12 → 8       | 6 → 2    |
| 16〜45   | 5×5    | 18 → 13      | 8 → 3    |
| 46〜80   | 6×6    | 26 → 20      | 11 → 6   |
| 81〜100  | 7×7    | 34 → 28      | 14 → 10  |

**ティアの列はない。**難易度はこの 2 つの数だけが担う(理由は §7)。

- **端点は実測から引いた。**サイズごと・不等号の本数ごとに、技法が許す限り掘ったとき
  どこまで届くかを走査し(12 seed ずつ)、**各帯の終点をその「届く深さ」の中央値に
  置いてある**。最も深く掘れた seed に合わせないのは、そこを狙うと多くの seed が届かず、
  派生 seed を食いつぶした末に**帯が要求したより易しい盤面**を出荷することになるためで
  ある(§8 の手順 5)。
- **帯の内側では、不等号の本数と初期数字が線形に下がる**(Nonogram の充填率と同じ形)。
  隣り合うレベルが跳ねない。
- **帯の変わり目で密度が上がるのは意図的である。**同じ密度でも盤面が大きいほど難しい —
  1 つの推論が届く距離が伸び、鎖が長くなり、hidden single までに読む行が長くなる。密度を
  そのまま持ち越すと、帯の 1 レベル目が壁になる([TAKUZU_RULES.md](TAKUZU_RULES.md) §7)。
- seed は `futoshiki-level-<n>`。

**レベル数は 100 で、999 には引き伸ばさない。**999 にすると 1 レベルあたりの変化がマス
1 個を割り、同じ盤面が seed 違いで何百も並ぶだけになる(Sudoku §9 / Nonogram §6 の圧縮
判断を、最初から採る)。レベルは順番に解放し、解放済みはいつでも選び直せる(seed が
同じなので同じ盤面)。

**デイリー**: 1 日 1 問。seed は `futoshiki-daily-<YYYY-MM-DD>`(端末のローカル日付のみ。
サーバー時刻もネットワークも使わない)。

- **毎日 6×6・不等号 23 本・初期数字 9 個で固定。**曜日でサイズや深さを変えると「当たり日 / 外れ日」という圧を
  生むため採らない(Sudoku §10)。6×6 はレベル 46〜80 の 35 レベルを費やすサイズで、
  そこまで歩いたプレイヤーが見慣れている形である。
- **過去 30 日は無条件に開いている**(`DAILY_BACKLOG_LIMIT = 30`)。前の日を解かないと次が
  開かない、という連鎖解錠は付けない — Sudoku だけが持つ形であり、貯まった過去日を宿題に
  しないため新しいタイトルには採らない(Nonogram / Takuzu と同じ)。
- 達成した日は記録する。**ストリークは数えない・表示しない。**

中断はレベル用・デイリー用・フリープレイ用の **3 スロットを独立して保持**する(§11)。別のレベルを
始めると、レベル用スロットは置き換わる(確認を出す)。

### フリープレイ(ティアを選んで新しい盤面)

レベルの坂とデイリーの隣に、**ティアを選んで新しい盤面を引く**入口を置く(2026-09-03 追加)。

- ホームの「フリープレイ」ボタンと、その下のティア選択(Easy / Medium / Hard)。選んだティアは
  `ft.prefs` の `freeTier` に残り、次回も同じ位置から始まる(フィールドのない旧レコードは
  medium として読む)。
- **ティアは新しい生成条件ではなく、代表レベルの名前である。**このゲームにティアはなく(§7)、
  難易度は不等号の本数と初期数字の個数だけが担う。だから Easy / Medium / Hard は
  **レベル 10 / 50 / 95 と同じ生成条件(サイズ・不等号の本数・初期数字の個数)で、seed だけ
  違う**(`levels.ts` の `FREE_TIER_LEVEL`)。4×4・6×6・7×7 の 3 面で、新しく調整した数は
  1 つもない。§8 の走査はレベルとデイリーの seed だけを見るので、フリーの seed が手順 5 に
  落ちることはありえる — そのときも一意解で推測不要なことは変わらず、ティアが求めたより
  易しいだけである(§8 と同じ、出荷してよい唯一の失敗の形)。
- seed は `futoshiki-free-<token>`(token = 起動時刻 + 乱数)。**同じ seed なら同じ盤面**なので、
  「同じ盤面で再挑戦」も中断からの復帰も正確に成立する。レベル・デイリーの seed とは接頭辞で
  分かれ、衝突しない。
- レベル番号も日付も持たない。したがって**レベル進行(到達レベル・レベル別ベスト)にもデイリー
  の記録にも一切触れない** — 坂を飛ばす近道ではなく、坂の隣にある別の道である。
- 統計にはサイズ別の数(プレイ数 / クリア数 / 時間 / 最短)として入る(§10)。クリア画面の
  「記録」はそのサイズの最短時間(統計画面と同じ数)と比べる — フリーの盤面には盤面ごとの
  記録を置く場所がないからである。
- クリア画面の第一ボタンは「新しいゲーム」(同じティアで次の盤面)。第二が同じ盤面での再挑戦。
- 中断は独立した第 3 のスロット(§11)。中断中に新しい盤面を求めたときだけ確認を出す。

なぜ足したか: 7×7 はレベル 81 からで、そこまでに 80 レベルある。大きな盤面を遊びたい人が
80 レベル登る必要があるのは坂の設計であって、望んだ盤面で遊べないことの理由にはならない。
100 を終えた人に残るのが 1 日 1 問だけ、というのも同じ。フリープレイは中身がゲームそのもので
あり、課金にも広告にも時間にも結び付かない。

## 10. 時間と統計

- **プレイ中に時計を表示しない**(ブランド原則)。経過時間は内部で記録し、結果画面と統計で
  のみ見せる。
- 統計: **サイズ別のクリア数、サイズ別の最短時間、合計プレイ時間、デイリー達成日数。**
  サイズのキーは `size4` / `size5` / `size6` / `size7`(Nonogram / Takuzu の sizeKey 方式)。
- **難易度別には集計しない。**そもそもティアがない(§7)し、プレイヤーが選ぶのは
  レベル番号なので、それ以外の軸の表は「自分では選べない軸の表」になる。
- ミス回数と Hint 回数はクリア画面で見せるが、統計には積まない(§5・§6)。
- **スコアは作らない。**ランキングもストリークも作らない。自己ベストの更新は、更新した
  ときだけ静かに示す。
- クリア画面には、比べる記録があれば**記録との差を符号付きで添える**(`+0:18` = 記録より
  遅い / `−0:05` = 記録を縮めた)。比べる相手は自分の記録だけで、初めてのクリアには何も
  添えない(`ui/components/BestDelta.tsx`)。レベルとデイリーはその盤面の記録と、フリープレイは
  そのサイズの最短時間と比べる(§9)。
- フリープレイもサイズ別の数に入る(§9)。

## 11. 中断と再開

- レベル用・デイリー用・フリープレイ用の**3 スロットを独立して保持する**。レベルを中断して
  デイリーやフリープレイを遊んでも、どれも失われない。
- 保存するのは モード / seed / レベル番号または日付またはフリープレイのティア / サイズ /
  初期数字 / 解 /
  **不等号(エッジの列挙)** / プレイヤーの数字 / メモ / ミス回数 / Hint 回数 /
  経過秒数 / 保存時刻。**Undo 履歴は保存しない**(§5)。
- **不等号は「小さい方のマスと大きい方のマス」の対で持つ**(`{ less, greater }`)。向きを
  別のフィールドにしない — 対そのものが `board[less] < board[greater]` という文であり、
  読み手(§7 の伝播・§5 の違反表示・下の検証)が向きを解釈してから使う段が消える。
  **解釈の要らないデータは、解釈を間違えない。**
- **どのスロットのレコードかを決めるのはキーである。**3 つのスロットは同じ形のレコードを
  持つので、レベル用のキーに入っている `mode: 'daily'` のレコードは「デイリーだった」の
  ではなく壊れている。復元せず既定値へ落とす([ARCHITECTURE.md](ARCHITECTURE.md))。
  この規則は `src/test/savedGameSlots.test.ts` が二重スロットのゲームを走査して自動強制する。
- **検証は fail-closed。**プレイから生まれえないレコードは読み捨ててホームへ戻す:
  - **解がラテン方陣でない**(どこかの行・列に 1〜N が 1 つずつ入っていない)
  - **不等号が解と矛盾する**(向きが解の大小と逆、または隣接していない 2 マスを結んでいる)
  - **プレイヤーの数字が初期数字のマスを上書きしている**(初期数字は動かない — §4)
  - 盤面またはメモの**長さがサイズと合わない**、サイズが 4 / 5 / 6 / 7 でない
  - 盤面に **1〜N と空以外の文字**が入っている、メモに範囲外の数字が入っている
  - 初期数字が解と食い違っている
  - **フリープレイのレコードがレベル番号か日付を持っている、ティアがない、またはティアの
    代表レベルとサイズが合わない**(§9)。レベル・デイリーのレコードがティアを持つのも同じ

  **不等号と解の矛盾は、この形式で最も強い不変量である。**生成は向きを解から読むので
  (§8 手順 2)、食い違うレコードはプレイからは生まれえない。

- 背景へ回るとき、盤面の保存と未計上秒の計上を**同じ同期処理で**行う。OS は別のイベント
  なしにアプリを終了できるため、盤面だけを保存すると前回の同期以降の秒数が永久に失われる。
- 保存キーは `ft.saveGame` / `ft.saveDaily` / `ft.saveFree` / `ft.stats` / `ft.progress` /
  `ft.flags` / `ft.prefs` の **7 つ**。`ft.stats` はサイズ別の記録、`ft.progress` は解放済みレベルと
  レベル別・日付別のベスト(デイリー達成日はこの疎マップから導出し、カレンダー専用の
  レコードは持たない)、`ft.flags` はチュートリアル完了。

  **`ft.prefs` があるのは、盤面をまたいで覚えるものがあるからである** — ミスの即時表示の
  トグル(§5)と、フリープレイのティア(§9)。Takuzu の `tk.prefs` はフリープレイと同時に
  生まれ、覚えているのはティアの 1 つだけである([TAKUZU_RULES.md](TAKUZU_RULES.md) §11):
  あちらは置ける数字が 2 つしかなく「解と違う」という表示自体を作っていないので、
  ミス表示の設定は発生しない。**キーの数は揃えるものではなく、そのゲームが覚えるものの
  数である。**

- 保存の失敗でゲームを止めない。バリデータは例外を投げない。

## 12. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ原則 1 文・図中心([I18N_POLICY.md](I18N_POLICY.md))。

1. どの行・列にも 1〜N を 1 つずつ入れる。
2. 不等号に従う — とがった側が小さい。
3. 迷ったらメモ、詰まったら Hint。

詳細ルール・攻略・FAQ はアプリに入れず、ゲーム別 Landing Page
(`https://pixapps.ai/simple-games/games/futoshiki/<locale>/`)へ分離する。チュートリアルの
「詳しく見る」から開く。オフラインでは静かに何もしない(ゲームは止めない)。

## 13. 演出とアクセシビリティ

- **不等号は装飾ではなくテキストである。**スクリーンリーダーが読める形で盤面に置く。
  図形だけで描いて `aria-hidden` にすると、この盤面は「数字が虫食いの表」になり、
  **ルールの半分が読み上げから消える。**
- 各マスはボタンで、**行・列と状態(空 / 数字 / 初期数字)**を読み上げる。初期数字である
  ことが読み上げから分かること。そのマスに接する不等号も同じ読み上げに含める
  (「3 行 2 列、空。右のマスより小さい」の形)。向きは記号の形ではなく**言葉で**言う —
  「小なり」では、どちらのマスが小さいのかが伝わらない。
- 初期数字とプレイヤーの数字は、**色ではなく字の太さ**で分ける。
- 違反表示も色だけに頼らない。警告色に枠を併用する。選択マスと同じ行・列のハイライトも
  同様で、色だけに意味を持たせない。
- Reduced Motion が有効なら、数字が変わる演出は即時にする。
- **盤面が埋まってから結果カードが出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。完成した
  盤面 — すべての行・列・不等号が成立した形 — を見る時間であり、その間に押せるものはない。
  Reduced Motion では従来どおり即時に出す。
- 不等号はセル間のギャップに描く。**ギャップはタップの対象ではない** — 押せるのはマスだけ
  で、不等号は表示専用である。押せそうに見えて押せないものを盤面に置かないため、不等号は
  押下の見た目(枠・影)を持たない。
- **7×7 の 320px でのタップ精度と不等号の視認性は、まだ測っていない。**実装 PR の冒頭に
  静的モックの門(320 / 360 / 420px × ライト / ダーク)を置く。通らなければ上位帯を 6×6 に
  落とし、**この文書を先に直す。**実機では
  [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) §2 で確認する。

## 14. 意図的な差分

ブランド原則により合わせないもの:

- ミス上限・ライフ制・ゲームオーバー(しない。ミスは数えるが、その数が何かを止めることは
  ない — §5)
- プレイ中のタイマー表示、連続日数ストリークとその表示(しない — §9・§10)
- オンラインランキング、スコア(作らない — §10)
- Hint / Undo を広告視聴やコインの報酬にすること(しない。常に無料・無制限 — §5・§6)

設計判断として合わせないもの:

- **サイズは 4〜7 のみ。8×8 以上は作らない。**320px の画面で 1 マスが指で押せる大きさを
  下回るためである(Nonogram §1 が 15×15 を落としたのと同じ床)。
  **「Sudoku は 9×9 で成立しているではないか」への答えは形にある** — Sudoku はマスを
  隙間なく敷き詰められるが、Futoshiki は**隣接するマスの間すべてに不等号のための隙間**を
  要求する。同じ幅に置ける最大サイズは Sudoku より小さく、しかも隙間に載る記号自体が
  読める大きさでなければならない。**上限を 7×7 に置いたこと自体、まだ測って確かめて
  いない**(§13)。
- **不等号のない変種。**それはボックスのない Sudoku であり、同じ収録の中に同じ推論しか
  要求しない 2 本を置くことになる。
- **対角制約・重複許容などの変種ルール。**v1 は 1 規則セットだけを扱う(Connect Four /
  Checkers の前例)。
- **技法名の UI 表示。**平易な言い換えのみ(§6)。
- **不等号ごしのメモ自動消去。**推論そのものを肩代わりする(§4)。
- **推測が必要な盤面・複数解の盤面。**出さない(§7)。
- **問題データの同梱・配信。**すべて端末上で生成する(§8)。パック同梱は性能予算が破れた
  ときの最後の手段としてのみ検討し、採ったらこの文書に書く。

合わせたもの:

- ラテン方陣 + 不等号の標準ルール、一意解、常時の違反表示、メモ、数字の残数表示、
  同数字ハイライト。
