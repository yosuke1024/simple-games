# Schulte Table — 正式ゲームルール

この文書は Simple Games 収録タイトル「Schulte Table(順番タッチ)」の唯一の
ルールソースである。実装(`apps/simple-games/src/games/schulte-table/game/`)、
テスト、Quick Rules はすべてこの文書に従う。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

脳トレドリル 3 本(Schulte Table / Number Recall / Quick Math)に共通する
ジャンル原則は §14 にまとめてある。**そのうち最も重いのは「時間は計るが、
プレイヤーを止めない」**である。このジャンルの定番である制限時間・
タイムアタックはこの収録では作らない。

## 1. 盤面

- N×N のマス。N は 3 / 4 / 5 のいずれか。
- 各マスに `1` から `N²` までの数字が 1 つずつ、重複なく散らばって置かれる。
  空きマスはない。
- **マスには数字だけを描く。画像・記号は使わない**(翻訳不能な文字を画像へ
  埋め込まないという原則、および ASCII 0-9 は全言語で同じ見た目になるため。
  [I18N_POLICY.md](I18N_POLICY.md))。
- 数字の色は 1 色(インク)。**色で意味を持たせない** — 次に押す数字を色で
  示せば探す作業そのものが消えるうえ、色覚特性のある読者に別のゲームを配ることになる。

## 2. 勝利条件

その回の**並び順**(§5)に従って全マスを 1 つ残らずタップした状態。
ゲームオーバーは存在しない — どの盤面も必ず完了できる(§4)。

## 3. 操作

- 次に押すべき数字のマスをタップすると、そのマスが「済み」になる。
  済みマスは沈んだ面になり、数字は薄いまま**盤面に残す**(消さない。
  消すと盤面が虫食いになり、残りを探す難度が回ごとに変わってしまう)。
- **順番が違うマスのタップは何も起こさない。** 音も振動も出さず、盤面も動かない。
  誤タップとして数だけ数える(§4)。
  - 叱らないのは意図である([SOLITAIRE_RULES.md](SOLITAIRE_RULES.md) の
    「無効操作を叱らない」と同じ)。この遊びは「探して、見つけて、押す」の
    繰り返しであり、外した瞬間に音が鳴れば、次から探す前に押さなくなる。
- 済みマスへの再タップも無効な手であり、誤タップとしても数えない
  (**押す相手を間違えた**のではなく、**もう押した相手を押した**だけである)。

## 4. 時間と誤タップ

- **時間はプレイ中に表示しない。** 内部で記録し、完了画面と統計でのみ見せる。
  1 面が数十秒で終わる遊びであり、進行中の秒読みは急かす装置にしかならない。
- **制限時間はない。時間切れも存在しない。** このジャンルの定番である
  「60 秒で何面」は作らない([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md)
  「タイマープレッシャーを既定にしない」)。時間は**結果**であって**締切**ではない。
- **誤タップ数はプレイ中に表示しない。** 完了画面でその回の事実として見せ、
  統計には合計だけを残す。
- **次に押すべき数字は画面に表示する。** 盤面の上に 1 つだけ、大きく出す。
  記憶ではなく注意の遊びなので、「次が何番か」を覚えていること自体は
  この遊びの中身ではない(覚えている必要があるのは Number Recall の担当である)。

## 5. 並び順(order)

その回にどの順でタップするかを **order** と呼ぶ。3 種類。

| order         | 順番                         | 例(3×3)           |
| ------------- | ---------------------------- | ----------------- |
| `ascending`   | `1, 2, 3, …, N²`             | 1→2→3→…→9         |
| `descending`  | `N², …, 3, 2, 1`             | 9→8→7→…→1         |
| `oddThenEven` | 奇数を昇順、続けて偶数を昇順 | 1→3→5→7→9→2→4→6→8 |

- **色で 2 系列に分ける変形(Gorbov 型)は作らない。** 2 色を交互に追う形は
  Schulte の定番変形だが、区別が色だけになる。§1 の「色で意味を持たせない」に
  反し、色覚特性のある読者には別のゲームになってしまう。形で区別する案
  (丸と四角の 2 系列など)も検討したが、Quick Rules 3 ステップで説明できる
  範囲を超える。**この 3 つはすべて数の順序だけで定義でき、1 文で説明できる。**
- order が変わっても盤面の配置生成(§6)は変わらない。変わるのは
  「次に押すべき数字」を決める列だけである。

## 6. 配置生成

- `1..N²` の配列を seed 由来の乱数で Fisher–Yates シャッフルして敷く。
- 同じ seed は常に同じ配置を返す(golden テストで固定する)。
- **配置に制約は課さない。** 「1 と 2 が隣り合わない」等の条件を足すと、
  条件を満たすまで引き直す生成になり、盤面が偏る。散らばりは乱数に任せる。

不変条件:

- `1..N²` が過不足なく 1 度ずつ現れる。
- 同じ seed は常に同じ配置を返す。

## 7. レベル(1〜100)

level から (盤面サイズ, order, seed) を決定的に導出する。seed は `schulte-level-<n>`。

| レベル帯 | サイズ | order         | 意図                                       |
| -------- | ------ | ------------- | ------------------------------------------ |
| 1–15     | 3×3    | `ascending`   | 操作を覚える。数秒で終わる                 |
| 16–20    | 3×3    | `descending`  | 順番が変わりうることを、小さい盤で知る     |
| 21–45    | 4×4    | `ascending`   | 標準の広さ                                 |
| 46–55    | 4×4    | `descending`  |                                            |
| 56–80    | 5×5    | `ascending`   | 本命のサイズ                               |
| 81–90    | 5×5    | `descending`  |                                            |
| 91–100   | 5×5    | `oddThenEven` | 最後の帯。探索に「次は奇数か偶数か」が乗る |

**新しいサイズは必ず `ascending` から始める。** サイズと order を同時に
上げると 2 つの跳躍が重なる([SLIDING_PUZZLE_RULES.md](SLIDING_PUZZLE_RULES.md)
§6 の帯の作り方と同じ考え方)。

- レベルは順番に解放する(クリアした level の次が解放)。
- 解放済みレベルはいつでも選び直せる。再挑戦は同じ配置(seed が同じ)。
- 各レベルの **最短時間** を記録する(§9 の「最少誤タップを記録しない」も参照)。

## 8. デイリーチャレンジ

- 1 日 1 面。seed は `schulte-daily-<YYYY-MM-DD>`(端末のローカル日付のみ)。
- **5×5 / `ascending` 固定。** 曜日で難易度を変えない。
- 過去 30 日に遡って挑戦できる。**過去の日は無条件に開く**
  (Sliding Puzzle 型。前日クリアを条件にする Sudoku 型にしない — この遊びに
  配給すべき難易度がなく、条件は中身のない障害物にしかならない)。
- 達成した日は記録する。**ストリークは数えない・表示しない。**

## 9. Undo と Hint

- **Undo は作らない。** タップは「見つけた」という主張そのものであり、
  取り消す対象がない。盤面には隠れた情報がなく、押した順は結果に影響しない。
- **Hint は作らない。** 盤面は完全に見えており、次の数字の位置を示す助けは
  探す作業そのものを肩代わりする(Sliding Puzzle の Hint 不採用と同じ理屈。
  §1 で色を使わないのも同じ理由である)。
- **代わりに、同じ面への即時・無料の再挑戦を出す。** 完了画面から 1 タップで
  同じ配置をやり直せる。これがこのゲームの「助け」である
  ([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md):
  そのゲームの中身を空にしない形の助けを、どのタイトルにも用意する)。

### 最少誤タップを記録として持たない理由

時間と誤タップの両方を「ベスト」にすると、**ゆっくり押すほど有利な記録**が
1 つできてしまう。誤タップ 0 は落ち着いて探せば誰でも出るので、記録として
機能しないうえ、速さと正確さのどちらをこのゲームが求めているのかを
記録の形が黙って指示することになる。**記録は時間だけ**にし、誤タップは
その回の事実(完了画面)と統計の合計としてだけ残す。

## 10. 統計

- サイズ別(3×3 / 4×4 / 5×5)に: プレイ回数、完了回数、最短時間、
  合計プレイ時間、**合計誤タップ数**。
- レベル進行: 到達レベル、クリア済みレベル数。
- デイリー: 達成日数(ストリークなし)。
- スコアは持たない。抽象ポイント・偏差値・ランクを作らない(§14)。

## 11. 中断と再開

- **途中のゲームは保存しない。** 保存キーは `st.progress` / `st.stats` /
  `st.flags` の 3 つだけ。
- 理由: 1 面が数十秒で終わり、しかも中身は「注意を切らさずに追い切ること」で
  ある。中断した注意を復元することはできないので、途中から再開しても
  「12 まで押した盤面」が出てくるだけで、記録としても遊びとしても意味を持たない
  (アーケード 2 本・Bunny Hop と同じ判断)。
- 画面を離れた時点で、その回は破棄される。統計の**プレイ回数には数えるが、
  完了回数には数えない**(始めたのは事実、完了していないのも事実)。
- **プレイ時間と誤タップは、区切りごとに「まだ数えていない分だけ」を確定する。**
  区切りはバックグラウンド化・完了・離脱(Home / Retry)の 3 つ。ラウンドを保存
  しない以上、**バックグラウンド中に OS がプロセスを殺せば、そのとき確定して
  いなかったものは失われる** — 秒を離脱前に確定しているのと同じ理由で、誤タップも
  そこで確定する。差分にするのは二重計上を防ぐためで、区切りのたびに `missCount`
  の全量を足すと、戻ってきて続きを遊んだ人が前半の誤タップを何度も数えられる。
  合計誤タップ数は「これまでに押した誤タップの数」であり、その回が
  どう終わったか(完了・離脱・プロセス死)に依存してはならない。
- 保存の失敗でゲームを止めない。壊れた保存データは読み捨てて既定値に戻す。

## 12. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ原則 1 文・図中心。

1. 散らばった数字を、1 から順にタップする。
2. 上に出ている数字が、次に押すもの。
3. 全部押せば完了。時間は記録するだけ — 制限時間はない。

詳細は Landing Page(`https://pixapps.ai/simple-games/games/schulte-table/<locale>/`)へ。
**ガイド公開までは Learn More を出さない**(`src/ui/landing.ts`)。

## 13. 演出とアクセシビリティ

- 済みマスへの変化は短いトランジションで示すが、**Reduced Motion が有効なら
  即時に切り替える**。
- 各マスは「数字・行・列・済みかどうか」を読み上げられること。
- 5×5 でもタップ目標が小さくなりすぎないよう、盤面は列幅いっぱいまで使う
  (`width: min(100%, 420px)`。vw は使わない)。
- 次に押すべき数字は読み上げ対象にする(視覚だけの手がかりにしない)。
- 済みマスは「薄い数字 + 沈んだ面」で示し、**色だけで区別しない**。

## 14. ジャンル原則(脳トレドリル 3 本の共通事項)

Schulte Table / Number Recall / Quick Math の 3 本すべてに適用する。

1. **時間は計るが、プレイヤーを止めない。** 制限時間・カウントダウン・
   時間切れを作らない。時計はプレイ中に表示せず、結果と統計でだけ見せる
   ([MEMORY_MATCH_RULES.md](MEMORY_MATCH_RULES.md) §4 の前例)。
2. **効能を謳わない。**「脳年齢」「IQ」「認知機能の改善・予防」を
   アプリ内文言・ストア文言のどちらにも書かない。科学的裏付けが係争的な主張で
   あり、Honest by design と両立しない。**この禁止は
   `.github/scripts/check-principles.sh` §7 が grep で強制する**(英語・日本語の
   範囲で。[I18N_POLICY.md](I18N_POLICY.md) の機械チェックと同じ限界を持つ)。
   - **検査対象は利用者の目に触れる面**である: アプリ内の文字列(`apps/*/src`,
     `packages/*/src`)と**ストア掲載文面**(`apps/*/store/listing.md`)。
     ストアは効能を誤って謳うリスクが最も高い面なので、`src` の外にあることを
     理由に外さない。
   - **ジャンル名そのものも対象に含まれる。** 日本語の「脳トレ」は
     「脳を鍛える」と言っており、名前の形をした主張である。掲載文面では
     ジャンル名を使わず、何をする遊びなのかを書く。
   - **この文書と README は検査対象ではない。** 規則を説明するには禁止語を
     書く必要があり、blanket scan すると規則を書くこと自体が違反になる。
     内部文書がジャンルを通称で呼ぶのは利用者への主張ではない — 線引きは
     「利用者に向けて言うかどうか」であって「どのファイルにあるか」ではない。
   - **パターン自身の生存も毎回検査する。** 不在を検査するガードの最悪の壊れ方は
     落ちなくなることではなく、**何も見ていない状態で緑になる**ことなので、
     既知の違反文で毎回叩いている(§7 の自己検査)。
3. **スコアを発明しない。** 指標は時間と正確さ(誤タップ・誤答の数)だけ。
   抽象ポイント・偏差値・ランク・「脳の調子」を作らない。
4. **ストリークなし。** デイリーは達成日の記録のみ。
5. **急かす演出をしない。** 点滅・警告音・カウントダウンを作らない。
   誤りは叱らず、記録にだけ残す。

## 15. 意図的な差分

ブランド原則により合わせないもの:

- 制限時間・タイムアタック(作らない。§4)
- 脳年齢・IQ・認知機能の主張(作らない。§14-2)
- ストリーク、オンラインランキング(作らない)
- 誤タップへのペナルティ、リトライの有料化(作らない。§9)

設計判断として合わせないもの:

- Undo / Hint(作らない。§9)
- 色で 2 系列を分ける Gorbov 型変形(作らない。§5)
- 途中保存(作らない。§11)
- 6×6 以上のサイズ(採用しない。5×5 でタップ目標が下限に近い)
