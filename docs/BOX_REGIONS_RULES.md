# Box Regions — 正式ゲームルール

この文書は Simple Games 収録タイトル「Box Regions」の唯一のルールソースである。
実装(`apps/simple-games/src/games/box-regions/game/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。コードはここへ `§n` で言及する。数値を変える場合はここを先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Hint と Undo は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

ゲーム ID は `box-regions`、i18n キーの接頭辞は `boxRegions`、保存キーの接頭辞は `br.`
である。配信チャンネルは **Web 先行公開(`web-beta`)**で、アプリには正式収録しない
([WEB_VERSION.md](WEB_VERSION.md)「先行公開」、issue #210)。古典的な**長方形分割**
(四角に切る)系のメカニクスに、形の種類(正方形 / 縦長 / 横長 / 自由)の手がかりと
「数字も形も無い手がかり」を足したものを、Simple Games の名前と表現で作る。
[Shape Regions](SHAPE_REGIONS_RULES.md) とは**別のゲーム**である — あちらは 5 種類の
ポリオミノ(直線 / 長方形 / L 字 / T 字 / 段違い)で盤面を敷き詰め、こちらは長方形だけで
敷き詰める。Shape Regions の実装・保存・ルールには触れない(§14)。他社の商品名・
アセット・画面デザインは複製しない。5 種類の練習セットの中での位置づけと、比較対象との
対応表は [PUZZLE_PRACTICE_SET.md](PUZZLE_PRACTICE_SET.md)。

## 1. 盤面

- W×H のマス。いくつかのマスが **手がかりマス**で、**手がかり 1 つにつき領域 1 つ**。
- 領域は**軸に沿った、中の詰まった長方形**である。**1×1 も長方形**(正方形)として合法。
- 領域のマス数(面積)は **1〜12**(`MAX_REGION_SIZE` = 12)。13 マス以上は作らない
  (手がかりの数字が 2 桁に収まり、候補配置の列挙が有限で小さい。7×7 の盤面で 12 マスは
  面積の 1/4 で、それより大きな箱は盤面のほとんどを 1 つの答えで埋めてしまう)。
- 領域は最大 26 個(`MAX_REGIONS`)。保存形式が領域を 1 文字の英小文字で表すため(§11)。
  生成は 1×1 の領域を **1 盤面に 2 個まで**(`MAX_UNIT_REGIONS`)に抑え、26 個を超える
  敷き詰めは捨てる(§8)。

難易度プリセット(スマートフォンの画面に収まる形で決めた):

| 難易度 | 盤面 |
| ------ | ---- |
| Easy   | 5×5  |
| Medium | 6×6  |
| Hard   | 7×7  |

8×8 以上は作らない。手がかりマスには数字と記号が同居するので、1 マスは Takuzu の 10×10 より
大きく要る(Shape Regions §1 と同じ床)。**難易度はサイズだけでは決めない** — ティアは
技法の集合と手がかりの削り方で定義する(§7)。

**盤面に翻訳の要る文字は 1 つも載らない。**数字は ASCII の `0-9`、形の記号は小さな
インライン SVG(§2、§13)。読み上げ名だけが i18n を通る。

## 2. 手がかりと形の種類

手がかりマスは**形の種類**と、あれば**数字**(その領域のマス数)を示す。

### 形の種類(4 つ、`ShapeKind`)

長方形の幅 w と高さ h で読む:

| 種類       | 記号の意味 | 定義                              | 例                     |
| ---------- | ---------- | --------------------------------- | ---------------------- |
| **square** | 正方形     | w = h(1×1 を含む)                 | 1×1、2×2、3×3          |
| **tall**   | 縦長       | h > w                             | 1×2、2×3、1×5          |
| **wide**   | 横長       | w > h                             | 2×1、3×2、5×1          |
| **free**   | 自由       | 制約なし(どんな長方形でもよい)    | 上のどれでも           |

4 つの定義のうち square / tall / wide は互いに排他的で、どの長方形もそのどれか 1 つに
入る。**free は「形を言わない」手がかり**であり、`free` + 数字なしの手がかりは「ここに
領域が 1 つある」以外の何も言わない(比較対象の「どちらも指定なし」に当たる — §14)。

### 手がかりの 4 形

| 手がかりが持つもの | 意味                                                         | 表示                     |
| ------------------ | ------------------------------------------------------------ | ------------------------ |
| 数字 + 形          | マス数がその数字で、形がその種類                             | 記号の下に数字           |
| 形だけ             | 形がその種類(マス数は自由)                                   | 記号だけ                 |
| 数字 + free        | マス数がその数字(形は自由)                                   | free の記号の下に数字    |
| free だけ          | 何も言わない(領域が 1 つあることだけ)                        | free の記号だけ          |

実装上、手がかりは常に `kind`(4 種のどれか)を持ち、`size` は `number | null` である
(`types.ts` の `Clue`)。「数字だけ」は `kind: 'free'` + 数字として表現する — free の記号を
必ず描くので、**手がかりマスは常に何かの記号を持ち、空のマスと見分けがつく**(§13)。

## 3. ルールと勝利

1. 全マスがちょうど 1 つの領域に属する。
2. 各領域は長方形で、ちょうど 1 つの手がかりマスを含む(自分の手がかり)。他の領域の
   手がかりマスは含まない。
3. 各領域のマス数は 1〜12(§1)。
4. 手がかりに数字があれば、その領域のマス数はその数字。手がかりの形が square / tall /
   wide なら、その領域の形はその種類(§2)。free は何も求めない。

出題は常に一意解を持つ(§8)。

- **勝利**: 全マスが割り当てられ、上の 4 規則をすべて満たした時点。判定は**規則で**行い、
  解と照合しない(一意解なので一致する)。表示(§5)と判定が同じ読みから出るので、
  「きれいに見えるのに完成しない盤面」は作れない。
- 敗北は存在しない。ミス回数の制限も、ライフも、ゲームオーバーもない(§14)。

**合法な形の集合は 1 か所で定義する。**「面積 1〜12 の長方形」という同じ読みを、勝利判定
(`engine.ts`)・違反表示(§5)・候補配置の列挙(§7)・一意性の証明(§8)・Hint(§6)・
保存の検証(§11)が共有する。生成の都合で候補を狭めたまま「一意解」と判定することは
できない構造にしてある(issue #210 §D)。

## 4. 操作

領域は**角から角へなぞって描く**。

- **なぞる(ドラッグ)**: マス A を押し、マス B まで指を動かして離すと、A と B を対角とする
  長方形が描かれる。なぞっている間はその長方形をプレビューし、離した時点で次のどちらか:
  - 長方形が**ちょうど 1 つ**の手がかりマスを含む → その手がかりの領域になる。長方形と
    重なる既存の領域は**丸ごと**消える(長方形から欠けた長方形は長方形ではないので、部分
    だけ残す意味がない)。同じ手がかりの領域を描き直す場合も同じ扱い(古い領域が消えて
    新しい長方形になる)。
  - 手がかりマスを含まない、または 2 つ以上含む → 何も起きない。なぞっている間の
    プレビューは警告色で「置けない」ことを示すが、エラー音も警告文も出さない。
  - 指が 2 マス目に達した時点で「ストローク」になり、離したときの click は捨てる
    (Nonogram §3 と同じ判定)。
  - `touch-action: none`。ポインターキャプチャで盤面外へ出た指も追う(盤面外は最寄りの
    マスへ丸める)。
  - `pointercancel`(OS がジェスチャーを取り上げた)はストロークを**捨てる**。プレビュー
    だけが消え、盤面は変わらない — 長方形は「離した瞬間に 1 つの決定」なので、途中で
    奪われた決定は無かったことにするのが正しい(Number Path が描いた分を残すのと逆で、
    あちらは 1 マスずつが決定だからである)。
- **タップ**:
  - 領域に属するマスをタップすると、その領域が丸ごと消える。
  - まだ領域の無い手がかりマスをタップすると、その手がかりの **1×1 の領域**になる
    (角から角へのなぞりが 1 マスに退化した形。1×1 が合法なので、この近道を置く)。
  - 割り当てのない手がかり以外のマスをタップしても何も起きない。
- **マウス**: 左ボタンのドラッグが指と同じ。右ボタン・中ボタンは何もしない。盤面の上で
  ブラウザのコンテキストメニューは出さない。
- **キーボード**: `Ctrl/Cmd+Z` = Undo、`H` = Hint。押しっぱなしのキーリピートでは動かさない。
  結果カードと確認ダイアログの間は効かない。
- 長押し・モード切替・自動補完は作らない(§14)。

**手がかりマスは最初は未割り当てである**(Shape Regions §4 と違う)。1×1 が合法なこの
ゲームで手がかりマスを最初から自分の領域に入れておくと、描いていない手がかりが
「1×1 の領域」として判定に混ざる。描いた領域だけが領域である。

## 5. 表示と違反

- 各領域は**薄い地色 + 領域境界の太い線**で区別する。地色は 8 色のパレットを領域番号で
  回す(`box-regions.css`、ライト / ダーク各 8 色 — ゲーム内容なのでこのファイルが持つ)。
  領域は長方形なので、境界は 4 辺の直線で、Shape Regions のような凹角の処理は要らない。
  **色だけに意味を持たせない**: 地色を全部外しても、太線だけで領域は読める(§13)。
- 手がかりマスは記号(形の種類)と、数字があればその下に数字。領域が数字に達するまで
  `現在/目標`(例 `3/4`)を出し、達したら数字だけを出す。free の記号は常に出る(§2)。
- **違反表示は常時オン**。次のどれかに当たる領域は、その全マスを `--warn` で示す(地色を
  `--warn-soft`、文字を `--warn` にし、領域の輪郭に沿った 2px の内側の輪を引く):
  - 数字と違うマス数(領域は描いた瞬間に完成形なので、超過も不足も違反)。
  - 12 より大きい(§1 の上限)。
  - 形が記号と一致しない(square / tall / wide のとき)。
- **これはルール違反の指摘であって、答え合わせではない。**規則を破っていない領域は、
  それが解と違っていても何も言われない(Hint だけが解と比べる — §6)。

## 6. Undo と Hint

### Undo

- **1 手 = 1 ストローク(描いた長方形と、それが消した領域)または 1 タップ(消した領域 /
  置いた 1×1)。**
- 履歴はセッションに持ち、上限 200 手(`UNDO_HISTORY_LIMIT`)。**保存しない** — 再開時は
  空(§11)。Undo は Hint 回数を戻さない。
- **Undo を作る理由**: 1 つのストロークが複数の領域を消す(§4)。手で戻すには消えた
  領域を描き直す必要があり、非自明に不可逆である(Shape Regions §6 と同じ判断)。

### Hint

無料・無制限・回数を数える(結果画面に出す)。**盤面には書き込まない。**順に:

1. **解と違う領域**があれば、その領域を示す(「この箱は成立しない」)。一意解の出題なので
   誤りは定義できる。描いた長方形は規則を破らないまま解から外れた状態を長く保てるので、
   誤った領域の上に積んだ確定を教えるより、その領域を示す方が正しい導きになる
   (Shape Regions §6 と同じ判断)。
2. なければ技法ソルバー(§7)の**次の一手**を示す:
   - T1「このマスは領域 R にしか入れない」— そのマスを強調し、根拠として**そのマスを覆う**
     R の候補配置の和集合を淡く示す。
   - T2「領域 R の置き方は 1 つしかない」— その長方形の全マスを強調する。
   - T3「領域 R のどの置き方にも入るマス」— それらのマスを強調し、候補配置の和集合を淡く示す。
   - T4 で候補を除外した後に見つかる T1〜T3 の一手も同じ形で示す(技法名は UI に出さない)。
3. どちらも見つからないときは「今わかる手が見つかりません」と表示し、盤面は変えない。
   出荷した盤面では、描いた領域が解の部分集合である限り 2 が必ず見つかる(技法は単調)。

## 7. 技法とティア

**候補配置** = ある手がかりについて、その手がかりマスを含み、他の手がかりマスを含まず、
盤面に収まり、面積 1〜12 で、手がかりの数字と形の種類を満たす長方形。現在の割り当てと
矛盾しない(他の領域に確定したマスを含まない・自分の領域に確定したマスをすべて含む)ものが
生きている候補である。

候補配置は手がかりごとに一度だけ列挙してビットマスクで持ち(`placements.ts`)、以後は
割り当てとの整合だけを見る。手がかりマスを含む長方形は 7×7 で最大でも数百なので、
free + 数字なしの手がかりでも列挙は小さい。

技法(`solver.ts`。安い順に試し、どれかが 1 つでも確定したら先頭からやり直す):

- **T1 forced cell**: 未確定のマスを覆える候補配置がただ 1 つの領域のものだけ → そのマスは
  その領域。どの領域の候補配置も覆えない未確定マスがあれば矛盾。
- **T2 sole placement**: 領域の候補配置が 1 つ → その長方形を確定。候補配置が 0 なら矛盾。
- **T3 common cells**: 領域の全候補配置に共通するマス → その領域に確定。
- **T4 hypothesis(深さ 1)**: 領域 R の候補配置 P を 1 つ仮定し、T1〜T3 を不動点まで回す。
  矛盾なら P を R の候補から**以後ずっと除外**する(確定は増える一方なので除外は失効
  しない)。全領域の全候補配置について 1 巡し、除外が 1 つでもあれば T1〜T3 へ戻る。

**4 つとも健全である。**したがってこの技法だけで全マスが確定した出題は解が 1 つだけである。
技法の実装は 1 つだけ持ち、3 人の利用者が共有する — 生成時の等級判定(§8)、Hint(§6)、
`guarantee.test.ts`。仕事量は `solverWork`(候補配置の整合判定の回数 + 完全探索の
ノード数 + ソルバーの入口ごとに候補表の総数を 1 回 + T4 の仮定 1 回につき 1)で数える。

### ティア(許容技法の集合 + 手がかりの削り方)

「削減」は手がかりから情報を落とすこと: 数字を落とす(形だけ)/ 形を落とす(free + 数字)/
両方落とす(free だけ)。

| ティア | 許容技法     | 手がかりの削減(§8)                                                 | 追加条件                                   |
| ------ | ------------ | ------------------------------------------------------------------ | ------------------------------------------ |
| Easy   | T1 / T2 / T3 | 手がかり数の **25% 以下**を**片方だけ**落とす(free だけにはしない) | T1〜T3 だけで解ける                        |
| Medium | T1 / T2 / T3 | 手がかり数の **50% 以上**を落とす(free だけも可)                   | T1〜T3 だけで解ける                        |
| Hard   | T1〜T4       | 一意を保つ限り**すべて**の手がかりを、できるだけ深く落とす         | **T1〜T3 だけでは解けず**、T1〜T4 で解ける |

Easy と Medium は削減の各段で T1〜T3 solvable も一意性と一緒に見る(`keepBasic`)。Hard は
一意性だけを見て削り、等級は手順 5 でまとめて確認する(Shape Regions §7 と同じ理由)。

## 8. 生成と Seed

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。
(`generator.ts` の `generatePuzzle(seed, difficulty)`。)

1. **敷き詰める。**最初の空マス(行優先)を左上の角とする長方形(幅 × 高さ、面積 1〜12、
   盤面に収まるもの)で覆う。試す寸法の順は seed 由来のシャッフル(ノードごと)。1×1 は
   `MAX_UNIT_REGIONS`(2)個までしか置かない。置いた結果、空マスの連結成分に幅か高さが
   足りずどの長方形でも覆えない欠片ができれば戻る。バックトラックで全マスを覆う。ノード数が
   `TILING_NODE_LIMIT`(4,000)を超えたら、または領域が 26 個を超えたら、その敷き詰めを
   諦めて派生 seed へ。
2. **手がかりマスを選ぶ。**各領域から seed で 1 マス。手がかりは数字 + 形の種類の両方。
3. **一意性を確かめる。**完全探索(exact cover — 候補配置が最も少ない領域から分岐、解を
   2 つまで数える)で解が 1 つになるまで、同じ敷き詰めのまま手順 2 を最大 `CLUE_DRAWS`(4)回
   繰り返す。4 回とも一意でなければこの候補は捨てて派生 seed へ。
4. **削る。**手がかりを seed 由来のシャッフル順に 1 つずつ取り、seed で決めた順に
   「数字を落とす」「形を落とす」を試し、一意なら採用、駄目ならもう一方、それも駄目なら
   両方残す。Medium / Hard は採用したあと、さらに残りの側も落とす(free だけ)を試す。
   Easy と Medium は採用の条件に T1〜T3 solvable も加える(`keepBasic`)。ティアの目標数に
   達したら止める。Hard は全部を試す。**1 パスで十分** — 手がかりが減れば解は増える一方。
5. **等級判定。**T1〜T3 の技法ソルバーを回し、解けなければ T1〜T4 を回す。ティアの条件(§7)に
   合えば出荷。
6. 合わなければ **seed を派生させて作り直す**(`<seed>#2`, `#3`, …)。上限 `ATTEMPT_LIMIT` = 60 回。
7. 上限に達したら、それまでに見つかった**ティアの技法で解ける一意解の候補のうち、最も多く
   削れたもの**を `fallback` 付きで出荷する。一意解であることも、そのティアの技法で解けることも
   変わらない — Hard だけは「T4 が要る」の保証を失い、Medium は削減率を、Easy は何も失わない。
   発生率は `guarantee.test.ts` が監視する。

不変条件:

- 同じ seed なら、必ず同じ盤面になる(`compatibility.test.ts` の golden で固定する)。
- 出題は一意解を持つ(手順 3 で構成として保証。削減の各段でも保つ)。
- 出題はそのティアの技法だけで解ける(手順 5)。Hard は Medium 集合では解けない。
- 手順 7 の発生は監視値である。

### 予算は仕事量で門にする

門は壁時計ではなく**仕事量**(`solverWork`)と**派生 seed の回数**で測る(Shape Regions §8 /
[SUDOKU_RULES.md](SUDOKU_RULES.md) §7)。生成は UI スレッドで同期に走らせる(Worker は
使わない)ので、端末の予算は 1 盤面 100ms 未満、開発機で Hard 1 面が 100ms より十分に
小さいことを設計条件にした。

実測(開発機、`guarantee.test.ts` が走査するのと同じ集合。難易度ごとに固定 token 40 seed +
デイリー 730 日。2026-09-29 計測。壁時計は 1 盤面あたりの ms で、出力するだけ):

| ティア   | n   | 仕事量 p50 | p90     | 最悪    | 派生 seed 最悪 | fallback | 壁時計 p50 | 壁時計 最悪 |
| -------- | --- | ---------- | ------- | ------- | -------------- | -------- | ---------- | ----------- |
| Easy     | 40  | 153        | 312     | 433     | 1              | 0        | 0.2 ms     | 2.9 ms      |

## 9. モードとデイリー

- **難易度モード**: Easy / Medium / Hard を選んで遊ぶ。seed は
  `box-regions-<difficulty>-<token>`(token = 起動時刻 + 乱数、Takuzu の `newSeedToken`)。
  同じ seed なら同じ盤面なので「同じ盤面で再挑戦」も中断からの復帰も正確に成立する。
  レベル 1〜100 は作らない。クリア画面の第一ボタンは同じ盤面での再挑戦、第二が「新しい盤面」。
- **デイリー**: 1 日 1 問。seed は `box-regions-daily-<YYYY-MM-DD>`(端末のローカル日付のみ)。
  **毎日 Medium 固定**(曜日で当たり外れを作らない — Sudoku §10)。
- **過去 30 日は無条件に開いている。**連鎖解錠は付けない。達成した日は記録する。
  **ストリークは数えない・表示しない。**
- 中断は難易度モード用・デイリー用の **2 スロットを独立して保持**する(§11)。
- 最後に選んだ難易度は `br.prefs` に残る(初期値 Easy)。

## 10. 統計

- **プレイ中に時計を表示しない。**経過時間は内部で記録し、結果画面と統計でのみ見せる。
- 難易度別に: プレイ回数 / クリア数 / 合計プレイ時間 / 最短時間。デイリー: 達成日ごとの
  最短時間(`dailyTimes`)と達成日数。Shape Regions §10 と同形。
- **スコアは作らない。**自己ベストの更新は、更新したときだけ静かに示す(`BestDelta`)。

## 11. 中断と再開

- 難易度モード用・デイリー用の **2 スロット**(`br.saveGame` / `br.saveDaily`、v1)。
- 保存するのは mode / seed / difficulty / dailyDate / width / height / clues(index /
  size|null / kind の列)/ solution(1 マス 1 文字: 領域を `a`〜 の英小文字)/ assignment
  (1 マス 1 文字: 領域の英小文字 or `.`)/ hintCount / elapsedSeconds / savedAt。
  **Undo 履歴は持たない**(§6)。ミス回数も持たない(概念がない — §5)。
- **どのスロットのレコードかを決めるのはキーである**(`gameSlotSchema(key, expectedMode)`、
  `src/test/savedGameSlots.test.ts` が強制)。
- **スロットを置き換える前に確認する**(中断中と違う難易度・違う日を選んだとき)。
- **検証は fail-closed。**プレイから生まれえないレコードは読み捨ててホームへ戻す:
  - サイズが難易度のプリセットと合わない、文字列の長さがマス数と合わない
  - clues が壊れている(重複・範囲外・数字が 1〜12 でない・未知の種類・26 個超)
  - solution が §3 の 4 規則を満たさない(長方形でない・手がかりを含まない / 他の手がかりを
    含む・数字や種類と食い違う・領域番号が範囲外・空の領域がある)
  - assignment の領域が長方形でない・自分の手がかりを含まない・他の手がかりマスを含む・
    未知の文字(描いていない手がかりは未割り当てでよい — §4)
  - mode が `daily` なのに日付が無い、または日付があるのに難易度が medium でない
- 背景へ回るとき、盤面の保存と未計上秒の計上を**同じ同期処理で**行う。
- 保存キーは `br.saveGame` / `br.saveDaily` / `br.stats` / `br.flags` / `br.prefs` の
  **5 つ**。`br.flags` はチュートリアル完了。`br.prefs` は**最後に選んだ難易度**だけを持つ。
- 保存の失敗でゲームを止めない。バリデータは例外を投げない。
- Web 先行公開中はスキーマを変えることがある(`WebBetaNotice` が伝える)。黙って変えない
  ために golden(`compatibility.test.ts`)は最初から敷く。

## 12. Quick Rules(アプリ内チュートリアル)

3 ステップ・各ステップ 1 文・図中心([I18N_POLICY.md](I18N_POLICY.md))。

1. 盤面を長方形の箱に切り分ける。どの箱にも手がかりが 1 つ。
2. 数字は箱のマス数、記号は形(正方形 / 縦長 / 横長 / 自由)。
3. 角から角へなぞって箱を描く。タップで箱を消す。詰まったら Hint。

Learn More は出ない(ガイド未公開 — `ui/landing.ts` の `PUBLISHED_GAME_IDS` に入れない)。

## 13. 演出とアクセシビリティ

- **領域は太線で読める。**地色は補助で、色覚によらず境界線だけで分割が分かる。違反表示も
  色だけに頼らず、警告色に枠を併用する。
- 記号は言語非依存のインライン SVG(`ShapeKindIcon`: square = 正方形の輪郭 / tall = 縦長の
  輪郭 / wide = 横長の輪郭 / free = 左上と右下の角括弧だけの「どんな四角でも」)。
  文字も絵文字も使わない。比較対象の記号のデザインは写さない(§14)。
- なぞっている間のプレビューは、置ける長方形ならアクセント色の輪郭、置けない(手がかり 0 個 /
  2 個以上)なら警告色の輪郭。離した瞬間に確定し、`pointercancel` で消える(§4)。
- 各マスはボタンで、**行・列・領域(`A`〜 の英大文字)または「未割り当て」・手がかりの内容
  (数字の `現在/目標`、形の種類名)・違反**を読み上げる。種類名は i18n。
- 1 マスは 320px 幅で 7×7 が収まる大きさ(`clamp(34px, …, 48px)`)。手がかりマスは記号と
  数字を上下に重ねる。
- **押下フィードバックは地色の切り替えで出す**(`filter` は使わない)。
- **盤面が解けた一拍**: `solved` prop が立つと、盤 1 枚の `::after` に `--accent-soft` を
  900ms だけ重ねて消す。**盤面が埋まってから結果カードが出るまでに約 1 秒置く**
  (`ui/useResultReveal.ts`)。Reduced Motion では即時。
- **7×7 の 320px でのドラッグ精度は、まだ実機で確認していない。**通らなければ Hard を
  6×6 に落として**この文書を先に直す**。

## 14. 意図的な差分

ブランド原則により合わせないもの:

- ミス回数制限・ライフ制・ゲームオーバー(しない。§3)
- プレイ中のタイマー表示、ストリーク、オンラインランキング、スコア(しない)
- Hint / Undo を広告視聴やコインの報酬にすること(しない。常に無料・無制限 — §6)
- 1 日 1 問だけの供給(しない。難易度を選べばいつでも新しい盤面 — §9)
- レベル 1〜100(段階が存在しないので作らない。§9)

設計判断として合わせないもの:

- **他社の名称・アセット・画面デザイン。**「Patches」は他社の商品名であり、名前も記号の
  デザインも配色も複製しない。
- **Shape Regions との共有**(しない)。別 ID・別フォルダ・別保存領域。Shape Regions の
  5 カテゴリのルールは変えない — あちらは別のパズルであり、issue #210 が求めたのは
  「Shape Regions を Patches の練習用と言い換えない」ことである。
- **13 マス以上の領域**(§1)。**8×8 以上**(§1)。
- **長押し・モード切替・自動補完**(§4)。なぞる / タップの 2 操作で全状態に届く。
- **Reset / Clear ボタン**(作らない。「同じ盤面で再挑戦」が同じ結果を与える)。
- **推測が必要な盤面・複数解の盤面**(出さない。§7、§8)
- **問題データの同梱・配信**(すべて端末上で生成する。§8)

### 比較対象との対応(2026-09-29 確認、issue #210)

公式 Help([LinkedIn Help — Patches](https://www.linkedin.com/help/linkedin/answer/a10314037)、
2026-09-29 閲覧)の記述: 「重ならずに盤面全体を埋める」「各 shape は手がかりマスを 1 つ含む」
「各マスはちょうど 1 つの shape に属する」「手がかりは数字(shape のサイズ)/ 記号(square、
tall rectangle、wide rectangle、または freeform)/ 両方 / どちらも無し」「なぞって shape を
描く」「タップで shape を消す」「Hint / Undo / Reset」。**Help 自身は shape が長方形に限る
とは書いていない**が、同日に第三者の解説 3 本(patchesgame.org / techwiser.com /
patchesgame.com)がいずれも「shape は長方形だけ」「freeform = どんな長方形でもよい
(正方形を含む)」「1×1 の正方形も可」と説明している。このゲームはその読みに従い、
**freeform を「形を言わない手がかり(free)」として実装する**(§2)。公式のチュートリアルや
問題データは参照していない。

| 公式の規則 / 機能                                              | Box Regions                                                    |
| -------------------------------------------------------------- | -------------------------------------------------------------- |
| 重ならず全マスを埋める・各 shape に手がかり 1 つ・各マスは 1 つの shape | 規則 1・2(§3)。同じ                                             |
| 手がかり: 数字 / 記号 / 両方 / どちらも無し                     | 数字 + 形 / 形だけ / 数字 + free / free だけ(§2)。同じ 4 形      |
| 記号: square / tall rectangle / wide rectangle / freeform      | square / tall / wide / free(§2、独自の SVG)                     |
| shape は長方形(第三者解説による)                                 | 長方形だけ(§1)。1×1 も可                                          |
| 領域の大きさの上限(記載なし)                                     | 1〜12(§1)                                                       |
| 盤面サイズ(記載なし)                                             | 5×5 / 6×6 / 7×7(§1)                                              |
| なぞって描く / タップで消す                                       | 角から角へなぞる / タップで消す(§4)。重なった箱は丸ごと消える     |
| Hint(マスか領域を示す)                                           | Hint(誤った箱 → 次の一手、§6)                                    |
| Undo / Reset                                                     | Undo は同じ。Reset は作らない(再挑戦)                            |
| 1 日 1 問                                                        | 難易度 3 種 + デイリー(§9)                                        |

合わせたもの: 長方形の分割、手がかり 1 つにつき箱 1 つ、4 種類の形の手がかりと「どちらも
無し」、一意解、なぞって描く操作、常時の違反表示、Undo + Hint。
公式の問題・解答・アセットは取得も転載もしない(すべて端末上で生成する — §8)。
