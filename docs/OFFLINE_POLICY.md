# Simple Games — オフラインポリシー

## 基本方針

**オフラインは正常系である。** 機内モードはエラーではない。
すべてのゲーム機能は、一度もオンライン接続していない端末の初回起動から利用できる。

適用範囲: この文書は**アプリ**の約束。Web 版は初回アクセスにダウンロードが必要で、
同一ではない([WEB_VERSION.md](WEB_VERSION.md))。ただし下の「オフライン時の広告
(ゼロリクエスト)」の原則は Web 版の広告にも同じく適用される
([ADS_POLICY.md](ADS_POLICY.md)「Web 版」)。

**Nearby Multiplayer**(issue #268、2026-10-25)の「オフライン」はインターネット不要を
意味する。本人が開始した近隣端末との対戦には Bluetooth、または端末間通信が可能な
同一 LAN が必要で、無線がすべて OFF の状態で対戦できる約束ではない。通常のソロ / CPU
戦はそのまま利用できる。Nearby Play として製品実装する(下)。

## 初回起動

以下を初回オンライン取得に依存させない。すべてアプリに同梱する。

- ゲームデータ / チュートリアル / 翻訳 / フォント(システムフォントのみ使用) /
  アイコン / 効果音(WebAudio で合成、外部アセット不要) / Daily Challenge /
  ゲームルール / 初期設定

## オフラインで利用可能であるべき機能(全機能)

初回起動、チュートリアル、Classic、Daily Challenge、New Game、Restart、Resume、
Undo、Hint、Add Numbers、ゲームクリア、ゲームオーバー、設定、統計、言語変更、
テーマ変更、効果音、振動、Reduced Motion、ローカルデータ削除、
バックアップの書き出しと復元。

結果画面の共有(issue #86)もここに入る。共有する文とリンクは**端末内で組み立てる**
ので、オフラインでも共有シートは開き、リンクのコピーもできる。実際に送れるかは
受け取り側のアプリの都合であって、こちらが判断することではない —— 「オフラインだから」
とボタンを隠したり無効にしたりはしない。

バックアップの書き出しと復元(issue #160)もここに入る。**どちらも通信を一切
使わない** —— ファイルは端末内で組み立てて OS の保存 / 共有導線へ渡し、取り込みは
端末内のファイルを 1 つ読むだけである。機内モードで最初から最後まで完了すること。
ユーザーが AirDrop やドライブを転送手段に選んだ後の通信は Simple Games の責任範囲
外で、アプリは転送先を認識しない(docs/architecture/backup.md)。

広告削除を購入済みの場合、その状態は端末内キャッシュ(`sg.iap`)で判定するため、
オフラインでも有効(購入・復元の操作自体はストア接続を要する)。**この entitlement
はバックアップに入らない** —— ファイルはコピーできるので、入れた時点で「コピー
できる買い切り」になる(docs/ADS_POLICY.md)。

Managed オーナーの 50 名特典も、確認済みの `sg.club.managedOwner` 内の資格を端末で
読む。契約期限内はオフラインでも広告を非表示にし、起動時・タイマー・接続回復で
契約を問い合わせない。新しい人数や失効はオーナー画面を開く・更新する操作で確認する。
通信失敗だけでは期限内のキャッシュを消さず、期限切れ・無効なキー・キーの削除や交換・
Reset では特典を外す。`sg.iap` の購入状態を変更せず、資格も通常のバックアップには含めない。

## オフライン時の広告(ゼロリクエスト)

- オフライン時は広告を表示せず、**広告リクエストを 1 件も送らない**。
- 取得失敗後のリトライループを作らない(電池を消費するだけで、
  オフラインでは成功しない)。オンライン復帰イベントを契機に再開する。
- バナー枠は静かな空きスペースのままにする。

## ネットワーク障害時の動作

- エラーダイアログを表示しない
- 広告取得をスキップする(バナー枠は静かな空きスペースのまま)
- ゲーム開始を遅延させない / ゲーム進行を変更しない
- オンライン時より機能を制限しない

## 実装ルール

- ネットワークを使う処理(バナー広告 / 広告同意)はすべて fire-and-forget とし、
  失敗を握りつぶす(ログのみ)。
- 広告・Club 等の外部サービスへのネットワーク処理の完了を UI 描画・通常のゲーム開始・
  画面遷移の条件にしない。Nearby の任意対戦は相手との接続と確認を必要とするが、
  その待ち時間でソロ / CPU 戦を制限しない。
- 「オフラインです」という表示を毎回出さない。
- Daily Challenge は端末のローカル日付を Seed に使い、サーバー時刻を使わない。
- 通常のゲームに定期ポーリング・バックグラウンド処理・常時接続を持たない。Nearby の
  本人が開始した集まりだけは、ゲームtopへ戻った間とアプリ切替中の接続維持、前面での
  同じ相手への再接続を許容する(PRODUCT_PRINCIPLES.md「低消費電力の原則」「Nearby Play」)。

## Nearby Play の近隣通信

開始する入口は native の対応ゲームtopの「誰かと遊ぶ」とし、近くの相手との
Bluetooth／同一 Wi-Fi 通信であることを短く補足する。1対1ターン制の13本とLudoに置き、
コレクションのClub House直下には、参加専用の「近くの対戦相手を探す」を控えめなテキスト行で置く。
接続方法を選び明示的に探索すると、
全対応ゲームの募集名・ゲーム名・人数を一覧表示する。選んだゲームの参加確認へ直接進む。
Club Houseからの開始導線、未対応ゲームのボタンは持たない。
ゲームを選んだ状態で募集／参加し、host承認と双方Readyを経て共通のゲーム画面へ進む。
初回に同じゲームをもう一度提案する操作は不要。募集時にhostがチャットの有無を選ぶ（初期値OFF）。
設定は双方に適用し、終了まで固定する。OFFでは会話ボタンとメッセージ送受信を無効にする。
ONの会話はボタンから任意に開き、受信で自動表示しない。
「仲間と／近くの人を募集」の2択は設けず、すべての参加にhost承認を求める。既存13本の定員は2人。
募集名はゲーム名＋短い番号から編集でき、個人の表示名とは別に扱う。

2026-10-26の追加対象Ludoは4席固定で、人間とCPUの合計を4にする。人間端末はhostを含め最大4台。
CPUはhost端末内で進め、インターネット・対戦サーバー・アカウントを必要としない。
hostは対局中にも参加者の席をCPUへ変更でき、盤面・手番・出目をそのまま引き継ぐ。
接続中の参加者への操作返却、再参加へのhost承認も可能とする。hostの退出・切断では全員の対局を
終了し、hostを自動移譲しない。参加者だけの切断では盤面を保持し、hostがCPUへ変更すれば続行できる。
Ludoにはチャットを設けず、対局履歴はNearby専用の端末内保存へ追加する。ソロ保存やバックアップへ
混ぜない。Ludoの再参加はhostによる再承認を要し、自動再接続の保証はしない。
4台のBluetooth／LAN・混在OSでの実機確認は未実施。本節の双方Ready・任意チャット・同じ相手への
自動再接続は既存13本の2人対戦についての契約であり、Ludoにそのまま適用しない。

本人が開始した募集の募集名・ゲーム名を近隣探索者に公開することと、探索・参加申請・host承認と、その集まりでの短いテキスト・ゲームの
操作／状態／結果を相手へ渡す通信を許容する。Bluetooth または同一 Wi-Fi が必要だが、
インターネットやアカウントは不要。無線は利用時だけ開始し、探索画面の退出・探索停止、または参加後の退出・解散で止める。
個人の表示名は探索情報に含めず、接続後の相手に渡す。募集名と個人の表示名は本人認証ではない。
接続を画面から分離し、ゲームtopへ戻るだけでは終了しない。同じ入口から進行中の対戦へ戻れる。
終局後は結果と再戦を主にし、接続を保持したまま双方Readyで次の局を始める。
探索60秒、接続／鍵交換15秒、承認待ち60秒。承認後の操作／メッセージ受信確認15秒の
期限超過や物理切断では、盤面・未確認操作を保持して再接続待ちにする。前面では同じ相手へ
再接続を試み、元の集まりの鍵による確認後に続行する。背景では新しい再接続試行を開始しない。
無操作中の即時切断検知・背景での無制限実行は保証しない。自動transport切替・周期heartbeatは無い。
継続状態と鍵はメモリ内に限り、プロセス終了後の復元は未対応。

送受信したチャットと参加した対局の履歴（募集名と参加者の表示名を含む）は専用の端末内ファイルに保存する。退出では消さず、
履歴を見るだけなら無線も権限も不要。通常のアプリバックアップと OS バックアップから除外する。
保存失敗は表示し、同じ端末の履歴削除とローカルデータ削除で消せる。相手のコピーは消せない。
次回入力用の自分の表示名も同じ専用データに保存する。別端末へ設定を同期しない。
履歴1件の削除ではこの表示名を残し、Nearby全削除・設定のローカルデータ削除では消す。
既存のゲーム記録・Club への送信は増やさない。Web へ Nearby の実行コード・権限要求・
接続開始の導線を加えない。Web コレクションの無効な「近くの対戦相手を探す」と、対応14本のトップに表示する無効な「誰かと遊ぶ」ボタンと
「アプリ専用の機能です」は通信を伴わない案内で、オフラインでも表示する。
ネットワーク状態で有効化せず、探索・接続・Nearby履歴読取を行わない。

通報時は本人が選択した内容と理由を確認・同意した後、メール下書きかコピーを用意する。
アプリ自身は外部へ送信せず、メールの実送信は本人が別のメールアプリで行う。
通報メールの送信にはメールサービスへの通信が必要で、対戦のオフライン動作とは分ける。
受信相手のアプリ識別子を新しい履歴に保存し、退出後も端末内でブロックできる。

技術と検証の境界は [architecture/nearby-multiplayer.md](architecture/nearby-multiplayer.md)。
今回のゲームtopからの導線・画面から独立した接続保持は採用方針であり、実機確認は別に行う。
PoCや1.5.1での実機成功を、この修正版の実機成功へ読み替えない。

## ネットワーク権限の用途(これ以外に使わない)

バナー広告の取得 / 広告同意(UMP) / 広告削除購入とその復元(ストア処理) /
設定・About からの外部リンク(GitHub、**プライバシーポリシー、利用規約**)と
フッターの PixApps(pixapps.ai のトップ。2026-10-02)。開けなくてもアプリは正常動作

**Club House を本人が操作したときに限り**、選んだデプロイ(PixApps の Public、
誰かが建てた Self-hosted、または Managed)との通信が加わる(2026-09-09 の issue #176、2026-09-30 の
`simple-games-club#1`。実装は 2026-10-02、[architecture/club.md](architecture/club.md))。
Club を操作しない未参加の端末ではこの用途は存在せず、リクエストは 0 件(未参加の端末での 0 件は
[RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) 5.16 でエミュレータ実測、実機は未)—
**Public があっても既定の接続はしない**(Public の住所は本人が参加を押すまで使われない。
同じ住所は Managed の origin として `ui/clubFeatures.ts` にもあり、起動時の広告判定が
端末内に保存した特典の origin と照らすためだけに読む — 通信には使わない)。2026-10-23 に加えた Managed では、公開一覧や
オーナー画面の読み込み・更新、無料 Trial の開始も本人の操作に含む。広告特典のために
Core の起動やゲームから契約を問い合わせることはない。加わるときも、この
一覧の他の項目とオフラインの約束は変えない — ポーリング・バックグラウンド同期・
常時接続を持たず、サーバの障害でゲームを止めない。境界は
[PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md)「Club House」。

参加している間は、**遊び終えた結果が、結果画面が現れた直後に自動で送られる**(2026-10-02。
参加の画面で先に言う。送るのは対応するゲームの結果画面が表示した事実だけで、参加する前に遊んだ局は
送らない)。送信は fire-and-forget で、結果画面の描画もゲームの進行も待たない。**オフラインや失敗で届か
なかった結果は端末のキュー(`sg.clubOutbox`)に残り、本人の行為の直後にだけ送り直す** — 次の結果を送る
ときと、Club の画面を開いたとき(その画面で再読み込みを押したときも)。**アプリの起動時・タイマー・接続の回復では送らない**(リトライループも
無い)。結果画面の状態 1 行(送った / 開いたときに送る)は参加済みの端末だけで、「オフラインです」を
毎回出す表示は作らない。

**Android の獲得計測(Meta)を有効化したビルドに限り**、同意が要る地域(EU 加盟国・
EEA 残り・英国・スイスなど)の外にある新規インストールでは、インストールを 1 回だけ
Meta に知らせる通信が加わる(2026-09-27 決定・2026-09-29 に同意 UI を廃止して自動
送信へ変更、issue #204 —
[META_ANDROID_ACQUISITION.md](META_ANDROID_ACQUISITION.md))。質問も設定のスイッチも
無い。オフラインでは SDK を初期化せず、オンライン復帰の OS イベントを 1 回待つだけで
リトライループを作らない。起動・ゲーム開始・購入/復元はこの通信を待たず、通信の失敗
でゲームは止まらない。報告が受理された後は二度と通信しない。同意が要る地域の端末・
地域が分からない端末・既存のインストールからの更新(`firstInstallTime` が 7 日より前)、
そして Meta を含まないビルド(既定)では、この用途は存在せずリクエストは 0 件。受理された
後と、3 回試して受理されなかった後も 0 件。

**結果画面の共有はここに入らない。** 共有はアプリからの通信ではなく OS への受け渡しで
あり、`services/share/` は fetch も送信も行わない(`.github/scripts/check-principles.sh`
§1 が製品 Core のソースにネットワーク API が無いことを見る — 例外は `src/club/` の
1 ディレクトリだけで、そこへの到達経路は `src/test/importBoundaries.test.ts` が縛る)。

**プライバシーポリシーと利用規約はオフラインでは読めない**(2026-08-02)。
文面をアプリに同梱するのをやめ、公開ページへのリンクにしたため。上の
「オフラインで利用可能であるべき機能」一覧にはもともと入っていないので約束違反では
ないが、後退であることは事実として記録しておく(理由と代償は
`docs/PRIVACY_POLICY.md`)。オフラインでも読めるのは、プレイヤーに直接影響する
2 点だけ — 削除すると何が消えるか、バナー 1 枠と任意の買い切りがあること。

Analytics・Remote Config は存在しない。製品からネットワークに送信されるゲームデータもない。
製品の例外は 2 つ。上の Android の獲得計測(Meta)は、送るのはインストールの報告 1 件であり、
ゲームのデータは含まない。もう 1 つは、**本人が参加した Club House への結果の送信**で、
参加している間は遊び終えた結果(時間・手数・スコアなど、結果画面が表示した事実だけ)が送られる。
これは本人が参加を選び、参加の前に開示された用途である(上)。(Web 版のページ解析は本文書の範囲外 —
[WEB_VERSION.md](WEB_VERSION.md)「計測」、その運用は
[GROWTH_MEASUREMENT.md](GROWTH_MEASUREMENT.md)。ゲームデータを送らない点は
版をまたいで同じ。)

Nearby Play の製品実装では、本人が始めた募集の募集名・ゲーム名を近隣探索端末へ公開し、
接続後の相手へ個人の表示名・チャット・ゲーム進行を送信する。nativeのBLE/LAN権限が加わる。
インターネットへは送らない。
