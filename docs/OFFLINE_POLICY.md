# Simple Games — オフラインポリシー

2026-11-14: 招待リンクでインターネット越しに遊ぶ遠隔対戦を、Nearby の対象ゲームの任意モードとして採った(issue #280)。方針の採用であり、実装も出荷もしていない。遠隔対戦はインターネットを要し、下の「遠隔対戦の通信(インターネット)」に従う。近隣対戦はインターネット不要のまま、ソロ／CPU 戦は初回から通信不要のまま。境界は [PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md)「遠隔対戦」を正とする。

2026-11-05: Nearbyは28本(2席18本・4席10本)に拡張。Bluetooth／同一LANの任意機能という条件は共通で、ソロ／CPU戦は初回から通信不要。対象は [近隣対戦の契約](architecture/nearby-multiplayer.md) を正とする。

## 基本方針

**オフラインは正常系である。** 機内モードはエラーではない。
すべてのゲーム機能は、一度もオンライン接続していない端末の初回起動から利用できる。
遠隔対戦(未実装、下)はインターネットを要する任意の接続機能で、どのゲームもそれが無くても
遊べる(ソロ / CPU 戦・近隣対戦はオフラインのまま)。

適用範囲: この文書は**アプリ**の約束。Web 版は初回アクセスにダウンロードが必要で、
同一ではない([WEB_VERSION.md](WEB_VERSION.md))。ただし下の「オフライン時の広告
(ゼロリクエスト)」の原則は Web 版の広告にも同じく適用される
([ADS_POLICY.md](ADS_POLICY.md)「Web 版」)。

**Nearby Multiplayer**(issue #268、2026-10-25)の「オフライン」はインターネット不要を
意味する。本人が開始した近隣端末との対戦には Bluetooth、または端末間通信が可能な
同一 LAN が必要で、無線がすべて OFF の状態で対戦できる約束ではない。通常のソロ / CPU
戦はそのまま利用できる。Nearby Play として製品実装する(下)。
同じ対象ゲームを招待リンクでインターネット越しに遊ぶ遠隔対戦(issue #280、未実装)は、
この意味でもオフラインではない(下の「遠隔対戦の通信(インターネット)」)。

## 初回起動

以下を初回オンライン取得に依存させない。すべてアプリに同梱する。

- ゲームデータ / チュートリアル / 翻訳 / フォント(システムフォントのみ使用) /
  アイコン / 効果音(WebAudio で合成、外部アセット不要) / Daily Challenge /
  ゲームルール / 初期設定

## オフラインで利用可能であるべき機能(全機能)

初回起動、チュートリアル、Classic、Daily Challenge、New Game、Restart、Resume、
Undo、Hint、Add Numbers、ゲームクリア、ゲームオーバー、設定、統計、言語変更、
テーマ変更、効果音、振動、Reduced Motion、ローカルデータ削除、
バックアップの書き出しと復元。

結果画面の共有(issue #86)もここに入る。共有する文とリンクは**端末内で組み立てる**
ので、オフラインでも共有シートは開き、リンクのコピーもできる。実際に送れるかは
受け取り側のアプリの都合であって、こちらが判断することではない —— 「オフラインだから」
とボタンを隠したり無効にしたりはしない。

バックアップの書き出しと復元(issue #160)もここに入る。**どちらも通信を一切
使わない** —— ファイルは端末内で組み立てて OS の保存 / 共有導線へ渡し、取り込みは
端末内のファイルを 1 つ読むだけである。機内モードで最初から最後まで完了すること。
ユーザーが AirDrop やドライブを転送手段に選んだ後の通信は Simple Games の責任範囲
外で、アプリは転送先を認識しない(docs/architecture/backup.md)。

広告削除を購入済みの場合、その状態は端末内キャッシュ(`sg.iap`)で判定するため、
オフラインでも有効(購入・復元の操作自体はストア接続を要する)。**この entitlement
はバックアップに入らない** —— ファイルはコピーできるので、入れた時点で「コピー
できる買い切り」になる(docs/ADS_POLICY.md)。

Managed オーナーの 50 名特典も、確認済みの `sg.club.managedOwner` 内の資格を端末で
読む。契約期限内はオフラインでも広告を非表示にし、起動時・タイマー・接続回復で
契約を問い合わせない。新しい人数や失効はオーナー画面を開く・更新する操作で確認する。
通信失敗だけでは期限内のキャッシュを消さず、期限切れ・無効なキー・キーの削除や交換・
Reset では特典を外す。`sg.iap` の購入状態を変更せず、資格も通常のバックアップには含めない。

## オフライン時の広告(ゼロリクエスト)

- オフライン時は広告を表示せず、**広告リクエストを 1 件も送らない**。
- 取得失敗後のリトライループを作らない(電池を消費するだけで、
  オフラインでは成功しない)。オンライン復帰イベントを契機に再開する。
- バナー枠は静かな空きスペースのままにする。

## ネットワーク障害時の動作

- エラーダイアログを表示しない
- 広告取得をスキップする(バナー枠は静かな空きスペースのまま)
- ゲーム開始を遅延させない / ゲーム進行を変更しない
- オンライン時より機能を制限しない
- 遠隔対戦(未実装)はインターネットが無いとつながらない。それは遠隔の画面の中でだけ伝え、
  ほかの機能を制限しない(下の「遠隔対戦の通信(インターネット)」)

## 実装ルール

- ネットワークを使う処理(バナー広告 / 広告同意)はすべて fire-and-forget とし、
  失敗を握りつぶす(ログのみ)。
- 広告・Club 等の外部サービスへのネットワーク処理の完了を UI 描画・通常のゲーム開始・
  画面遷移の条件にしない。Nearby の任意対戦(近隣・遠隔)は相手との接続と確認を必要とするが、
  その待ち時間でソロ / CPU 戦を制限しない。
- 「オフラインです」という表示を毎回出さない。
- Daily Challenge は端末のローカル日付を Seed に使い、サーバー時刻を使わない。
- 通常のゲームに定期ポーリング・バックグラウンド処理・常時接続を持たない。Nearby の
  本人が開始した集まりだけは、ゲームtopへ戻った間とアプリ切替中の接続維持、前面での
  同じ相手への再接続を許容する(PRODUCT_PRINCIPLES.md「低消費電力の原則」「Nearby Play」)。
  遠隔対戦(未実装)も本人が開始した集まりに限るが、背景での接続維持は持たない。接続中は
  WebRTC の下層が数秒ごとに疎通の確認を送るが、アプリ層の周期的な生存確認は足さない
  (下の「遠隔対戦の通信(インターネット)」)。

## Nearby Play の近隣通信

この節は近隣(Bluetooth／同一 Wi-Fi)の通信である。招待リンクでインターネット越しに遊ぶ遠隔対戦は、
承認・発見・再接続・背景の扱いがこの節と異なり、次の「遠隔対戦の通信(インターネット)」に従う。

開始する入口は native の対応ゲームtopの「誰かと遊ぶ」とし、近くの相手との
Bluetooth／同一 Wi-Fi 通信であることを短く補足する。1対1ターン制の13本とLudoに置き、
コレクションのClub House直下には、参加専用の「近くの対戦相手を探す」を控えめなテキスト行で置く。
接続方法を選び明示的に探索すると、
全対応ゲームの募集名・ゲーム名・人数を一覧表示する。選んだゲームの参加確認へ直接進む。
Club Houseからの開始導線、未対応ゲームのボタンは持たない。
ゲームを選んだ状態で募集／参加し、host承認と双方Readyを経て共通のゲーム画面へ進む。
初回に同じゲームをもう一度提案する操作は不要。募集時にhostがチャットの有無を選ぶ（初期値OFF）。
設定は双方に適用し、終了まで固定する。OFFでは会話ボタンとメッセージ送受信を無効にする。
ONの会話はボタンから任意に開き、受信で自動表示しない。
「仲間と／近くの人を募集」の2択は設けず、近隣の参加はすべてhost承認を求める(遠隔対戦の招待は例外 — 次節)。既存13本の定員は2人。
募集名はゲーム名＋短い番号から編集でき、個人の表示名とは別に扱う。

2026-10-26の追加対象Ludoは4席固定で、人間とCPUの合計を4にする。人間端末はhostを含め最大4台。
CPUはhost端末内で進め、インターネット・対戦サーバー・アカウントを必要としない。
hostは対局中にも参加者の席をCPUへ変更でき、盤面・手番・出目をそのまま引き継ぐ。
接続中の本人への操作返却も可能とする。hostを自動移譲しない。
Ludoにはチャットを設けず、対局履歴はNearby専用の端末内保存へ追加する。ソロ保存やバックアップへ
混ぜない。
3席以上の集まり（現在はLudoだけ）の離席・退出・復帰・参加の受付・探索への出し方は
[architecture/nearby-multiplayer.md](architecture/nearby-multiplayer.md)「2026-10-27: 3席以上の集まりの共通契約」に従う。
要点は、通信が切れても席を本人のものとして残して全員が待つこと、明示的な退出は即座にCPUへ替わること、
参加は対局と対局の間だけで対局中の部屋は探索一覧に出さないこと。
4台のBluetooth／LAN・混在OSでの実機確認は未実施。本節の双方Ready・任意チャットは
既存13本の2人対戦についての契約であり、Ludoにそのまま適用しない。

本人が開始した募集の募集名・ゲーム名を近隣探索者に公開することと、探索・参加申請・host承認と、その集まりでの短いテキスト・ゲームの
操作／状態／結果を相手へ渡す通信を許容する。Bluetooth または同一 Wi-Fi が必要だが、
インターネットやアカウントは不要。無線は利用時だけ開始し、探索画面の退出・探索停止、または参加後の退出・解散で止める。
個人の表示名は探索情報に含めず、接続後の相手に渡す。募集名と個人の表示名は本人認証ではない。
接続を画面から分離し、ゲームtopへ戻るだけでは終了しない。同じ入口から進行中の対戦へ戻れる。
終局後は結果と再戦を主にし、接続を保持したまま双方Readyで次の局を始める。
探索60秒、接続／鍵交換15秒、承認待ち60秒。承認後の操作／メッセージ受信確認15秒の
期限超過や物理切断では、盤面・未確認操作を保持して再接続待ちにする。前面では同じ相手へ
再接続を試み、元の集まりの鍵による確認後に続行する。背景では新しい再接続試行を開始しない。
無操作中の即時切断検知・背景での無制限実行は保証しない。自動transport切替・周期heartbeatは無い
(近隣と遠隔のあいだも自動で切り替えない。遠隔対戦の周期heartbeatはアプリ層に無く、WebRTC の下層が疎通の確認を送る — 次節)。
継続状態と鍵はメモリ内に限り、プロセス終了後の復元は未対応。
3席以上の集まりでも同じ条件で、承認後のstate受信確認15秒の超過や物理切断ではその席を離席中として
本人のために保持し、全員が待つ。ゲストは前面で同じhostのlabelを見つけ直し、最初に承認されたリンクの
継続鍵による確認後にhostの承認なしで同じ席へ戻る。hostの無線が落ちたときは、hostが前面で同じlabelのまま
無線を起動し直す。リンクが切れている間に押した退出は相手に届かない。

送受信したチャットと参加した対局の履歴（募集名と参加者の表示名を含む）は専用の端末内ファイルに保存する。退出では消さず、
履歴を見るだけなら無線も権限も不要。通常のアプリバックアップと OS バックアップから除外する。
保存失敗は表示し、同じ端末の履歴削除とローカルデータ削除で消せる。相手のコピーは消せない。
次回入力用の自分の表示名も同じ専用データに保存する。別端末へ設定を同期しない。
履歴1件の削除ではこの表示名を残し、Nearby全削除・設定のローカルデータ削除では消す。
既存のゲーム記録・Club への送信は増やさない。Web へ Nearby の実行コード・権限要求・
接続開始の導線を加えない。Web コレクションの無効な「近くの対戦相手を探す」と、対応14本のトップに表示する無効な「誰かと遊ぶ」ボタンと
「アプリ専用の機能です」は通信を伴わない案内で、オフラインでも表示する。
ネットワーク状態で有効化せず、探索・接続・Nearby履歴読取を行わない。

通報時は本人が選択した内容と理由を確認・同意した後、メール下書きかコピーを用意する。
アプリ自身は外部へ送信せず、メールの実送信は本人が別のメールアプリで行う。
通報メールの送信にはメールサービスへの通信が必要で、対戦のオフライン動作とは分ける。
受信相手のアプリ識別子を新しい履歴に保存し、退出後も端末内でブロックできる。

技術と検証の境界は [architecture/nearby-multiplayer.md](architecture/nearby-multiplayer.md)。
今回のゲームtopからの導線・画面から独立した接続保持は採用方針であり、実機確認は別に行う。
PoCや1.5.1での実機成功を、この修正版の実機成功へ読み替えない。

## 遠隔対戦の通信(インターネット)

2026-11-14 のオーナー判断(issue #280)で採った方針であり、**実装・実機検証・出荷はしていない**。
製品の境界は [PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md)「遠隔対戦」、技術の契約は
[architecture/nearby-multiplayer.md](architecture/nearby-multiplayer.md) 冒頭の 2026-11-14 節が定める。
この節にはオフラインと通信の約束だけを書く。

Nearby Play の対象ゲームを、招待リンクでインターネット越しに遊ぶ任意モードである。近隣対戦と違い、
**インターネットが要る**。ソロ / CPU 戦と近隣対戦は、これが無くても従来どおりオフラインで遊べる。

- **招待制だけ**。本人が招待のリンクを OS の共有シートかコピーで渡し、相手が返事のリンクを返すと、
  端末どうしが直接つながる。公開ロビー・ランダムマッチ・探索一覧は無く、アプリは送り先を知らない。
  招待を持つ人は host の承認なしに着席する(近隣の「すべての参加に host 承認」の例外)。招待は
  1 席に 1 つで、1 回だけ使え、期限がある。転送された招待は先に開いた人が座る。
- **経路**。対局のデータは端末どうしの WebRTC DataChannel だけで運び、その上に近隣と同じ
  アプリ層の暗号を重ねる。PixApps は対戦サーバー・シグナリングサーバー・アカウントを持たない
  (シグナリングサーバーは #280 の Phase 2 で比べる。PRODUCT_PRINCIPLES.md「遠隔対戦」13)。
  中継サーバー(TURN)は使わない。つながらないネットワークの組み合わせがある前提で、失敗したら
  案内する(近くにいるなら近隣対戦を勧める)。
- **STUN は Cloudflare の 1 社だけ**(`stun.cloudflare.com`)。自分の公開アドレスを知るためにだけ
  問い合わせ、ゲームの中身は送らない。予備の事業者を足さない。
- **IP アドレスは相手と STUN 事業者に伝わる**。招待と返事には接続に使う IP アドレスが入り、
  受け取った相手(転送された人を含む)と STUN 事業者がそれを知る。IP からおおよその地域が
  推定されうる。招待を作る前と、招待を開いて参加する前に、これを説明して同意を得る。
  端末の LAN 内アドレスは招待・返事に載せない(同じ LAN の相手とは近隣対戦を使う)。
- **招待の中身をサーバーに送らない**。`pixapps.ai` のリンクで渡す場合も、中身は URL の
  フラグメント(`#` 以降)に置き、受けるページはそれを読まず、送らず、計測しない。PixApps は
  招待・返事の中身(そこに入った IP を含む)を受け取らず、保存しない。アプリの入っていない端末などで
  リンクを開いたときのページ取得の扱い(そのページの計測を含む)は、出荷前に決める
  (PRODUCT_PRINCIPLES.md「遠隔対戦」10・15)。招待・返事・接続の情報は、履歴・バックアップ・ログに残さない。
- **前面だけ**。背景に移ると OS がアプリを止めるので、遠隔の接続は切れる前提にする。近隣の
  「アプリ切替でも切らない」は当てはまらない。遠隔のための接続維持の通知・背景処理・背景モードを足さない。
- **生存確認**。アプリ層の周期的な生存確認は足さない。接続中は WebRTC の下層が ICE の consent
  (RFC 7675、約 5 秒ごと)と SCTP の heartbeat を送る(資料の値で、実機では測っていない)。
- **リトライループを作らない**。切れたら近隣と同じく席と盤面を保持して待つ(離席)。アプリは自動で
  相手を探し直さず、失敗した接続を自動で試し直すループも作らない。戻るのは host が出す再接続の
  リンクに返事を返す 1 往復で、最初の着席で得た継続鍵の確認が通れば承認なしで同じ席へ戻る。
- **オフラインのとき**、遠隔の接続は成立しない。つながらないことは遠隔の入口の中で伝えるだけにし、
  ほかの画面にエラーダイアログや「オフラインです」を出さず、ソロ / CPU 戦・近隣対戦を制限しない。
  オフラインの間の遠隔の入口の見せ方(押せなくするか、押した後に案内するか)は出荷前に決める。
- **時間の窓**。近隣の「探索 60 秒・承認待ち 60 秒」は遠隔には無い(探索も host の承認も無い)。招待の期限と、
  候補の収集を打ち切る秒数は、#280 の Phase 1 で測ってから決める。
- **Android / iOS アプリだけ**。Web 版には近隣と同じく、通信を伴わない無効なボタンとアプリ専用の
  説明だけを置く。Android は既存の INTERNET 権限だけで足りる見込みで、遠隔のために権限も
  iOS の Info.plist も足さない(実機では未確認)。

**機械で示すこと**: WebRTC の語(`RTCPeerConnection` ほか)を製品の TypeScript ソースに書けるのは
`apps/simple-games/src/nearby/remote/` だけで、STUN / TURN の URL は `stun:stun.cloudflare.com:3478` の 1 つ以外を
書かず、WebRTC の npm パッケージと native のライブラリを依存に足さない(`.github/scripts/check-principles.sh` §1c)。remote/ にも fetch / WebSocket は書けない(§1・§1b は変えない)。

## ネットワーク権限の用途(これ以外に使わない)

バナー広告の取得 / 広告同意(UMP) / 広告削除購入とその復元(ストア処理) /
設定・About からの外部リンク(GitHub、**プライバシーポリシー、利用規約**)と

コレクションホーム末尾の「PixApps のほかのアプリ」の PixMeal・PixWork(端末のストアの掲載ページ。

**本人が遠隔対戦を始めたときに限り**(2026-11-14 に採った方針で未実装、issue #280)、STUN の
