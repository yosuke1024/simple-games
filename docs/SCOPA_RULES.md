# Scopa — 正式ゲームルール

この文書が Scopa の仕様の正本になる。**いまはスタブである。**本文 — 場と対局者・一手の解決・終了条件と採点・
CPU・CPU が見ているもの・Undo(作らない)・助けの形・スコアと統計・中断と再開・Quick Rules・演出と
アクセシビリティ・多言語・意図的な差分・比較対象との対応・選定の記録と検証の範囲 — は Phase 2 で
**コードより先に**ここへ書き、以後は実装(`apps/simple-games/src/games/scopa/`)・テスト・Quick Rules が
この文書に従う(コードはここへ `§n` で言及し、挙動を変えるときは同じコミットでこの文書を直す)。それまでは、
計画 [plans/2026-10-20-overtake-make-the-target-nested-tic-tac-toe-scopa-tangram.md](plans/2026-10-20-overtake-make-the-target-nested-tic-tac-toe-scopa-tangram.md)
の「55. Scopa」が着手時点の合意である。本文が書かれたら、この文書が計画に勝つ。このゲームに実機の Phase 0 は
無い(Phase 0 があるのは Overtake と Tangram)。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

ゲーム ID は `scopa`、i18n キーの接頭辞は `scopa`(名称キーは `scopaName`)、保存キーの接頭辞は `sc.`、
カテゴリは `cards`、No. 55。名称は一般名の「Scopa」で、全言語で訳さない([I18N_POLICY.md](I18N_POLICY.md)
「誤訳が「約束の反故」になる文言」の 6「ゲーム名」— 定訳がないため全言語で英語のまま。Hearts / Gin Rummy と
同じ扱い)。**Web 先行公開(ベータ)のタイトル**(registry では遊べるようになるまで `channel: 'in-development'` — どのビルドにも出ない — その後 `'web-beta'`。
[WEB_VERSION.md](WEB_VERSION.md)「先行公開(ベータ)」)で、アプリには正式収録していない。ストア掲載文にも
landing のガイドにも出さない。Club House には登録しない(registry の `challenge` を持たず、この文書に
Club House の節は無い)。保存スキーマは正式収録まで凍結しない。

姉妹タイトルの Hearts / Gin Rummy は同じ「対戦カード」で、不完全情報・探索しない CPU・CpuView・Undo なし・
マッチ全体の途中保存をここも引き継ぐ([HEARTS_RULES.md](HEARTS_RULES.md) §4〜§9、
[GIN_RUMMY_RULES.md](GIN_RUMMY_RULES.md) §4〜§9)。強さが 1 段階である点は Dominoes
([DOMINOES_RULES.md](DOMINOES_RULES.md) §5)の形を採る。同じ棚の設計が揃っていないのは意図である
([FREECELL_RULES.md](FREECELL_RULES.md) §8)。

## これまでに決まったこと

製品オーナーの判断(2026-10-20、5 本の採用)と計画で決めたこと。理由と未決の点は計画の「55. Scopa」にある。
ここには決まったことだけを書き、決まっていないことは「未決 — 計画」と書く。

- 対局相手は CPU だけで、**強さは 1 段階**。難易度・デイリー・時計・レーティング・対人戦は無い。
  Hearts / Gin Rummy の 3 段階からの意図的な差で、前例は Dominoes §5。
- **40 枚**(4 スート × A・2〜7・J・Q・K。J = 8、Q = 9、K = 10)。スートはフランス式で描き、♦ がコイン、
  7♦ がセッテベッロ。札は 1 つの整数で持ち、表は Hearts / Gin Rummy から**コピーする**(共有しない)。
- **各 3 枚の手札、場に 4 枚。**両者の手札が尽きるたびに 3 枚ずつ配り直し、1 ディールは 6 ラウンドで
  40 枚が尽きる。配札はシード決定的。最初の配り手はシードで決め、以後はディールごとに交代。配り手でない
  側が先に出す。先手を選ぶ画面は無い。
- **取り**: 出した札と同じ数字が場にあれば必ずそれを 1 枚取る(**同じ数字が和に優先**)。無ければ足して
  その数になる場の札の組を取る。取り方が複数あるときは**場札を直接タップして選ぶ**。取れないときは場に置く。
- **スコパ** = 取りで場を空にして 1 点。ディールの最後に残った場札は最後に取った側が得るが、スコパではない。
  最後の一手(40 枚目)のスコパを数えるかは未決 — 計画。
- **採点はディールの終わりごと**: 札の多さ・♦ の多さ・7♦・プリミエラ(スート別の最高札の値の合計。
  7 = 21、6 = 18、A = 16、5 = 15、4 = 14、3 = 13、2 = 12、J・Q・K = 10)が各 1 点、スコパは回数ぶん。
  同数の区分は誰の点にもならない。スートが欠けたときのプリミエラは未決 — 計画。
- **11 点先取で 1 局**(マッチ)。11 点以上の側があれば終局で、両者 11 点以上なら高いほう、同点なら次の
  ディールへ。引き分けは存在しない。判定をディールの終わりに限る(推奨)か、途中で達した瞬間に終えるかは
  未決 — 計画。
- **助けは「規則が許す札」と「規則の算術」だけ**: 取れる手札と、持ち上げた札で取れる場札を常時示す。
  **プリミエラのスート別の最良札 4 枚を常時表示する。** Undo / Hint は作らない(Hearts §6 / Gin Rummy §6 と
  同じ線 — 隠れた手札がある)。広告視聴や課金による助けも作らない。
- **CPU は探索しない**(ヒューリスティック 1 段階。取りの価値と、場に残す札の危険度の重み付き和)。
  **CpuView 型で、相手の手札と山の並びを CPU に見せない**(Hearts §5 / Gin Rummy §5 / Dominoes §6)。
  同点はシード決定的。拍は `CPU_DELAY_MS`(450ms)の 1 本のタイマーで、ディールの清算画面はタップを待つ。
  公開の履歴を CPU が推理に使うかは未決 — 計画(推奨は v1 では使わない)。画面にも公開文面にも
  「強い」「AI」と書かない。
- **操作はタップだけ**(二度タップ確定。ドラッグは作らない — Hearts §12 / Gin Rummy §12)。確定の細部は
  未決 — 計画。
- **途中保存する。**`sc.saveGame`(1 スロット。マッチ全体 — シード・ディール番号・配り手・両者の点・手数・
  経過秒・符号化したディール)/ `sc.stats` / `sc.flags` / `sc.prefs`(計画の決定事項の表。`sc.prefs` に
  入れるものが今は無く、作るかは未決 — 計画)。デイリーが無いので 2 スロット規則はかからない。いまの
  `storage/keys.ts` はスキャフォールドの `stats` / `flags` だけで、残りはこの文書の保存の節と同じコミットで足す。
  保存は fail-closed(40 枚の保存則・規則から生まれえない局面・終局済みは読み捨ててホームへ戻る。勝手に
  新しい対局を始めない)。符号化の粒度(公開履歴の再生か、局面の検証か)は未決 — 計画(推奨は再生)。
- 統計は全体で 1 組: `played`(開始で数える)/ `wins` / `losses` / `totalPlaySeconds`。`draws` の列は無い。
  ディールの勝ちは記録しない。放棄は負けに数えない。ベスト記録・平均点は持たない。ストリークは数えない。
  **時計は出さない。**
- **ヘッダの ↻ は新しい対局の確認**(`newGame` + `ConfirmDialog`。Hearts / Gin Rummy / Dominoes と同じ)。
  結果カードは勝ち / 負けと最終点、New game / Home / `ShareAction`。負けを叱る文言は書かない。
- 場札の枚数に規則上の上限は無い。360×640 で何段まで置くかは、自己対局で分布を数えてから決める — 未決、計画。
- 同名のアプリなど他社の商品名はアプリ内にもストア文言にも書かず、この文書の §14「比較対象との対応」にだけ、
  出典と確認日つきで書く([BRAND.md](BRAND.md)「自社タイトルと比較対象の名前」)。Escoba / Escova / Pişti /
  Scopone は伝統ゲームの一般名で、多言語の注意として書いてよいが、規則の比較は §14 に置く。§14 には
  **Escoba 規則との比較**(和 15・同じ数字の優先の有無・採点区分・終局の点)と、**商標・両ストアの検索結果と
  確認日**を書く。§15 には選定で「僅差で越えた枠」だったことと、実装後に
  自己対局で数えた取りの比率、検証の範囲を書く。
- **選定時の算術・試作の値**(取りの約 7 割が同じ数字、など)は、実装のテストと自己対局で再現するまで
  「検証済み」と書かない。
- Quick Rules の文案(仮。3 ステップ・図中心・各 1 文。図は場と同じカード部品で描く)
  1. 手札を 1 枚出す。場に同じ数字があればそれを取り、無ければ足して同じ数になる札を取る。
  2. 取れない札は場に置く。取って場を空にすれば 1 点(スコパ)。
  3. ディールの終わりに、札の多さ・♦ の多さ・7♦・プリミエラで 1 点ずつ。先に 11 点で勝ち。

## 多言語(来歴)

`en` が原文になる。**訳はまだ無い** — いまは 14 言語とも、スキャフォールドが置いた英語の仮文(11 キー)である。
`ja` と他 12 言語(de / es / fr / hi / id / ko / pt-BR / th / tr / vi / zh-Hans / zh-Hant)は、用語集
(スコパ / プリミエラ / 7♦ / 札 / ♦ / 取る / 置く / 配り手)をこの文書に置いてから AI が書く予定で、書いた後も
作者とネイティブが読むまでは未読として扱う([I18N_POLICY.md](I18N_POLICY.md)「翻訳の状態は「等級」ではなく
「来歴と、検証できた事実」で書く」)。es / pt-BR の読者は Escoba / Escova を、tr の読者は Pişti を思い浮かべる
ので、1 点の名はどの言語でも `scopa` の借用語にし、同名の別規則の語に置き換えない。スート名は翻訳キーに
する。高リスク文言(無料・オフライン・課金・削除・保存の約束)はこのゲームの文言に足さない。
