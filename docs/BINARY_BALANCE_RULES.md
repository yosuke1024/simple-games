# Binary Balance — 正式ゲームルール

この文書は Simple Games 収録タイトル「Binary Balance」の唯一のルールソースである。
実装(`apps/simple-games/src/games/binary-balance/game/`)、Hint、テスト、Quick Rules は
すべてこの文書に従う。コードはここへ `§n` で言及する。数値や挙動を変えるときは、
同じコミットでこの文書を先に直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。
Hint は無制限・無料、広告視聴で解放しない、ストリークで急かさない、
プレイ中に時計を見せない。

ゲーム ID は `binary-balance`、i18n キーの接頭辞は `binaryBalance`、保存キーの接頭辞は
`bn.` である。配信チャンネルは **Web 先行公開(`web-beta`)** で、アプリには正式収録して
いない([WEB_VERSION.md](WEB_VERSION.md)「先行公開」、issue #210)。
[Takuzu](TAKUZU_RULES.md) と同じ二値配置の系譜だが、**規則の集合が違う別のゲーム**である
— 「同じ並びの行(列)は禁止」を持たず、代わりに隣り合う 2 マスを結ぶ **同値 / 異値の
リンク**を持つ(§3)。Takuzu の名前の読み替えでも、Takuzu の validator の流用でもない
(§14)。他社の名称・アセット・画面デザインは複製しない(§14)。
5 種類の練習セットの中での位置づけと、比較対象との対応表は
[PUZZLE_PRACTICE_SET.md](PUZZLE_PRACTICE_SET.md)。

## 1. 盤面

- 6×6 のマス(N = 6)。マスに入るのは **☀(太陽)と ☾(月)の 2 種類**だけ。
- プレイ中の各マスの状態: 未定 / ☀ / ☾。
- **初期記号は固定**で、プレイヤーは動かせない(§4)。初期記号とプレイヤーの記号は
  別々に保持する(Takuzu §1 と同じ理由 — 混ぜると §11 の fail-closed 検証が言えない)。
- 隣り合う 2 マスの辺のいくつかに **リンク**がある: `=`(同じ記号)または `×`(違う記号)。
  リンクは上下左右に隣接するマスの間にだけある。盤面は生成後に変わらない。

サイズは 3 つの難易度すべてで 6×6 である:

| 難易度 | サイズ | 用途           |
| ------ | ------ | -------------- |
| Easy   | 6×6    | 導入           |
| Medium | 6×6    | 標準・デイリー |
| Hard   | 6×6    | 上位           |

比較対象の盤面は 6×6 であり、このタイトルはその練習の場である。**難易度の差は §7 の
技法の集合だけで作る** — 大きさで難しくはしない。3 つの難易度が同じ盤面に並ぶので、
Hard で要るのが「盤面が広いこと」ではなく「深さ 1 の仮置き(T5)」であることが、
そのまま遊びの違いになる。

**8×8 は測ったうえで外した(2026-09-30)。**当初 Hard は 8×8 だったが、固定シード 40 本の
Hard 生成の最悪が開発機で 120.9ms となり、1 盤面 100ms 未満という設計条件(§6)を
開発機の時点で割った。計り直しても最悪は 122ms / 115ms で、40 本中 2 本が 100ms を
超えた — 1 本だけの外れ値ではない。同じ 40 本を 6×6 の Hard で作ると最悪は 26ms。
T5 の要る盤面が引ける率は 6×6 で約 41%、8×8 で約 48% で、6×6 でも Hard の盤面は
珍しくない(§6 の実測表)。低スペック端末は開発機の数倍遅いので、8×8 に戻す理由は
残っていない。

奇数サイズは作らない(行を 2 等分できず規則 2 が何も言わなくなる)。6×6 以外のサイズも
作らない(§14)。

**盤面に翻訳の要る文字は 1 つも載らない。**☀ と ☾ は言語非依存のインライン SVG
(`MarkGlyph`)、リンクは `=`(U+003D)と `×`(U+00D7)の記号で、言語を変えても盤面表記は
変わらない([I18N_POLICY.md](I18N_POLICY.md))。読み上げ名(丸 / 四角)だけが i18n を通る。
実装は ☀ を `0`、☾ を `1` として持つ(`types.ts`)— 数字は内部表現であって表示ではない。

## 2. 勝利

- **勝利**: すべてのマスが埋まり、§3 の 3 規則をすべて満たした時点。
- 敗北は存在しない。ミス回数の制限も、ライフも、ゲームオーバーもない(§14)。

判定は「埋まっている」かつ「§9 の違反が 1 つも出ていない」で行い、**解と照合しない**。
表示と判定が同じ読みから出るので、「きれいに見えるのに完成しない盤面」は作れない。
出題は一意解なので(§5)、この状態は解と一致する。

## 3. ルール(3 つ)

**規則 1 — 同じ記号は縦にも横にも 3 つ続かない。**

```
☀ ☾ ☾ _   → 右端は ☀(☾ にすると ☾ が 3 つ続く)
☾ _ ☾     → 中は ☀
```

**規則 2 — 各行・各列で、☀ と ☾ はちょうど N/2 個ずつ。**

```
6×6 の 1 行:  ☀ ☀ ☾ ☀ ☾ _   → ☀ が既に 3 個なので、残りは ☾
```

**規則 3 — `=` で結ばれた 2 マスは同じ記号、`×` で結ばれた 2 マスは違う記号。**

```
☀ = _   → 右は ☀        _ × ☾   → 左は ☀
```

**Takuzu の規則 3(同じ並びの行・列は禁止)は持ち込まない。**この 3 規則が全部である
(§14)。出題は常に一意解を持つ(§5)。

## 4. 操作

- **タップ**: 未定 → ☀ → ☾ → 未定 の循環。これが操作の全部である。
- **初期記号のマスは変更できない。**タップしても何も起きない。
- **キーボード**(あれば): `H` = Hint(§8)。画面のボタンと同じ処理を呼ぶだけの別の
  入力経路で、ボタンは残す。押しっぱなしのキーリピートでは発火しない。結果カードと
  確認ダイアログの間は効かない。

**長押しもモード切り替えも作らない。**3 状態は 1 本の循環の上に並んでいて、どれも同じ
「記号を置く」操作である(Takuzu §4 と同じ理由)。

## 5. 「推測なし」の保証

**これがこのタイトルの中心的な設計判断である。**出題は必ず、§7 の技法だけで最後まで
解ける。技法はどれも健全(sound)で、「合法な完成形すべてが一致する記号」しか書かない。
したがって技法だけで埋め切れる盤面は解が 1 つだけであり、推測なしで必ず完成できる。

**技法の実装は 1 つだけ持ち、3 人の利用者が共有する** — 生成時の検査と等級判定(§6)、
Hint(§8)、`guarantee.test.ts`。約束と検査と助けを別々に実装すると、静かに食い違う
(Takuzu §5 / Sudoku §8 と同じ理由)。生成では技法ソルバーの結論を信じず、完全探索で
解の個数を数え直す(§6 の不変条件)— 技法ソルバーは健全性を信じる相手ではなく、
検査される相手である(Crown Grid §7)。

## 6. 盤面生成と Seed

すべての盤面は seed から決定的に作る。問題データの同梱もダウンロードもしない。
(`generator.ts` の `generatePuzzle(seed, difficulty)`。)

1. **完成盤を作る。**合法な行(半分が ☀、3 連続なし)はサイズごとの短い固定の
   アルファベットである(6 幅で 14 本 — Takuzu §6)。これを seed で
   シャッフルし、上から 1 行ずつ置く(**同じ行を使い回してよい** — 規則 3 が無いので
   行の重複は合法)。埋めながら見るのは列(規則 1・2)だけでよい。置いた行が
   `SEARCH_LIMIT`(20,000)を超えたらその seed は諦める。
2. **リンクを置く。**隣接するマスの対(6×6 で 60 辺)を seed で
   シャッフルし、ティアの初期本数(下の表)だけ取る。種類は完成盤から読む —
   両側が同じ記号なら `=`、違えば `×`。
3. **記号を掘る。**マスを seed 由来のシャッフル順に 1 つずつ取り除き、**そのティアの
   技法集合**(§7)のソルバーが全マスを確定できる間だけ取り除きを残す。**1 パスで十分**
   (初期記号が減ればソルバーの言えることは減る一方 — Takuzu §6)。下限は置かない —
   掘れるところまで掘る。
4. **リンクを削る。**リンクを seed 順に 1 本ずつ外し、同じティアのソルバーが全マスを
   確定できる間だけ外したままにする。記号を先に掘るのは、リンクが手がかりとして
   働いている状態で記号を減らすためで、そのあと残るリンクは「その記号の数で盤面を
   1 つに決めるために要るリンク」である。**リンクが 1 本も残らない盤面は出題しない**
   — それは Takuzu の盤面であってこのゲームではない(そういう候補は捨てて派生 seed へ)。
5. **等級を判定し**(§7)、求めるティアに一致すれば出荷する。一致しなければ **seed を
   派生させて作り直す**(`<seed>#2`, `#3`, …)。派生 seed は `ATTEMPT_LIMIT`(60)本で
   必ず止まる。
6. 上限に達したら、それまでの候補(一意で、そのティアの技法で解ける盤面)のうち
   **初期記号が最も少ないもの**を `fallback: true` で出荷する。一意解であることも
   推測が要らないことも変わらないが、ティアが求めたより易しい(Medium / Hard が
   下位の技法だけで解ける)。出荷してよい唯一の失敗の形なのでこれを選んである。
   発生率は `guarantee.test.ts` が監視する。
7. **例外を投げるのは 1 つの場合だけ**: 派生 seed を使い切っても一意でティアの技法で
   解ける候補が 1 つも出なかったとき。これは質の落ちた盤面ではなく生成器が壊れている
   ことを意味し、何も押せない空の盤面を渡すよりは失敗として表に出す(Takuzu と同じ線)。

ティアの生成条件(`types.ts` の `TIERS`。初期リンク本数は seed で範囲から 1 つ引く):

| ティア | サイズ | 初期リンク本数 | 掘削に使う技法集合 | 等級の条件                       |
| ------ | ------ | -------------- | ------------------ | -------------------------------- |
| Easy   | 6×6    | 6〜9           | {T1, T2, T3}       | Easy 集合で解ける                |
| Medium | 6×6    | 6〜10          | {T1〜T4}           | Medium で解け、Easy では解けない |
| Hard   | 6×6    | 10〜16         | {T1〜T5}           | Hard で解け、Medium では解けない |

不変条件:

- 同じ seed なら、必ず同じ盤面になる(`compatibility.test.ts` の golden で固定する。
  ベータ中はスキーマ変更が許されるが、黙って変えないための門として最初から敷く)。
- 出題は一意解で、そのティアの技法集合だけで解ける(推測不要)。生成の最後に完全探索
  (`solver.ts` の `countSolutions` — 列ごとの候補を絞りながら行を 1 本ずつ置く探索で、
  解を 2 つまで数える)で「解はちょうど 1 つ」を数え直す。
- 出題には **`=` か `×` のリンクが 1 本以上**ある(手順 4)。
- **ティアの一致は目標であって約束ではない。**手順 6 の盤面は一意解で推測不要のまま、
  求めたより易しい。発生率は監視する(実測は下の表)。

### 予算は仕事量で門にする

これは**端末の予算**であって、開発機やテストランナーの予算ではない。だから門は
壁時計ではなく**ソルバーの仕事量**(`solverWork` = 読んだ行の本数 + 列挙した行の
完成形の数 + 立てた仮説の数 + 完全探索のノード数)で測る。同じ seed なら、どのマシンでも
常に同じ数になる。理由ごと [SUDOKU_RULES.md](SUDOKU_RULES.md) §7 と
[TAKUZU_RULES.md](TAKUZU_RULES.md) §6 に詳しい。

実測(開発機、`guarantee.test.ts` が走査するのと同じ集合。難易度ごとに固定シード 40 本、
デイリーは 2026-08-01 から 730 日。2026-09-30 計測、Hard を 6×6 にしたあとの値)—
**数字は実測値だけを書く**:

| ティア   | n   | 仕事量 p50 | p90     | 最悪    | 派生 seed 最悪 | fallback | 壁時計 p50 | 壁時計 最悪 |
| -------- | --- | ---------- | ------- | ------- | -------------- | -------- | ---------- | ----------- |
| Easy     | 40  | 10,148     | 11,237  | 11,922  | 1              | 0        | 2.2ms      | 7.6ms       |
| Medium   | 40  | 15,416     | 19,061  | 32,626  | 2              | 0        | 2.4ms      | 4.7ms       |
| Hard     | 40  | 73,770     | 191,812 | 212,654 | 7              | 0        | 7.9ms      | 24.0ms      |
| デイリー | 730 | 15,914     | 25,282  | 51,287  | 4              | 0        | 2.3ms      | 41.6ms      |

出題の初期記号は Easy 2〜7 個(p50 6)、Medium 2〜8 個(p50 5)、Hard 1〜5 個(p50 2)、
デイリー 1〜9 個(p50 5)。残るリンクは Easy 2〜7 本、Medium 2〜7 本、Hard 4〜11 本、
デイリー 1〜9 本。Hard は 40 本を作るのに派生 seed を計 97 本引いた(約 41% が T5 の要る
盤面になる)。デイリーの壁時計最悪 41.6ms は同じ集合の直前の計測では 8.6ms で、
テストランナーの負荷による揺れである — 壁時計を門にしない理由そのものである。

参考として残す 8×8 Hard の実測(同じ 40 本、2026-09-30、§1 で外した理由): 仕事量 p50
423,008 / p90 1,117,151 / 最悪 1,792,986、派生 seed 最悪 8(計 84)、壁時計の最悪は
2 回の計測で 122ms / 115ms、100ms を超えた盤面は 40 本中 2 本。

**仕事量の列は再現し、壁時計の列は再現しない。**門(`guarantee.test.ts` が上の集合を
走査して固定する):

- 1 盤面あたりの仕事量の上限(実測の最悪の 2〜4 倍に置く。退行の門であって端末の約束
  ではない): Easy 40,000(最悪の 3.4 倍)、Medium 150,000(デイリーも Medium の門で
  測る。両者を合わせた最悪 51,287 の 2.9 倍)、Hard 650,000(最悪の 3.1 倍)。
- 派生 seed の上限(実測の最悪よりずっと手前、`ATTEMPT_LIMIT` の 60 より手前に置く):
  20(最悪は 7)。
- 手順 6 の発生は 0 件。全盤面が一意で、等級が求めるティアに一致し、リンクが 1 本以上ある。
- 壁時計は計測して出力するだけで、判定には使わない。

端末の予算は 1 盤面 100ms 未満で、生成は UI スレッドで同期に走る(Worker は使わない —
[GAME_LIFECYCLE.md](GAME_LIFECYCLE.md))。Hard を 6×6 に落とす手はすでに使った(§1)。
これから超えた場合の対処順序は次のとおりで、どれも**この文書を先に直す**:

1. Hard の初期リンク本数を増やす(掘削のあと残る手がかりが増え、試行回数が減る)。
2. `ATTEMPT_LIMIT` を下げる(上限に達した盤面は手順 6 の fallback になる)。
3. (最後の手段)Hard の条件を「Easy の集合では解けない」まで緩める — T4 だけで解ける
   盤面も Hard として出す。8×8 のときに測ったところ、この条件では 40 本中 17 本が T4
   だけで解け、Hard と Medium の差が薄れる。だから最後に置く。

**低スペック実機での実測はまだ行っていない。**

## 7. 技法とティア

難易度は盤面の大きさではなく、**解くのに必要な技法の集合**で定義する。

| 技法 | 名前            | 内容                                                                                                                                                                                                                           |
| ---- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T1   | pair-gap        | 隣り合う 3 マスに同じ記号が 2 つと未定が 1 つあれば、その未定は反対の記号(規則 1。`☀ ☀ _` / `_ ☀ ☀` / `☀ _ ☀` は同じ話)。                                                                                                      |
| T2   | line-count      | 一方の記号がその行(列)で N/2 個に達したら、残りの未定はすべてもう一方(規則 2)。                                                                                                                                                |
| T3   | link            | `=` の片側が決まればもう片側は同じ記号。`×` の片側が決まればもう片側は反対の記号(規則 3)。                                                                                                                                     |
| T4   | line-completion | 1 本の行(列)について、規則 1・2 と**その行の中で閉じるリンク**、および行の外の**確定済み**マスと結ぶリンクを満たす完成形をすべて列挙し(6 幅で最大 20 通り、8 幅で 70 通り)、すべての完成形で同じ記号になる未定マスを確定する。 |
| T5   | hypothesis      | 深さ 1 の仮置き。未定マスに片方の記号を仮置きし、T1〜T4 を不動点まで走らせて矛盾したら、そのマスは反対の記号。候補の少ない行から順に試し、最初に矛盾した 1 マスを一手とする。                                                  |

**5 つとも健全である。**T4 は「その行の合法な完成形の集合」の共通部分しか書かず、
盤面全体の解を行に制限したものは必ずその集合に入る。技法は**安い順に**適用し、上位の
技法は下位の技法が何も言えなくなってから初めて参照する — これが人の解き方であり、
仕事量が小さく収まる理由でもある。

**ティア**(技法の集合 — 上位は下位を含む):

| ティア | 技法集合 | 条件                                               |
| ------ | -------- | -------------------------------------------------- |
| Easy   | {T1〜T3} | この集合だけで解ける                               |
| Medium | {T1〜T4} | この集合で解け、**かつ Easy の集合では解けない**   |
| Hard   | {T1〜T5} | この集合で解け、**かつ Medium の集合では解けない** |

等級判定は「Easy 集合で不動点まで → 解けなければ Medium 集合で続き → 解けなければ Hard
集合で続き」と 1 本の流れで行う(技法は単調 — 確定が増えても導ける結論は減らない)。
T5 でも解けない盤面は等級なしで、出題しない。

## 8. Undo と Hint

- **Undo は作らない。**すべてのマスはタップで 未定 → ☀ → ☾ → 未定 と一巡する(§4)。
  すべての手がもともと可逆なゲームに Undo を重ねても、同じ操作が 2 つ並ぶだけである
  (Takuzu §8 / Crown Grid §14 と同じ判断)。比較対象の Undo / Clear は§14。
- **Hint は作る。無制限・無料。**マスを書き換えることはしない。次の順で 1 つだけ示す:
  1. **違反があれば、それを示す**(§9 の行・列・リンク)。壊れた並びの上に積んだ確定を
     教えても、正しい導きにならない(Takuzu §8 と同じ順序)。
  2. **解に無い記号があれば、その 1 つを「この記号は成立しない」として示す**(行順で
     最初のもの)。一意解の出題なので、解に無い記号は「まだ矛盾していないだけ」ではなく
     確実に誤りであり、その上に技法を積んでも導けるものが無い。Takuzu §9 は「解と違う」
     表示を退けているが、あちらは常時表示であり、こちらは**プレイヤーが Hint を押した
     ときにだけ、1 つだけ**言う(Crown Grid §6 と同じ判断 — §14)。
  3. **技法ソルバーの次の一手**(§7)。確定するマスと、根拠になった行(列)、根拠を担う
     記号(T1 の対・T2 の N/2 個・T3 の相手・T4 の行全体)を強調して示す。一文は技法ごとに
     1 つ用意し、平易に言う。**技法名は UI に出さない。**
  4. どれも見つからないときは「今わかる手が見つかりません」と表示し、盤面は変えない。
- Hint の使用回数は記録し、結果カードで事実として見せる(コストにはしない)。

Hint の技法集合は常に全部(T1〜T5)である。出題はティアの技法だけで解けるように
作ってあるので、Easy の盤面で T5 の Hint が出ることはない(例外は §6 手順 6 の
fallback で Easy が上のティアへ落ちた盤面だけで、発生は監視している)。

## 9. 違反表示

常時オンで、3 規則それぞれに対応する。該当するマスを警告色と枠で示す:

- 同じ記号が縦横に 3 つ続いたとき、その 3 マス。
- 行(列)の一方の記号が N/2 を超えたとき、その記号のマス。**埋まりきる前に出す** —
  超えた時点で、その行はもう完成できない。
- `=` の両側が違う記号、または `×` の両側が同じ記号のとき、その 2 マスとリンク記号。

**これはルール違反の指摘であって、答え合わせではない。**規則を破っていない記号は、
それが解と違っていても何も言われない。「解と違う」の常時表示は作らない(Takuzu §9)。
ただし **Hint は解に無い記号を 1 つ指摘する**(§8)。

この判断の結果として、**このゲームには盤面の見え方や操作を変える設定が 1 つもない**。
`bn.prefs` にあるのは最後に選んだ難易度だけで(§10)、それは覚えておく位置であって、
ルールの切り替えではない。ミス回数も概念ごと存在しないので、記録も表示もしない。

## 10. モード・デイリー・統計

- **難易度モード**: Easy / Medium / Hard を選んで遊ぶ(§1、§7)。レベル 1〜100 は作らない
  (段階的な進行は存在せず、水増しになる — Crown Grid §9)。seed は
  `binary-balance-<difficulty>-<token>`(token = 起動時刻 + 乱数、Takuzu の `newSeedToken`)。
  **同じ seed なら同じ盤面**なので、「同じ盤面で再挑戦」も中断からの復帰も正確に成立する。
  クリア画面の第一ボタンは同じ盤面での再挑戦、第二が「新しい盤面」(同じ難易度・新しい seed)。
- **デイリー**: 1 日 1 問。seed は `binary-balance-daily-<YYYY-MM-DD>`(端末のローカル
  日付のみ。サーバー時刻もネットワークも使わない)。**毎日 Medium(6×6)固定。**
  曜日で難易度を変えると「当たり日 / 外れ日」という圧を生むため採らない(Sudoku §10)。
- **デイリーは今日の 1 問だけ。** 過去の日付には遡れず、一覧も入口も持たない。日付が過ぎた
  中断中のデイリーは次に読み込むとき(起動・ゲームを開く)にレコードごと捨て、ホームの
  「デイリーチャレンジ」はつねに今日の問題へ向く。遊んでいる最中の盤面は日付が変わっても
  取り上げない。達成した日の記録は残す(`docs/PRODUCT_PRINCIPLES.md`「デイリーは今日の 1 問」、
  2026-10-02 に過去日への遡りを廃止)。
- **ストリークは数えない・表示しない。**
- 最後に選んだ難易度は `bn.prefs` に残り、次回のホームはその難易度を第一に出す。
  チュートリアル直後に始まる盤面もこの難易度(初期値 Easy)。
- **プレイ中に時計を表示しない**(ブランド原則)。経過時間は内部で記録し、結果画面と
  統計でのみ見せる。
- 統計: 難易度別に プレイ回数 / クリア数 / 最短時間 / 合計プレイ時間、デイリーは
  達成日ごとの時間(`dailyTimes`)。Minesweeper §9 / Crown Grid §10 と同形。
- **スコアは作らない。**ランキングもストリークも作らない。自己ベストの更新は、更新した
  ときだけ静かに示す。クリア画面の記録は、難易度モードではその難易度の最短時間、
  デイリーではその日の記録。記録があれば差を符号付きで添える(`ui/components/BestDelta.tsx`)。

## 11. 中断と再開

- 難易度モード用・デイリー用の **2 スロットを独立して保持する**。
- 保存するのは(`bn.saveGame` / `bn.saveDaily`、v1)mode / seed / difficulty / dailyDate /
  size / solution(1 マス 1 文字: `0` = ☀ / `1` = ☾)/ givens(1 マス 1 文字: `0` / `1` /
  `.`)/ marks(同形)/ links(辺の列挙: `h<i>=` = マス i とその右が `=`、`v<i>x` = マス i と
  その下が `×`。`,` 区切り)/ hintCount / elapsedSeconds / savedAt。**ミス回数は持たない** —
  このゲームにミスという概念がない(§9)。
- **どのスロットのレコードかを決めるのはキーである。**難易度用のキーに入っている
  `mode: 'daily'` のレコードは「デイリーだった」のではなく壊れている。復元せず既定値へ
  落とす(`gameSlotSchema(key, expectedMode)`、`src/test/savedGameSlots.test.ts` が強制)。
- **スロットを置き換える前に確認する。**中断中の難易度と違う難易度を選んだときは確認を
  出す(同じものを選ぶのは再開)。デイリーは今日の 1 問だけなので、別の日を選ぶ場面はない。
- **検証は fail-closed。**プレイから生まれえないレコードは読み捨ててホームへ戻す:
  - size が 6 でない(どの難易度も 6×6 — §1)、または文字列の長さがマス数と合わない
  - links が辺を指さない(範囲外・右端の `h` / 下端の `v`・重複)、種類が `=` / `x` 以外
  - solution が §3 の 3 規則(リンクを含む)を破っている
  - givens またはマークに `0` / `1` / `.` 以外が入っている
  - givens が解と食い違っている、またはマークが givens のマスを上書きしている
  - リンクが 1 本も無い(§6 の不変条件。出題から生まれえない)
  - mode が `daily` なのに日付が無い、または日付があるのに難易度が medium でない
- 背景へ回るとき、盤面の保存と未計上秒の計上を**同じ同期処理で**行う(Minesweeper §10)。
- 保存キーは `bn.saveGame` / `bn.saveDaily` / `bn.stats` / `bn.flags` / `bn.prefs` の
  **5 つ**。`bn.flags` はチュートリアル完了、`bn.prefs` は最後に選んだ難易度だけ(§10)。
- 保存の失敗でゲームを止めない。バリデータは例外を投げない。
- **ベータ中の注意**: 先行公開の間はスキーマを変えてよく、その場合この保存データは消える
  ことがある。ホームの `WebBetaNotice` がそのことを英日で告げる([WEB_VERSION.md](WEB_VERSION.md))。

## 12. Quick Rules(アプリ内チュートリアル)

3 ステップ以内・各ステップ原則 1 文・図中心([I18N_POLICY.md](I18N_POLICY.md))。

1. タップで 空 → ☀ → ☾ → 空。同じ記号は 3 つ続けない。
2. どの行・列も、☀ と ☾ が同じ数になる。
3. `=` で結ばれた 2 マスは同じ、`×` で結ばれた 2 マスは違う。詰まったら Hint。

Learn More は出ない(ゲーム別ガイドは未公開。ベータのため)。詳細ルール・攻略・FAQ を
アプリ内に持たない方針は変わらない。

## 13. 演出とアクセシビリティ

- **☀ と ☾ は形で区別する** — 塗った円と三日月。Takuzu と同じく 2 つの控えめな地色
  (`--stone` の 2 段の不透明度)は補助であって、色だけに意味を持たせない。地色を全部
  外しても盤面は読める。**記号そのものは 2 色で塗る**(`--bn-sun` / `--bn-moon`、
  `binary-balance.css` — Minesweeper の数字と同じ「ゲームの中身」の色で、クロムの
  1 タイトル 1 色の外)。色は補助で、意味は形が担う。
  - ライトは塗りを明るくし(太陽 `#f0ad3a`、月 `#6d8fe0`)、**同系色の暗い細い縁取り**
    (`#a9670f` / `#3f5b9e`)が輪郭のコントラストを担う。縁取りは置かれるどの地
    (マス面・固定マスの沈んだ面・紙・警告の地)に対しても 3:1 以上(太陽 3.57〜4.46、
    月 5.16〜6.45)。塗り自体は意図してそれより淡い(太陽 1.5〜1.9、月 2.5〜3.1) —
    暗い塗りは紙の上で濁って見えた(2026-09-30 の指摘)。
  - ダークは塗りだけで 3:1 を超える(太陽 `#e6b054` 6.98〜9.15、月 `#9db1e3`
    6.41〜8.41)ので縁取りは塗りと同色(見えない)。
  - 違反中は塗りも縁取りも警告色(§9)。比較対象の配色は借りず、シリーズの紙の上で
    成立する範囲で選んだ(§14)。
- リンクは 2 マスの間の辺の中央に置いた小さな記号(`=` / `×`)で、インク色。マスの
  ボタンの外側に `aria-hidden` で描き、読み上げはマスの側が持つ(下記)。
- 違反表示も色だけに頼らない。警告色に枠を併用する(§9)。
- 初期記号とプレイヤーの記号は、色ではなく輪郭で分ける(初期記号だけインクの縁取りを持つ)。
- 各マスはボタンで、**行・列と状態(未定 / 丸 / 四角 / 初期記号)、およびそのマスから
  出るリンク(右へ「同じ」/ 下へ「違う」)**を読み上げる。違反に関わるマスは
  「ルール違反」を添える。
- Hint の対象マスは太い枠、根拠のマスは淡い色つき、根拠の行(列)は薄い帯で示す
  (Takuzu §13 と同じ 3 段)。
- 6×6 が 320px 幅に収まるようにマスの大きさを clamp する(Takuzu §13 と同じ算段。
  リンク記号の分だけマス間の gap を Takuzu より広く取る — 8px の gap で 1 マス約 41px)。
- 記号が変わるときは一拍のポップで現れる(90ms ease-out)。**盤面が埋まってから結果カードが
  出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。Reduced Motion では即時。
- 効果音は既存の合成音(`services/sound`)のみ: 記号を置いて `select`、クリアで `clear`。

## 14. 意図的な差分

ブランド原則により合わせないもの:

- ミス回数制限・ライフ制・ゲームオーバー(しない。そもそもミス判定をしない — §9)
- プレイ中のタイマー表示、ストリーク、オンラインランキング、スコア(しない)
- Hint を広告視聴やコインの報酬にすること(しない。常に無料・無制限 — §8)
- 1 日 1 問だけの供給(しない。難易度を選べばいつでも新しい盤面 — §10)

設計判断として合わせないもの:

- **他社の名称・アセット・画面デザイン。**「Tango」は他社の商品名であり、名前もアセットも
  配色も複製しない。記号は当初 ○ と □ の独自表現だったが、練習の場として比較対象と同じ
  読みになるよう **太陽と月** に揃えた(2026-09-30、ユーザー判断)。描画は独自の SVG
  (塗った円と三日月)で、色はシリーズの紙の上で選んだ 2 色(§13)。
- **Undo / Clear**(作らない。§8)。タップ循環で全状態に 2 タップで届く。Clear は
  「同じ盤面で再挑戦」が同じ結果を与える。
- **Takuzu の規則 3**(持ち込まない。§3)。比較対象にこの規則は無く、Takuzu の validator
  や solver を流用すると「合法な完成形」の集合が変わってしまう。`engine.ts` /
  `solver.ts` はこのゲーム自身のものである(`guarantee.test.ts` は「同じ並びの行を持つ解」
  が生成されうること、および同じ並びの行を含む完成盤が違反にならないことを確かめる)。
- **6×6 以外のサイズ**(作らない。§1)。比較対象の盤面は 6×6 で、難易度は技法の集合で
  作る。奇数サイズは規則 2 が成り立たず、8×8 は Hard の生成が端末予算を割ったので外した。
- **「解と違う」の常時表示**(作らない。§9)。ただし **Hint は解に無い記号を 1 つ指摘する**
  (§8。Crown Grid §14 と同じ理由)。
- **レベル 1〜100**(作らない。§10)。
- **推測が必要な盤面・複数解の盤面**(出さない。§5〜§7)。
- **問題データの同梱・配信**(すべて端末上で生成する。§6)。

### 比較対象との対応(2026-09-29 確認、issue #210)

公式 Help([LinkedIn Help — Tango](https://www.linkedin.com/help/linkedin/answer/a6861672/)、
2026-09-29 閲覧)が挙げる規則と、このゲームの対応:

| 公式の規則 / 機能                                   | Binary Balance                                    |
| --------------------------------------------------- | ------------------------------------------------- |
| 2 種類の記号(太陽 / 月)                             | ☀ / ☾(同じ読み。描画と配色は独自、§1・§13)        |
| 各行・各列で 2 種類の個数が同じ                     | 規則 2(§3)。同じ                                  |
| 縦横に同じ記号を 3 つ以上続けない                   | 規則 1(§3)。同じ                                  |
| `=` で結ばれたマスは同じ、`×` で結ばれたマスは違う  | 規則 3(§3)。同じ                                  |
| 同じ並びの行・列の禁止                              | 公式にも無い。持ち込まない(§3)                    |
| 盤面サイズ(Help に記載なし。公開されている盤は 6×6) | 全難易度 6×6。同じ(§1)                            |
| Hint(置くべき場所を示す)                            | Hint(違反 → 誤り → 次の一手、§8)                  |
| Auto-check(違反を赤い縞で示す設定)                  | 違反表示は常時オンで設定なし(§9)                  |
| Undo / Clear                                        | 作らない(§8、上記)                                |
| 1 日 1 問                                           | 難易度 3 種 + デイリー。新しい盤面はいつでも(§10) |

合わせたもの: 3 規則の集合、一意解、常時の違反表示、タップ 1 種類だけの操作。
公式の問題・解答・アセットは取得も転載もしない(すべて端末上で生成する — §6)。
