# Connect Four — 正式ゲームルール

このドキュメントが Connect Four の仕様の正本である。実装
(`apps/simple-games/src/games/connect-four/`)、テスト、Quick Rules はここに従う。
コードはここへ `§n` で言及する。挙動を変えるときは、同じコミットでこの文書を直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

ゲーム ID は `connect-four`、i18n キーの接頭辞は `four`(識別子を数字で始められない
ため)、保存キーの接頭辞は `c4.` である。

## 1. 盤面と対局者

- 7 列 × 6 段の 42 セル(`game/types.ts`。行優先の配列、0 = 空、1 = プレイヤー、
  2 = CPU。行 0 が最上段)。
- **先攻・後攻はプレイヤーが選ぶ**(ホーム画面。既定は先攻)。選択は次の対局に
  適用される設定であり、**対局中のゲームには触らない** — 始めた側のまま終わる。
  保存キーは `c4.prefs`、セッションは開いた側を `first` として持つ(盤面だけでは
  「同数=開いた側の番」が誰か分からないため)。対局相手は CPU だけである —
  オンライン対戦もローカル対人戦も作らない([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md)
  「初期リリースで実装しないもの」)。
- ディスクは色だけを描く。プレイヤーはタイトルのアクセント色、CPU はこのゲームが
  持つ第 2 色(ゲームコンテンツの色。2048 のタイルランプと同じ立場)。文字は
  置かない — 盤面は全言語で同じに読める([I18N_POLICY.md](I18N_POLICY.md))。

## 2. 一手の解決

1. 列を 1 つ選ぶ。ディスクはその列の**いちばん下の空きセル**に落ちる。
2. 満杯の列への入力は、何も起きない。音も鳴らさない — 盤面は完全に見えており、
   叱る間違いがない(docs/GAME_2048_RULES.md §3 と同じ)。

## 3. 終了条件

- 自分のディスクが縦・横・斜めのいずれかに 4 つ並んだ側の勝ち。
- 42 セルが埋まって 4 つ並びがなければ引き分け。
- 遷移は `status`(`'playing' | 'won' | 'lost' | 'draw'`)で一度だけ起きる
  (`game/session.ts`)。勝った 4 つ並びは盤面上で示す(§10)。

## 4. CPU(後手)

- 探索は**プレイヤーの着手(タップ)を起点にのみ**走る。ポーリングも先読みもしない
  ([GAME_LIFECYCLE.md](GAME_LIFECYCLE.md)「CPU 探索」)。
- 難易度は 3 つ(`easy` / `normal` / `hard`)。いずれも α–β 付き negamax で、
  読む深さだけが違う:
  - **easy** — 1 手読み。自分が勝てる手は打つが、相手のリーチは見えない。
  - **normal** — 4 手読み。すぐの脅威は受けるが、二重の狙いには掛かる。
  - **hard** — 反復深化で最大 8 手読み。ノード上限 `HARD_NODE_LIMIT`(30,000)に
    達したら**完了済みの深さの最善で打つ** — 上限は正直に守り、長時間 CPU を占有する
    「強い CPU」は作らない(issue #26 非目標)。完全読みの序盤データベースは積まない。
    上限値は実測で決めた: 上限まで使い切る手で開発機 160ms 程度である。
    **ただし探索は下記 450ms の「間」の中では走らない** — `CPU_DELAY_MS` は
    1 本の timeout を張り、探索はその**中**で走る(`state/GameContext.tsx`)ので、
    着手が現れるのは概ね **450ms + 探索時間**である。**着手までの待ちが伸びすぎない
    範囲でいちばん強い CPU** がこの選択であって、そこからはみ出す強さは採らない。
    低スペック端末での体感は実機確認(リリース Gate)で見る。
- 評価は 4 マス窓の数え上げ(自分 3 + 空き 1 を高く、相手の同形を負に)+ 中央列の
  加点。探索順は中央列から(枝刈りのため)。
- 同点の候補はセッションのシードと手数から決定的に選ぶ:
  `createRng(`${seed}:cpu:${moveCount}`)`。同じシードで同じ手順を踏めば、CPU は必ず
  同じ手を返す。ゴールデンテスト(`game/compatibility.test.ts`)が固定する。
- CPU の着手は約 450ms 置いてから盤面に現れる(`CPU_DELAY_MS`)。探索が一瞬でも、
  相手の手番が**手番として見える**ためであって、思考の演出を盛るためではない。
  アンマウント・Undo・新規対局はこの遅延を破棄する。

## 5. Undo

- **無制限・無料**。自分の直前の決定点まで戻す — CPU の応手と自分の一手がまとめて
  取り消される。CPU の手番の途中には戻さない。
- Undo は振り直しではない: 戻して同じ列に落とせば、CPU も同じ手を返す(§4 の決定性)。
- 広告視聴や課金による Undo は作らない([ADS_POLICY.md](ADS_POLICY.md))。

## 6. 助けの形

- 助けは Undo ひとつ(§5)。無料で、無制限で、初回起動から使える。
- **Hint は作らない**: 盤面は完全に見えており、隠れた情報がない。次の一手を教える
  機能は CPU がプレイヤーの側でも打つことになる(docs/REVERSI_RULES.md §7 と同じ)。
- 落下先のプレビュー(列に触れたときの影)は置かない。落ちる場所は列を見れば
  一意に分かり、プレビューは低速端末でのドラッグ描画コストにしかならない。

## 7. スコアと統計

- スコアという数はない。対局の結果は勝ち / 負け / 引き分けだけである。
- 統計は難易度ごとに `played`(開始した回数)・`wins`・`losses`・`draws`、全体で
  `totalPlaySeconds`。ストリークは数えないし表示しない。
- 対局を放棄して新しく始めた場合、負けには数えない(`played` には既に数えている)。
  記録されるのは実際に終局した対局だけ — 統計が脅しになってはならない。
- プレイ時間は逐次計上(bookedRef 方式、2048 と同じ)。

## 8. 中断と再開

- **途中保存する。** 盤面はターン制で、保存して開き直した盤面は保存した瞬間と同じ
  である(docs/GAME_2048_RULES.md §10 と同じ理由)。
- 保存スロットは 1 つ(`c4.saveGame`)。盤面(42 文字、セルごとに `0`/`1`/`2`)・
  **開いた側**(`first`)・難易度・シード・手数・経過秒を持つ(`game/serialize.ts`)。
  **手番は保存しない** — 交互が崩れないゲームなので、枚数と `first` から導出できる
  (`sideToMove`)。
- CPU の手番中(遅延中)に離れた場合もこの導出で同じ手番に戻り、再開時に CPU が打つ。
- **Undo 履歴は保存しない**。再開した対局はその局面から始まる。
- 壊れた保存は読み捨てて、ホームへ戻る(勝手に新しい対局を始めない)。検証は
  fail-closed: 浮いたディスク・駒種以外の文字・枚数が合わない盤面・終局済みの盤面は
  破棄する。**手数が盤面のディスク数と一致しない保存も破棄する** — 1 手につき
  ディスクはちょうど 1 枚増えるので両者は必ず一致し、食い違う保存はプレイから
  生まれえない。手数は CPU の抽選の半分(§4)なので、放置すると保存した対局とは
  違う応手を返す盤面を再開させてしまう。

## 9. Quick Rules(アプリ内チュートリアル)

3 ステップ・図中心・各 1 文(初回起動時に表示、以後はホームから):

1. 列をタップするとディスクがいちばん下まで落ちる。
2. 縦・横・斜めのどれかに 4 つ並べたら勝ち。
3. 相手(CPU)のリーチは先にふさぐ。

詳細は Landing Page へ。ガイドを公開するまで「詳しく見る」は出さない
(`src/ui/landing.ts`)。オフラインでは何も起きない(ゲームは止めない)。

## 10. 演出とアクセシビリティ

- ディスクは DOM 要素。落下は落ちる段数に応じた transform のスライド(1 段あたり
  約 55ms、上限 220ms)。着地のバウンドは作らない。要素は増やさない — 粒子も
  画面揺れもない。
- Reduced Motion(アプリ設定または OS)では落下アニメーションを無効にし、ディスクは
  着地位置にすでにある状態で描かれる。
- 勝った 4 つ並びはリングで示し、他のディスクを薄くする。色だけに頼らない。
- 最後に落ちたディスクには小さな印を付ける(CPU の手を見失わないため)。
- 列は縦 1 本のボタンで、その列の盤面を読み上げる。満杯の列は無効になる。
- 効果音は既存の合成音(`services/sound`)のみ: 着手で `select`、勝ちで `clear`、
  負け・引き分けで `gameOver`。設定に従う。
- **時計を出さない**。経過時間は統計にだけ残る。

## 11. 意図的な差分

市中のコネクトフォー / 四目並べ系アプリを調べたうえで、意図的に合わせないものを
記録する。

**ブランド原則により合わせないもの**

- **Undo・強さ解放を広告や課金に結び付けない**。難易度は最初から全部選べる。
- レーティング・ランキング・オンライン対戦はない。記録は端末の中だけにある(§7)。
- デイリーやストリークで毎日呼び戻さない。

**設計判断として合わせないもの**

- ~~**先後は選べない(プレイヤーは常に先手)**~~ → **撤回した(2026-08-07)**。
  「コネクトフォーは先手が理論上有利だから、その有利をプレイヤーに渡すのが親切」と
  書いていたが、それは**選ばせない理由にはならない**。既定を先攻にしておけば親切さは
  そのまま残り、後手で挑みたい人はそれを選べる。既定と禁止を取り違えた判断だった。
- **最強 CPU を作らない**。このゲームは解かれており(先手必勝)、完全読みの CPU は
  「勝てない相手」にしかならない。hard は上限付き探索で止める(§4)。
- **盤面サイズは 7×6 だけ**。8×7 等は別の遊びになる。v1 では 1 つに絞る。
