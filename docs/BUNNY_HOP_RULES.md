# Bunny Hop — 正式ゲームルール

このドキュメントが Bunny Hop の仕様の正本である。実装
(`apps/simple-games/src/games/bunny-hop/`)、テスト、Quick Rules はここに従う。
コードはここへ `§n` で言及する。挙動を変えるときは、同じコミットでこの文書を直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

ゲーム ID は `bunny-hop`、i18n キーの接頭辞は `bunny`、保存キーの接頭辞は `bh.` である。

## 1. コース

- 論理盤面は **600×150**、地面は上端から 127px の高さに引く。**この比率は
  ブラウザのオフライン画面から続くこのジャンルの形**であり、意味がある:
  横に長いほど「次に何が来るか」を読む時間が増え、最高速でも 0.77 秒先まで
  見える。縦は「障害物の上か下か」しか意味を持たないので浅くてよい。
- **うさぎは前後に動かない**。うさぎは x=24 に固定され、世界のほうが左へ流れる。
- 障害物の位置は「走った距離」から読む(`obstacleX`)。障害物ごとに座標を
  積み上げないので、3 分走っても位置がずれない。

## 2. 終了条件

- **終了**: 走者が障害物に 1 度でも触れたとき。ライフはない(§7)。
- クリアはない。エンドレスに続き、記録はスコア = 走った距離である(§6)。
- 走り出す前に `ready` の状態がある。最初の入力まで世界は止まっているので、
  ゲームを開いただけで 1 回分を失うことはない。遷移は `game/engine.ts` の
  `status`(`'ready' | 'running' | 'over'`)で一度だけ起きる。

## 3. 操作

**入力はジャンプ 1 つだけ**である。しゃがみは持たない(§13)。届く経路は 3 つ:

- **プレイ領域のどこをタップしても**跳ぶ。コースは縦に浅い帯なので、
  親指が帯そのものを探す必要はない。
- **画面下の「↑」ボタン**。名前が付いているので支援技術からも触れる。
  ボタン 1 つが画面幅いっぱいで、**指で押す場所を探す時間**が勝敗を決める
  遊びだから、当たり判定は大きくとる。
- **Space・↑・W キー**(Web 版)。ボタンにフォーカスがあるときは、ボタン
  自身のキー操作に任せて二重に跳ばない。
- ジャンプは**地上からのみ**。空中での二段ジャンプは作らない — どんな
  間隔も飛び越せるようになり、コースが意味を失うため(§13)。

## 4. ジャンプ

- 初速 580 px/s、重力 2100 px/s²。したがって**高さ 80px・滞空 0.55 秒**。
  「どれだけ飛べるか」はこの 2 つの数から出るので、他に調整点を作らない。
- 頂点でも走者は盤面の中に収まる(上端まで数 px)。

## 5. コースの生成と難易度

- 障害物は (シード, 連番) から決定的に生成される(`game/obstacles.ts`)。
  同じシードは同じコースを再生し、ゴールデンテスト
  (`game/compatibility.test.ts`)がそれを固定する。
- 形は 7 種類。問いは**「跳ぶか、跳ばないか」の 1 つだけ**で、違うのは
  「いつ跳ぶか」の厳しさである:

  | 形                      | 大きさ  | 答え       | 出現            |
  | ----------------------- | ------- | ---------- | --------------- |
  | 茂み                    | 18×36   | ジャンプ   | 最初から        |
  | 生垣(高い)              | 26×50   | ジャンプ   | 最初から        |
  | 茂み 2 つ               | 62×36   | ジャンプ   | 最初から        |
  | 茂み 3 つ               | 106×36  | ジャンプ   | スコア 150 から |
  | 生垣 2 つ               | 86×50   | ジャンプ   | スコア 150 から |
  | 低い鳥(地上 6px)        | 46×40   | ジャンプ   | スコア 400 から |
  | 高い鳥(地上 58px)       | 46×40   | 何もしない | スコア 400 から |

  低い鳥はうさぎの高さを飛ぶので、茂みと同じく跳んで避ける。
  高い鳥は立って走る限り当たらない。**反射で飛ぶと当たる**唯一の形である。
- 間隔は**ピクセルではなく秒**で決める(最短 0.72 秒、最長 1.6 秒)。
  340px/s で公平な間隔が 780px/s で不可能になるなら、それは間隔ではなく
  死刑宣告である。最短 0.72 秒はジャンプの滞空 0.55 秒より長いので、
  1 つを飛び越している最中に次が入ってくることはない。
- 高い鳥の**後ろ**には最低 1.1 秒を空ける。高い鳥は頭上にいる限り無害で、
  不公平になるとすれば「頭上にいる間に次の障害物のために飛ばされる」場合
  だけだからである。
- 難易度は**速度だけ**が上げる: 340px/s から 1 秒につき 3.6px/s ずつ、
  780px/s で頭打ち(約 2 分)。密度は増やさない。速くなるのであって、
  混むのではない。

## 6. スコア

- スコアは走った距離であり、それ以外の要素を持たない(40px = 1 点)。
- **スコアはコース上に描く**。5 桁ゼロ埋めで右上に、自己ベストがあれば
  その左に `HI` を付けて並べる。数字は翻訳が要らず、フォントの読み込みも
  要らない — 走者と同じ矩形で描ける(§12)。アプリの文字列としては
  読み上げ用にだけ残す(canvas は読み上げられないため)。
- 100 点ごとにスコアが 1 度だけ点滅する。**目印であって報酬ではない** —
  ボーナスも倍率も鳴り物も付かない。Reduced Motion では点滅しない。

## 7. 当たり判定

- 走者の当たり判定は描かれた姿(40×42)を四方 4px 内側に縮めたもの。
  **見た目の 1px の重なりを死としない**ため。
- 1 度でも触れれば終わり。ライフも無敵時間も持たない。エンドレスで、
  リトライが即時・無料である以上、失敗は安くあるべきで、
  「もう少しだけ生き延びる仕組み」は売り物になりうる形をしている(§13)。

## 8. 助けの形(Undo / Hint を作らない)

- リアルタイムの反射がこの遊びの中身なので、Undo は中身を空にする。
  隠れた情報がないので Hint も持たない。
- **代わりの無料・無制限の助けは「即時リトライ」**である。結果画面と
  ゲーム画面の右上から、確認も待ち時間も広告もなしに次のランへ入れる。
- 「続きから」「復活」は作らない。無料でも作らない — それは後から
  売り物にできる形をしており、この製品はその形を持たない(§13)。

## 9. 統計

- 記録するのは 4 つ: プレイ回数 / 自己ベスト / 越えた障害物の総数 /
  総プレイ時間。ストリークは持たない(どの日に遊んだかを知る理由がない)。
- 自己ベストはゲーム全体で 1 つ。難易度もレベルもないので、
  分ける根拠がない。
- プレイ時間は**走っている間だけ**数える。`ready` と結果画面は数えない。
  バックグラウンドに入った時点で、そこまでの秒は書き込む。
- オンラインランキングはない(維持費の原則。docs/PRODUCT_PRINCIPLES.md)。

## 10. 中断と再開

- **保存されるランはない**。リアルタイムのコースを復元しても、
  「開いた瞬間に生垣が目の前にある」ものにしかならない。
  ゲームを離れればそのランは終わり、次のランは無料で即座に始まる。
- 保存キーは `bh.stats` と `bh.flags` の 2 つだけ(§9 と初回チュートリアル)。

## 11. Quick Rules(アプリ内チュートリアル)

3 ステップ・図中心・各 1 文(初回起動時に表示、以後はホームから):

1. タップでジャンプ — 走りは止まらない。
2. 鳥も飛んでくる — 低い鳥は茂みと同じく跳ぶ。高い鳥は跳ばなければ安全。
3. 速くなっていく — 一度当たれば終わり、次のランはすぐ・無料。

詳細は Landing Page(`https://pixapps.ai/simple-games/games/bunny-hop/<locale>/`)へ。
**ページが公開されるまで「詳しく見る」は出さない**(`src/ui/landing.ts` の
`PUBLISHED_GAME_IDS`)。自分のサイトの 404 を初見の人に見せないため。

## 12. 演出とアクセシビリティ

- 描画はすべて矩形で、**形はソースに絵として書く**(`ui/components/sprites.ts`。
  1 マス 2px の `#` / `.` / 目の穴 `o`)。座標の配列で描いた最初の版は、
  数字としては妥当でも動物に見えなかった — 絵で書けば、形の間違いが
  差分で見える。40×42px のうさぎは曲線より四角の集まりのほうがよく読めて、
  1 フレーム数十回の `fillRect` で済み、ダークモードで色が反転しても形が
  崩れない。スプライト画像は持たない — オフラインのゲームが自分の主人公を
  描くのにバイトを待つべきではない。
- 走者はインク、障害物はアクセント。**形より先に色が「これは邪魔物だ」と
  言う**。雲と小石は `--ink-soft`。
- ぶつかった走者は**目を失う**。終わったことを、翻訳すべき言葉なしで
  伝える唯一の表現である。爆発・破片・画面揺れは作らない。
- スコアの数字も同じ矩形で描く(4×6 マスの字形)。**画像フォントも
  Web フォントも持たない**。
- Reduced Motion では、遊びに関係しない動きだけを止める:
  雲・小石・足の交互・羽ばたき・100 点の点滅は静止し、コースの流れ
  (=ゲームそのもの)とジャンプは止めない。
- 効果音は既存の合成音(services/sound)のみ。ジャンプ・100 点・
  ゲームオーバーの 3 か所で、設定に従う。
- ループはゲーム画面が見えている間だけ回る。決着後・バックグラウンド・
  アンマウントで停止する(低消費電力原則)。

## 13. 意図的な差分

- **レベルなし・デイリーなし**: エンドレスで、記録はスコアである。
  生成はシード決定的なので、必要になれば後から足せる。
- **しゃがみなし**: 入力を 1 つに絞った。ジャンプだけで答えが出る形しか
  置かないので、鳥も茂みと同じ問いになる。
- **二段ジャンプなし**(§3)・**ライフなし**(§7)・**復活なし**(§8)。
  どれも「もう少し生き延びる」仕組みであり、この製品が売らないと決めている
  ものの形をしている。
- **昼夜の切り替えなし**: 見た目のテーマはアプリ設定(ライト / ダーク)が
  すでに持っている。ゲームが勝手に画面の色を反転させない。
- スコアはあるがオンラインランキングはない(維持費の原則)。
