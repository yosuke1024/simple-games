# Hit & Blow — 正式ゲームルール

このドキュメントが Hit & Blow の仕様の正本である。実装
(`apps/simple-games/src/games/hit-and-blow/`)、テスト、Quick Rules はここに従う。
コードはここへ `§n` で言及する。挙動を変えるときは、同じコミットでこの文書を直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

ゲーム ID は `hit-and-blow`、i18n キーの接頭辞は `hitAndBlow`、保存キーの接頭辞は `hb.` である。
配信チャンネルは **Web 先行公開(`web-beta`)** で、アプリには正式収録していない
([WEB_VERSION.md](WEB_VERSION.md)「先行公開」、issue #197)。古典的な数当て
(Bulls and Cows / Hit & Blow)系の推理を、Simple Games の名前と表現で作る。
他社の商品名・盤面・ペグの配色は複製しない(§11)。

## 1. 用具と難易度

- **記号は 8 種**。順番と ID は固定で、保存と i18n はこの index と ID で読む:

  | index | ID         | 形     | キー |
  | ----- | ---------- | ------ | ---- |
  | 0     | `circle`   | 丸     | `1`  |
  | 1     | `triangle` | 三角   | `2`  |
  | 2     | `square`   | 四角   | `3`  |
  | 3     | `diamond`  | ひし形 | `4`  |
  | 4     | `star`     | 星     | `5`  |
  | 5     | `cross`    | 十字   | `6`  |
  | 6     | `hexagon`  | 六角   | `7`  |
  | 7     | `heart`    | ハート | `8`  |

  記号は**形 + 色**で区別する。形だけで全部を見分けられるように選び、色は 2 つ目の
  合図である(§10)。記号はインライン SVG で、盤面に翻訳の要る文字は 1 つも載らない。
  読み上げ名は i18n(`hitAndBlowSymbol_<id>`)。

- 難易度は 3 つ。**マスの数と使う記号の数**だけが違う:

  | 難易度   | マス | 記号         | ありうる答え |
  | -------- | ---- | ------------ | ------------ |
  | `easy`   | 4    | 6(index 0–5) | 360          |
  | `normal` | 4    | 8            | 1,680        |
  | `hard`   | 5    | 8            | 6,720        |

  (`game/types.ts` の `SLOTS_FOR` / `POOL_FOR`。ありうる答えは重複なしの順列の数 —
  §2 の方針から出る。)

- 最後に選んだ難易度は `hb.prefs` に残り、次回のホームはその難易度を先頭の
  (強調した)ボタンにする。遊び方を変える設定ではない — 選び直しを 1 回省くだけである。
  中断中のゲームがあれば、そちらの難易度が先頭になる。

## 2. 答えの生成

- 答えは seed から決定的に作る:
  ``shuffled(記号の候補, createRng(`${seed}:secret`)).slice(0, マス数)``
  (`game/engine.ts` の `secretFor`)。seed は
  `hit-and-blow-<difficulty>-<token>`(token = 起動時刻 + 乱数、Connect Four と同じ
  `newSeedToken`)。同じ seed なら必ず同じ答えになる(`compatibility.test.ts` の golden)。
- **答えは保存しない。**保存するのは seed で、答えは読み込み時に導出し直す(§8)。
  保存ファイルを開いても答えは書かれていない。
- **答えにも推測にも同じ記号は入らない。**これは明示した方針で、テストで固定する
  (`engine.test.ts`)。答えはシャッフルの先頭 N 個なので構成上重複しない。推測は入力が
  拒む(§3)。重複を許す変種は、同じ Blow が「どの記号のぶんか」を読む作業を増やすだけで、
  4 マスの推理を面白くしない。

## 3. 推測の入力

- **パレット**(画面下、その難易度の記号の数だけ)をタップすると、入力行の
  **最初の空きマス**に入る。
- 入力行の**埋まったマスをタップすると空く**。次にパレットを押せば、その空いた
  マスから埋まる。
- **すでに入力行にある記号は、パレットで無効**(押せない。`aria-pressed` で
  「使用中」を読み上げる)。入力行が全部埋まっている間は、パレット全体が無効になる —
  置く場所がない入力を黙って捨てるボタンは置かない。
- **Check** は入力行が全部埋まったときだけ押せる。押すと推測が履歴に加わり、
  入力行は空に戻る。
- **キーボード**(あれば): `1`〜`8` で記号(§1 の表、その難易度に無い番号は何もしない)、
  `Backspace` で最後に埋まったマスを空ける、`Enter` で Check。画面のボタンと同じ処理を
  呼ぶだけの別の入力経路である。すでに入力行にある記号の番号は拒み、`invalid` の音を
  鳴らす(パレットと違って無効の見た目を持てないため)。押しっぱなしのキーリピートでは
  発火しない。結果カードと確認ダイアログの間は効かない。
- **同じ推測をもう一度出すことは拒まない。**判定は前回と同じで、回数が 1 つ増える。
  履歴は常に見えているので、止める理由を足さない。
- 入力途中の行(draft)は保存しない(§8)。

## 4. 判定(Hit と Blow)

- **Hit** = 記号も位置も合っている数。**Blow** = 記号は答えに入っているが位置が違う数。
- 判定関数(`judge`)は重複があっても正しい **multiset 方式**で書く:
  Hit = 位置ごとの一致の数、Blow = Σ min(答え中のその記号の数, 推測中のその記号の数) − Hit。
  UI が重複を作ることはないが(§2)、判定は入力の出どころを信用しない形にしてあり、
  重複入りの入力でもテストする(例: 答え `[1,1,2,3]`・推測 `[1,2,1,1]` → Hit 1・Blow 2)。
- 履歴の 1 行 = 推測の記号 + **ペグ**(塗り = Hit、白抜き = Blow)+ 数(`2 · 1`)。
  ペグは Hit を先に、Blow を後に並べる — **どの位置が Hit かは示さない**。位置を
  示せば推理そのものを渡すことになる。読み上げは「Hit 2、Blow 1」の形の一文で、
  色にも形にも頼らない。

## 5. 終了条件

- **Hit = マス数 で勝ち**(答えと同じ並び)。遷移は `status`(`'playing' | 'won'`)で
  一度だけ起きる(`game/session.ts`)。
- **推測回数の上限は置かない。**ライフもゲームオーバーもない。解けるまで何回でも
  推測できる。
- 途中でやめるのは、上部の「新しいゲーム」(確認あり)かホームで別の難易度を選ぶこと
  (確認あり)。やめたゲームの答えは表示しない — やめることは負けでも答え合わせでもない。

## 6. 助けの形

- **Undo も Hint も作らない。**推測は情報であり、一度出した推測を消せば、その上に
  積んだ推理が壊れる。Hint は「どれを試せば多く分かるか」を教えることになり、
  推理そのものを肩代わりする。
- **メモ・消去の道具(この記号は無い、と印を付ける機能)は v1 では作らない。**
  履歴が常に見えていることがこのゲームの助けであり、4〜5 マスの推理は履歴だけで
  追える大きさに収めてある(§1)。要望が出たら、この節を直してから作る。

## 7. スコアと統計

- スコアは**推測回数**(少ないほど良い)。結果カードに回数を出し、その難易度の
  自己ベストがあれば一言添える(更新したときは「自己ベスト」、そうでなければ
  ベストの回数と差)。比べる相手は自分の記録だけである。時間は結果カードに出さない。
- 統計は難易度ごとに `played`(開始した回数)・`solved`(解いた回数)・
  `bestGuesses`(最少の推測回数、未達成なら null)・`totalGuesses`(解いたゲームの
  推測回数の合計。平均 = `totalGuesses / solved`)、全体で `totalPlaySeconds`。
  ストリークは数えないし表示しない。
- **放棄したゲームは解けなかった記録にしない**(`played` には開始時に数えている)。
  平均も解いたゲームだけで出す — やめたゲームの回数が平均を悪く見せることはない。
- プレイ時間は逐次計上(bookedRef 方式、Connect Four §7 と同じ)。

## 8. 中断と再開

- **途中保存する。**保存スロットは 1 つ(`hb.saveGame`)。デイリーは無いので 2 スロット
  規則(`src/test/savedGameSlots.test.ts`)の対象外。
- 保存するのは(`hb.saveGame`、v1)seed / difficulty / guesses(記号 index の列の列)/
  elapsedSeconds / savedAt。**答えは書かない**(§2)。**入力途中の行も書かない** —
  再開した画面の入力行は空である。
- 保存するのは、ゲームを始めたとき・推測を出したとき・画面を離れるとき・背景へ
  回るとき(盤面の保存と未計上秒の計上を同じ同期処理で行う)。
- **検証は fail-closed。**プレイから生まれえないレコードは読み捨ててホームへ戻す
  (勝手に新しいゲームを始めない):
  - 推測の長さがその難易度のマス数と違う
  - 記号の index がその難易度の記号の数の範囲外
  - 1 つの推測に同じ記号が 2 回ある
  - **最後の推測が答え**(終局済み — 次のゲームは無料で、新しく始まる)
- 保存キーは `hb.saveGame` / `hb.stats` / `hb.flags` / `hb.prefs` の **4 つ**。
- ホーム画面ショートカット(issue #113)から開いたときは、中断中のゲームがあれば
  その盤面へ直接入る(Quick Rules を見る前は除く)。
  Quick Rules を終えると、待っているゲームがあればそれを再開する(新しく始めて上書きしない — フラグと保存は別々の記録なので、フラグの書き込みだけが失われることがある)。
- 保存の失敗でゲームを止めない。バリデータは例外を投げない。

## 9. Quick Rules(アプリ内チュートリアル)

3 ステップ・図中心・各 1 文(初回起動時に表示、以後はホームから):

1. 隠れた記号の並びを当てる。
2. 記号を並べて Check。
3. ● は記号も位置も合っている、○ は記号だけ合っている。何回でも推測できる。

初回に最後まで進むと Easy のゲームが始まる。ハードウェアの戻るボタンで離れた場合も
「見た」ことにする(issue #142)。ゲーム別 Landing Page はまだ無い(先行公開中)ので、
「詳しく見る」は出ない。

## 10. 演出とアクセシビリティ

- **記号の色はゲームの中身**なので、このゲームの CSS が持つ
  ([architecture/css-split.md](architecture/css-split.md) — Memory Match の記号色や
  Connect Four の相手色と同じ線)。`ui/hit-and-blow.css` にライト / ダーク各 8 色を置き、
  どれも地色(`--surface`、および画面の下地 `--paper`)に対して **3:1 以上**
  (`ui/contrast.test.ts` が CSS から計算し直して固定する)。8 色は互いに色相が離れて
  いるが、**色だけに頼らない** — 形が 8 つとも違う。
- ペグは塗りと白抜きの**形**で Hit と Blow を分け、数(`2 · 1`)も並べる。
- 入力行の各マスはボタンで、「マス n: 記号名」または「マス n: 空き」を読み上げる。
  パレットの各記号もボタンで、記号名を読み上げる。履歴の各行は推測の記号と
  「Hit n、Blow n」を 1 つのラベルで読み上げる。
- 新しい行が履歴に加わったら、その行を履歴の中でスクロールして見せる
  (即時。スムーズスクロールはしない)。
- 360×640 で画面全体はスクロールしない: 履歴だけが自分の領域の中でスクロールし、
  入力行・パレット・Check は画面の下に固定される。
- 効果音は既存の合成音(`services/sound`)のみ: 記号を置くと `select`、拒まれた
  重複で `invalid`、Check で `match`、正解で `clear`。設定に従う。
- **解けてから結果カードが出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。
  最後の行(全部 Hit)を見る時間である。Reduced Motion では即時に出す。
- **時計を出さない**。経過時間は統計にだけ残る。

## 11. 意図的な差分

市中の数当て / コード当て系アプリを調べたうえで、意図的に合わせないものを記録する。

**ブランド原則により合わせないもの**

- **推測回数の上限・ライフ・ゲームオーバー**(作らない。§5)。
- **プレイ中のタイマー表示**、ストリーク、オンラインランキング(作らない)。
- Hint を広告視聴やコインの報酬にすること(Hint そのものが無い。§6)。

**設計判断として合わせないもの**

- **他社の名称・盤面・配色。**「Mastermind」は他社の商品名であり、名前も、
  縦長の穴あき盤も、ペグの 6 色の配色も複製しない。古典的な Hit & Blow の呼び名と
  記号 8 種で作る(Reversi / Crown Grid と同じ物差し)。
- **同じ記号の重複**(答えにも推測にも入れない。§2)。
- **Undo**(作らない。推測は取り消せない情報である。§6)。
- **メモ・消去の道具**(v1 では作らない。§6)。
- **答えの表示・ギブアップ**(作らない。やめたゲームの答えは出さない。§5)。
- **同じ推測の再提出を止めること**(止めない。§3)。
