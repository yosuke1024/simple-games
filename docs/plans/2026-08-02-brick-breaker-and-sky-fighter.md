# Brick Breaker と Sky Fighter — アーケード2本の本実装計画 (2026-08-02)

プロトタイプ2本(ブロック崩し・縦シュー)で手応えが確認できたため、正式タイトルとして
収録する。同じリリースでストア副題を **"Offline Puzzles" → "Offline Games"** に変更し、
「パズル集」から「ゲーム集」へ位置づけを広げる。

## 決定事項(ユーザー承認済み)

| 項目         | 決定                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| 収録         | Brick Breaker(ブロック崩し)と Sky Fighter(縦シューティング)の**両方**   |
| 正式タイトル | `Brick Breaker`(id: `brick-breaker`) / `Sky Fighter`(id: `sky-fighter`) |
| ストア副題   | `Simple Games: Offline Games`(27字。30字制限内)                         |

## 前提(検証済み)

- プロトタイプは `prototype.html` + `src/games/{block-breaker,vertical-shooter}/` に実装済み。
  エンジンは純TS・固定タイムステップで、**24ユニットテスト通過**、既存770テストに影響なし。
- 描画は Canvas 2D + rAF(このシリーズ初のゲームループ)。低スペック床(Chromium 88 /
  es2018)で問題になる API は使っていない。DPR上限2、shadowBlur/filter 不使用。
- ループは visibilitychange で完全停止(低消費電力原則)。
- `setPointerCapture` は捕捉失敗で操作を殺さないよう try/catch 済み(実バグ修正)。

## ゲーム仕様の要点(ルール文書の骨子)

両ゲームとも「静かなアクション」として設計する。**敵は撃ってこない・急かす演出をしない・
失敗は即時無料リトライ**。プレイ中に時計を表示しない。Undo / Hint は作らない
(リアルタイムであり、隠れた情報もないため — 各ルール文書の「助けの形」に理由を明記)。

### Brick Breaker

- **進行**: 100レベルの梯子。レベル = シード生成の左右対称な配置(`generator.ts`)。
  生成は決定的。

  **初期試作の単調さと、その修正**(2026-08-02 実測): 配置は**3種類の無限ループ**、
  速度は**27面で頭打ち**、面の中では速度一定 — 面をまたぐ方向でも面の中でも
  変化がなかった。加えて自動プレイ検証で、球が**完全な垂直往復に入り96秒間
  ブロックを1つも壊さない**膠着を観測した。次の3点で作り直した。

- **難しくなる方向(面の中)**: ブロックを壊すほど球が加速する。盤面が減っても
  簡単にならない。
- **強くなる方向(面の中)**: 枠だけで描かれた**ボールブロック**を壊すと球が増える
  (最大3個)。球を1つ失ってもライフは減らず、**最後の1個を失ったときだけ**
  ライフが減る。Sky Fighter の砲門と同じ言語(無料・面内で完結・持ち越しなし・
  上限あり)だが、動作は「受け取る」ではなく「壊して出す」。
- **壁のせり下がり(ユーザー提案)**: ブロック全体が毎秒数 px ずつ下がり、パドル上の
  点線に触れたらライフに関係なく**そのレベルは失敗**。これが膠着を構造的に不可能にし、
  「なんとかクリア」の緊張を作る。
  **急かさない原則との関係**: 禁じているのはカウントダウン・エナジー・期間限定の
  ような**人工的な急かし**であり、これは数字を一切出さない。**盤面そのものが残り時間**で、
  増える UI は点線1本だけ。タイマー表示より正直だという整理をルール文書に明記する。
  実測: レベル1で毎秒3px、レベル100で毎秒8px。
- **操作**: ドラッグ追従 + ←→。パドルの当て位置で反射角 ±60°(検証済みの中核の面白さ)。
  パドル幅はレベルとともに 76 → 56 px と狭まる(表示しない難易度レバー)。
- **ライフ**: 3/挑戦。クリアで次レベル開放。スコアは v1 では持たない。
- **中断**: バックグラウンドでポーズ(ループ停止)。ゲーム退出で挑戦は破棄 —
  リアルタイム盤面の途中保存は作らない(§意図的な差分に記録。復元した瞬間に死ぬ
  保存は保存ではない)。
- **storage**: `progress` v1(最高クリアレベル)+ `stats` v1(挑戦数・クリア数・playSeconds)。
- **カーブ実測**:

  | レベル | 行  | ブロック | パドル幅 | 球速(開始→終了) | ボールブロック | せり下がり |
  | ------ | --- | -------- | -------- | --------------- | -------------- | ---------- |
  | 1      | 3   | 16       | 76       | 240→288         | 1              | 3 px/s     |
  | 25     | 4   | 24       | 71       | 262→348         | 1              | 4.2 px/s   |
  | 50     | 5   | 28       | 66       | 285→403         | 1              | 5.5 px/s   |
  | 100    | 7   | 56       | 56       | 330→480         | 2              | 8 px/s     |

### Sky Fighter

- **進行**: **100レベルの梯子**(Brick Breaker と同じ。エンドレス案から変更)。1レベル =
  4〜6 wave、全 wave を捌ければクリア、ライフ3を失えば失敗して同じレベルを即時無料で再挑戦。
  敵機は 大→中×2→小×2 と分離し、小さいほど高得点。

  **エンドレスをやめた理由**(2026-08-02 実測): 初期案は wave 9 で敵機の数、wave 18 で
  落下速度が上限に達し、以降**何も変化しなくなっていた**。一方 power は wave 2 で最大に
  届いていたため、「最大強化のまま変わらない盤面が延々続く」形だった。
  `game/levels.ts` の全レバー(数・大型機率・速度・wave 数)を level に対して連続にし、
  100 まで飽和しないことをテストで固定する。

- **レベル内の弧(この設計の中心)**: レベル開始時は**必ず砲門1**。wave が進むほど難しく
  なり、その間にトークンで強化され、**最終 wave が一番きつい**。強化はレベルをまたいで
  持ち越さないので、この緊張は毎レベル作り直される。
  実測(レベル1): wave1 power1 → wave3 で power2 → wave4(最終・敵機3機)を power3 でクリア。
  実測(レベル50): 途中で被弾して power 2→1 に落ち、取り返して最終 wave をライフ2でクリア。
  同時表示は最大8個。
- **敵の攻撃(2026-08-02 追加)**: 当初は敵弾ゼロだったが、戦闘機テーマにした以上
  受け身すぎるため、**爆撃機(tier 0)だけが撃つ**。全機を武装させない理由は2つ。
  画面が埋まって分離・接触・強化喪失の上に4つ目の圧力が乗ることと、**機種の区別に
  戦術的な意味を与えたい**こと — 「まず爆撃機を落とす」という優先順位が生まれ、
  分離した戦闘機・小型機は非武装なので、落とすほど空が静かになる。
  - 弾速 175(自機の 540 より遅い)。反応ではなく**避けて動く**速さ。
  - 発射間隔 2.3 秒。編隊が同時に撃たないよう、シードから機体ごとにずらす。
  - 画面外(y ≤ 0)の爆撃機は撃たない。被弾はライフ -1・砲門 -1・1.2秒の無敵で、
    接触と完全に同じ扱い。
  - 描画は**縦長のトレーサー**。自機の丸い弾と形で見分けがつき、色を増やさない。
- **残る2原則**: 通り抜けた敵機はライフを取らない(失うのは点数だけ)/ wave 間に
  0.9秒の静かな間(タイマーではない)。
- **操作**: ドラッグ + ←→ のみ。射撃は自動(動くこと = 狙うこと)。
- **ライフ**: 3。被弾後1.2秒の無敵(点滅表示)。
- **テーマ(2026-08-02 変更)**: 当初は「泡を割る」= 静かなトーンを守るための設定だったが、
  ユーザー判断で**戦闘機と敵機**へ変更し、タイトルも Bubble Pop → **Sky Fighter** に改名した。
  - 自機は上を向き、敵機は下を向く。**向きの対立だけ**で敵味方が読め、色は
    「敵=アクセント / 自機=インク」の2値。凡例も翻訳文字列も不要。
  - **撃墜は爆発させない**。機体が縮み・傾き・薄くなって220msで消える。破片・閃光・
    画面揺れは作らない(シリーズの静かなトーンを保つため)。
  - **敵機は大きさごとに3シルエット**(大=爆撃機 / 中=戦闘機 / 小=小型機)。
    これは「情報量は足さない」基準からの**意図的な逸脱**で、ユーザー判断。理由は
    「大きさの区別は既に存在しており、形はその区別を読みやすくするだけで、
    形によってルールは変わらない」。ルール文書の §意図的な差分に記録する。
- **強化**: 初回試作は「上手くなっても手応えが増えない」という問題があった(スコアは
  伸びるが遊び方が最後まで変わらない)。軸を**砲門数ひとつだけ**に絞って解消する。
  - **最小の敵機を落とし切ったとき**に一定確率で**小さな自機型のトークン**が落ちてくる。
    機体で受けると砲門 +1(1発 → 平行2発 → 扇状3発)。上限3、被弾で1段階だけ戻る
    (全損しない)。大型機を削るだけでは出ないので、強化は「編隊を最後まで片付けたか」の
    報酬になる。
  - 画面上のトークンは**常に1個まで**。取得アイコンが自機のミニチュアなので、HUD 表示・
    アイコン凡例・翻訳文字列がいずれも不要。強化段階は弾の見た目そのもので分かる。
  - ドロップ判定は `(seed, 敵機id)` から決定的。リプレイ性とテスト可能性を保つ。
  - **ブランド上の位置づけ**: これは「課金アイテム」でも「広告視聴による機能解放」でも
    ない。無料・ラン内で完結・持ち越しなし・通貨なし・メタ成長なし。ルール文書に
    この4条件を明記し、将来ここに課金を接続しないことを制約として残す。
  - 検証済み: エンジンに12テスト追加(計30)、ブラウザ実走でトークン出現 → 取得 →
    砲門1→2→3 と画面上の弾数増加を確認。
- **storage**: `progress` v1(最高クリアレベル)+ `stats` v1(挑戦数・クリア数・
  ベストスコア・playSeconds)。Brick Breaker と同型。
- **デイリーなし(v1)**: 生成はシード決定的なので後から足せる。§意図的な差分に記録。

## フェーズ分割

### Phase 1 — 命名・ブランド整備(小)

1. プロトタイプのフォルダ名を正式 id へ(`block-breaker` → `brick-breaker`、
   `vertical-shooter` → `sky-fighter`(実施済み))。
2. `packages/brand` の `titleAccents` に2色追加。既存8色と色相で衝突しない low-sat の
   light/onLight/softLight/dark/onDark/softDark 三つ組。候補: Brick Breaker =
   テラコッタ系(煉瓦)、Sky Fighter = シアン系(Water Sort のアクアと要距離確認)。
3. グリフ案: Brick Breaker `≡`、Sky Fighter `✦`(24グリッドSVGはUI実装時)。

### Phase 2 — Brick Breaker 本実装(大)

- `game/`: 既存 engine.ts / levels.ts / generator.ts / rng.ts + 24テストを維持
  (rng のコピー方針は water-sort の前例に従う)。生成の決定性・左右対称・盤外に
  出ないこと・100 まで飽和しないカーブ・球の増減とライフの関係・せり下がりの
  失敗条件はテストで固定済み。
- `state/`: GameContext(screen 遷移 / 挑戦ライフサイクル)、progressLogic、statsLogic。
  プレイ時間は **bookedRef 方式の逐次計上**(7ゲームと同じ側。number-match 方式にしない)。
- `storage/`: schemas.ts(`BB_STORAGE_KEYS`、キー命名は既存ゲームの実物を踏襲)、
  gamePersistence、**compatibility.test.ts(v1 の golden を最初から敷く)**。
- `ui/`: HomeScreen / LevelsScreen / GameScreen(canvas + BannerSlot)/ ResultOverlay
  (クリア・失敗 + **ResultAdSlot**)/ TutorialScreen(3ステップ・図中心)。
  canvas の色は直書きをやめ、`data-game` のアクセントトークンを computed style から
  読む(テーマ変更で再読)。sound / haptics は既存 services を GameScreen から。
  reduced-motion は UI 遷移に適用(ゲームプレイ自体は対象外と§演出に明記)。
- `docs/BRICK_BREAKER_RULES.md`: memory-match と同じ章立て(盤面/終了条件/操作/生成/
  難易度/助けの形/統計/中断と再開/Quick Rules/演出とアクセシビリティ/意図的な差分)。
  コードから §n を引用。
- i18n: `brickBreaker*` キー(~20個)。en/ja は手書き、他12言語は機械翻訳
  (購入・復元・削除・プライバシー文言は含まれない)。
- `app/registry.ts`: 1 import + 1 要素。**並び順は Minesweeper の後(4番目)を提案**
  (名前で探される可能性順の原則)。storageKeys 登録(Reset Local Data を嘘にしない)。

### Phase 3 — Sky Fighter 本実装(中)

- `game/`: 既存 engine.ts / levels.ts / waves.ts / rng.ts + 30テストを維持。
  レベル1本が目安1〜2分で、Web リザルト広告(3局に1回)の体感頻度もこれで収まる。
  実機で通しプレイした上で、レベル 60 以降の同時表示数の上限だけ再確認する。
- `state/` `storage/` `ui/` `docs/SKY_FIGHTER_RULES.md` `i18n` `registry`(**末尾10番目を
  提案**)は Phase 2 と同型。ResultOverlay はスコア + ベスト + リトライ。
- プロトタイプ基盤の撤去はここで完了: `prototype.html` / `src/prototype-main.tsx` /
  `src/prototype.css` / `window.__bbFrame` 等の TEMP フックを削除。

### Phase 4 — 文言スイープとリリース準備

1. **副題と数の更新**(ゲーム2本がマージされるリリースに同乗):
   - `apps/simple-games/store/listing.md` — タイトル第1候補を
     `Simple Games: Offline Games` に。収録リスト・キーワード優先順に2本追加、
     「8本の状態で書いてある」注記を更新。**Play Console への反映は手動・要承認**。
   - `apps/simple-games/index.html` — `<title>` / description / og(「Eight classic
     puzzles」→ 10本列挙の「Ten classic games」)。
   - `android/.../strings.xml` — コメント内の full store title(app_name は
     `Simple Games` のまま)。
   - スイープコマンド: `grep -rn "Offline Puzzles\|[Ee]ight\|8 本" README.md docs apps/simple-games --include="*.{md,html,ts,tsx,xml}"`
     で残りを拾う(AGENTS.md はローカルのみ更新・コミット禁止)。

## リスクと対処

| リスク                        | 対処                                                                               |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| 低スペック実機の 60fps 未計測 | エミュ + CPU スロットルで測定。超過時は泡の同時数上限・DPR 1.5 に調整余地          |
| 「急かさない」原則との緊張    | 敵弾なし・通過ペナルティなし・タイマー非表示・即時無料リトライをルール文書に明文化 |
| MT 12言語の品質               | ゲーム文言のみ(高リスク文言なし)。i18n テストが placeholder 整合を機械検証         |
| canvas とテーマトークンの連動 | computed style から読む方式。jsdom テストは reduced 扱いで決定的                   |
| 2本同時でレビュー量が大きい   | PR を3分割し、リリースは1回に束ねる                                                |
