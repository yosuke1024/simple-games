| | Web 版 | アプリ版 |

  Only a small banner—or remove ads permanently for $3.99."

## 1. 配信基盤(v1 から不変)

- URL 案: `https://pixapps.ai/simple-games/play/`(§7 未決)。
- **Cloudflare Pages の静的配信のみ**。Functions / Workers / D1 / KV / DO / R2 /
  独自 API / 認証 / クラウドセーブ / サーバー側生成は使わない。AdSense は
  クライアントサイドのみなのでこの原則と両立し、**継続コストゼロ**を維持。
- pixapps-landing は `pages_build_output_dir: "."` の「リポジトリ = サイト」構成。
  ビルド成果物を `simple-games/play/` としてコミットするだけで配信される
  (`jurypress/` と同じ生成物コミット運用)。`functions/_middleware.ts` の
  `validPrefixes` に `/simple-games` は登録済み → ルーティング変更不要。
- 保存はブラウザ内(Capacitor Preferences web 実装 = localStorage)。同期なし。
- ロケール解決はアプリ内(`navigator.languages`)。URL は 1 本で 14 言語対応。
- コスト注意: `_routes.json` が無いため middleware が全リクエストで起動する。
  現状の規模は無料枠内。増えたら `/simple-games/play/*` を Functions 除外 +
  `_headers` で `assets/*` 長期キャッシュ(将来の任意最適化)。

## 2. Web 広告方針(ADS_POLICY.md に「Web 版」節として明文化する内容)

許容する形式と場所:

1. **ディスプレイ広告**: ゲーム選択画面(ホーム)/ リザルト画面 / 詳細ルール・
   Landing Page / デスクトップのサイドレール。盤面や操作ボタンの近くに置く場合は
   誤タップ防止のため操作領域と十分な距離を取る。
2. **アンカー広告**(Auto ads): ゲーム中は非表示、選択・ルール・リザルト画面のみ。
3. **Vignette**(Auto ads、スキップ可): 自然な区切りのみ —
   別ゲームへの切替時 / ゲームを終えてホームへ戻るとき / 数局遊んだ後。
   **出さない**: 初回訪問時 / ゲーム開始直前 / プレイ途中 / Undo・Hint 操作時 /
   ゲームオーバー直後の毎回 / ブラウザ戻る操作時。

頻度の初期値:

- ゲーム中: 広告なし(または盤面から十分離れた固定 1 枠)
- 選択画面・リザルト画面: 各ディスプレイ 1 枠
- Vignette: 最短 15 分間隔 / 初回セッションなし / 1 セッション最大 2 回程度
- **課金・広告視聴によるゲーム機能解放はしない**(アプリと共通の絶対原則)

位置づけ: アプリより広告は多いが、一般的な無料ゲームサイトよりかなり控えめ。

## 3. 技術方針

### ビルド分岐(単一ソース・2 モード)

- `vite build`(native, 既定)/ `vite build --mode web`。web モードのみ
  `services/ads/web/`(AdSense 統合)をエントリから参照する。native ビルドは
  参照自体を持たず、バンドルに含まれない。
- **検証を CI に**: 原則ガードを拡張し、(a) native 用 dist に
  `adsbygoogle|googlesyndication` が**不在**であること、(b) 広告フォーマット識別子
  検査(Interstitial 等)は現行どおり src 全体で維持(AdSense の vignette は
  こちらの語彙に触れない)、(c) `ca-app-pub-` に加えて **`ca-pub-`** の本番 ID も
  ソース不在を検査。ポリシー文書とガードは同じ PR で更新(ガードの設計思想どおり)。
- AdSense の client / slot ID は AdMob と同様 **ビルド時 env 注入**
  (`VITE_ADSENSE_CLIENT` / `VITE_ADSENSE_SLOT_*`)。未設定なら広告なしで動く。
  ※ pub ID は ads.txt で公開済みのため秘匿情報ではないが、扱いを AdMob と揃える。
- pixapps.ai の `ads.txt` には `pub-6649925654956606` が既にあり
  (AdMob / AdSense は同一パブリッシャー ID)→ **ads.txt 変更は不要の見込み**。
  AdSense コンソールでのサイト追加・審査・Auto ads 設定・Privacy & messaging
  (認定 CMP、GDPR 同意)は人間作業(§6)。

### SPA と Auto ads の現実 → 二段階で入れる

- 手動ディスプレイユニット(`<ins class="adsbygoogle">`)は現状の URL なし SPA でも
  配置できる。**アンカーと Vignette は Auto ads 機能で URL ナビゲーションに依存**し、
  URL が 1 本のままでは「ゲーム中だけアンカー非表示」「区切りだけ Vignette」の制御が
  できない。
- **Phase A(手動ユニットのみ)**: 選択画面・リザルト画面・デスクトップサイドレール。
  アンカー・Vignette なし。
- **Phase B(hash ナビゲーション導入後)**: web のみ `#/`・`#/game/<id>` の軽量 hash
  遷移を導入(シェルの画面状態を URL に写すだけ。ルーターは入れない)。これで
  (a) Vignette のトリガーが「ゲーム切替・ホーム復帰」の実ナビゲーションになる、
  (b) アンカーのゲーム中非表示を画面単位で制御できる、
  (c) 旧計画 M3 の**ディープリンク(ゲーム別 Landing Page からの直接起動)が同時に
  手に入る**。頻度は AdSense 側設定(15 分・セッション上限)+「区切りでしか
  ナビゲーションを発生させない」実装の二重で絞る。
- 広告スロットの層構造: ゲームのリザルト画面には共有 `ui/components/WebAdSlot.tsx`
  を置く(native では常に null。ゲーム → 共有 UI の import は `BannerSlot` の既存
  前例どおり)。選択画面はシェル側。
- オフライン時: AdSense スクリプトのロード失敗・広告なしは**静かに**扱う
  (既存の広告失敗原則と同じ。リトライループなし。ゲームは常に動く)。

### レビュー導線ほか(v1 から維持)

- `services/review.ts` の `shouldPromptReview()` にネイティブ限定ガードを追加
  (ストアレビューは Android のみの概念。web では質問自体を出さない)。
- `index.html` head の Web 向け補強(description / OGP / canonical / theme-color)は
  1 枚のまま(Android WebView は余分な meta を無視)。
- es2018 床・相対 base はそのまま Web の古いブラウザにも効く。

### M2 — Web 広告 Phase A(手動ディスプレイユニット)

- §4 のドキュメント一式 + 原則ガード拡張(同一 PR)。
- ビルド 2 モード化 + `services/ads/web/` + `WebAdSlot`(選択画面・リザルト・
  デスクトップサイドレール)+ About の支援文言 + 送客ブロック(en/ja)+ i18n。
- native dist の `adsbygoogle` 不在検証を CI へ。
- 人間作業(§6)完了後に env 注入で本番有効化。未設定の間は広告なしで動く。
- **M1 の検証で判明した、M2 で決着させる論点**:
  1. **サイトの Google タグとの関係**: pixapps.ai の各ページ(`simple-games/index.html`
     等)は GA(`G-V1BJW2MQ2D`)を読み込む。**ゲーム本体(`play/`)は読み込まない**
     (M1 の UI テストで固定済み)。ただし同一オリジンなので、ランディング側の
     プライバシー記述で「アプリには解析コードがない」と「Web 版のゲーム画面にも
     解析タグを置かない」を**別々に**書き分ける必要がある。
     推奨: play/ には GA を入れない(入れると「解析なし」の説明が成立しなくなる)。
  2. **アプリ前提の文言が Web に残っている**: web で表示されるプライバシー要約
     privacy2「運営サーバーはなく」/ privacy4「アプリの削除、または…」は、
     ブラウザで読むと意味がずれる(実際にページは配信されているし、
     「アプリの削除」に相当する操作がない)。Web 専用文言を足すか、
     共通で成立する言い回しに直すかを決める。**14 言語 + プライバシー文言の
     機械翻訳禁止**が効くため、en/ja 先行になる可能性が高い。
  3. AdSense を入れると privacy3 相当の記述が Web 版にも必要になる(AdMob ではなく
     AdSense として)。上記 1・2 とまとめて 1 回で書く。
