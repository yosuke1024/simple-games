## 共通要件(5 本とも)

- **オフラインで完結**し、ログイン・サーバー・外部 API を使わない。全機能無料。Hint / Undo を
  広告や課金に結び付けない。タイムリミット・ストリーク・通知・ログインボーナスを作らない。
- **ゲームロジックは Pure TypeScript**(`game/` は React・DOM・storage を import しない)。
  Android / iOS / Web で同じルール。乱数はシード付き PRNG で決定的。
- **生成と探索には仕事量の上限**(試行回数・ノード数)を付け、上限に達したら
  「見つからなかった」と正直に返す。生成が上限に達したら、**自前の生成器で作り、テストで
  解けること(と一意性)を検証した同梱盤面**にフォールバックする。探索は同期で、明示的な
  操作(新しい盤面・Hint のタップ)のときだけ走る。ポーリングも先読みもしない
  ([GAME_LIFECYCLE.md](../GAME_LIFECYCLE.md)「CPU 探索」)。性能の門は仕事量で、壁時計は出力するだけ。
- **保存は fail-closed。**規則から生まれえない盤面・終局済みの盤面・破損データは読み捨て、
  黙って新しい対局を始めない。他ゲームのキーに触れない。デイリーを持つゲームは 2 スロット規則
  (`dailyGame` キー・`expectedMode`・`slots.test.ts`。`src/test/savedGameSlots.test.ts`)。
  日付の過ぎた中断デイリーは読み込みで捨てる(既存デイリーと同じ)。
- **シェル統合**: registry に `channel: 'web-beta'`・`loadStorageSchemas`。`storage/keys.ts` は
  import ゼロの葉。ホームは `GameHomeHeader` を 1 回、`WebBetaNotice` を置く(スキャフォールドに
  置いてあり、`src/test/webBetaNoticeWiring.test.ts` が外させない)。結果カードは
  `ShareAction`。ヘッダの ↻ は `RestartDialog`(結果カードと同じ 2 択)。Back ボタンの唯一の
  持ち主は GameContext。保存スロットが 1 つのゲームはショートカットで盤面へ直接入れる
  (`entry`)。検索・お気に入り・バックアップはシェルが registry から行う。
- **Quick Rules は最大 3 ステップ・図中心・1 文ずつ。**初回の Quick Rules を終えたら、
  そのまま 1 タップで遊べる(既存ゲームの初回フローに合わせる)。Learn More は出ない
  (ガイド未公開)。
- **UI**: 1 ゲーム 1 アクセント(ライト / ダーク)。360×640 でスクロールなしに盤面と主要操作が
  収まり、タブレット・PC では幅を使う。タッチ・マウス・キーボードで遊べる。操作対象は
  ボタン(または role 付き要素)で位置と状態を読み上げる。色だけで状態を伝えない。
  Reduced Motion を尊重。音は既存の `services/sound.ts` だけ。新しい画像・音声・動画アセットは
  足さない(盤面は CSS / インライン SVG)。盤面に翻訳の要る文字を置かない(数字は ASCII)。
- **ライフサイクル**: アンマウントで timer / RAF / listener / observer をすべて解放
  (`src/test/lifecycle.test.tsx` が自動で掃引する)。ループを持つ Snake は arcade に倣った
  `*.leak.test.tsx` を足す。一時 UI は `useTransientTimeout`。
- **i18n**: 14 言語。新しいキーは各ゲームの `i18n/*.ts`(ゲーム専用カタログ、キー接頭辞は
  上の表)。`en` が原文。`ja` と他 12 言語は **AI が書いたものであり、ネイティブ / 作者は
  まだ読んでいない**(ルール文書の i18n 節にそう書く。`ja` の作者確認は未了として残す)。
  高リスク文言(無料・オフライン・課金・削除・保存の約束)はゲーム文言に書かない。
  ヒンディー語・タイ語・ベトナム語・インドネシア語・日本語・ドイツ語でボタンと盤面が崩れない
  ことを 360 幅で確認する。
- **テスト(各ゲーム必須)**: ① ルールの単体 ② 正常系・異常系の状態遷移 ③ 生成と決定性
  ④ 保存・復元のラウンドトリップ ⑤ 破損保存の拒否 ⑥ アンマウント時の解放 ⑦ 主要操作の UI
  ⑧ Undo / Hint の正当性 ⑨ 複数シードでの問題品質(難易度の分布・一意性) ⑩ 他ゲームと
  データが衝突しない(`gameKeys.test.ts`)。探索系は成功例に加えて**ノード上限・解なし・
  複数解**のケースを検証し、生成した盤面のうち**実際に解いて確かめた範囲**(全数 / サンプル数)を
  ルール文書に書く。
- 既存 41 本の挙動・設定・保存スキーマ・golden テストを変えない。各ゲームの作業は
  **自分のフォルダと自分のルール文書**の中で閉じる(registry / gameKeys.test / styles.css /
  brand / README / WEB_VERSION 等の共有ファイルは Phase 1・4 で扱う。例外は自分のゲームの
  `gameKeys.test.ts` の 1 エントリだけ)。

## 42. Unblock Puzzle(`unblock-puzzle`)

6×6 の盤面でブロックをスライドさせ、ターゲットを右の出口から出す空間推理パズル。
Sliding Puzzle(15 パズル)とはルール・id・保存キーを完全に分ける。

- **盤面**: 6×6。ターゲットは横向き・長さ 2・上から 3 行目(行 index 2)に固定。出口は
  3 行目の右端。他のブロックは横 / 縦、長さ 2 または 3。重なり・盤外・回転は禁止。
- **一手**: ブロック 1 つを自身の向きに沿って連続でスライドさせる 1 回を 1 手と数える
  (移動マス数とは区別し、両方を数える)。ターゲットが右端(列 4〜5)に着いたらクリア。
  初期状態でクリア済みの盤面は出さない。
- **生成**: シードから決定的。解けた配置を作り、その配置が属する状態グラフを幅優先探索で
  上限つきに列挙し、ゴールからの距離が最大(または難易度帯に入る)状態を出題する
  (ゴール集合からの多始点 BFS)。最短手数は BFS で検証する。難易度は**最短手数と探索上の
  複雑さ**(状態数・分岐など)で分類し、しきい値は複数シードの実測分布から決めてルール文書に
  書く。Hard が簡単にならないこと(Hard の最短手数の下限)をテストで固定する。
  試行回数・ノード数に上限を付け、上限で同梱の検証済み盤面へフォールバックする。
- **操作**: ドラッグでスライド(タッチ / マウス)。タップだけでも遊べる代替(ブロックを
  タップで選び、行き先のマス / 矢印ボタンをタップ)。キーボード(ブロックの選択と矢印キーで
  移動)。Undo 無料・無制限、Reset で同じ盤面へ。
- **Hint**: 現在の状態から BFS(上限つき)で最短解の最初の一手を示す(盤面を勝手に動かさない)。
  上限に達したら推測を正解として出さず「見つからなかった」と言う。
- **モード**: Easy / Medium / Hard の Free Play(何度でも新しい盤面)と、端末のローカル日付の
  Daily 1 問(Medium)。過去日への遡り・ストリークは作らない。
- **テスト**: 合法移動 / 衝突 / 勝利 / 最短手数(独立な総当たりと照合)/ シード再現性 / Undo /
  Hint(示した手で最短手数が 1 減る)/ 生成上限とフォールバック / 保存・復元。

## 43. Snake(`snake`)

固定グリッドでヘビを操作し、食べ物を取り、壁と自分を避けるクラシックアーケード。

- **規則**: 固定サイズの盤(360 幅に収まる大きさ。ルール文書で確定)。一定間隔の tick で
  1 マス進む。食べ物を取ると 1 マス伸び、スコアが増える。壁か自分に当たればゲームオーバー。
  正反対への即時転換は禁止。食べ物はヘビのいないマスに出る。盤面全体がヘビで埋まったら
  クリアとして終了。障害物・パワーアップ・課金アイテムは作らない。
- **衝突の順序**: 新しい頭の位置を求め、食べ物なら尾は残る(伸びる)、そうでなければ尾が
  先に抜ける — **食べないときに頭が今の尾のマスへ入るのは合法**。テストで固定する。
- **入力**: 方向入力は次の tick で適用。短時間の複数入力はキュー(上限あり)に積み、各入力を
  「直前に積んだ方向」に対して検証して、tick をまたいでも 180 度転換が起きないようにする。
  スワイプ・画面上の方向ボタン・矢印キー / WASD。
- **モード**: Endless のみ。速度 Slow / Normal / Fast(既定 Normal。選択を強制しない — `sn.prefs`)。
- **UX**: 開始前に盤面が見える。Start / Pause / Resume / Restart。バックグラウンド(visibilitychange /
  native pause)で自動停止し、**復帰後に勝手に再開しない**(再開はタップ)。Undo / Hint は作らない。
  派手な演出・連続再描画をしない(描画は tick でだけ変わる)。
- **技術**: Pure TS の `step(state, input)`。描画更新と tick を分離。食べ物の生成は PRNG 状態ごと
  保存・復元できる(同じ状態から同じ食べ物)。画面を離れたら timer / RAF / listener を解放。
  保存は毎 tick ではなく Pause・バックグラウンド・退出・終局で。
- **テスト**: 方向転換(連打で 180 度にならない)/ 衝突(壁・自分・尾の追いかけ)/ 成長 /
  食べ物生成(空きマスのみ・決定的)/ 満杯クリア / Pause / Resume / バックグラウンド復帰で
  止まったまま / シード決定性 / リソース解放(leak テスト)。

## 44. Loop Puzzle(`loop-puzzle`)

数字を手がかりに格子の辺をつなぎ、1 本の閉じたループを作る論理パズル(一般に Slitherlink と
呼ばれる形式。正式名称は Loop Puzzle)。

- **規則**: 正方形グリッドの点を辺で結ぶ。数字 0〜3 はそのマスを囲む 4 辺のうちループに
  含まれる本数。空白は指定なし。線は 1 本の閉じたループで、交差・分岐・複数ループは禁止。
  使う頂点の次数は 2、使わない頂点は 0。数字の条件と単一ループの条件をすべて満たせばクリア。
- **モード**: Easy 4×4 / Medium 5×5 / Hard 6×6(マス数)の Free Play と Daily(Medium)。
- **操作**: 辺をタップで Unknown → Line → X → Unknown。X は「含めない」のメモで、完成判定は
  Line だけを見る。辺の当たり判定はトラック幅いっぱいに広く取る。Undo 無料・無制限。
- **生成と検証**: ランダムな単純閉路(穴のない領域の境界)を作り、数字を計算し、解の個数を
  最大 2 まで数えるソルバーで一意性を保ちながら手がかりを削る。生成・探索に仕事量上限。
  公開する問題は一意解を保証する。不完全な探索(上限到達)で一意と宣言しない。検証済み盤面の
  同梱も可。難易度はサイズだけでなく、必要な推論の深さ・手がかりの密度で調整する。
- **支援**: Hint は検証済みの解と現在の状態に基づく(解と違う Line / X があればそれを示す。
  無ければ解の 1 辺を示す)。勝手に書き換えない。矛盾(次数 3 以上・数字超過など)はそれと
  伝える。満たした数字は穏やかに示す(色だけに頼らない)。
- **テスト**: 頂点次数 / 閉路の連結性 / 複数ループの拒否 / 数字の制約 / 未完成の拒否 /
  一意解の検証(複数解・解なし・上限到達のケース)/ シード再現性 / 保存・復元。
- **文書**: Number Path(番号順の一筆書き・マスを通る)と Dots and Boxes(対戦・箱を取る)との
  ルールの違いをルール文書に書く。

## 45. Bridges(`bridges`)

数字の島を橋でつなぎ、すべての島を 1 つのネットワークにする論理パズル(一般に
Hashiwokakero と呼ばれる形式)。

- **規則**: 各島に接続する橋の本数 = 島の数字。橋は水平・垂直のみ。同じ 2 島間は最大 2 本。
  橋は島や他の橋を横切れない(島を飛び越えた接続は不可 — 隣接は「その方向で最初の島」)。
  橋を介して全島が連結。ネットワーク内のループは禁止しない。
- **モード**: Easy / Medium / Hard(盤サイズ・島数・推論の複雑さ)の Free Play と Daily(Medium)。
- **操作**: 島を選び、接続可能な島をタップすると、その 2 島間が 0 → 1 → 2 → 0 本と切り替わる。
  選んだ島の接続候補を見やすく示す。細い橋の線を唯一の操作対象にしない。Undo 無料・無制限。
- **生成**: 島の配置と解のネットワークを生成し、数字を結果から計算する。解のある問題だけを
  出し、原則として一意解を確認する(解の個数を最大 2 まで)。交差禁止・本数・全島連結を検証。
  ノード数・試行数に上限、失敗時は検証済み盤面へフォールバック。
- **Hint**: 現在の状態が解と矛盾しないかを確かめ(矛盾していればそれを伝える)、解へつながる
  橋の情報を示す。探索に失敗したら不確実な答えを出さない。
- **テスト**: 接続数 / 交差 / 2 本上限 / 島の飛び越え禁止 / 連結判定 / 一意解(複数解・解なし・
  上限)/ 保存・復元 / タッチ操作。

## 46. Peg Solitaire(`peg-solitaire`)

コマを跳び越えて取り除き、できるだけ少なく残すクラシックパズル。カードの Solitaire とは
別の独立ゲーム(別 id・別接頭辞・別ルール文書)。

- **English Board**: 十字型 33 穴。開始は中央 1 穴が空き、32 個。コマは縦横に 2 穴移動し、
  間の穴にコマが必要、行き先は空き。跳んだコマを取り除く。斜めは禁止。最後の 1 個が中央に
  残れば完全クリア。合法手が無くなれば終了し、中央以外に 1 個 / 複数個残った場合は完全クリアと
  区別して結果を出す。
- **Triangle Board**: 15 穴。三角格子の 3 軸(6 方向)に沿ったジャンプを許す。English と合法方向が
  違うことをロジックとテストで明示する。開始の空き穴と目標穴は、**解けることを確認した
  組み合わせだけ**(全状態の探索 2^15 で検証)。
- **操作**: コマをタップで選択 → 行ける穴を表示 → 行き先をタップでジャンプ。ドラッグにも対応
  (必要なら)。キーボード対応。Undo 無料・無制限。Restart で同じ盤面へ。Hint は作らない
  (詰めの判断そのものがゲームである)。
- **モード**: English / Triangle を選ぶ。デイリー・ステージ制・時間制限は作らない。
- **統計と保存**: 進行中の盤面 / 盤ごとの最少残存数 / 完全クリアの回数 / 累計プレイ時間。
- **テスト**: 合法ジャンプ / ジャンプ後の除去 / 斜め禁止(English)/ Triangle の 6 方向 / 盤外 /
  勝利 / 手詰まり / Undo / 2 盤面 / 解ける組み合わせの検証(English は既知解の再生で中央 1 個に
  なること)/ 保存・復元。
