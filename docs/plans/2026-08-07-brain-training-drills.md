# 脳トレドリル 3 本 — Quick Math / Schulte Table / Number Recall の実装計画 (2026-08-07)

新ジャンル「脳トレドリル」を 3 本で立てる。既存収録は熟考型パズルとアーケードが中心
で、このジャンルは「1 プレイ 1〜3 分の反復と自己記録の更新」を中身とする — 重複しない
柱になる。3 本とも盤面は数字と記号だけで成立し、生成も記録も端末内で完結する
([CONTRIBUTING.md](../../CONTRIBUTING.md) の収録条件)。翻訳できない文字を盤面に
埋め込まない([I18N_POLICY.md](../I18N_POLICY.md))という原則に対しても、このジャンルは
最初から適合している — 追加する i18n キーは UI ラベルだけで、盤面は ASCII 0-9 のまま。

**この文書は着手前の実装計画である。**実装は未着手。仕様の正本は実装時に
`docs/QUICK_MATH_RULES.md` / `docs/SCHULTE_TABLE_RULES.md` / `docs/NUMBER_RECALL_RULES.md`
として起こし、以後はそちらが勝つ。

## 提案(実装はこの既定で進める。変える場合は本文書を更新してから)

| 項目         | Quick Math                     | Schulte Table                        | Number Recall                     |
| ------------ | ------------------------------ | ------------------------------------ | --------------------------------- |
| id           | `quick-math`                   | `schulte-table`                      | `number-recall`                   |
| 保存接頭辞   | `qm.`                          | `st.`                                | `nr.`                             |
| i18n 接頭辞  | `qmath*` + `quickMathName`     | `schulte*` + `schulteName`           | `recall*` + `recallName`          |
| グリフ       | `±`(代替 `÷`)                  | `⌖`(代替 `25`)                       | `?`(代替 `⁇`)                     |
| 進行         | 100 レベル + デイリー          | 100 レベル + デイリー                | 100 レベル + デイリー             |
| 助け         | 無制限の解き直し(Undo/Hint なし) | 即時無料リトライ(Undo/Hint なし)   | 同レベル新配置の即時リトライ      |
| 途中保存     | あり(問題単位で再開)           | なし(1 テーブル数十秒)               | なし(1 ラウンド数秒)              |

- **名前はジャンル / 動作をそのまま名乗る**流儀([BRAND.md](../BRAND.md)、Water Sort /
  Block Puzzle / Bunny Hop と同じ)。`Schulte Table` は学術姓由来だが、このジャンルの
  検索語そのものであり、人名由来のジャンル名は Nonogram の前例がある。`Number Recall` が
  Number Match と語を共有するのは、Memory Match / Number Match が既に「Match」を
  共有しているのと同型で許容する。3 語とも他社商標ではない(実装時に最終確認)。
- 並び順は **Number Match の直後に 3 本を束ねる**(数字系の並び。検索されやすさ順に
  Quick Math → Schulte Table → Number Recall)。FreeCell ブランチが上位の並びを
  変えるため、確定は後から入る側の rebase 時。
- グリフ `⌖` は Sudoku の `⌗` と同じ Misc Technical ブロックで描画リスクは同等。
  `?` はヘルプボタンと紛れる懸念があるため、ホームでの見た目確認で代替 `⁇` と
  比較して確定する(Reversi が実装時に色を差し替えた前例に倣う)。

選定の理由:

- **Quick Math = マスタード `#8c831e`**。鉛筆とドリル帳の黄色。Brick Breaker の黄土
  (h40)と Bunny Hop のオリーブ(h70)のちょうど中間(各 15°)で、コレクションに
  「黄色」と呼べる札を初めて足す。
- **Number Recall = エメラルド `#2f7a3e`**。伏せた札をめくるテーブルの緑。Solitaire の
  セージ(h104)と 2048 のジェイド(h154)の間で、**現在の色相環で最も広い空き**
  (各 28° / 22°)。ダークは 2048 の `#79c39c` と隣接するため、確定時に距離を実測する。
- **Schulte Table = ペトロール `#187a7e`**。静かな集中の青緑。Sudoku(h168)と
  Water Sort(h199)の間(各 14° / 17°)。彩度を両隣より上げて暗く沈め、
  「濃いティール」対「灰みのスチール」として読み分ける — 同一色相帯を彩度で分けるのは
  Minesweeper(h216 灰)と Number Match(h219 藍)が既にやっている分け方である。
- 3 色とも白インク前提で明度を揃えた(概算コントラスト: マスタード 3.9:1 /
  エメラルド 5.3:1 / ペトロール 5.1:1)。**確定は [BRAND.md](../BRAND.md) の基準
  (本文 4.5:1 / アクセント面 3:1、両テーマ)を実装時に実測してから**。ダーク値は
  シリーズの流儀(同色相の明色化)に沿った提案値で、同じ実測を通す。
- 色相環はこの 3 本 + FreeCell + Spider で **20 スロットがほぼ埋まる**。以後のゲームは
  色相ではなく明度・彩度の帯で差を作ることになる — 次の計画への申し送り。

## ジャンル共通の原則(3 本すべてに適用)

1. **時間は計るが、プレイヤーを止めない。**「60 秒で何問」型は作らない。すべて
   「この課題を仕上げるのに何秒かかったか」型(時間切れが構造的に存在しない)。
   時計はプレイ中に表示せず、結果と統計でだけ見せる(Memory Match §4 の前例)。
2. **効能を謳わない。**「脳年齢」「IQ」「認知機能の改善・予防」をアプリ内文言・
   ストア文言のどちらにも書かない。科学的裏付けが係争的な主張であり、Honest by
   design と両立しない。**`.github/scripts/check-principles.sh` §6 の禁止表現に
   脳年齢 / brain age / IQ / 認知症 / dementia / cognitive improvement を追加して
   コードで強制する**(en/ja のみ grep 可能という既存の限界はそのまま)。
3. **スコアを発明しない。**指標は時間と正確さ(誤答・誤タップ数)だけ。抽象ポイント・
   偏差値・ランクを作らない(FreeCell 計画の「スコアは作らない」と同じ判断)。
4. **ストリークなし。**デイリーは既存どおり達成日カレンダーの記録のみ。
5. **急かす演出をしない。**カウントダウン・点滅・警告音を作らない。誤答/誤タップは
   叱らず(Solitaire の「無効操作を叱らない」)、記録にだけ残す。

## 前提(調査済み)

**Number Match(実装 約 2,100 行)が骨格の正本。**「100 レベル + デイリー + DOM 盤面」の
最小完全形で、3 本ともこの骨格(`game/ state/ storage/ ui/ i18n/`、
`levels.ts` / `daily.ts` / `session.ts` / `progressLogic.ts` / 6 スクリーン構成)を写す。

- **`rng.ts`(xmur3 + mulberry32 + Fisher–Yates)はゲームごとにコピーが正**。共有しない。
- デイリーは per-game 実装 + 共有クローム。**過去 30 日は無条件に開く**(Solitaire 型。
  進行でゲートしない)。
- プレイ時間は ref + 可視時のみ加算 + bookedRef 方式の逐次計上。
- 3 本とも **Canvas を使わない**(DOM + CSS のみ)。RAF ループが無いので lifecycle は
  掃引テスト(`src/test/lifecycle.test.tsx`)の自動編入で足り、`*.leak.test.tsx` は
  不要。一時演出(誤答の明滅・失敗時の開示)は `useTransientTimeout` のみ。
  低消費電力の原則に対して最も軽い部類のゲームになる。
- **ゲーム追加の接続点**(PR #45 が実物): ゲームフォルダを作ればチャンク・lifecycle・
  i18n 型強制・サイズ計測は自動編入。手で触るのは `app/registry.ts` /
  `app/gameKeys.test.ts` / `ui/styles.css`(アクセント 2 ブロック × 3)/
  `packages/brand` の `titleAccents` × 3 / `size-baseline.json`(`pnpm size:update`)/
  `ui/landing.ts` は触らず `landing.test.ts` の「リンクなし」配列に 3 id を足す /
  文書類(Phase 4)。
- レビュー依頼は **L11 以上のレベルクリアとデイリー完了だけ** `recordGameCompleted()` を
  呼ぶ(序盤レベルは数十秒で終わるため。Bunny Hop の score≥100 と同じ理由。
  [REVIEW_PROMPT_POLICY.md](../REVIEW_PROMPT_POLICY.md))。
- i18n は 1 本あたり 25〜30 キー × 14 言語を見込む。**高リスクキーは発生させない**:
  ゲーム文言に無料・オフライン・課金の約束を書かない(書いた瞬間に
  [I18N_POLICY.md](../I18N_POLICY.md) の門の対象が増える。約束はシェルが既に語っている)。

## ゲーム仕様の要点(ルール文書の骨子)

ルール文書は 3 本とも既存の 13 章テンプレート(盤面 / 勝利条件 / 操作 / 手数・時間 /
生成 / デイリー / (ゲーム別章) / Undo と Hint / 統計 / 中断と再開 / Quick Rules /
演出とアクセシビリティ / 意図的な差分)で書く。

### Quick Math(計算ドリル)

- **1 レベル = 10 問**。出題はシード決定的。誤答は同じ問題を解き直し(先へ飛ばない)、
  誤答数を記録。全問正解でクリア、かかった時間が記録。
- レベル曲線: L1–20 加減算(1 桁 → 2 桁。引き算は答えが負にならない範囲)/
  L21–40 掛け算(九九 → 2 桁 × 1 桁)/ L41–60 割り算(割り切れる問題のみ)/
  L61–80 虫食い(`7 + □ = 15`、`6 × □ = 42`)/ L81–100 混合 + 連鎖(`12 + 7 − 9`)。
  九九帯(L21–30)が「学習系」の実需(子どもの計算練習)への入口を兼ねる。
- 入力は画面下の 0–9 キーパッド(このゲーム専用 UI。盤面数字は ASCII)。
- デイリー: 日付シードの混合 20 問。
- **Hint を作らない**(中身が「自分で計算すること」なので、答えを教える助けは中身を
  空にする)。**Undo も作らない**(確定した答えは正誤どちらかで、取り消す対象がない)。
  助けは「無制限・無ペナルティの解き直し + 問題単位の途中保存」。
- 保存キー: `qm.progress` / `qm.session` / `qm.stats` / `qm.flags`。

### Schulte Table(順タッチ)

- N×N に散った数字を 1 から順にタップする。全部タップで完了、時間と誤タップ数が記録。
  誤タップは無反応 + カウントのみ(叱らない・進行は止めない)。
- レベル曲線: L1–20 3×3 / L21–50 4×4 / L51–85 5×5 /
  L86–100 5×5 変則(逆順 25→1、奇数→偶数、2 色交互 = Gorbov 変形)。
- 配置は Fisher–Yates。同一シード同一配置(golden テスト)。
- デイリー: 日付シードの 5×5 標準 1 面。
- **Undo / Hint を作らない**(盤面は完全に見えており、次の数字の位置を示す助けは
  ゲームの肩代わり。Sliding Puzzle と同じ理屈)。助けは即時・無料のリトライ。
- 保存キー: `st.progress` / `st.stats` / `st.flags`(数十秒のラウンドは途中保存しない —
  注意力の中断復元は意味を持たない。Bunny Hop §5 と同じ判断)。

### Number Recall(位置記憶)

- グリッドに数字タイルが表向きで出る。**制限時間はなく、覚える時間はプレイヤーが
  決める** — `1` をタップした瞬間に残りが伏せられ、以後は記憶だけで 2, 3, … と
  順にタップする(急かさないをこのジャンルで成立させる中心設計。見ていた時間も
  記録に含め、「早く始めるほど速いが不確か」というトレードオフ自体を遊びにする)。
- 誤タップでラウンド失敗: 正解配置を一拍見せてから、**同レベル・新配置**で即時・
  無料にリトライ(同一配置の再挑戦は「開示を暗記して勝つ」になり、記憶という中身を
  空にするため作らない — Memory Match が同一盤面再挑戦を選んだのと逆の結論になる
  理由をルール文書に書く)。
- レベル曲線: タイル数 3 → 12、グリッド 3×3 → 5×5(L1–15 3×3 / L16–55 4×4 /
  L56–100 5×5)。初回一発クリア率を統計に持つ(表示は事実のみ、煽らない)。
- デイリー: 日付シードの 1 課題。
- **Undo を作らない**(タップは記憶の主張そのものであり、取り消せるなら記憶を
  試していない)。**Hint を作らない**(位置を見せる助けは答えの開示)。
- 保存キー: `nr.progress` / `nr.stats` / `nr.flags`。

## 進め方(Phase)

1. **Phase 0 — ルール文書 3 本**を先に起こす(13 章テンプレート、この計画の骨子を
   正本化。効能非表示・時間設計の理由もここに書く)。
2. **Phase 1 — Schulte Table**(最小実装。ドリル系の結果画面・統計・レベル梯子の
   イディオムをここで確立する)。
3. **Phase 2 — Number Recall**(Phase 1 のグリッド + タップ基盤を写して伏せ札を足す)。
4. **Phase 3 — Quick Math**(キーパッド UI とレベル曲線が最大なので最後。3 本の中で
   唯一の途中保存を持つ)。
5. **Phase 4 — 接続と門**: registry / gameKeys / styles.css / titleAccents /
   size-baseline / landing.test「リンクなし」配列 / check-principles §6 の効能語追加 /
   i18n 14 言語 × 3 カタログ / README・ARCHITECTURE の収録数(**マージ時点の実数**に
   合わせる — FreeCell ブランチとどちらが先でも成立させる)/ Web 先行公開
   ([WEB_VERSION.md](../WEB_VERSION.md)。アプリ正式収録はストア公開設定で人間が決める)。

各 Phase の完了条件に **ブラウザでの試遊(ライト / ダーク両テーマ)** を含める。
2048 / Block Puzzle の教訓 —「動作テストが全部緑でも遊べるとは限らない」— を
このジャンルにもそのまま適用する。

## 検証

- ユニット: 各 `game/` の生成・判定・レベル曲線・シード決定性(golden)。
  Quick Math は「引き算が負にならない」「割り算が割り切れる」「虫食いの解が一意」を
  生成域全体で property テストする。
- 画面: Root テスト + lifecycle 掃引(自動編入)。Canvas なしのため leak テスト不要。
- i18n: `MessageKey` 型と `i18n.test.ts` の自動検証(キー欠落はビルドが落ちる)。
- 配色: 新 3 色 × 両テーマのコントラスト実測(BRAND 基準)+ ホームグリッドでの
  隣接確認(特にエメラルドのダーク値と 2048)。
- サイズ Gate: 3 チャンクとも gzip 15KB 以下を見込む(Bunny Hop 12.6KB より軽い構造)。

## 作らないもの

- **脳年齢・IQ・偏差値・「今日の脳の調子」**: 効能と診断の顔をした演出は全部作らない。
- **制限時間・タイムアタックモード**: 時間は記録であって圧力ではない。
- **ストリーク・連続日数**: 既存原則どおり。デイリーは達成日カレンダーのみ。
- **成績の他者比較・ランキング**: オンラインランキングは維持費の原則で禁止済み。
- **単語・クイズ系への拡張**: 14 言語のコンテンツ供給が `machine` 来歴と正面衝突する
  ため、このジャンルには入れない(検討記録は本計画に先行する提案の会話にある)。
- **広告・課金との接続**: 解き直し・リトライは全部無料。このジャンルは他社アプリで
  最も課金圧が強い場所であり、そこが全部無料であることがこの収録の差別化になる。
