# Hearts と Gin Rummy — 対戦カード2本の本実装計画 (2026-08-08)

カードの棚(Solitaire / Spider Solitaire / FreeCell)は 3 本すべてが 1 人用の
ペイシェンスである。ボードの棚で確立した CPU 対局の型(Reversi / Connect Four /
Checkers / Gomoku — 難易度 3 種・デイリーなし)をカードへ持ち込み、対戦カード
2 本で棚を広げる。Hearts と Gin Rummy はどちらも「名前で探される」定番で、ルールは
パブリックドメイン、配札も対局も端末内で完結し、コンテンツサーバーも絵素材も
必要としない([CONTRIBUTING.md](../../CONTRIBUTING.md) の収録条件。カードは
Solitaire と同じく DOM + インライン SVG スートで描く)。

既存の CPU 4 本と違い、この 2 本は**不完全情報**の対局である。ここはソース公開の
ブランドがいちばん効く場所でもある — クローズドソースのカードアプリは「CPU は
こちらの手札を覗いているのでは」と疑われ続けてきたが、このプロダクトは「CPU が
何を見て打つか」を型とテストで固定し、ルール文書に書き、コードで検証可能にする
(4 本の「探索がどこで走るか」の明記(`da308a6`)の続きである)。

検討の経緯: 対戦カードの候補のうち、Blackjack / Poker はストアの模擬ギャンブル
レーティングを引き、賭けの意匠がブランドと両立しないため見送った(テトリスを
権利リスクで見送った判断と同じく、遊び自体の出来と無関係の理由で落とす)。
大富豪 / President は日本では最強だがローカルルールの分裂が激しく、14 言語へ
「標準ルール」を一本で主張できない。Spades は CPU がパートナーになる遊びで、
意思疎通できない相棒はストレスの設計になる。Durak はロシア語圏の定番だが
ロケール外。ババ抜き・七並べは対 CPU では中身が薄い。残った Hearts(4 人
トリックテイキング)と Gin Rummy(2 人ドロー & メルド)は系統も被らない。

**この文書は着手前の実装計画である。**実装は未着手。仕様の正本は実装時に
`docs/HEARTS_RULES.md` / `docs/GIN_RUMMY_RULES.md` として起こし、以後はそちらが
勝つ。README の後続候補(Kakuro / Futoshiki / Takuzu)とは独立で、収録本数の
文言はマージ時点の実数に合わせる(Phase 4。現行 22 本 → この 2 本で 24 本)。

## 前提(調査済み)

**カードの作法は Solitaire(+ FreeCell / Spider)、対局の作法はボード 4 本が正本。**
2 本とも同じ骨格(`game/ state/ storage/ ui/ i18n/`)で作る。踏襲する設計は:

- **カードは整数**(`suit * 13 + (rank - 1)`)。`isValidBoard()` が 52 枚の存在
  一意性まで検証し、storage のバリデータがそれを再利用する。カード面は両テーマとも
  紙のまま。盤面幅は `width: min(100%, 420px)`(vw を使わない)。カードは
  `aspect-ratio: 5/7`、重なりは幅基準の負のマージン(%)。
- **`rng.ts`(xmur3 + mulberry32 + Fisher–Yates)はゲームごとにコピーが正**。配札も
  CPU の同点タイブレークもシード決定的(`createRng(` `` `${seed}:cpu:${moveCount}` ``
  `)` の同型)。ゴールデンテスト(`game/compatibility.test.ts`)を最初のコミット
  から敷く(「直すのは実装であってテストではない」の契約文込み)。
- **CPU の手番はセッション依存の effect + `CPU_DELAY_MS`(450ms)**。アンマウント・
  新規対局・画面遷移のどれでも cleanup がタイマーを外し、着地したタイマーは
  「いま本当に CPU の手番か」を ref で確かめてから打つ。難易度 3 種
  (easy / normal / hard)。長時間 CPU を占有する「強い CPU」は作らない。
- **統計は難易度ごと**に played / wins / losses(+ Hearts は draws)、全体で
  totalPlaySeconds。放棄は負けに数えない。プレイ時間は bookedRef 方式の逐次計上
  (可視時のみ加算。Root テストに背景化パターンを複製する)。時計はプレイ中に
  表示しない。
- **途中保存 1 スロット**(マッチ途中の点数・配り手・進行中ハンドの全体を含む)。
  デコードは fail-closed — プレイから生まれえない状態は破棄してホームへ戻る
  (勝手に新規対局を始めない)。終局済みの保存は破棄。
- マッチ勝利時のみ `recordGameCompleted()`(REVIEW_PROMPT_POLICY。ハンド勝利では
  呼ばない)。効果音は既存の合成音のみ。Reduced Motion で全停止。粒子も画面揺れも
  ない。ローカル対人戦・オンライン対戦は作らない(PRODUCT_PRINCIPLES)。

**ゲーム追加の接続点は調査済み**(2026-08-06 / 08-07 の追加コミットが実物)。ゲーム
フォルダを作ればチャンク・lifecycle 掃除・i18n ゲート・境界ゲート・サイズ計測は
自動編入。手で触るのは: `app/registry.ts`(union + keys import + cards 束に
2 要素)/ `app/gameKeys.test.ts`(ht / gr 行)/ `ui/styles.css`(アクセント
2 ブロック × 2 ゲーム)/ `packages/brand` の `titleAccents` /
`size-baseline.json`(`pnpm size:update`)/ `landing.test.ts` の「リンクなし」配列
(`ui/landing.ts` は触らない)/ 文書類(Phase 4)。

### この 2 本で初めて作るもの

- **不完全情報の CPU 視界契約**: cpu.ts の入力を `CpuView` 型(自席の手札 + 公開
  情報だけ)に限定し、他席の手札・山札の並び・伏せ札を**型の上で渡せなく**する。
  view を組み立てる関数のテストで隠し領域が落ちることを固定し、ルール文書に
  「CPU が見ているもの」の章を置く。探索上限の明記(4 本)に続く誠実性の明記で
  ある。
- **多段の CPU 手番連鎖**(Hearts): 既存 4 本は「あなたの 1 手 → CPU の 1 応手」
  だが、Hearts はあなたの 1 手のあと最大 3 席が順に出し、トリック解決を挟んで次の
  リードが CPU のこともある。連鎖は「着手で状態が変わるたび、いま CPU の手番なら
  1 本のタイマーを張る」effect の繰り返しで作る(ポーリングなし・先読みなし・
  cleanup は既存と同一)。保存復元の直後に CPU 手番から始まる場合も同じ effect が
  拾う。GAME_LIFECYCLE.md「CPU 探索」へこの形の 1 項を Phase 4 で追記する。
  Gin は同じ機構の最小形(ハンド開始時と自分の捨てのあとに、CPU がドロー + 捨ての
  2 拍で動く)。
- **手札ファン UI**: 13 枚(Hearts)/ 10–11 枚(Gin)を 420px 以下で重ねて並べ、
  タップで持ち上げ → 二度タップで確定。320px での 1 枚あたりのタップ幅が成立する
  かを Phase 2 冒頭に静的モックで実測し、不成立なら 2 段組み(7+6)に落とす
  (Gomoku の「実測してから確定」の前例。勝手に札を縮めない)。
- **Undo のない CPU 対局**: ボード 4 本の Undo は完全情報だから成立していた。
  ここでは CPU の応手を見てから戻せる Undo は情報の取り消せない漏れになる
  (Minesweeper の「取り消せるなら賭けが残らない」と同族の理由)。README の
  「助けの内容が…」段落へ 2 本の 1 文を足す(Phase 4)。

## ゲーム仕様の要点(ルール文書の骨子)

ルール文書は 2 本ともボード 4 本の章立て(盤面と対局者 / 一手の解決 / 終了条件 /
CPU / Undo(不在の理由) / 助けの形 / スコアと統計 / 中断と再開 / Quick Rules /
演出とアクセシビリティ / 意図的な差分)を踏襲し、「CPU が見ているもの」の章を
加える。以下は各章に入る決定。

### Hearts

- 4 人・52 枚・13 枚配り。パスは 3 枚(左 → 右 → 対面 → なし、ハンド番号の輪番)。
  CPU のパスもヒューリスティック(Q♠ 周りの整理・短スート作り)。
- 2♣ 保持者が 2♣ でリード。スート追い義務。初トリックは点札禁止(手札の都合で
  点札しか出せない端は例外 — 配られ得る端はテストで固定)。♥ のリードはブレイク
  後(手札が ♥ しかないときの例外込み)。トリックの勝者(リードスートの最大)が
  次をリード。
- ♥ 1 点 × 13・Q♠ 13 点。ムーン(26 点独占)は他 3 席に +26(自席 −26 の選択式は
  作らない — 意図的な差分)。ハンド終了時に誰かが 100 点以上で終局、最少点の勝ち。
  J♦ ボーナスなどの変則も採らない(意図的な差分に列挙)。
- CPU: 探索でなくヒューリスティック(できるだけ取らない・Q♠ の下落とし・危険
  スートの整理・ムーン検知と妨害)。easy は緩め、hard は公開情報のカード
  カウント込み。**hard の中身(強化ヒューリスティック or 決定化ロールアウト)は
  450ms 予算の実測で決め、採った方式と予算をルール文書に書く**(ボード 4 本の
  ノード上限明記と同じ扱い)。同点タイブレークはシード決定的。
- 演出: トリック 4 枚は中央に十字で置き、勝者へ寄せて畳む。CPU の着手間隔は
  450ms を起点に Phase 3 で体感実測(追えない速さと待たされる遅さの間)。直前の
  トリックの取り主に小さな印(ボード 4 本の「最後に動いた駒の印」の同型)。

### Gin Rummy

- 2 人・52 枚・10 枚配り・21 枚目が台札、残りが山。デッドウッドは A=1 /
  2–10 = 額面 / J, Q, K = 10。A は低位のみ(K-A-2 のランなし)。
- ハンド開始: 非配り手 → 配り手の順に台札の取得権、両者パスなら非配り手が山から
  引いて開始。ターンはドロー(山 or 捨て札の頭)→ 1 枚捨て。捨て札から取った札は
  同じターンに捨てられない。
- ドロー後にデッドウッド 10 以下ならノック可(宣言札は捨て札の頂点に**表で**置く
  — 物理の作法は「伏せて捨てる」だが、宣言と同時にハンドが終わるため情報漏れは
  なく、52 枚の保存則を型で保てる。意図的な差分に含める。2026-08-08 実装時決定)。
  ジン(デッドウッド 0)は +25。非ジンのノックへは相手がレイオフしてから差分を清算し、
  相手が同点以下ならアンダーカット(相手に差分 +25)。ジンへのレイオフはない。
  Big Gin は作らない(意図的な差分)。
- 山残り 2 枚でハンド無効・同じ配り手が配り直し。100 点先取で終局。ライン
  ボーナス・シャットアウト倍付けは作らない(マッチは 100 到達の一発 — 意図的な
  差分)。引き分けは存在しないので統計は難易度別 played / wins / losses。
- 自席のメルドは常に最適分割(デッドウッド最小)で自動整理して表示する
  (10–11 枚なら総当たりで足りる)。ノックボタンは可能なときだけ現れる。
- CPU: ドロー元の選択・安全な捨て札(公開情報 = 見えた捨て札と相手が拾った札)・
  ノック時期のヒューリスティック。難易度はその深さで分ける。決定性はシード。

### CPU が見ているもの(2 本共通)

- CPU が受け取るのは**自席の手札と、テーブルに公開された履歴だけ**(出された札、
  捨て札の並び、誰が何を拾ったか、点数)。他席の手札・山札の並び・伏せ札は型の
  上で渡らない。人間の熟練者が覚えていられる情報は CPU も覚えてよい(それ以上は
  持てない)。
- 配札はシード決定的だが、CPU はシードから配札を逆算しない(cpu.ts はシードを
  受け取らない。タイブレーク用の乱数列は配札と独立の系で渡す)。

### Phase 2 — Gin Rummy 本実装(大)

**先に 2 人の方から作る。**CPU 視界契約・手札ファン UI・Undo なしの助けという
新規 3 点を最小の席数(CPU 1 席)で確立してから、Hearts で連鎖手番だけを積む
(新しい作法を小さい方で敷くのは FreeCell → Spider の順の前例)。

- 冒頭に**手札ファンの静的モック実測**(320 / 360 / 420px × ライト / ダーク、
  10–11 枚)。1 枚のタップ幅が成立しなければ 2 段組みへ(本文書を更新してから)。
- `game/`: types(`CpuView` 含む)・rng(コピー)・cards(整数カード。Solitaire から
  コピー)・melds(最適分割 = デッドウッド最小化・レイオフ判定)・engine(台札の
  初手権・ドロー / 捨て / ノック / 清算 / ハンド無効 / マッチ進行)・serialize
  (fail-closed)・session・cpu・index。
- テスト: melds(最適性を総当たり参照実装と突き合わせ・A 低位のみ・レイオフ)、
  engine(台札の初手権・拾い札の即捨て禁止・ノック境界 10・アンダーカット・
  山 2 枚無効・100 到達)、cpu(3 難易度の決定性・`CpuView` に隠し領域がない
  こと)、session(保存再開・ハンドまたぎの点数・CPU 手番からの復元)、
  compatibility(v1 golden)。
- `state/`: GameContext(CPU タイマー effect・bookedRef 計上・visibilitychange +
  Capacitor pause・ハードウェア back)、statsLogic。`storage/`: keys(ゼロ
  import)・schemas・gamePersistence + テスト。
- `ui/`: GinRummyRoot(+ Root テスト: 背景化計上・初回 Quick Rules・時計の不在)、

| リスク                                   | 対処                                                                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 手札ファンが 320px で押せない            | 二度タップ確定を最初から設計に含め、Phase 2 冒頭の静的モックで実測。不成立なら 2 段組み(勝手に札を縮めない)                                     |
