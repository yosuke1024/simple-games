収録を 10 本から 12 本へ広げる。どちらも「名前で探される」タイトルで、生成も進行も
端末内で完結し、コンテンツサーバーを必要としない([CONTRIBUTING.md](../../CONTRIBUTING.md)
の収録条件)。

**Snake は作ったうえで落とした**(下記「試遊で落ちたもの」)。実装は残っており、
コミット `7a71849` から取り戻せる。

## 名前の選び方

`Blockudoku` / `Block Blast` は他社の商標なので採らない。ジャンル名の
**Block Puzzle** は検索需要が大きく、同じ収録の `Water Sort` `Sliding Puzzle` と同じ
「ジャンルそのものを名前にする」流儀に揃う。`2048` は原作がジャンル名になりきっている
ため、そのまま採用した([BRAND.md](../BRAND.md): タイトルは英語の固有名詞・全言語で
同一表記)。

| ゲーム       | アクセント | ライト    | ダーク    | 選んだ理由                                    |
| ------------ | ---------- | --------- | --------- | --------------------------------------------- |
| 2048         | ジェイド   | `#2b7d59` | `#79c39c` | Solitaire の緑と Sudoku のティールの間        |
| Block Puzzle | オーキッド | `#8b4f80` | `#c795bd` | Nonogram のプラムと Memory Match のローズの間 |

## 2 本の性格(同じ骨格・違う約束)

|          | 2048             | Block Puzzle     |
| -------- | ---------------- | ---------------- |
| 進行     | エンドレス       | エンドレス       |
| 途中保存 | あり(1 スロット) | あり(1 スロット) |
| 助け     | Undo 無制限      | Undo 無制限      |
| 保存キー | `tm.` 3 キー     | `bp.` 3 キー     |

**レベルの梯子を作らなかった。** アーケード 2 本は 100 レベルを持つが、この 2 本は
難しさが盤面自身から出てくる(タイルが埋まる・ピースが入らなくなる)。レベルを刻むと、
既にある緊張の上に人工的な区切りを重ねることになる。

## Undo をこの 2 本の中心に置いた

原作系アプリの収益は Undo・復活・追加ピースに集まっている。ここではそれが全部無料で、
無制限である。そのうえで**乱数を引き直さない Undo** を実装した: 新しいタイルもピースの
補充もシードと連番から決まるので、戻して同じ手を指せば同じものが出る。引き直せる Undo は
助けではなくスロットマシンになる([GAME_2048_RULES.md](../GAME_2048_RULES.md) §6 /
[BLOCK_PUZZLE_RULES.md](../BLOCK_PUZZLE_RULES.md) §7)。ブラウザで確認済み。

## 試遊で落ちたもの・直したもの

最初の版は「動くこと」しか確かめておらず、人が触ると 3 本とも落第だった。試遊で出た
指摘と、それぞれの原因は次のとおり。**動作テストが全部緑でも遊べるとは限らない**、が
この日いちばん高くついた教訓である。

### Block Puzzle — 手に何も持っていなかった(直した)

ドラッグ中、**指の下にピースが描かれていなかった**。トレイの元スロットが薄くなるだけで、
盤面に出るのは「置ける位置のゴースト」だけ。しかもそのゴーストは指より 1.5 マス上に、
低コントラストの色で出て、持ち上げ量はピースの高さによって変わり、置けない位置では
消えた。**狙っている最中に画面から手がかりが消える**という、いちばん困る作りだった。

直した内容(§3 / §12 に反映):

- 運んでいるピースを**盤面のマス目に吸着した実物として描く**。画面に出ているものが、
  離したときに起きること。
- **置けない位置でも描き続ける**。置ける = アクセントの面と枠、置けない = インクの枠。
  消えるのは盤面から完全に外れたときだけ。
- 持ち上げ量を全ピース共通の **1 行**に固定。「ピースは指の 1 行上に乗る」で言い切れる。

### 2048 — 数字の色が値を区別できていなかった(直した)

タイルの色をアクセント(ジェイド)の濃淡だけで作った結果、**プレイ時間の大半を占める
2 と 4 が空きマスとほとんど見分けられなかった**。ライトではほぼ白、ダークでは黒に沈む。
盤面が読めないので「同じ形の別物」に見える。

**1 タイトル 1 アクセントの例外**として、タイルのランプに色相の進行を許した。石 → ジェイド
→ ティール → 青 → 藍 → 菫 → プラム → ローズ → 金(2048)。Minesweeper の数字スケールや
Memory Match の 15 色シンボルと同じ「盤面はクロームではなくゲーム内容」という立て付けで、
[BRAND.md](../BRAND.md) にも例外として記録した。本家の彩度の高いオレンジは使わず、
シリーズの紙の上で成立する彩度に収めてある。各段は色相と明度の両方が動くので、色覚特性や
グレースケールでも順序が残る。

### Snake — 落とした

盤面にマス目がなく蛇と餌だけが平面に浮いていて「フィールド」に見えない、開始速度が
遅く長さ 3 から始まるので序盤に何も起きない、スコアも 1 点ずつしか増えない。ルール文書に
「静かなアクション」と書いた結果、静かすぎるものになった。ここは配色や 1 か所の操作では
なく、**遊びの設計そのものをやり直す必要がある**と判断し、今回の収録から外した。

実装・テスト・14 ロケールは `7a71849` に残っている。作り直すときは、盤面の見せ方
(マス目・フィールドの縁)と序盤のテンポ(初速・餌の価値)から決め直すこと。

## 実装中に決めたこと(ルール文書が決めていなかったもの)

- **中断した挑戦もベストに数える(2048)**。まだ遊べる盤面を「新しいゲーム」で置き換えた
  ときも `bestScore` / `bestTile` を確定させる。`played` だけ数えて記録を捨てるのは、
  12,000 点の盤面を置き換えた人にとって嘘になる。`recordGameCompleted()` は終局時のみ。
- **Block Puzzle は終局後に Undo できない**。終局で記録が確定し保存も消えているため、
  戻すと見せた統計を巻き戻すことになる。代わりに無料の新しい盤面を出す。
- **ピース表の並びは互換性契約**。保存には id が入るので、途中に足すと中断した盤面の
  ピースが別物になる。追記のみ、と表のヘッダーに書いた。
- **盤面のタップ標的は 42px**(8 列 × 360dp で取れる最大)。44px の目安には届かないが、
  ドラッグの起点であるトレイのピースは 88px を確保した。CSS に理由を残してある。
- **ゲーム内ホームのグリフは registry のタイルと同じ字にする**。タップしたタイルと同じ
  マークが出るのが自然で、2 つ用意する理由がない。

## Learn More を出さないようにした

`src/ui/landing.ts` は今まで**どの id でも URL を返して**いた。2 本のガイドはまだ
書かれていないので、公開済み id の明示リストに変え、未公開なら `null` を返す。
チュートリアルの最後に「詳しく見る」が出ないだけで、押すと自社サイトで 404 になる
ボタンよりずっと正直である。ガイドを書いたら、その id をリストに足すのが公開の手順になる。

## 共有キー `newGame` を追加した

既存の `tryAgain` は "Retry same board"(同じ盤面で再挑戦)で、毎回新しい盤面になる
この 2 本には成立しない約束だった。14 言語に `newGame` を足した。
