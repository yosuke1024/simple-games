# 2048 / Block Puzzle / Snake — 3本追加の記録 (2026-08-06)

収録を 10 本から 13 本へ広げる。3 本とも「名前で探される」タイトルで、生成も進行も
端末内で完結し、コンテンツサーバーを必要としない([CONTRIBUTING.md](../../CONTRIBUTING.md)
の収録条件)。

## 決定事項(ユーザー承認済み)

| 項目       | 決定                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| 収録       | 2048 / Block Puzzle / Snake の**3 本**(当初案は 2 本)                       |
| id         | `2048` / `block-puzzle` / `snake`                                           |
| 実装の分岐 | **作らない**。コードは Web 版とアプリ版で差を持たず、3 本とも両方に収録する |

[WEB_VERSION.md](../WEB_VERSION.md)「先行公開」(新作はまず Web 版で公開し、検証を経て
アプリへ正式収録する)は**変わっていない**。今回決めたのは、その段取りを**コードで
表現しない**ということである: registry の channel フィールドも、シェルの出し分けガードも、
BETA バッジも作らない。アプリの利用者の目にいつ触れるかは、ストアのリリース公開設定で
人間が決める — 出し分けの装置をアプリに持たせるより、公開そのものを止めるほうが単純で、
止め忘れが画面に出ることもない。

## 名前の選び方

`Blockudoku` / `Block Blast` は他社の商標なので採らない。ジャンル名の
**Block Puzzle** は検索需要が大きく、同じ収録の `Water Sort` `Sliding Puzzle` と同じ
「ジャンルそのものを名前にする」流儀に揃う。`2048` と `Snake` は原作がジャンル名に
なりきっているため、そのまま採用した([BRAND.md](../BRAND.md): タイトルは英語の固有名詞・
全言語で同一表記)。

見た目は真似しない。とくに 2048 は原作のサンド系の配色が有名だが、アクセントは
シリーズの空き色相から**ジェイド**を割り当てた。他社のゲームの見た目を借りないのは
ブランドの決まりであり、ここはその決まりが具体的に効いた場所である。

| ゲーム       | アクセント | ライト    | ダーク    | 選んだ理由                                     |
| ------------ | ---------- | --------- | --------- | ---------------------------------------------- |
| 2048         | ジェイド   | `#2b7d59` | `#79c39c` | 盤面がタイルで埋まる。Solitaire と Sudoku の間 |
| Block Puzzle | オーキッド | `#8b4f80` | `#c795bd` | Nonogram のプラムと Memory Match のローズの間  |
| Snake        | モス       | `#6d7a34` | `#b4bd6d` | Brick Breaker の黄土と Solitaire の緑の間      |

## 3 本の性格分け(同じ骨格・違う約束)

|          | 2048             | Block Puzzle     | Snake            |
| -------- | ---------------- | ---------------- | ---------------- |
| 進行     | エンドレス       | エンドレス       | エンドレス       |
| 途中保存 | あり(1 スロット) | あり(1 スロット) | **なし**         |
| 助け     | Undo 無制限      | Undo 無制限      | 即時リトライのみ |
| 保存キー | `tm.` 3 キー     | `bp.` 3 キー     | `sn.` 2 キー     |

**レベルの梯子を作らなかった。** アーケード 2 本は 100 レベルを持つが、この 3 本は
どれも難しさが盤面自身から出てくる(タイルが埋まる・盤面が詰まる・体が伸びる)。
レベルを刻むと、既にある緊張の上に人工的な区切りを重ねることになる
([SNAKE_RULES.md](../SNAKE_RULES.md) §7 に理由を残した)。

**Snake だけ途中保存を作らない。** リアルタイムの盤面は復元した瞬間に動き出すので、
保存として正直でない — Brick Breaker / Sky Fighter と同じ判断である。2048 と
Block Puzzle はターン制なので、開き直した盤面は保存した瞬間と同じ盤面になる。

## Undo をこの 3 本の中心に置いた

原作系アプリの収益は Undo・復活・追加ピースに集まっている。ここではそれが全部無料で、
無制限である。そのうえで、2048 と Block Puzzle には**乱数を引き直さない Undo** を実装した:
新しいタイルもピースの補充もシードと連番から決まるので、戻して同じ手を指せば同じものが
出る。引き直せる Undo は助けではなくスロットマシンになる
([GAME_2048_RULES.md](../GAME_2048_RULES.md) §6 /
[BLOCK_PUZZLE_RULES.md](../BLOCK_PUZZLE_RULES.md) §7)。ブラウザで実際に確認した:
Undo 後に同じ方向へ倒すと、盤面もスコアも spawnIndex も一致する。

## 実装中に決めたこと(ルール文書が決めていなかったもの)

- **中断した挑戦もベストに数える(2048)**。まだ遊べる盤面を「新しいゲーム」で置き換えた
  ときも `bestScore` / `bestTile` を確定させる。`played` だけ数えて記録を捨てるのは、
  12,000 点の盤面を置き換えた人にとって嘘になる。`recordGameCompleted()` は終局時のみ。
- **Block Puzzle は終局後に Undo できない**。終局で記録が確定し保存も消えているため、
  戻すと見せた統計を巻き戻すことになる。代わりに無料の新しい盤面を出す。
- **ピース表の並びは互換性契約**。保存には id が入るので、途中に足すと中断した盤面の
  ピースが別物になる。追記のみ、と表のヘッダーに書いた。
- **盤面のタップ標的は 42px**(8 列 × 360dp で取れる最大)。44px の目安には届かないが、
  ドラッグの起点であるトレイのピースは 88px を確保した。CSS に理由を残してある。
- **Snake の逆走無視は「最後に予約した向き」に対して判定する**。画面上はまだ右へ進んで
  いても、上を予約済みなら下は 180° として捨てる。

## Learn More を出さないようにした

`src/ui/landing.ts` は今まで**どの id でも URL を返して**いた。3 本のガイドはまだ
書かれていないので、公開済み id の明示リストに変え、未公開なら `null` を返す。
チュートリアルの最後に「詳しく見る」が出ないだけで、押すと自社サイトで 404 になる
ボタンよりずっと正直である。ガイドを書いたら、その id をリストに足すのが公開の手順になる。

## 共有キー `newGame` を追加した

既存の `tryAgain` は "Retry same board"(同じ盤面で再挑戦)で、毎回新しい盤面になる
3 本には成立しない約束だった。14 言語に `newGame` を足し、3 本の結果画面とリトライ操作は
そちらを使う。

## 検証

```
pnpm lint / pnpm typecheck            → 緑
pnpm --filter simple-games test        → 108 ファイル 1036 テスト 緑
pnpm build && pnpm build:web           → 緑
pnpm --filter simple-games size:check  → 緑(エントリは 90.7KB → 90.3KB と微減)
.github/scripts/check-principles.sh    → 緑
.github/scripts/check-dist-ads-separation.sh → 緑
```

ゲームチャンク(gzip): 2048 = 13.4KB / Block Puzzle = 12.7KB / Snake = 10.8KB。
いずれも 1 タイトル 500KB の予算に対して十分小さく、エントリは増えていない
(keys.ts の葉は 3 つ増えたが、他の変化と相殺した)。

ブラウザ(dev サーバー・モバイル幅)で 3 本とも通しで確認した:

- **2048** — 矢印キーで結合とスコア加算、Undo で盤面・スコア・spawnIndex が戻り、同じ手を
  指し直すと同じタイルが出る(§6)。
- **Block Puzzle** — タップ配置とドラッグ配置(ゴースト表示つき)、ライン消し 2 回、
  詰みで終局、`bp.saveGame` が終局で消え `bp.stats` に自己ベストが残る。
- **Snake** — スワイプ / キーで曲がり、逆走は無視、餌で伸びて加速、壁で終局。途中で
  ゲームを離れた挑戦のプレイ秒も計上された。
