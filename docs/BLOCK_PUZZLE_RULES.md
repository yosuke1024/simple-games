# Block Puzzle — 正式ゲームルール

このドキュメントが Block Puzzle の仕様の正本である。実装
(`apps/simple-games/src/games/block-puzzle/`)、テスト、Quick Rules はここに従う。
コードはここへ `§n` で言及する。挙動を変えるときは、同じコミットでこの文書を直す。

ブランド原則([PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md))はこの文書より上位にある。

ゲーム ID は `block-puzzle`、i18n キーの接頭辞は `block`、保存キーの接頭辞は `bp.` である。

## 1. 盤面とトレイ

- 盤面は 8×8 の 64 セル。各セルは空か埋まっているかの 2 状態しか持たない。
  埋まったセルは、置いたピースの族の色(§12)を**見た目として**持つ。判定(置ける・
  ラインが消える・終わる)は 2 状態だけを読み、色は読まない — 色は盤面が見せている
  絵なので一緒に持つが、規則ではない(`game/types.ts` の `Board` と `Tones`)。
- トレイには常に 3 つのピースが並ぶ。3 つすべてを置き切ると、次の 3 つが補充される。
- ピースは §6 のカタログから決まる形で、回転も反転もできない。**置く場所だけが選択で
  ある** — 回転を足すと詰みがほとんど起きなくなり、この遊びの緊張が消える(§13)。

## 2. 終了条件

- **終了**: トレイに残っているどのピースも、盤面のどこにも置けなくなったとき。
- クリアはない。エンドレスに続き、記録はスコアである(§5)。
- 遷移は `game/session.ts` の `status`(`'playing' | 'over'`)で一度だけ起きる。

## 3. 操作

- **ドラッグ**: トレイのピースを押さえて盤面へ運ぶ。運んでいる間、**ピースは盤面の
  マス目に吸着した実物として描かれる**。浮かせて指に追従させるのではなく、盤面の上に
  そのまま置かれた姿を見せる — 画面に出ているものが、離したときに起きることである。
- 持ち上げ量は **`DRAG_LIFT_ROWS` = 1 行、全ピース共通**。ピースの底辺が、指のいるマスの
  1 行上に来る。覚える規則は「ピースは指の 1 行上に乗る」の一文で、1 マスのピースでも
  5 マスの棒でも同じである。左右は指のマスを中心に置く。
- **置けない位置でも、ピースは消えない**。置ける位置ではアクセント色の面と枠で、
  置けない位置ではインクの枠だけで描く。**狙っている最中に画面から手がかりが消えるのが、
  この画面の最初の作りが失敗していた点である**(消えるのは、盤面から完全に外れたとき
  だけ)。
- **タップ**: ピースをタップして選び、盤面のセルをタップしても置ける。このとき、
  ピースの左上の埋まったセルがタップしたセルに来る。ドラッグできない環境
  (支援技術・外部入力)のための道であり、おまけではない。
- **置けない場所で離しても何も起きない**。ピースはトレイに戻り、音も鳴らない。
  盤面は変わらないので、間違いは無料である。離す前に置けないと分かるようになったので、
  ここで叱る必要はますますない。

## 4. ライン消し

- **消える予定のラインは、置く前に見える。** ピースを手に持っている間、その位置に置くと
  埋まりきる行・列があれば、その行・列全体が明るくなる。狙って消すのがこの遊びの中心
  であり、離してから結果を知るのでは狙えない。判定は実際の配置と消去をコピー盤面で
  走らせて出す(`clearPreview`) — 「どのラインが埋まるか」の実装を 2 つ持たない。
- ピースを置いた直後、埋まりきった行と列を**同時に**すべて消す。
- 行と列が同時に埋まったときも、まとめて 1 回の消しとして数える(§5 のボーナスは
  消えたライン数 n に対して 1 回だけ計算する)。
- 消えるのはラインだけである。3×3 ブロックは見ない(§13)。

## 5. スコア

- 置いたピースのセル数だけ 1 点ずつ加える(`1×cells`)。
- 同時に n ライン消したとき、追加で `10 × n × (n + 1) / 2` 点(1 本 = 10、2 本 = 30、
  3 本 = 60、4 本 = 100)。まとめて消すほど伸びるが、伸び方は二次までにとどめる —
  一発逆転を作ると、置き場所を選ぶ本来の判断が薄くなる。
- 連鎖ボーナス(コンボ)は持たない(§13)。
- 保存するのは自己ベスト(`bestScore`)だけ。ランキングはない。共有は結果画面の
  任意ボタンだけで、押したときにそのプレイのスコアと消したライン数を載せる
  (自己ベストは載せない)。

## 6. ピースのカタログと補充

- カタログは `game/pieces.ts` の固定表。1×1 から 3×3 まで 19 種:
  1×1 / 1×2 / 2×1 / 1×3 / 3×1 / 1×4 / 4×1 / 1×5 / 5×1 / 2×2 / 3×3 /
  2×2 の角(3 セル)4 向き / 3×3 の角(5 セル)4 向き。
- 補充は一様抽選で、**盤面を見ない**。置ける形を選んで助けることも、置けない形を選んで
  詰ませることもしない。抽選はシードと補充回数から決定的に決まる:
  `createRng(`${seed}:${batchIndex}`)`。
- したがって「配られた 3 つがどれも置けない」は正当な終了である(§2)。盤面を見て
  救う実装は、負けを演出に変えてしまう。
- ゴールデンテスト(`game/compatibility.test.ts`)がシード `block-golden` の最初の
  2 バッチを固定する。
- **色はカタログ自身の 4 つの族で決まる**(`game/tones.ts` の `TONE_BY_PIECE`、§12)。
  抽選は盤面も色も見ない — 色を足しても、配られる 3 つは 1 つも変わらない。色の番号
  (tone)は保存データに入るので(§10)、番号を付け替えたり別の色に使い回したりしない。

  | 族                  | id       | 置かれるマスの割合 | tone | 色                          |
  | ------------------- | -------- | ------------------ | ---- | --------------------------- |
  | 四角(1×1・2×2・3×3) | 0・9・10 | 19%                | 5    | 弁柄                        |
  | 棒(2〜5 マス)       | 1〜8     | 38%                | 3    | 青磁                        |
  | 小さい角(3 マス)    | 11〜14   | 16%                | 4    | 黄土                        |
  | 大きい角(5 マス)    | 15〜18   | 27%                | 2    | 藍                          |
  | (配らない)          | —        | —                  | 1    | アクセント(v1 の保存のセル) |

  割合は一様抽選での期待値(19 種で 74 マス。棒は 28 マス)。**いちばん多く置かれる族に
  いちばん静かな色**を当てた(青磁の彩度が最も低い)。

## 7. Undo

- **無制限・無料**。1 手戻すと、盤面・トレイ・スコア・`batchIndex` が置く直前へ戻る。
  消えたラインも戻る。履歴の上限は 2000 手(`UNDO_HISTORY_LIMIT`)。
- Undo は補充を引き直さない: 戻して同じピースを同じ場所に置けば、同じ結果になる。
- 広告視聴や課金による Undo は作らない([ADS_POLICY.md](ADS_POLICY.md))。原作系アプリと
  最も違うのはここである(§13)。

## 8. 助けの形

- 助けは Undo ひとつ(§7)。無料で、無制限で、初回起動から使える。
- Hint は作らない: 盤面もトレイも完全に見えており、隠れた情報がない。
- 詰みの回避・盤面の一部消去・追加のピースといった救済は作らない。終わったら新しい
  盤面が無料で始まる。

## 9. 統計

- `played`(開始した回数)・`bestScore`・`linesCleared`(累計)・`totalPlaySeconds` のみ。
  ストリークは数えないし表示しない。
- プレイ時間は逐次計上(bookedRef 方式): 画面を離れる・バックグラウンドへ回る・終局の
  各時点で、まだ計上していない秒だけを足す。
- 終局カードのベストスコアには、記録との差を符号付きで添える(`+120` = 記録を伸ばした /
  `−3` = 記録に届かなかった)。比べる相手は自分の記録だけで、記録がまだ無い(ベストが
  0 の)うちは何も添えない(`ui/components/BestDelta.tsx`)。

## 10. 中断と再開

- **途中保存する。** ターン制の盤面なので、開き直した盤面は保存した瞬間と同じ盤面である。
- 保存スロットは 1 つ(`bp.saveGame`)。盤面・トレイ・スコア・シード・`batchIndex`・
  経過秒を持つ。
- **盤面は 64 文字の数字**: `'0'` は空、`'1'`〜`'9'` は埋まったセルとその色(tone、§6・§12)。
  空いたセルの下に残る色(消えるラインの退色に使う)は保存しない。
- **v2(2026-10-29、ピースの色)が Block Puzzle で初めての移行**である。v1 の字母は
  `'0'`/`'1'` で、v2 はそれを `'0'`〜`'9'` に広げただけで、欄は増えない。v1 の `'1'` は
  アクセントで描かれていた = tone 1 なので、**移行は恒等**(文字列を 1 文字も書き換えない)。
  再開した盤面は、v1 のセルがアクセントのまま見え、ラインが消えるにつれて族の色に入れ替わる。
- v1 の記録は旧字母(`'0'`/`'1'`)のものだけを受ける。`'2'` などを含む v1 の記録はどの版も
  書いていないので、色として読まずに壊れた記録として捨てる。v2 の記録は `'0'`〜`'9'` を
  すべて受け、この版が塗らない番号(6〜9)はアクセントで描く — 色の数や族の割り当てを後で
  変えても v3 は要らず、新しい版の色のせいで盤面を失うこともない。数字以外は捨てる。
- v2 を含むバックアップを v1 の版へ戻すと、「新しい版のファイル」として拒まれる
  (`backup/restore.ts` の `newer`)。静かには壊れない。v1 の版が自分の保存として v2 を
  読んだ場合は、その盤面を捨てて新しい盤面から始める(版を戻したときだけ起きる)。
- 公開済みの記録(`storage/releasedRecords.test.ts`)は無編集で通る。移行そのものは
  `storage/v2Migration.test.ts` が同じ記録の文字列で確かめる。
- **Undo 履歴は保存しない**。再開した盤面はその局面から始まる。
- 初回の Quick Rules を終えると、中断中の盤面があればそれを再開する(新しく始めて上書き
  しない — フラグと保存は別々の記録なので、フラグの記録だけが失われたり読めなくなったり
  することがある)。
- 保存の失敗はゲームを止めない。壊れた保存は読み捨てて新しい盤面から始める。

## 11. Quick Rules(アプリ内チュートリアル)

3 ステップ・図中心・各 1 文(初回起動時に表示、以後はホームから):

1. 3 つのピースを盤面へ運ぶ — 回転はしない。
2. 埋まる行・列は運んでいる間に光る — 同時に消すほど点が伸びる。
3. どれも置けなくなったら終わり — Undo は何度でも無料。

詳細は Landing Page(`https://pixapps.ai/simple-games/games/block-puzzle/<locale>/`)へ。
ガイドを公開するまで「詳しく見る」は出さない(`src/ui/landing.ts`)。オフラインでは
何も起きない(ゲームは止めない)。

## 12. 演出とアクセシビリティ

- 置いたセルは 110ms で沈み込む: 運んでいたピースの輪がブロック自身の縁(上の光と
  下の影)へ溶け、面が族の色になる。遷移はブロックが**入るとき**だけで、持っているピースの
  輪と光るラインは即座に出る — 狙いが指に遅れないため。消えるラインは 150ms かけて、
  **わずかに持ち上がりながら**(6%。1 マス 42px で片側約 1.3px、隙間 2px の内側なので
  隣のマスに掛からない)薄くなって消える。盤から外されるタイルとして見せ、色が消灯する
  ようには見せない。消え方は**置いたピースを中心に外側へ 20ms 刻みでずれる**
  (`CLEAR_STAGGER_MS`)。配置と消去が 2 つの出来事ではなく 1 つの動きとして読めるように
  するためで、盤面が波を待つほどの遅れは作らない。要素は増やさない — 粒子も画面揺れもない。
  消えるラインが動かすのは不透明度と transform で、色のキーフレームは退色する面を描き直す
  ためだけに両端へ同じ値を書く(消えたセル自身の下地は `--surface` なので)。置いたときの
  110ms は背景色と box-shadow の遷移で、状態が変わったセルにだけ掛かる。指に付いて動く
  要素は無く(手のピースは盤のセルのクラスで描く — §3)、そこに filter などは掛けない。
- **ピースの色**(2026-10-29、製品オーナーの「ピースが一色でなく、もっとカラフルでも
  良いかも」を受けて): 置いたセルとトレイのピースは、カタログの 4 つの族ごとの顔料色で
  塗り、**置いた後も色が残る**(族と番号は §6)。同じ形の族は同じ色で、成形した積み木の
  論理にする — 1 個ずつランダムに塗らない(§13)。面はベタ塗りで、艶・グラデーションは
  付けず、**上 1px の光と下 2px の影**だけを持つ(Hanoi のトレイと同じ縁の語彙。ホームの
  絵の「上端のハイライトと影のあるブロック」と同じ物に見せる)。
  - **持っているもの = アクセント、置いたもの = 顔料**: 運んでいるピースの影(ghost)・
    選択中のスロットの枠・Quick Rules の図・ホームの絵はアクセント(オーキッド)のまま。
    Hanoi で持ち上げた円盤だけがアクセントになるのと同じ語彙で、置いた瞬間に 110ms で
    顔料の色へ移る。顔料はアクセントの色相族を避けた(最も近い藍でも ΔE 32.1 / 29.0)。
  - 光るライン(§4)は**各ブロックの色の上に白 45% のベール**を掛ける。光ったとたんに色が
    剥がれることはない。消えるラインは置いたときの色のまま薄れる(盤は消えたセルの色を
    退色が終わるまで持っている — §1 の `Tones`)。
  - 色は何の状態も運ばない。埋まっている/空は面の有無、置ける/置けないは面と枠、選択は
    枠で伝わる。そのため色覚特性のための記号や柄は足さない(Water Sort で「シールに
    見える」と退けた形)。
  - v1 の保存を再開した盤のセルは tone 1 = アクセントで描かれる(§10)。この版が塗らない
    tone(6〜9)もアクセントに落ちる。
  - 値はゲーム内容の色として `ui/block-puzzle.css` 冒頭のライト / ダークの 2 つのブロックだけに
    書く([BRAND.md](BRAND.md)「盤面が自前の色階調を持つ場合の例外」)。それ以外に色の
    リテラルは無い。

- 盤面はシリーズ共通の**紙の縁と浅い持ち上げ**で囲む。値は他の盤面ゲームと同じで、
  持ち上げを先に書いて紙の縁の上に描く:
  `0 3px 0 var(--line), 0 0 0 3px var(--paper), 0 0 0 4px var(--line), 0 8px 18px var(--accent-ring-soft)`。
  以前は汎用の影(`--shadow`)だけで、Takuzu や Nonogram などの盤が持つ縁が無かった。
- 空きセルは**上辺に 2px の影のある浅い凹み**(`--bp-well`)。ブロックは凹みにはまり、
  ラインが消えると凹みが戻る。トレイのスロットも同じ凹みで、選択中のスロットは
  アクセントの枠が、使い終えたスロットは平らな破線が代わる。スロットは押すと 1px 沈む
  (状態で、動きではない)。沈むのは押せるスロットだけで、使い終えたスロット(無効の
  ボタン)は押しても沈まない — 沈むと、まだ使えるように見えるため。
- 補充された 3 つのピースは、トレイに**置かれる**(220ms で沈み込む)。出現ではなく
  到着として見せる。
- スコアは数え上がり、動いた瞬間だけアクセント色をまとう(260ms)。画面に要素は
  足さない — すでにある数字の質感だけを上げる。
- Reduced Motion(アプリ設定または OS)では消滅演出をスキップし、盤面は即座に更新する。
  置いたときの 110ms の遷移も止める(`block-puzzle.css` の末尾で、OS の
  `prefers-reduced-motion` とアプリの `data-reduced-motion` の両方に規則を持つ)。
  **ドラッグ中の「手にあるピース」は演出ではなく操作の一部**なので、Reduced Motion でも
  常に描く。置ける/置けないの区別も色だけに頼らず、面の有無と枠で示す(§3)。
- ドラッグ中はスクロールを殺す(`touch-action: none`)。ピースとセルのタップ標的は
  44px 以上を確保する。
- 盤面は `role="group"`、セルは「埋まっている / 空」を、トレイのピースは大きさを
  読み上げる。色だけで状態を伝えない(埋まったセルは面で塗る)。
- 効果音は既存の合成音(`services/sound`)のみ: 設置で `select`、ライン消しで `clear`、
  終局で `gameOver`。設定に従う。
- **同時に消えた列の数で `clear` の高さが変わる**: 1 列は素のアルペジオ、2 列以上は
  1 列増えるごとに音階を 1 段上がり、最後の 3 音が和音として重なる。2 列同時は
  「消しが 2 回」ではなく 1 つの出来事なので、音も 1 つで言う。
- **置けなくなってから結果カードが出るまでに約 1 秒置く**(`ui/useResultReveal.ts`)。
  埋まった盤面を見る時間であり、その間に押せるものはない。Reduced Motion では
  従来どおり即時に出す。
- **時計を出さない**。経過時間は統計にだけ残る。

## 13. 意図的な差分

同ジャンルの人気タイトル(Blockudoku、Block Blast など)を調べたうえで、意図的に
合わせないものを記録する。**名前・盤面・配色を似せない**のはシリーズの決まりである
([BRAND.md](BRAND.md))。

**ブランド原則により合わせないもの**

- **広告や課金で Undo・復活・追加ピースを売らない**。原作系アプリの収益はここに集まって
  いるが、この収録では助けが無料であること自体がブランドの約束である(§7、§8)。
- **インタースティシャル広告を出さない**。終局は広告の合図ではない。アプリ版はバナー
  1 枠だけ、Web 版は共通のルールに従う([ADS_POLICY.md](ADS_POLICY.md))。
- ランキング・フレンドはない。記録は端末の中だけにあり、外へ出るのは本人が
  結果画面の「共有」を押したときのそのプレイの数字だけ。
- デイリーやストリークで毎日呼び戻さない。

**設計判断として合わせないもの**

- **3×3 ブロック消しを採用しない**。Sudoku 風の 3×3 消しは同じ収録の Sudoku と紛らわしく、
  行・列だけの方がルールが 1 文で言い切れる(§4)。
- **コンボ倍率を持たない**。連続で消し続けることへの倍率は、盤面を読む判断より
  「途切れさせない」焦りを作る。人工的な緊急性を持ち込まない原則に沿わない。
- **回転を作らない**(§1)。置く場所だけが選択であることが、この盤面の緊張である。
- **色はピースの族で決まり、ランダムに塗らない**(2026-10-29、§6・§12)。ピースを 1 個ずつ
  違う色で塗る方式も、飽和した虹色の配色も採らない。同じ族は同じ顔料で、艶も
  グラデーションも付けない。色数も族の数(4)にとどめる — 色数を稼ぐために族を割らない。
- **色はルールに関与しない**。同色をそろえて消す・色でボーナスを付ける、は採らない
  (コンボ倍率を持たないのと同じ理由)。
- 色を足したことで撤回した記録済みの決定は無い。§1 の「2 状態」はそのまま残し、
  `game/types.ts` の「盤面が見せないものは持たない」という理由も変わらない — 色は盤面が
  見せているものなので持つ。
- **デイリーなし**。生成はシード決定的なので、必要になれば後から足せる。

## 14. Club House

正典は [architecture/club.md](architecture/club.md) §6・§16。ここにはこのゲームの側で決まることだけを書く。

- **順位の軸は点数。** `challenge/contract.ts` は `order: 'score'`、高いほどよい。軸にする値はゲームオーバー画面の点数(`score`)。
- **表を分けるもの。** mode を持たない(`params` は `{}`、表は `standard` の 1 枚)。
- **結果画面が送る事実**は `{ score, lines }`(消したライン数 `lines` も同じ画面の値)。共有(`ShareAction`)の `details` と同じ変数から作り、ここで計算しない。
- **ピースの出方は局ごとに違うが、それでよい**(club.md §16)。順位表は同じ盤面で競わせるものではない。勝利数の表は作らない。
- 終局した局は `outcome: completed` で送る。
- それ以外は変わらない。統計・自己ベスト・保存データ・広告・共有の挙動に触れない。
