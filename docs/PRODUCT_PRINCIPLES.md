# Simple Games — プロダクト原則

Simple Games シリーズの全タイトルは以下を守る。これはブランドプロミスであり、
個別ゲームの都合で破ってはならない。

## 必須原則

- アプリ内課金なし / サブスクリプションなし
- アカウント登録なし / ログインなし
- ゲームの全機能をオフラインで利用可能(**初回起動から**)
- ゲームデータは端末内に保存。クラウド同期なし
- オンラインランキングなし
- 広告を見なくてもゲームを最後まで遊べる(Hint / Undo を含む)
- 広告取得を待つ必要がない。広告取得失敗でゲームが停止しない
- API サーバーなし / アプリ用データベースなし / コンテンツ配信サーバーなし
- 継続的なゲームイベント運営なし

## 維持費の原則

以下の有料インフラを使用しない。

独自 API サーバー / アプリ用クラウド DB / ユーザー認証基盤 / クラウドセーブ /
オンラインランキング / マッチングサーバー / Push 通知配信サーバー / 独自分析サーバー /
AI API / CMS / 定期実行ジョブ / 有料問題生成 API / 有料ゲームバックエンド

既存の Google Play・Apple Developer・GitHub・Firebase 無料枠などを除き、
追加の固定インフラ費を発生させない。無料枠超過時に自動課金される構成に依存しない。

## 初回体験の原則

初回起動時に求めてはならないもの:

ログイン / メールアドレス / ニックネーム / プロフィール / 通知許可 / 課金 /
サブスクリプション / レビュー投稿 / 不要なアンケート

説明(How to Play)は 3 ステップ以内。説明後すぐゲームを開始する。
広告同意が法的に必要な場合でも、ゲーム初期化と切り離し、同意処理の失敗で
ゲームを停止させない。

## UI / UX の原則

- シンプル・静か・読みやすい・操作が予測可能
- ゲーム盤を最優先。不要な情報・演出を表示しない
- ユーザーを急かさない。ログインストリークを強制しない
- Reduced Motion 有効時は不要なアニメーションを停止する

## エンジニアリングの原則

- ゲームロジックは UI / 広告 / Firebase / Capacitor に依存しない Pure TypeScript
- 依存方向は `apps → packages` のみ。循環依存禁止
- 一度しか使われていないコードを共通化しない(第 2 弾で重複が確認されてから抽出)
- 巨大な共通ゲームフレームワークを作らない
- あるゲームのリリースが別ゲームのリリースを強制しない
- ストア公開は明示的な手動実行またはタグを必要とする
- 実施していない検証を成功扱いにしない

## 初期リリースで実装しないもの

対人戦 / オンラインランキング / フレンド / チャット / シーズン / 期間限定イベント /
ログインボーナス / 課金アイテム / ガチャ / バトルパス / ユーザープロフィール /
クラウド同期 / ソーシャルログイン / AI 機能 / オンライン問題配信 / Coming Soon 表示 /
Push 通知 / ローカル通知 / Rewarded 広告 / App Open 広告 / Native 広告
